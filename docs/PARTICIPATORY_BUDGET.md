# PARTICIPATORY_BUDGET — 참여예산

> 기준 v9.0 · 2026-11-14 · 상태: PHP 서버(`CG\Service\Budget`), 관리자 화면, 게임 화면(작전 본부 → 도시 살림 → 참여예산) 구현. 로컬 테스트 DB에서만 돌려 보았고 운영에는 배포하지 않음. **꺼진 채로 들어감** (`budget.enabled = 0`) · 투표 기간과 정족수는 확정 전의 초기값

## 1. 방향

우리 도시의 재정([CITY_TREASURY_SYSTEM](CITY_TREASURY_SYSTEM.md))을 어디에 쓸지 주민이 제안하고 투표로 정합니다. 게임 안의 교육용 활동이고, 실제 돈과 이어지지 않습니다.

```
예산 제안 → 제안 검토 → 주민 투표 → 결과 확정 → 예산 집행 → 집행 내역 공개
 (주민)     (관리자)     (주민)     (자동)      (관리자)     (누구나 봄)
```

지키는 원칙:

1. **한 사람이 한 표.** 가진 GC, 낸 세금, 레벨, 기여도는 표의 무게에 들어가지 않습니다. 표의 무게를 담는 열 자체가 없습니다 (`city_budget_votes`에는 누가, 어느 제안에, 찬성·반대만 있습니다).
2. **한 계정은 한 제안에 한 번.** 바꿀 수 없습니다.
3. **나이를 묻지 않습니다.** 미성년자도 그 도시의 주민이면 제안하고 투표할 수 있습니다. 나이·실명·실제 주소를 받지 않습니다.
4. **제안은 검토를 거친 뒤에만 공개됩니다.** 부적절한 글이 그대로 다른 주민(어린이 포함)에게 보이지 않게 합니다.
5. **결과는 숨기지 않습니다.** 투표 수, 결과, 집행 내역이 그 도시를 보는 누구에게나 보입니다.

## 2. 상태

| 상태 | 뜻 | 누구에게 보이는가 |
|---|---|---|
| `submitted` 검토 대기 | 주민이 냄 | 제안한 사람, 관리자 |
| `rejected` 반려 | 관리자가 돌려보냄. 사유는 제안한 사람에게만 보임 | 제안한 사람, 관리자 |
| `withdrawn` 철회 | 검토 전에 제안한 사람이 거둠 | 제안한 사람, 관리자 |
| `voting` 투표 중 | 관리자가 승인. 투표 기간과 정족수가 이때 정해짐 | 누구나 |
| `passed` 가결 | 투표가 끝났고 통과 | 누구나 |
| `failed` 부결 | 투표가 끝났고 통과하지 못함 | 누구나 |
| `executed` 집행 완료 | 도시 재정에서 나감. 집행 내역과 이어짐 | 누구나 |
| `cancelled` 취소 | 투표 중이거나 가결된 뒤에 관리자가 취소 (규칙을 어긴 글이 뒤늦게 발견된 경우 등) | 제안한 사람, 관리자 |

## 3. 제안

- **누가:** 전입신고를 한 주민, 레벨 `proposerMinLevel`(3) 이상. 자기 주거 도시에만.
- **무엇을:** 분야(예비비를 뺀 여섯 분야), 제목(1~60자), 설명(600자까지), 금액(1 ~ `maxRequestGc` 50,000 GC). 분야가 공동 방어시설이면 어느 시설인지, 방어시설 유지보수이면 어느 주요 시설인지 고릅니다.
- **한 번에 하나:** 검토 대기·투표 중인 제안이 `maxOpenProposalsPerPlayer`(1)개 있으면 새로 낼 수 없습니다.
- 제어 문자는 받지 않고, 화면에 낼 때 모두 이스케이프합니다.
- 검토 전에는 거둘 수 있습니다 (`POST /cities/budget/proposals/{id}/withdraw`).

**게임 화면의 제안:** 클라이언트에는 글자를 입력하는 화면이 없어서, 분야·대상·금액(1,000 / 3,000 / 5,000 / 10,000 / 30,000 GC 가운데 한도 안의 것)을 고르면 제목과 설명이 정해진 문장으로 만들어집니다. 자유롭게 쓴 글이 없으니 검토할 것도 적습니다. 서버는 자유로운 글을 받을 수 있게 되어 있습니다 (입력 화면이 생기면 검토 절차가 그대로 쓰입니다).

## 4. 검토

관리자(`budget.manage` 권한: 최고 관리자, 운영 담당, 고객 지원)가 "참여예산 관리"에서 봅니다.

- **승인** → `voting`. 그 순간부터 `voteDays`(7)일 동안 투표. 정족수(`quorumVotes`, 5표)는 이때의 설정값이 제안에 적히고, 나중에 설정이 바뀌어도 그 제안의 정족수는 바뀌지 않습니다.
- **반려** → `rejected`. 사유는 제안한 사람에게만 보입니다.
- 둘 다 사유를 적어야 하고 감사 기록(`budget.approve`, `budget.reject`)에 남습니다.
- 참여예산이 꺼져 있으면 승인할 수 없습니다.

검토에서 보는 것은 **글이 적절한가**입니다 (욕설, 개인정보, 실제 돈·실제 사업과 헷갈리게 하는 내용). 좋은 제안인지 아닌지는 주민이 투표로 정합니다.

## 5. 투표

- **누가:** 그 도시의 주민, 레벨 `voterMinLevel`(2) 이상, 전입한 지 `voterMinResidentDays`(3)일이 지난 사람. 투표만 하려고 방금 만든 계정이나 방금 이사 온 계정은 투표할 수 없습니다.
- **어떻게:** 찬성 또는 반대. 한 번 하면 바꿀 수 없습니다.
- 투표할 수 없으면 목록이 그 이유를 알려 줍니다 (`can_vote`, `vote_block_reason`, `vote_block_message`): `not_voting`, `already_voted`, `not_resident_here`, `level_too_low`, `resident_too_new`, `budget_disabled`.

### 중복 투표 방지

1. `city_budget_votes`의 `(proposal_id, player_id)`가 유일 키입니다. 마지막 방어선입니다.
2. 투표할 때 제안 행을 잠급니다. 마감 처리와 겹치지 않습니다.
3. 요청에 멱등 키(`Idempotency-Key`)가 붙습니다. 같은 요청이 다시 오면 처음 응답을 돌려줍니다.
4. 같은 계정이 동시에 여러 번 눌러도 한 표만 들어갑니다 (`tests/ConcurrencyTest.php`).

이사해서 다른 도시의 주민이 되면 새 도시에서 `voterMinResidentDays`일이 지나야 투표할 수 있습니다. 이전 도시에서 이미 한 투표는 그대로 남습니다.

## 6. 결과 확정

투표 기간이 끝나면 예약 작업(`bin/tick.php`)이 확정합니다 (목록을 열 때에도 확인합니다).

- **가결:** 찬성이 반대보다 **많고**, 찬성 + 반대가 정족수 이상.
- **부결:** 그 밖의 모든 경우. 같은 수이면 부결.
- 집계 열(`yes_count`, `no_count`)을 믿지 않고 **표를 직접 세어** 확정합니다.

## 7. 집행

가결된 제안을 관리자(`treasury.execute` 권한: 최고 관리자, 운영 담당)가 집행합니다. 자동으로 집행되지 않습니다.

- 도시 재정의 **일반 회계**에서 나갑니다. 예비비로는 집행할 수 없습니다.
- 잔액이 모자라면 집행되지 않고 제안은 `passed`로 남습니다. 세금이 더 걷힌 뒤에 다시 집행할 수 있습니다.
- 분야의 효과는 [CITY_TREASURY_SYSTEM](CITY_TREASURY_SYSTEM.md) 4장과 같습니다. 실제로 쓰인 만큼만 빠집니다.
- **제안 하나는 한 번만 집행됩니다.** 제안 행을 잠그고 상태를 확인한 뒤, 집행과 상태 변경(`executed`)을 하나의 거래로 합니다. 동시에 두 번 눌러도 한 번만 나갑니다.
- 집행 내역(`city_budget_expenditures`)에 `proposal_id`가 적혀, 공개되는 내역에서 "주민 투표로 정한 예산"으로 보입니다.

## 8. API

| 요청 | 내용 |
|---|---|
| `GET /cities/budget/options` | 분야, 고를 수 있는 시설, 금액 한도, 제안·투표 자격, 투표 기간, 정족수 |
| `GET /cities/{code}/budget/proposals` | 그 도시의 공개된 제안과 내가 낸 제안 |
| `GET /cities/budget/proposals/{id}` | 제안 하나 (집행되었으면 집행 내역도) |
| `POST /cities/budget/proposals` | 제안 (멱등 키) |
| `POST /cities/budget/proposals/{id}/vote` | 투표 (멱등 키) |
| `POST /cities/budget/proposals/{id}/withdraw` | 검토 전의 내 제안을 거둠 |

형식은 [API_SPEC](API_SPEC.md) 20장. 누가 어디에 투표했는지를 돌려주는 API는 없습니다 (내 투표만 `my_vote`로 보입니다). 관리자 화면에도 개인별 투표 내용은 나오지 않습니다.

## 9. 운영 설정 (`game_config` 의 `budget`)

`enabled`(0), `voteDays`(7), `quorumVotes`(5), `voterMinLevel`(2), `voterMinResidentDays`(3), `proposerMinLevel`(3), `maxOpenProposalsPerPlayer`(1), `maxRequestGc`(50,000). "참여예산 관리" 화면에서 `city.policy` 권한으로 고치고, 범위 검증·사유·이력이 남습니다.

## 10. 테스트

`server/tests/BudgetTest.php` ([TEST_PLAN](TEST_PLAN.md) 15장): 꺼져 있음, 제안 자격과 값 검증, 검토 전에는 숨김·반려 사유는 본인만, 한 계정 한 표·바꿀 수 없음, 그 도시의 자격 있는 주민만, GC·세금·레벨과 무관한 한 표, 가결 조건과 정족수, 같은 수는 부결, 한 번만 집행·공개, 잔액 부족, 관리자 취소. `ConcurrencyTest.php`: 동시 투표, 동시 집행.

## 11. 남은 일

- 켜는 것은 운영 결정. 세금이 켜져 재정이 쌓인 뒤에야 의미가 있음.
- 정족수를 도시의 주민 수에 맞추는 방식 (지금은 고정 숫자).
- 게임 화면의 글 입력, 제안에 대한 의견.
- 여섯 분야 가운데 넷(인프라, NPC 복지, 교육, 행사)은 집행해도 기록만 남음.
- 투표가 끝난 제안의 알림 (지금은 목록을 열어야 보임).
