# HUNT_MODE — 헌트 모드 (3인칭 사냥)

> 기준 v8.0 · 2026-11-13 · 상태: v6.0의 3인칭 사냥을 그대로 두고 도시 위험도 연동을 더함. 서버는 사냥 보고의 검증·보상·위험도 반영을 구현 (아이템 드롭은 서버에 아직 없음). Unity 쪽은 형식 검사만 통과했고 실행해 보지 못함
>
> 조작, 무기, 피해 계산, 적의 행동, 보상 검증의 자세한 내용은 v6.0 문서에 그대로 있습니다: [COMBAT_SYSTEM](COMBAT_SYSTEM.md) 1~11장, [ENEMY_AI](ENEMY_AI.md), [ITEM_SYSTEM](ITEM_SYSTEM.md). 이 문서는 세 전투 모드 안에서의 자리와 v8.0에서 더한 것을 적습니다.

## 1. 방향

헌트 모드는 캐릭터를 3인칭으로 직접 움직여 도시 주변의 로봇을 사냥하는, 이 게임의 기본 전투입니다. v8.0에서 바꾼 것은 하나입니다: **사냥이 도시를 위한 일이 됩니다.** 사냥한 만큼 소속 도시의 위험도가 조금 내려가고, 위험한 도시일수록 사냥터가 거칠어집니다.

기존의 사냥 코드(`HuntZone`, `PlayerController`, `PlayerCombat`, `EnemyAgent`)는 고치지 않고, 모드 컨트롤러(`HuntModeController`)가 옆에서 위험도를 읽고 알립니다.

## 2. 진행

| 단계 | 내용 |
|---|---|
| 나서기 | 도시를 걸어 전투 구역으로 들어갑니다. 따로 입장 절차가 없습니다 |
| 사냥 | 로봇이 구역 안에 나타나고, 쓰러뜨리면 잠시 뒤 다시 나옵니다 |
| 보고 | 처치는 몇 초에 한 번 묶어서 서버에 보고합니다 (순번이 있어 다시 보내도 두 번 지급되지 않습니다) |
| 보상 | 서버가 인정한 처치만큼 GC와 경험치. 사냥 GC에는 하루 한도 3,000 GC가 있고, 한도를 넘어도 경험치는 받습니다 |
| 도시 | 인정된 처치 10마리마다 소속 도시의 위험도가 내려가고 기여도가 1 쌓입니다 |

### 사냥 구역

| 구역 | 나오는 적 | 동시에 | 다시 나오는 시간 | 분당 인정 한도 |
|---|---|---|---|---|
| 집 앞 거리 (튜토리얼) | 오작동 로봇 (약한 것) | 1 | 다시 나오지 않음 | 2 |
| 북동 전투 구역 | 오작동 로봇 | 5 | 8초 | 24 |
| 북서 전투 구역 | 기계 곤충, 오작동 로봇 | 9 | 6초 | 50 |

## 3. 조작과 카메라

| 입력 | 동작 |
|---|---|
| WASD | 이동 (카메라가 보는 쪽 기준) |
| 마우스 | 시점 돌리기 |
| 마우스 왼쪽 | 공격 (누르고 있으면 이어서) |
| 1 · 2 | 무기 바꾸기 (스파크 배턴 / 볼트 블래스터) |
| 3 | 회복 아이템 쓰기 |
| Space / Shift | 점프 / 달리기 |
| E | 상호작용 |

카메라는 3인칭(`OrbitCamera`)입니다. 지시서의 `ThirdPersonCamera`에 해당하며, 기존 코드와 테스트가 쓰는 이름이라 바꾸지 않았습니다.

**FPS 모드와 함께 쓰는 것:** 이동(`PlayerController`), 체력(`Health`), 적(`EnemyAgent`와 적의 행동 규칙), 보상 알림(`RewardService`). FPS 모드는 여기에 1인칭 카메라와 장착 장비로 쏘는 무기(`FpsWeapon`)만 바꿔 끼웁니다 ([COMBAT_SYSTEM](COMBAT_SYSTEM.md) 13장).

## 4. 위험도와 사냥

### 4.1 사냥이 위험도를 내린다

```
인정된 처치가 10마리 쌓일 때마다 (huntKillsPerStep)
  위험도 −1 (가중치 hunt_completed −100)
  도시 기여도 +1
```

- 10마리에 못 미친 나머지는 다음 보고로 넘어갑니다 (`player_combat_state.hunt_kill_carry`). 구역을 옮기거나 다시 접속해도 이어집니다.
- **조금만 내립니다.** 방어전 승리 한 번(−6)이 사냥 60마리와 같습니다. 사냥은 평소에 도시를 돌보는 일이고, 침공은 방어전과 FPS 임무로 막아야 합니다.
- 사냥은 침공의 진행도를 올리지 않습니다.
- 사냥은 **언제나 소속 도시**에 반영됩니다. 다른 도시를 지원하는 중이어도 같습니다 (사냥터는 내 도시에 있습니다).
- 이방인(전입하지 않은 플레이어)의 사냥은 보상만 받고 어느 도시에도 반영되지 않습니다.
- 다른 활동과 같은 제한을 받습니다: 활성 가디언이 20명을 넘는 도시에서는 한 사람의 몫이 그만큼 줄고, 한 사람이 하루에 내릴 수 있는 위험도는 모든 활동을 합쳐 20까지입니다 ([CITY_RISK_SYSTEM](CITY_RISK_SYSTEM.md) 4.2).

응답의 `city`에 반영된 내용이 들어 있고, 화면에는 "○○ 위험도 24 → 23" 같은 알림이 뜹니다.

### 4.2 위험한 도시의 사냥터

소속 도시의 단계에 따라 사냥터가 달라집니다.

| 단계 | 로봇 | 사냥의 효과 | 알림 |
|---|---|---|---|
| 안전 · 주의 | 평소대로 | 10마리에 −1 | — |
| 위험 | 구역마다 동시에 나오는 수 +1 | 10마리에 **−2** (`huntHighRiskPercent` 200%) | "위험 구역 소탕 임무!" |
| 긴급 | 구역마다 동시에 나오는 수 +2 | 10마리에 **−2** | 같음 |

- 위험 단계 이상에서의 사냥이 지시서의 "위험 지역 특별 사냥 임무"입니다. 지금은 **같은 사냥터에서 조건만 달라지는 것**이고, 따로 목표와 보상이 있는 임무는 아닙니다.
- "더 강한 적"은 지금 **더 많은 적**입니다. 새 종류의 적이나 강화된 수치는 없습니다. 분당 인정 한도는 그대로이므로 로봇이 늘어도 보상의 상한은 같습니다.
- 서버는 사냥 구역 목록과 사냥 시작 응답에 지금의 단계, 특별 임무 여부, 효과 비율을 넣어 줍니다 (`stage`, `special`, `risk_reduce_percent`). 로봇을 얼마나 더 낼지는 클라이언트가 정하고, 보상과 위험도 반영은 서버가 정합니다.
- 도시가 안정을 되찾으면 "도시가 안정을 되찾았어요" 알림과 함께 평소로 돌아갑니다.

## 5. 서버

| 항목 | 내용 |
|---|---|
| 검증 | [COMBAT_SYSTEM](COMBAT_SYSTEM.md) 10.1의 규칙을 PHP로 옮김 (`server/src/Domain/Hunt.php`). 구역에 나오지 않는 적, 분당 한도를 넘는 처치는 인정하지 않음. 걸린 시간은 서버가 잼 |
| 보상 | 적 정의의 값으로 서버가 계산. 원장 사유 `hunt_reward`. 하루 한도는 한국 날짜 기준 |
| 재전송 | 같은 순번(`seq`)을 다시 보내면 처음 응답을 그대로 돌려줌. 순번이 건너뛰면 `409 CONFLICT` |
| 위험도 | `CityService::applyHunt` |
| API | `GET /hunt/zones`, `POST /hunt/sessions`, `POST /hunt/sessions/{id}/report` ([API_SPEC](API_SPEC.md) 15장) |
| 테이블 | `hunt_zone_defs`, `hunt_sessions` |
| 관리자 | "적 유닛" 화면에서 적의 수치와 보상, 사냥 구역의 동시 수·다시 나오는 시간·분당 한도. 사냥의 위험도 효과는 "위험도 계산 정책" |

## 6. 구현 상태와 한계

| 항목 | 상태 |
|---|---|
| 기존 3인칭 사냥 | v6.0 그대로 (Unity에서 확인된 것은 v6.0 시점까지) |
| 위험도 연동, 위험 단계의 사냥터 | 구현. **Unity에서 실행해 보지 못함** |
| 서버의 사냥 검증·보상·위험도 | 구현, 테스트 통과 |
| 아이템 드롭 | **서버에 없음.** 응답의 `drops`는 빈 목록, `inventory`는 `null`. v6.0의 드롭과 가방은 클라이언트 모의 서버에만 있음 |
| 특별 사냥 임무 | 조건 변화뿐. 전용 목표·보상 없음 |
| 더 강한 적 | 수만 늘어남 |
| 사냥 세션의 끝 | 세션을 닫는 API가 없음. 오래된 세션은 그대로 남음 (정리 작업 필요) |
