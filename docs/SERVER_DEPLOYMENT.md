### 접속 정보 준비

조사를 위해 다음을 이 PC의 환경변수로 준비해 주시면 됩니다. 값은 문서나 저장소에 적지 않습니다.

| 환경변수 | 내용 |
|---|---|
| `CG_SSH_HOST` | 서버 주소 |
| `CG_SSH_PORT` | SSH 포트 |
| `CG_SSH_USER` | 접속 계정 |
| `CG_SSH_KEY_PATH` | 개인 키 파일 경로 (권장) |

- 비밀번호보다 **키 방식**을 권합니다. 배포 전용 키를 새로 만들어 등록하는 방법이 안전합니다.
- 가능하면 관리자(root)가 아닌, 웹 경로와 `city_guardians` DB에만 권한이 있는 계정을 권합니다.
- DB 계정은 서버의 `.env`에 있는 것을 서버 안에서 읽어 쓰므로 이 PC에 둘 필요가 없습니다.

첫 조사는 읽기 전용 명령만 사용합니다 (버전 확인, 목록 조회, 구조 덤프). 그 범위를 넘는 작업은 7장의 승인을 거칩니다.

## 3. 지시서와 실제의 차이 — PHP 버전

지시서는 PHP 8.3 이상을 요구하지만 운영 사이트는 PHP 7.3.33으로 동작하고 있습니다. PHP 7.3은 2021년 12월에 보안 지원이 끝난 버전입니다.

| 방안 | 내용 | 평가 |
|---|---|---|
| A | 서버에 PHP 8.3을 추가하고 이 사이트만 8.3으로 전환 | **권장.** 다른 사이트에 영향 없음. 기존 v1 코드가 8.3에서 도는지 스테이징에서 먼저 확인 필요 |
| B | PHP 7.3을 유지하고 7.3 호환 코드로 작성 | 비권장. 지원이 끝난 버전이고 지시서와 다름 |
| C | 서버 전체의 PHP를 8.3으로 교체 | 비권장. 같은 서버의 다른 사이트가 깨질 수 있음 |

방안 A도 서버 설정을 바꾸는 작업이므로 승인이 필요합니다. 서버에 이미 PHP 8.3이 설치되어 있고 사이트별로 고를 수 있는 구성이라면 작업이 작아집니다 (2장 2번에서 확인).

응답 헤더에 PHP 버전이 드러나는 것(`X-Powered-By`)은 끄는 것을 권합니다. 이것도 설정 변경이므로 함께 승인받습니다.

## 4. 환경 분리

| 환경 | 위치 | DB | 용도 |
|---|---|---|---|
| 개발 | 이 PC | `city_guardians_dev` (로컬) | 일상 개발, 자동 테스트 |
| 스테이징 | 운영 서버의 별도 사이트 (예: 하위 도메인) | `city_guardians_staging` | 배포 전 확인, 마이그레이션 예행 |

- 게임 클라이언트는 빌드 설정으로 접속할 API 주소를 고릅니다. 개발 빌드가 운영 API에 쓰기 요청을 보내지 않게 합니다.
- 스테이징은 검색 엔진 색인을 막고 접근을 제한합니다.

## 5. 서버 디렉터리 구조 (목표)

실제 구조는 2장의 조사 뒤 확정합니다. 원칙은 다음과 같습니다.

```
<사이트 경로>/
  public/          문서 루트. index.php와 정적 파일만
  src/             애플리케이션 코드
  config/          설정 (비밀 값 없음)
  migrations/      DB 마이그레이션
  storage/         로그, 캐시, 업로드 (웹에서 직접 접근 불가)
  .env             비밀 값. 소유자만 읽기
<사이트 경로 밖>/
  backups/         DB 덤프, 배포 전 백업
  builds/          게임 빌드 파일 (다운로드는 애플리케이션을 거쳐 제공)
```

- 코드, 설정, `.env`, 백업은 문서 루트 **밖**에 둡니다.
- 문서 루트를 바꿀 수 없는 구성이면 웹 서버 설정으로 `public` 외 경로의 접근을 막습니다.
- 기존 사이트가 다른 구조라면, 구조 변경은 별도 단계로 승인받아 진행합니다.

## 6. 배포 절차

### 6.1 배포 전

1. 자동 테스트 통과.
2. 스테이징에 같은 버전을 배포해 확인. 마이그레이션은 스테이징에서 먼저 실행.
3. 배포 내용과 영향 범위를 정리해 승인 요청.

### 6.2 백업

배포 때마다, 변경 전에 수행합니다.

| 대상 | 방법 |
|---|---|
| DB | `city_guardians`만 덤프 (일관된 시점으로). 다른 DB는 건드리지 않음 |
| 파일 | 사이트 경로를 묶어 보관 (`.env` 포함, 백업 폴더는 소유자만 접근) |
| 보관 | 문서 루트 밖. 날짜와 버전으로 이름. 최근 배포 5회분과 일일 백업 14일분 유지 |
| 확인 | 파일 크기와 덤프 끝부분을 확인해 백업이 온전한지 본 뒤 진행 |

**첫 작업 전에 현재 상태 전체를 한 번 백업하고**, 그 백업은 지우지 않고 보관합니다.

### 6.3 배포

1. 새 버전을 새 폴더에 올립니다 (기존 파일 위에 바로 덮어쓰지 않음).
2. 마이그레이션을 실행합니다. 추가만 하는 변경이어야 합니다 ([DATABASE](DATABASE.md) 5장).
3. 새 버전으로 전환합니다.
4. 확인: `/api/v1/health`, 홈페이지 주요 경로, 게스트 생성부터 구매까지의 점검 스크립트.
5. 문제가 있으면 바로 이전 버전으로 되돌립니다.

전환 방식(폴더 교체, 링크 전환 등)은 서버 구성을 확인한 뒤 정합니다.

### 6.4 되돌리기

| 상황 | 방법 |
|---|---|
| 코드 문제 | 이전 버전 폴더로 전환. 마이그레이션이 추가만 했으므로 이전 코드가 그대로 동작 |
| 데이터 문제 | 원인 파악 후 정정 마이그레이션. 덤프 복원은 마지막 수단이며 복원 시점 이후의 플레이 기록이 사라지므로 별도 승인 |

### 6.5 배포 수단

SSH를 통한 파일 전송과 원격 명령. 배포 스크립트는 `tools/deploy/`에 두고 접속 정보는 환경변수에서 읽습니다. 스크립트는 대상 경로가 이 사이트의 경로인지 확인한 뒤에만 동작하게 합니다.

## 7. 승인이 필요한 변경

기존 서비스에 영향을 줄 수 있는 작업은 실행 전에 내용, 영향, 되돌리는 방법을 알리고 승인을 받습니다.

| 작업 | 영향 |
|---|---|
| 서버 첫 로그인과 읽기 전용 조사 | 없음 (접속 정보 제공이 곧 승인) |
| 현재 상태 전체 백업 | 디스크 사용 |
| PHP 8.3 설치, 사이트의 PHP 버전 전환 | 이 사이트 전체 |
| 웹 서버 설정 변경 (문서 루트, 헤더, 스테이징 사이트 추가) | 이 사이트, 설정 오류 시 웹 서버 전체 |
| 스테이징용 하위 도메인과 DB 생성 | DNS, 서버 자원 |
| DB 계정 생성·권한 변경 | DB 서버 |
| 운영 DB 마이그레이션 | 기존 데이터 |
| 홈페이지 문구·페이지 교체 | 공개 사이트 |
| API 형식 변경 | 기존 클라이언트 (현재 공개 빌드 없음) |
| 예약 작업(cron) 등록·변경 | 이자, 시세 등 자동 처리 |
| 실시간 서비스 설치 (Node.js, WebSocket 중계 설정, 포트) | 웹 서버 설정, 서버 자원 |
| 게임 빌드 공개 (다운로드 활성화) | 공개 사이트 |
| 이 PC에 PHP 8.3, MySQL 8 설치 | 개발 PC |

하지 않는 일:

- 다른 사이트의 파일이나 다른 DB를 수정·삭제하는 일
- 기존 테이블이나 데이터를 삭제·덮어쓰는 일
- 서버 전체의 PHP·MySQL 버전을 바꾸는 일
- 운영 DB에 직접 손으로 데이터를 고치는 일 (관리자 기능이나 마이그레이션으로만)

- 실행 결과를 `system_logs`에 남기고, 마지막 성공 시각을 관리자 대시보드에 보여 줍니다.
- 기존 v1에 이자 지급 작업이 이미 있으면 중복으로 돌지 않게 확인합니다.

## 9. 실시간 서비스 (Phase 5)

- PHP와 별도 프로세스로 실행하고, 웹 서버가 `wss://www.dalfin.net/…` 경로를 그 프로세스로 중계합니다.
- 프로세스가 죽으면 자동으로 다시 뜨게 관리합니다.
- 외부에 새 포트를 열지 않고 443을 통해서만 접속하게 합니다.
- 이용자가 늘면 별도 서버로 옮길 수 있게 주소를 설정 값으로 둡니다.

1차 버전에는 설치하지 않습니다.

## 10. 점검과 감시

| 항목 | 방법 |
|---|---|
| 가동 여부 | `/api/v1/health` 주기 확인 |
| 오류 | 애플리케이션 로그 (문서 루트 밖), 관리자 시스템 로그 |
| 예약 작업 | 마지막 성공 시각 |
| 디스크 | 백업과 빌드 파일로 차지 않는지 확인 |
| 인증서 | 만료일 확인 |

점검 모드: `.env` 또는 관리자 설정으로 켜면 API가 `MAINTENANCE`를 돌려주고 홈페이지는 그대로 열립니다. 운영 중인 health 응답에 이미 `maintenance` 항목이 있으므로 기존 방식을 확인해 이어 씁니다.
