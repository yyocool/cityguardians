# ITEM_SYSTEM — 아이템과 상점

> 기준 v6.0 · 2026-11-13 · 상태: 1차 아이템(배턴·블래스터·수리 키트), 미소 상점, 가방, 장착, 사용, 드롭 (11장)과 방어구·의상·가구·되팔기·알록달록 가게·옷장 (12장)을 클라이언트와 모의 서버에 구현. 액세서리·보관함·강화는 설계 · 수치와 이름은 초기값

## 1. 분류

| 분류 | 코드 | 겹침 | 장착·사용 | 시점 |
|---|---|---|---|---|
| 근접 무기 | `weapon_melee` | 개별 | 장착 | 1차 |
| 원거리 무기 | `weapon_ranged` | 개별 | 장착 | 1차 |
| 회복 아이템 | `consumable` | 수량 | 사용 | 1차 |
| 방어구 | `armor` | 개별 | 장착 | Phase 3 |
| 액세서리 | `accessory` | 개별 | 장착 | Phase 3 |
| 의상 | `costume` | 개별 | 장착 (능력치 없음) | Phase 3 |
| 가구 | `furniture` | 개별 | 방에 배치 | Phase 3 |
| 장비 강화 재료 | `material` | 수량 | 강화에 소모 | Phase 3 이후 |
| 타워 | `tower_unlock` | — | 구매 즉시 타워 해금 | Phase 2 |

"개별"은 한 개가 한 칸을 차지하고 강화 단계 같은 고유 상태를 가진다는 뜻입니다. "수량"은 한 칸에 여러 개가 쌓입니다.

## 2. 아이템 정의

정의는 서버의 `item_defs`가 원본이고 관리자에서 편집합니다. 클라이언트는 접속 때 받아 캐시합니다.

| 항목 | 설명 |
|---|---|
| `code` | 고유 코드 (예: `wpn_bolt_blaster`) |
| `category` | 1장의 분류 |
| `name`, `description` | 표시 이름, 한 줄 설명 |
| `price_gc` | 기본 가격 |
| `sell_price_gc` | 되팔기 가격 (없으면 되팔기 불가) |
| `min_level` | 사용 가능 레벨 |
| `stats` | 분류별 수치 (JSON) |
| `max_stack` | 겹칠 수 있는 최대 수량 |
| `icon`, `model` | 클라이언트 자원 코드 |
| `is_active` | 판매·드롭 여부 |

`stats` 예시:

```json
{ "damage": 14, "rate": 4.0, "range": 25, "projectile": "bolt" }
```

## 4. 인벤토리

| 항목 | 값 |
|---|---|
| 칸 수 | 30 (추후 확장) |
| 정렬 | 분류 탭: 무기, 방어구, 소모품, 꾸미기 |
| 가득 찼을 때 | 구매 불가 안내, 드롭 아이템은 줍지 않음 |
| 보관함 | 방의 개인 보관함에 별도 30칸 (Phase 3) |
| 가구 | 인벤토리가 아닌 가구 보관 목록 |

인벤토리 화면(I 키)은 큰 아이콘 격자입니다. 아이템을 누르면 이름, 한 줄 설명, 버튼 하나("장착" / "사용")가 나옵니다.

인벤토리의 원본은 서버입니다. 클라이언트는 받아서 보여 주고, 변화는 서버 응답으로만 반영합니다.

## 5. 장착

| 칸 | 내용 |
|---|---|
| 근접 무기 | 1 |
| 원거리 무기 | 1 |
| 머리 | 방어구 또는 의상 |
| 몸 | 방어구 또는 의상 |
| 액세서리 | 2 |

- 장착은 `PUT /character/equipment` 로 서버에 저장합니다. 서버는 보유 여부, 분류와 칸의 일치, 레벨 조건을 확인합니다.
- 장착한 아이템은 인벤토리에 남아 있고 "장착 중" 표시가 붙습니다.
- 능력치는 서버가 장착 상태에서 계산한 값을 기준으로 하고, 클라이언트는 같은 식으로 표시합니다.
- 근접 무기는 비울 수 없습니다 (기본 무기는 되팔거나 버릴 수 없음).
- 머리와 몸에는 방어구든 의상이든 하나씩만 입습니다. 헬멧을 쓰고 있다가 머리띠를 쓰면 헬멧은 벗겨져 가방에 남고 그 방어도 빠집니다. "멋과 방어 가운데 고르기"가 됩니다.
- 방어는 입은 방어구의 합이고, 받는 피해를 그 비율(%)만큼 줄입니다. 한도는 80%입니다 ([COMBAT_SYSTEM](COMBAT_SYSTEM.md) 4장).

## 6. 사용

- 회복 아이템은 인벤토리 또는 빠른 사용 키(숫자 3)로 씁니다.
- `POST /inventory/use` 로 서버가 수량을 차감하고 결과를 돌려줍니다.
- 전투 중 응답을 기다리며 멈추지 않도록 클라이언트는 효과를 먼저 보여 주고, 서버가 거절하면 되돌립니다. 수량의 최종 값은 항상 서버 응답을 따릅니다.

## 7. 상점

### 7.1 구성

| 항목 | 내용 |
|---|---|
| 상점 정의 | `shops` — 코드, 이름, 담당 NPC, 위치 |
| 진열 | `shop_items` — 상점별 품목, 가격(기본값 덮어쓰기 가능), 순서, 해금 조건 |
| 1차 상점 | 미소 상점 (무기, 회복 아이템, 방어구) — 오미소 |
| Phase 3 상점 | 알록달록 가게 (의상, 가구) — 한아름. 광장 남동쪽 |
| 추후 | 방어기지 창구 (타워) |

### 7.2 구매 절차

1. 클라이언트: `POST /shops/{code}/buy` — 품목, 수량, 중복 방지 키.
2. 서버가 하나의 트랜잭션에서 처리합니다.
   - 품목이 이 상점에 진열되어 있고 판매 중인지
   - 레벨 등 조건
   - 가격은 서버의 값으로 계산 (클라이언트가 보낸 가격은 받지 않음)
   - 지갑 잔액 잠금 후 차감
   - 인벤토리 추가 (칸이 모자라면 전체 취소)
   - 원장 기록
3. 응답: 새 잔액, 바뀐 인벤토리.

같은 중복 방지 키로 다시 요청하면 처음 결과를 그대로 돌려줍니다. 네트워크가 끊겨 다시 보내도 두 번 차감되지 않습니다.

### 7.3 되팔기

되팔기 가격은 구매가의 30%(소수점 버림)로 두어 사고팔기 반복으로 이득을 볼 수 없게 합니다. 비율은 `economy.sellBackPercent`이고 관리자에서 바꿀 수 있어야 합니다.

| 규칙 | 내용 |
|---|---|
| 어디에 | 그 물건을 파는 상점에만 팝니다 (헬멧은 미소 상점, 머리띠는 알록달록 가게) |
| 팔 수 없는 것 | 기본 무기(스파크 배턴), 수리 키트 |
| 입고 있는 것 | 팔 수 있고, 팔면 그 칸이 빕니다. 팔기 전에 "팔면 벗겨져요"를 알립니다 |
| 가구 | 넣어 둔 것만 팝니다. 방에 놓인 가구는 먼저 넣어 두어야 합니다 |
| 확인 | 고르면 한 번 더 묻습니다 ("팔기 / 그만두기"). 판 물건은 돌아오지 않습니다 |
| 원장 | `shop_sale`. 요청 번호가 같으면 한 번만 팝니다 |

수리 키트를 되팔 수 없게 한 이유: 로봇이 떨어뜨리기도 하므로, 되팔 수 있으면 일일 사냥 보상 한도 밖의 수입이 됩니다.

## 8. 드롭

- 적마다 드롭 표를 연결합니다. 표는 (아이템, 확률, 수량 범위)의 목록입니다.
- 드롭 판정은 보상 지급 때 **서버가** 합니다. 클라이언트는 결과를 받아 줍는 연출만 보여 줍니다.
- 1차 드롭: 오작동 로봇이 수리 키트를 낮은 확률(5%)로 떨어뜨립니다.

## 9. 강화 (추후)

강화 재료와 GC로 무기·방어구의 단계를 올립니다. 실패해도 아이템이 사라지거나 단계가 내려가지 않게 합니다. 확률에 돈을 거는 구조를 만들지 않기 위해서입니다. 세부는 Phase 3 이후에 정합니다.

## 11. 구현된 것 (2026-11-13, 클라이언트와 모의 서버)

위 설계 가운데 "번 돈으로 무기를 사서 장착한다"에 필요한 부분을 만들었습니다. 서버 쪽은 `LocalMockBackend`에만 있고 PHP는 시작하지 않았습니다.

| 기능 | 구현 |
|---|---|
| 아이템 정의 | `GameDefs.items` — 스파크 배턴, 볼트 블래스터(200 GC), 수리 키트(30 GC, 체력 50, 99개까지 겹침) |
| 상점 | 미소 상점. 오미소에게 E → 진열과 값은 서버에서 받음 → 숫자 키로 구매 |
| 구매 | 값은 서버의 정의에서 읽고, 잔액 차감·가방 추가·원장(`shop_purchase`)을 한 번에 처리. 요청 번호가 같으면 한 번만 처리 |
| 가방 | I 키. 가진 아이템이 줄로 보이고 숫자 키로 장착·해제·사용 |
| 장착 | 근접 칸(비울 수 없음), 원거리 칸. 서버가 보유와 칸을 확인 |
| 손에 든 무기 | 숫자 1 근접, 2 원거리. 고른 칸은 서버에 남아 껐다 켜도 유지 |
| 수리 키트 | 숫자 3 또는 가방에서. 회복을 먼저 보여 주고 서버가 거절하면 되돌림. 체력이 가득하면 쓰지 않음 |
| 드롭 | 오작동 로봇이 수리 키트를 5%로 떨어뜨림. 서버가 사냥 보고를 인정할 때 판정 |
| 빠른 칸 표시 | 화면 오른쪽 아래. 원거리 무기나 수리 키트가 생기면 나타남 |
| 상점 안내 | 블래스터를 살 돈이 모이면 목표 줄과 표시가 미소 상점을 가리킴 |

설계와 다른 곳:

| 항목 | 설계 | 구현 | 이유 |
|---|---|---|---|
| 가방 화면 | 큰 아이콘 격자, 분류 탭 | 줄 목록 (선택 메뉴와 같은 화면) | 아이템이 세 가지뿐이라 격자와 탭이 필요 없음. 아이콘 자원도 아직 없음 |
| 무기 전환 | 1 / 2 / 휠 | 1 / 2 | 휠은 지도 확대에 쓰고 있어 미룸 |
| 구매 수량 | 품목과 수량 | 한 번에 하나 | 소모품은 사고 나면 상점이 다시 열려 이어서 살 수 있음 |
| 새 장비 | — | 사자마자 "바로 장착하기 / 나중에"를 물음 | 산 무기를 어떻게 드는지 몰라 헤매지 않게 |
| 가방이 찼을 때의 드롭 | 줍지 않음 | 줍지 않고 알리지도 않음 | 가방이 찰 만큼의 품목이 아직 없음 |

알려진 한계:

- 가방과 상점이 열려 있어도 게임은 멈추지 않습니다. 전투 구역 안에서 열면 맞습니다.
- 같은 사냥 보고를 다시 보냈을 때 돌아오는 가방 내용은 처음 응답 때의 것이 아니라 지금의 것입니다 (수량은 한 번만 늘어납니다).
- 액세서리, 보관함, 강화는 만들지 않았습니다. (되팔기, 방어구, 의상, 가구는 12장)

테스트: `Tests/EditMode/ItemTests.cs` (규칙과 모의 서버), `Tests/PlayMode/ShopTests.cs` (걸어가서 사고, 들고, 쏘고, 쓰고, 재시작).

## 12. 구현된 것: 방어구, 의상, 가구, 되팔기 (2026-11-13, 클라이언트와 모의 서버)

Phase 3의 남은 부분입니다. 서버 쪽은 `LocalMockBackend`에만 있습니다.

| 기능 | 구현 |
|---|---|
| 방어구 | 가디언 헬멧(머리, -10%), 가디언 조끼(몸, -20%). 미소 상점에서 삼. 입으면 받는 피해가 줄고 모습이 바뀜 |
| 의상 | 모자·머리띠·후드티·티셔츠 네 가지. 능력치 없이 모습만 바뀜. 방어구와 같은 칸을 씀 |
| 입기 | 사자마자 "바로 쓰기(입기) / 나중에"를 물음. 가방(I)이나 내 방의 옷장에서 입고 벗음 |
| 입은 모습 | 블록 캐릭터에 부품을 덧붙임 (`BlockCharacter.Wear`). 장면이 바뀌어도, 껐다 켜도 그대로 |
| 방어 표시 | 가방과 옷장의 윗줄, 입을 때의 알림에 "받는 피해 -N%" |
| 알록달록 가게 | 광장 남동쪽. 한아름에게 E. 물건이 아홉 가지라 "옷 사기 / 가구 사기 / 물건 팔기"부터 고름 |
| 되팔기 | 두 상점 모두 "물건 팔기" 줄. 규칙은 7.3 |
| 가구 구매 | 가방이 아니라 가구 목록에 들어감 (가방 칸을 쓰지 않음). 놓기는 [ROOM_SYSTEM](ROOM_SYSTEM.md) 8장 |
| 선택 메뉴 | 여섯 줄까지 (숫자 1~6). 넷을 넘으면 줄이 낮아지고, 여섯을 넘으면 마지막 줄이 "다음 쪽" |

설계와 다른 곳, 정한 값:

| 항목 | 설계 | 구현 | 이유 |
|---|---|---|---|
| 방어의 계산 | 피해 − 방어력 ([COMBAT_SYSTEM](COMBAT_SYSTEM.md) 4장의 옛 식) | 피해 × (1 − 방어%) | 뺄셈은 약한 적의 피해를 0으로 만들고 강한 적에게는 거의 소용이 없음. 비율은 "30% 덜 아프다"로 설명됨 |
| 방어구 수치 | 미정 | 헬멧 10%, 조끼 20%, 한도 80% | 둘 다 입으면 30%. 방어전 난이도는 다시 맞추지 않았음 (입지 않아도 이길 수 있는 지금 그대로) |
| 상점 구성 | 가구점, 옷가게 따로 | 알록달록 가게 하나 | 건물과 NPC를 하나만 더해도 되고, 메뉴에서 분류로 나뉨 |
| 방어구를 파는 곳 | 미정 | 미소 상점 | 전투 장비를 한곳에서 삼 |
| 되팔기 범위 | "일부" | 그 물건을 파는 상점에만, 소모품과 기본 무기는 불가 | 7.3 |
| 액세서리 칸 | 2 | 없음 | 미룸 |
| 무기 단계 | 각 3종 | 없음 | 미룸 |

알려진 한계:

- 방어구를 입어도 방어전이나 사냥의 난이도는 그대로입니다. 30%가 너무 큰지 작은지는 사람이 해 봐야 압니다.
- 옷을 입은 모습은 플레이어와 한아름에게만 있습니다. 다른 주민 NPC는 옷을 갈아입지 않습니다.
- 가방 화면은 여전히 줄 목록입니다. 품목이 여섯을 넘으면 "다음 쪽"으로 넘깁니다.
