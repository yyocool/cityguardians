# CITY_PASS_SYSTEM — CITY PASS (지역 제휴 멤버십)

> 기준 v7.0 · 2026-11-13 · 상태: **구현됨, 운영 전.** 서버(`server/`)는 로컬 테스트 DB에서 테스트를 통과했고, 게임 화면은 작성해 형식 검사와 규칙 테스트만 했습니다 (Unity에서 실행해 보지 못함). 운영 서버에는 올리지 않았습니다. 가입과 쿠폰 기능은 **꺼진 채로** 설치되고, 제휴 상점·혜택의 초기 데이터는 없습니다.

CITY PASS 는 게임 계정으로 가입하는 무료 멤버십입니다. 운영팀과 제휴 계약을 맺은 상점의 혜택을 지역별로 보고, 쿠폰을 받아 상점에서 씁니다. 게임의 GC, 전투 성적, 랭킹과는 이어지지 않습니다 ([`REAL_WORLD_REWARDS_POLICY.md`](REAL_WORLD_REWARDS_POLICY.md)).

관련 문서: [`PARTNER_MERCHANT_SYSTEM.md`](PARTNER_MERCHANT_SYSTEM.md) (제휴 업체·지점·혜택), [`COUPON_SYSTEM.md`](COUPON_SYSTEM.md) (쿠폰, QR, 상점 확인 화면), [`CITY_PASS_API.md`](CITY_PASS_API.md), [`ADMIN_SYSTEM.md`](ADMIN_SYSTEM.md) 11장

## 1. 무엇이고 무엇이 아닌가

| CITY PASS 는 | CITY PASS 는 아니다 |
|---|---|
| 지역 제휴 상점의 혜택을 모아 보는 무료 멤버십 | GC 로 사는 상품, 전투 보상, 랭킹 보상 |
| 게임 닉네임과 회원번호만 쓰는 서비스 | 실명·주소·연락처를 받는 회원제 |
| 관심 지역을 고르는 서비스 | 실제 거주지를 확인하는 서비스 |
| 쿠폰을 받아 상점에서 보여 주는 서비스 | 결제·예약·배달 서비스 (결제 기능이 없습니다) |

가입하지 않아도 게임을 하는 데에는 아무 차이가 없습니다. 가입해도 GC, 아이템, 경험치가 생기지 않습니다.

## 2. 멤버십

| 항목 | 내용 |
|---|---|
| 가입 | 약관에 동의하면 바로 가입됩니다. 값이 없습니다. 이방인(전입신고 전)도 가입할 수 있습니다 |
| 회원번호 | `CP-XXXX-XXXX` (서버가 만든다). 플레이어 번호나 닉네임에서 만들어지지 않습니다 |
| 관심 지역 | 기본값은 전입신고한 지역입니다. 가입할 때나 그 뒤에 다른 지역으로 바꿀 수 있습니다. **실제 거주지를 확인하지 않습니다.** 전입신고를 바꿔도 관심 지역은 그대로입니다 |
| 다른 지역 | 관심 지역은 "처음 보여 주는 지역"일 뿐입니다. 어느 지역의 상점과 혜택이든 볼 수 있고, 쿠폰도 받을 수 있습니다 |
| 저장하는 것 | 계정 번호, 회원번호, 관심 지역, 상태, 동의한 약관 버전, 가입한 날 (`city_pass_memberships`). 이름·전화번호·주소를 담는 열이 없습니다 |
| 약관 | 버전 `2026-11-draft`. **초안**이고 법률 검토 전입니다 |

화면에 나오는 것은 닉네임, 회원번호, 관심 지역, 쿠폰 수(사용 가능·사용함·기간 만료)입니다. 관리자의 쿠폰 목록에서는 회원이 회원번호로만 보입니다 (닉네임과 계정 번호를 붙여 보여 주지 않습니다).

## 3. 흐름

```
가입 ──→ 혜택 보기 (지역·업종) ──→ 쿠폰 받기 ──→ 내 쿠폰 ──→ 상점에 보여 주기 (QR · 코드, 5분)
                                                                      │
                              이용 내역 ←── 사용 처리 (상점 확인 화면, 서버) ←┘
```

- 혜택과 상점은 **승인된 것만** 보입니다: 승인된 업체(계약 기간 안)의 승인된 혜택이고 이용 기간 안인 것.
- 쿠폰을 받을 수 있는지는 가입 여부, 한 사람이 받을 수 있는 수, 남은 수량으로만 정합니다.
- 쿠폰이 "사용함"으로 바뀌는 것은 상점이 확인 화면에서 처리했을 때뿐입니다. 이용자의 기기(게임, 홈페이지)에는 쿠폰을 쓴 것으로 만드는 요청이 없습니다.

## 4. 게임 화면

게임 안에서는 **CITY PASS 안내센터**의 NPC와 **휴대전화**(P 키)가 같은 화면을 엽니다. 보여 주는 값은 모두 서버가 준 것이고, 홈페이지와 같은 자료입니다.

| 곳 | 내용 |
|---|---|
| CITY PASS 안내센터 | 도시 남쪽, 바다로 가는 길의 동쪽 건물 (`CityBuilder.CityPassCenter`). 민트색 벽과 청록 지붕, 문 옆에 "제휴 혜택 안내" 화면 |
| 시티패스 매니저 (윤서윤) | 문 앞. 말을 걸면 안내센터의 첫 화면이 열립니다 |
| 지역 혜택 안내원 (이가람) | 그 옆. 말을 걸면 "할인 혜택" 목록부터 열립니다. 쿠폰 기능이 꺼져 있으면 "준비 중"이라고 말하고 첫 화면을 엽니다 |
| 휴대전화 (P) | 튜토리얼을 마친 뒤(6단계) 방과 도시에서 꺼낼 수 있습니다. CITY PASS, 장학 안내, 홈페이지 로그인 코드 |

첫 화면의 메뉴 다섯 가지:

| 메뉴 | 내용 |
|---|---|
| 내 CITY PASS | 가입 전: 무료 가입 (약관 요약 보기 → 동의하고 가입). 가입 뒤: 닉네임, 회원번호, 관심 지역, 가입한 날, 관심 지역 바꾸기, 쿠폰 현황 |
| 주변 제휴 상점 | 관심 지역의 제휴 상점. 첫 줄에서 지역을 바꿉니다 (전국, 우리 도시, 다른 지역 고르기). 상점을 고르면 지점의 이름·지역·주소·전화 |
| 할인 혜택 | 지역별 혜택. 고르면 상점, 할인 내용, 이용 조건, 기간, "쿠폰 받기"(무료), 쓸 수 있는 지점 |
| 내 쿠폰 | 받은 쿠폰과 상태(유효기간, 사용함, 기간 만료). 고르면 "상점에 보여 주기" — QR 과 일회용 코드 ([`COUPON_SYSTEM.md`](COUPON_SYSTEM.md) 4장) |
| 이용 내역 | 상점에서 쓴 쿠폰의 날짜, 상점, 지점, 할인 내용 |

운영 승인 전에는 다섯 줄 모두 "준비 중"으로 보이고 고를 수 없습니다. 준비되지 않은 혜택을 있는 것처럼 보여 주지 않습니다.

**게임 화면에 없는 것**: GC 로 쿠폰 사기, 쿠폰을 GC·아이템으로 바꾸기, 쿠폰을 쓴 것으로 처리하기, 결제. `IGameBackend` 에 그런 요청이 없고, 테스트(`LocalMockBackendBenefitTests`)가 요청 이름과 인자를 훑어 확인합니다.

구현: `Gameplay/Benefits/BenefitActions.cs` (`CityPassActions`, `PhoneActions`), `Gameplay/Benefits/BenefitControllers.cs` (`CouponPresenter`, `PhoneController`), `UI/QrPanel.cs`, `Domain/BenefitRules.cs`, `Domain/QrCode.cs`, `Gameplay/World/CityBuilder.cs`, `Resources/Data/dialogues.json`.

> 지금 게임은 모의 서버(`LocalMockBackend`)만 씁니다. 모의 서버도 기능이 꺼진 채로 시작하고 자료가 없습니다. 견본 자료는 개발용 함수(`DevEnableBenefitSamples`)로만 들어가고 이름에 "(시험용)"이 붙습니다. PHP 서버와 통신하는 구현은 아직 없습니다.

## 5. 홈페이지

경로는 `{설치 경로}/city-pass` 입니다 ([`WEBSITE_SPEC.md`](WEBSITE_SPEC.md) 11장). 자바스크립트 없이 동작하고, 좁은 화면에서도 읽을 수 있게 만들었습니다.

| 경로 | 지시서의 메뉴 | 내용 | 로그인 |
|---|---|---|---|
| `/city-pass` | 서비스 소개 | CITY PASS 가 무엇인지, 게임 보상과 무관하다는 안내 | 불필요 |
| `/city-pass/merchants` | 제휴 상점 | 승인된 제휴 상점과 지점 (지역으로 고르기) | 불필요 |
| `/city-pass/offers` | 지역별 혜택 | 지금 받을 수 있는 혜택. 로그인했으면 "쿠폰 받기" | 보기는 불필요 |
| `/city-pass/coupons` | 쿠폰 | 가입, 관심 지역, 내 쿠폰, 일회용 코드 보기, 이용 내역 | 필요 |
| `/city-pass/partnership` | 제휴 문의 | 제휴 절차와 문의 주소 (`PARTNER_CONTACT_EMAIL` 이 없으면 "준비 중") | 불필요 |

- **로그인**: 게임의 휴대전화에서 받은 일회용 코드(`XXXX-XXXX`, 5분, 한 번)를 `/login` 에 넣습니다. 홈페이지에는 비밀번호가 없습니다 ([`CITY_PASS_API.md`](CITY_PASS_API.md) 2장).
- 홈페이지는 쿠폰의 일회용 코드를 **글자로** 보여 줍니다. QR 그림은 게임 화면에만 있습니다.
- 제휴 상점이나 혜택이 없으면 "아직 제휴 상점이 없습니다"라고 보입니다. 임의의 상점을 넣어 두지 않았습니다.

구현: `server/src/Web/SiteKernel.php`, `SitePassPages.php`, `public/assets/site.css`.

## 8. 한계와 남은 일

- 탈퇴 화면이 없습니다 (`withdrawn` 상태는 있고, 다시 가입하면 같은 회원번호로 이어집니다). 운영 전에 탈퇴와 자료 삭제 절차가 필요합니다.
- 지도 화면이 없습니다. 지점의 위도·경도는 저장하고 API 로 내주지만, 게임은 주소를 글자로만, 홈페이지는 주소와 위도·경도를 글자로만 보여 줍니다 (지도 그림이나 지도 서비스 연결이 없습니다).
- 지점 대표 이미지는 서버의 `public/media` 에 올려 둔 파일의 이름을 적는 방식입니다 (관리자 화면에 파일 올리기 없음).
- 알림(새 혜택, 만료 임박)이 없습니다.
- 게임의 HTTP 연동이 없습니다 (4장의 주).
