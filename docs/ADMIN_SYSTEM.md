# ADMIN_SYSTEM — 웹 관리자

> 기준 v6.0 · 2026-11-13 · 상태: 설계 (미구현)

## 0. 현황

운영 서버의 `/admin` 경로는 404를 돌려줍니다. 관리자 화면이 아직 없거나 다른 경로에 있는 것으로 보이며, 서버 소스 확인 뒤 판단합니다. 기존 관리자가 있으면 그 위에 메뉴를 더하는 방향으로 진행합니다.

## 1. 목적

- 경제 수치와 게임 밸런스를 코드 배포 없이 바꿉니다.
- 플레이어와 금융 거래를 조회하고 문제를 처리합니다.
- 신고를 처리하고 제재합니다.
- 홈페이지 공지와 다운로드 빌드를 관리합니다.

## 2. 접근과 보안

| 항목 | 내용 |
|---|---|
| 기술 | PHP, MySQL. 게임 API와 같은 애플리케이션 안의 별도 영역 |
| 경로 | 게임 API와 분리된 경로 |
| 계정 | 플레이어 계정과 별개의 `admins` 테이블 |
| 비밀번호 | 강한 해시로 저장. 최소 길이와 복잡도 규칙 |
| 2단계 인증 | 일회용 코드 앱(TOTP) 필수 |
| 세션 | 쿠키에 Secure, HttpOnly, SameSite=Strict. 일정 시간 조작이 없으면 만료 |
| 요청 위조 방지 | 모든 변경 요청에 CSRF 토큰 |
| 로그인 시도 제한 | 연속 실패 시 일시 잠금 |
| 접속 IP 제한 | 허용 목록 (선택. 설정 가능하게) |
| 감사 기록 | 모든 변경과 민감한 조회를 `admin_audit_logs`에 기록 |
| 검색 엔진 | 색인 금지 |

첫 관리자 계정은 서버에서 명령행 도구로 만듭니다. 웹에서 가입하는 기능은 두지 않습니다.

## 3. 역할

| 역할 | 할 수 있는 일 |
|---|---|
| 최고 관리자 | 전부. 관리자 계정 관리 |
| 운영자 | 플레이어, 제재, 신고, 공지, 수동 잔액 조정 |
| 밸런스 담당 | 적, 타워, 아이템, 상점, 스테이지, 금융 상품, 정책 수정 |
| 고객지원 | 플레이어 조회, 신고 처리, 채팅 제재 |
| 조회 전용 | 대시보드와 목록 조회 |

수동 잔액 조정처럼 영향이 큰 작업은 사유 입력을 필수로 하고, 일정 금액을 넘으면 최고 관리자만 할 수 있게 합니다.

## 5. 운영 대시보드

| 묶음 | 지표 |
|---|---|
| 이용 | 오늘 접속자, 신규 게스트, 전입신고 수, 이방인 → 주민 전환율 |
| 진행 | 첫 플레이 단계별 이탈 (방 → 도시 → 첫 전투 → 첫 구매 → 첫 방어전) |
| 경제 | 오늘 발행 GC, 회수 GC, 총 유통량, 예금 총액 |
| 금융 | 대출 총액, 연체율, 주식 거래량 (Phase 4) |
| 안전 | 미처리 신고 수, 오늘 제재 수, 거절된 보상 보고 수 |
| 상태 | 예약 작업의 마지막 성공 시각, 원장 정합성 점검 결과, 최근 오류 |

"첫 플레이 단계별 이탈"은 재미를 확인하는 가장 중요한 지표입니다. 어디서 그만두는지 보이면 무엇을 고칠지 알 수 있습니다.

## 6. 밸런스 수정 절차

1. 메뉴에서 값을 고칩니다.
2. 서버가 범위를 검사합니다 (음수 가격, 0 이하의 체력, 지나치게 높은 이율 등은 거부).
3. 변경 사유를 적고 저장합니다.
4. 변경 전후 값, 관리자, 사유가 `config_history`에 남습니다.
5. 정의 데이터 버전이 올라가고, 클라이언트는 다음 접속 때 새 정의를 받습니다.
6. 이력에서 이전 값으로 되돌릴 수 있습니다.

금융 조건을 바꿔도 이미 맺은 계약(정기예금의 약정 이율, 실행된 대출의 이율과 기한)은 바뀌지 않습니다.

스테이징 환경에서 먼저 값을 시험할 수 있도록 정의 데이터를 내보내고 가져오는 기능을 둡니다.

## 7. 플레이어 조회와 조치

| 조치 | 조건 |
|---|---|
| 조회 | 고객지원 이상. 조회 기록을 남김 |
| 이용 정지·해제 | 운영자 이상. 사유와 기간 필수 |
| 닉네임 강제 변경 | 운영자 이상 |
| GC 수동 조정 | 운영자 이상. 원장에 `admin_adjust`, 사유 필수 |
| 아이템 지급·회수 | 운영자 이상. 기록 필수 |
| 계정 삭제 요청 처리 | 최고 관리자. 절차는 [SECURITY_POLICY](SECURITY_POLICY.md) 8장 |

관리자는 플레이어의 게스트 비밀키나 접속 토큰을 볼 수 없습니다 (해시만 저장).

## 8. 화면 구성

- 왼쪽 메뉴, 오른쪽 내용의 단순한 구성. PC 화면 기준.
- 목록은 검색, 정렬, 쪽 나눔을 공통으로 제공합니다.
- 외부 스크립트·글꼴을 불러오지 않습니다 (운영 사이트의 콘텐츠 보안 정책과 같은 방침).
- 모든 화면 출력은 이스케이프합니다. 플레이어가 입력한 닉네임과 채팅이 관리자 화면에서 스크립트로 실행되어서는 안 됩니다.
