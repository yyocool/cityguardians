# ECONOMY_SYSTEM — 게임 경제, 은행, 저축

> 기준 v6.0 · 2026-11-13 · 상태: 지갑·원장, 상점 구매와 되팔기, 은행 보통예금(입금·출금·이자·거래 내역, 9장), 정기예금(10장)을 클라이언트와 모의 서버에 구현. 관리자·PHP 서버는 미구현 · 수치는 초기값이며 관리자에서 조정

## 1. GC

- 게임 화폐의 이름은 **GC**입니다. 이전 기획의 "크레딧"을 대체합니다.
- GC는 게임 안에서만 쓰는 재화이며 **현실 화폐로 교환할 수 없습니다.** 현실 결제로 GC를 사는 기능도 만들지 않습니다.
- 플레이어 사이에 GC나 아이템을 주고받는 기능은 두지 않습니다. 현금 거래와 괴롭힘의 통로가 되기 때문입니다. 필요해지면 따로 검토합니다.
- GC는 정수입니다. 소수점 금액이 없습니다.

운영 홈페이지와 기존 서버가 "크레딧"이라는 이름을 쓰고 있으므로 표시 이름을 GC로 바꾸는 작업이 필요합니다. 기존 잔액 데이터는 값 그대로 GC로 이어받습니다.

## 3. 원장

**모든 GC의 증감은 서버에서만 일어나고, 한 건도 빠짐없이 원장에 기록합니다.**

| 원칙 | 내용 |
|---|---|
| 서버 권한 | 클라이언트는 금액을 보내지 않는다. "무엇을 했다"만 보내고 금액은 서버가 계산한다 |
| 추가만 가능 | 원장 행은 수정·삭제하지 않는다. 정정은 반대 방향의 새 행으로 한다 |
| 잔액 일치 | 각 행에 거래 후 잔액을 남긴다. 지갑 잔액 = 마지막 원장 행의 잔액 |
| 트랜잭션 | 잔액 변경과 원장 기록, 그리고 대응하는 변화(아이템 지급 등)는 하나의 DB 트랜잭션 |
| 잠금 | 잔액 변경 전 지갑 행을 잠가 동시 요청에서 이중 차감을 막는다 |
| 중복 방지 | 변경 요청마다 중복 방지 키를 받아 같은 요청의 재전송을 한 번만 처리한다 |
| 음수 금지 | 잔액이 음수가 되는 거래는 거절한다 |

원장의 계정 구분: 지갑, 은행 계좌, 대출. 은행 입금은 "지갑 −, 은행 계좌 +" 두 행으로 기록되어 돈이 어디서 어디로 갔는지 추적할 수 있습니다.

사유 코드 예: `hunt_reward`, `battle_reward`, `quest_reward`, `residency_bonus`, `shop_purchase`, `tower_upgrade`, `bank_deposit`, `bank_withdraw`, `bank_interest`, `stock_buy`, `stock_sell`, `loan_disburse`, `loan_repay`, `admin_adjust`.

정합성 점검: 매일 지갑 잔액과 원장 합계가 일치하는지 검사하는 작업을 돌리고, 어긋나면 관리자 대시보드에 경고합니다.

## 4. 은행

### 4.1 이용 경로

은행 건물의 은행원, 또는 내 방 컴퓨터의 은행 아이콘. 두 경로는 같은 화면과 같은 API를 씁니다.

### 4.2 기능

| 기능 | 내용 | 시점 |
|---|---|---|
| 계좌 잔액 | 지갑과 통장을 나란히 표시 | 1차 |
| 입금 | 지갑 → 통장 | 1차 |
| 출금 | 통장 → 지갑 | 1차 |
| 이자 | 매일 지급, "내일 받을 이자" 미리 보기 | 1차 |
| 거래 내역 | 최근 거래 목록 (원장에서 조회) | 1차 |
| 저축 상품 | 정기예금 | Phase 3 (구현됨, 10장) |

### 4.3 상품

| 상품 | 이율 | 조건 | 중도 해지 |
|---|---|---|---|
| 보통예금 | 하루 1% (이자는 10,000 GC까지) | 자유 입출금 | — |
| 정기예금 7일 | 만기에 10% | 100 ~ 10,000 GC, 만기까지 출금 불가 | 원금만 반환 |
| 정기예금 30일 | 만기에 50% | 〃 | 원금만 반환 |

보통예금의 값은 2026-11-13에 사용자가 정했습니다 (처음 값은 하루 0.1%, 한도 100,000 GC — 9.5). 정기예금의 값은 그에 맞춰 개발 중에 정한 초기값입니다 (10.3).

이율은 `bank_products`에 두고 관리자에서 바꿉니다. 이율을 바꾸면 보통예금은 다음 날부터, 정기예금은 새로 가입하는 계좌부터 적용합니다. 이미 가입한 정기예금의 약속 이율은 바꾸지 않습니다.

초등학생이 이해하기 쉽게 "연 이율"이 아니라 "하루 이자"와 "만기에 받는 돈"으로 보여 줍니다.

### 4.4 이자 계산

보통예금:

```
하루 이자 = floor( min(그날의 최저 잔액, 이자 대상 한도) × 하루 이율 )
```

- **그날의 최저 잔액**을 쓰는 이유: 자정 직전에 넣었다가 직후에 빼는 방법으로 이자만 챙기는 것을 막기 위해서입니다.
- **이자 대상 한도** (10,000 GC): 이자가 이자를 낳아 재화가 끝없이 불어나는 것을 막습니다. 한도를 넘는 금액은 맡길 수는 있지만 이자가 붙지 않습니다.
- 계산 시점: 매일 자정(한국 시간) 이후 서버의 예약 작업이 전날 분을 지급합니다. 작업이 늦거나 빠져도 계좌별 "마지막 이자 지급일"을 기준으로 밀린 날짜만큼 정확히 한 번씩 지급합니다.
- 이자는 통장에 입금되고 원장에 `bank_interest`로 기록합니다.
- 1 GC 미만은 버립니다.

정기예금: 만기일에 원금 + 약정 이자를 보통예금으로 옮깁니다.

계산은 모두 서버가 합니다. 클라이언트는 서버가 준 "내일 받을 이자" 값을 표시만 합니다.

### 4.5 화면

- 왼쪽 "지갑", 오른쪽 "통장", 가운데 화살표 버튼 두 개 ("맡기기 →", "← 찾기").
- 금액 버튼: 100, 500, 1,000, 전부.
- 통장 아래에 "내일 이자 +12 GC".
- 처음 방문 때 은행원이 한 문장으로 설명합니다: "돈을 맡겨 두면 매일 조금씩 불어나요."

## 5. 재화 관리

돈이 풀리는 속도와 걷히는 속도를 관리자가 보고 조절할 수 있어야 합니다.

| 수단 | 내용 |
|---|---|
| 일일 한도 | 사냥 보상, 방어전 보상 횟수 |
| 이자 한도 | 이자 대상 잔액 |
| 소비처 | 타워 강화, 가구, 의상, 이사 수수료 |
| 대시보드 | 하루 발행량(보상·이자), 회수량(구매·수수료), 총 유통량, 사유 코드별 합계 |
| 조정 | 보상, 가격, 이율, 한도를 관리자에서 수정. 수정 이력 보관 |

## 6. 관리자 수동 조정

운영 중 잔액을 고쳐야 할 때는 관리자가 사유를 적고 조정합니다. 조정도 원장에 `admin_adjust`로 남고, 누가 언제 했는지 관리자 감사 기록에 남습니다. 직접 DB를 고치지 않습니다.

## 7. 확장을 위한 준비

1차 버전부터 다음을 갖춥니다.

- 원장의 계정 구분에 은행·대출을 포함
- 주식 매매 대금과 대출금이 같은 지갑·원장을 지나가도록 설계
- 금융 상품 테이블(`bank_products`, `loan_products`, `companies`)을 관리자에서 편집하는 구조

## 9. 구현된 것: 은행 보통예금 (2026-11-13, 클라이언트와 모의 서버)

서버 쪽은 `LocalMockBackend`에만 있고 PHP는 시작하지 않았습니다. 규칙은 `Domain/Bank.cs`(`BankRules`)에 Unity와 무관한 C#으로 있어, 실제 서버가 같은 규칙을 구현했는지 같은 예시로 맞춰 볼 수 있습니다.

### 9.1 흐름

1. 레벨 3이 되고 지갑에 100 GC 이상 있으면 목표 줄과 표시가 도시은행의 은다온을 가리킵니다 (볼트 블래스터를 살 수 있을 때는 상점 안내가 먼저). 은행 화면을 한 번 열면 안내가 사라집니다.
2. 은다온에게 E → "도시은행이에요. 돈을 맡겨 두면 매일 조금씩 불어나요." → 은행 화면.
   레벨이 모자라면 화면 대신 "은행은 레벨 3부터 이용할 수 있어요. (지금 레벨 2)"라고 알려 줍니다.
3. 첫 화면: 지갑과 통장의 금액, 이자 한 줄, 그리고 숫자 키 1 맡기기 / 2 찾기 / 3 정기예금 (10장) / 4 거래 내역.
4. 맡기기·찾기: 숫자 키 1~4로 100 / 500 / 1,000 / 전부. 줄마다 "맡기면 지갑 600 GC · 통장 1,000 GC"처럼 결과를 미리 보여 줍니다. 가진 것보다 큰 금액은 흐리게 보이고 눌러도 반응하지 않습니다. E는 은행을 닫지 않고 첫 화면으로 돌아갑니다.
5. 다음 날 방이나 도시에 들어오면 "통장에 이자 +N GC가 들어왔어요!"를 한 번 알립니다.
6. 내 방 컴퓨터: 레벨 3부터 E를 누르면 "도시 소식 / 도시은행"을 고르는 메뉴가 나오고, 같은 은행 화면이 열립니다.

### 9.2 이자를 화면에 보여 주는 방식

서버가 준 값만 보여 줍니다. 상황마다 한 줄입니다.

| 상황 | 화면 |
|---|---|
| 통장이 이자가 붙을 만큼 안 됨 | "통장에 100 GC가 있으면 하루에 1 GC씩 이자가 붙어요." |
| 오늘 맡긴 돈이 있음 | "내일 받을 이자 +0 GC      모레부터 하루 +10 GC" |
| 평소 | "내일 받을 이자 +10 GC" |
| 한도를 넘김 | 위에 "(이자는 10,000 GC까지 붙어요)"를 덧붙임 |

(금액은 하루 1%일 때의 예입니다. 문장은 설정에서 계산하므로 이율을 바꾸면 따라 바뀝니다.)

### 9.3 규칙의 세부 (4.4장을 코드로 옮기며 정한 것)

| 항목 | 정한 것 |
|---|---|
| 이율의 표현 | 1만분의 1 단위 정수 (`dailyInterestBp = 100` 은 1%). 소수 계산을 하지 않음 |
| 하루의 경계 | 한국 시간 자정 (사냥 보상 일일 한도와 같음) |
| 맡긴 날 | 그날의 최저 잔액은 맡기기 전의 잔액. 그래서 오늘 맡긴 돈의 이자는 모레 아침에 처음 들어옴 |
| 찾은 날 | 최저 잔액이 내려감. 같은 날 다시 넣어도 돌아오지 않음 |
| 정산 시점 | 접속, 내 정보 조회, 은행 조회, 입출금 때 밀린 날짜를 하루씩 (예약 작업 대신). 같은 날에는 한 번만 |
| 자정 뒤의 첫 거래 | 거래보다 정산을 먼저 함. 그래야 전부 찾아도 전날 이자를 받음 |
| 오래 비웠을 때 | 밀린 날짜마다 하루씩 복리로 지급. 한 번에 3,660일까지 |
| 시계가 뒤로 갔을 때 | 아무것도 지급하지 않고 기준 날짜도 되돌리지 않음 (같은 날 이자를 두 번 받지 못하게) |
| 원장 | 통장도 지갑과 같은 방식의 원장을 가짐. 입금·출금은 양쪽에 한 줄씩, 이자는 통장에 `bank_interest` 한 줄 (참조: 어느 날의 이자인지) |
| 정합성 | `FindLedgerInconsistency` 가 지갑과 통장을 모두 검사 |
| 한 번에 옮기는 금액 | 1 이상 10억 이하 |
| 해금 | 레벨 3 (`BankConfig.unlockLevel`). 이방인도 쓸 수 있음 |
| 이자 알림 | 서버의 "받은 이자 합계"와 클라이언트가 서버에 남긴 "알린 합계"의 차이. 껐다 켜도 두 번 알리지 않음 |

### 9.4 설계와 다른 곳, 없는 것

| 항목 | 설계 | 구현 | 이유 |
|---|---|---|---|
| 화면 배치 | 왼쪽 지갑, 오른쪽 통장, 가운데 화살표 버튼 | 선택 메뉴 (숫자 키) | 상점·가방과 같은 조작. 마우스 커서를 풀지 않아도 됨 |
| 은행 건물의 표시 | 해금되면 건물에 표시 | 목표 줄과 은다온 위의 표시 (한 번) | 다른 안내와 같은 방식 |

### 9.5 이율에 대한 관찰 — 결정됨: 하루 1%, 한도 10,000 GC

> **결정 (2026-11-13, 사용자)**: 아래 표의 첫 번째 방향 — 하루 1%, 이자 한도 10,000 GC. `BankConfig`와 테스트에 반영했습니다.
> 지금은 100 GC마다 하루 1 GC이고, 한도까지 채우면 하루 100 GC입니다 (처음 값의 최대와 같습니다).
> **Phase 4에 남기는 조건**: 대출 이율은 예금 이율보다 높아야 합니다. 정기예금(7일 10%, 30일 50%)까지 감안하면 하루 2% 이상이어야 빌려서 맡기는 것이 손해입니다.

아래는 결정 전의 기록입니다. 처음 값(하루 0.1%, 1 GC 미만 버림)은 **1,000 GC마다 하루 1 GC**였습니다. 만들어서 화면으로 보니 다음과 같았습니다.

- 통장에 999 GC까지는 이자가 **0**입니다. 볼트 블래스터(200 GC)를 사고 남은 돈을 맡긴 아이는 며칠을 기다려도 아무 일도 일어나지 않습니다.
- 1,000 GC를 맡기면 첫 화면이 "내일 받을 이자 +0 GC, 모레부터 하루 +1 GC"입니다. 로봇 한 대가 10 GC입니다.
- 사냥 보상 한도가 하루 3,000 GC이므로, 이자는 한도(100,000 GC)를 꽉 채워도 하루 100 GC입니다.

경제는 안전하지만 "맡기면 불어난다"는 재미는 약합니다. 값은 `BankConfig` 두 줄이고 테스트는 설정을 읽으므로 바꾸기 쉽습니다. 고려할 수 있는 방향:

| 방향 | 예 | 얻는 것 | 조심할 것 |
|---|---|---|---|
| 이율을 올리고 한도를 낮춤 | 하루 1% (100 GC마다 1 GC), 한도 10,000 GC | 500 GC만 맡겨도 다음 날 5 GC. 한도까지 채우면 하루 100 GC (지금의 최대와 같음) | Phase 4의 대출 이율은 반드시 예금 이율보다 높아야 함 (빌려서 맡기는 것을 막기 위해) |
| 지금대로 | 하루 0.1%, 한도 100,000 GC | 설계 그대로 | 첫 경험이 밋밋함 |
| 최소 이자 | 100 GC 이상이면 하루 최소 1 GC | 적은 돈에도 반응 | 100~999 GC에서는 얼마를 맡기든 1 GC라 "많이 맡길수록 많이 받는다"가 흐려짐. 규칙이 하나 늘어남 |

## 10. 구현된 것: 정기예금 (2026-11-13, 클라이언트와 모의 서버)

"기다리면 더 많이 받는다"를 겪게 하는 상품입니다. 규칙은 `Domain/Bank.cs`(`BankRules`), 서버 쪽은 `LocalMockBackend`에만 있습니다.

### 10.1 흐름

1. 은행 첫 화면의 3번 "정기예금" → 상품 두 줄 ("7일 정기예금  이자 10%", "30일 정기예금  이자 50%").
2. 상품을 고르면 금액 100 / 500 / 1,000 / 전부(한도까지). 줄마다 "만기에 +100 GC", "7일 뒤에 통장으로 1,100 GC"처럼 받을 돈을 미리 보여 줍니다.
3. 가입하면 **지갑**에서 돈이 빠지고, 상품 줄이 "7일 정기예금 (가입 중) · 7일 뒤에 이자 +100 GC와 함께 통장으로 들어와요."로 바뀝니다.
4. 가입 중인 줄을 누르면 중간에 찾을지 묻습니다. 기본 선택(1번)은 "계속 넣어 두기"이고, 2번 "지금 찾기"를 누르면 **원금만** 통장으로 돌아옵니다. 받지 못하는 이자를 먼저 알려 줍니다.
5. 만기일 자정이 지나 접속하면 원금과 이자가 **통장**으로 들어와 있고 "정기예금이 만기가 됐어요! 원금과 이자 +N GC가 통장에 들어왔어요!"를 한 번 알립니다.
6. 거래 내역에 "정기예금 만기 +1,000 GC", "정기예금 이자 +100 GC", "정기예금 찾음 +500 GC"로 남습니다.

### 10.2 규칙

| 항목 | 정한 것 |

| 상품 | 7일 (10%), 30일 (50%). `BankConfig.termProducts` — 코드, 이름, 기간, 기간 이율(1만분의 1), 최소·최대 금액 |

| 가입 수 | 상품마다 하나. 만기가 되거나 중간에 찾으면 다시 가입 가능 |

### 10.3 값을 이렇게 정한 이유와 조심할 것

보통예금이 하루 1%(복리)이므로 7일이면 약 7.2%, 30일이면 약 34.8%입니다. 정기예금은 묶어 두는 대신 그보다 많이 받아야 하므로 7일 10%, 30일 50%로 두었습니다. **사용자가 정한 값이 아니라 개발 중에 정한 초기값입니다.**

| 수입원 (하루 최대) | GC |
|---|---|
| 사냥 보상 한도 | 3,000 |
| 보통예금 (10,000 GC × 1%) | 100 |
| 7일 정기예금 (10,000 GC → +1,000 / 7일) | 약 143 |
| 30일 정기예금 (10,000 GC → +5,000 / 30일) | 약 167 |

가만히 있어도 받는 돈의 최대는 하루 약 410 GC이고, 그러려면 30,000 GC를 맡겨 두어야 합니다. 금액 한도(10,000 GC)가 이 상한을 정합니다. 한도를 올릴 때는 이 표를 다시 계산해야 합니다.
