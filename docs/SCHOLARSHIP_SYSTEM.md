# SCHOLARSHIP_SYSTEM — GUARDIANS SCHOLARSHIP (장학 지원)

> 기준 v7.0 · 2026-11-13 · 상태: **구현됨, 운영 전.** 서버는 로컬 테스트 DB에서 테스트 통과. 게임의 안내 화면은 작성해 형식 검사와 규칙 테스트만 함 (Unity에서 실행해 보지 못함). 신청 접수와 선정·지급 기록 기능은 **꺼진 채로** 설치되고, 장학 프로그램의 초기 데이터는 없습니다. **이 시스템은 돈을 보내지 않습니다.**

GUARDIANS SCHOLARSHIP 은 학생의 배움을 돕는 장학 프로그램입니다. 신청·심사·선정·지급 상태를 관리합니다. 게임 성적, 랭킹, GC, 결제 내역은 자격 확인에도 심사에도 쓰이지 않습니다.

관련 문서: [`SCHOLARSHIP_REVIEW_POLICY.md`](SCHOLARSHIP_REVIEW_POLICY.md) (심사 규정 초안), [`PRIVACY_DATA_FLOW.md`](PRIVACY_DATA_FLOW.md) (개인정보), [`SCHOLARSHIP_API.md`](SCHOLARSHIP_API.md), [`ADMIN_SYSTEM.md`](ADMIN_SYSTEM.md) 11장, [`REAL_WORLD_REWARDS_POLICY.md`](REAL_WORLD_REWARDS_POLICY.md)

## 1. 원칙

| 지시서 | 지키는 방법 |
|---|---|
| 전투 성적이나 GC 보유량으로 장학금을 주지 않는다 | 장학 테이블(0006 마이그레이션)은 지갑·원장·전투·랭킹 테이블을 참조하지 않는다. 장학 서비스 코드는 그 테이블들을 읽지 않는다 (`BenefitFeatureTest` 가 소스를 훑어 확인) |
| 게임 기록을 심사 점수로 쓰지 않는다 | 지원 자격의 종류는 넷뿐이고(2장) 게임 기록을 보는 종류는 서버가 거절한다. 평가 기준의 이름에 GC·랭킹·전투·레벨·결제 같은 말이 있으면 거절한다. 심사위원 화면에는 게임 계정이 나오지 않는다 |
| 게임 안에서는 안내만 한다 | 게임에는 신청·심사·지급 요청이 없다 (4장) |
| 신청은 별도 웹 절차로 한다 | 홈페이지 `/scholarship` (5장) |
| 미성년자는 보호자 동의를 받는다 | 6장 |
| 자동 송금을 만들지 않는다 | 지급은 상태 기록뿐이다 (8장). 계좌번호를 담는 열이 없다 |

## 2. 프로그램

| 항목 | 내용 |
|---|---|
| 종류 | 금융 역량 장학(`finance`), 창의력 장학(`creativity`), 협력·리더십 장학(`leadership`), 성장 지원 장학(`growth`) |
| 지원 방식 | 교육비 지원, 도서·교재 지원, 온라인 교육 이용권, 학습 프로젝트 지원, 별도 장학금 |
| 선발 인원, 접수 기간, 결과 발표 예정일 | 관리자가 정한다 |
| 지원 자격 (`scholarship_eligibility_rules`) | 종류는 **학교급, 태어난 해, 본인이 확인하는 문구, 제출 자료** 넷뿐. 신청서에 적은 값으로만 확인한다 |
| 평가 기준 (`scholarship_criteria`) | 이름, 설명, 만점, 가중치. 공고에 그대로 공개된다 |
| 보호자 동의가 필요한 나이 | 기본 만 19세 미만. 14세 아래로 내릴 수 없다 |
| 지원서마다 필요한 심사 수, 이의신청 기간, 개인정보 보관 기간 | 기본 2건, 7일, 선정되지 않으면 180일·선정되면 1825일(5년) |

공고의 한살이:

```
초안 ──submit──→ 승인 대기 ──publish──→ 공고(접수) ──close──→ 접수 마감 ──(선정·발표)──→ 결과 발표 ──archive──→ 보관
  ↑────return──────┘   (다른 관리자가 승인)        (마감 시각이 지난 뒤)
```

공고를 내려면(`publish`): 신청 접수 기능이 켜져 있고, 작성하거나 마지막으로 고친 사람이 아닌 다른 관리자가 승인하며, 평가 기준이 하나 이상 있고, 심사위원이 필요한 수만큼 배정되어 있어야 합니다. 공고가 나간 뒤에는 내용·자격·평가 기준을 바꿀 수 없습니다.

## 3. 신청에서 지급 상태까지

```
신청 (홈페이지) ─→ [미성년자: 보호자 동의 → 담당자 확인] ─→ 자격 확인 ─→ 심사 (심사위원 여럿)
     ─→ 결과 집계 ─→ 선정 제안 ─→ 최종 승인 (다른 관리자) ─→ 결과 통지 ─→ [이의신청] ─→ 지급 상태 기록
```

| 신청의 상태 | 뜻 |
|---|---|
| `submitted` | 접수됨. 자격 확인(과 보호자 동의)을 기다린다 |
| `ineligible` | 지원 자격에 해당하지 않음 (사유가 본인에게 보인다. 이의신청 가능) |
| `in_review` | 심사 중 |
| `decided` | 심사 완료, 발표 전. **결과는 아직 본인에게 보이지 않는다** |
| `announced` | 결과 발표: 선정 / 예비 선정 / 선정되지 않음 |
| `withdrawn` | 본인이 철회 (접수·심사 중일 때만). 30일 뒤 개인정보 삭제. 같은 프로그램에 다시 낼 수 없다 |

한 계정은 한 프로그램에 한 번만 신청할 수 있습니다. 신청 데이터의 구조는 [`PRIVACY_DATA_FLOW.md`](PRIVACY_DATA_FLOW.md) 2장.

| 지시서의 신청 데이터 | 저장하는 곳 |
|---|---|
| 프로그램 ID, 신청자 계정 ID, 신청 일시 | `scholarship_applications.program_id`, `player_id`, `submitted_at` |
| 지원 자격 확인 상태 | `eligibility_status` (+ 확인한 사람, 때, 메모) |
| 보호자 동의 상태 | `consent_status`, `scholarship_consents` |
| 신청서 | `form_enc` (암호화: 지원 동기, 계획, 확인한 문구) |
| 제출 자료 | `scholarship_documents` (내용은 암호화, 또는 https 주소) |
| 심사 상태, 심사 결과 | `status`, `result`, `scholarship_reviews`, `scholarship_awards` |
| 지급 상태 | `disbursement_status`, `scholarship_disbursement_records` |

## 4. 게임 화면

게임 안에서는 **장학센터**의 NPC와 **휴대전화**(P 키)가 같은 안내 화면을 엽니다.

| 곳 | 내용 |
|---|---|
| 장학센터 | 도시 남쪽, 바다로 가는 길의 서쪽 건물 (`CityBuilder.ScholarshipCenter`). 크림색 벽과 남색 지붕, 시계탑, 문 옆에 "모집 공고" 게시판 |
| 장학센터 선생님 (문세빈) | 문 앞. 말을 걸면 장학센터의 첫 화면이 열립니다 |
| 교육 프로그램 안내원 (한루리) | 그 옆. 말을 걸면 모집 일정부터 보여 줍니다 |
| 휴대전화 (P) → 장학 안내 | 같은 화면 |

메뉴 여섯 가지 (지시서의 순서):

| 메뉴 | 내용 |
|---|---|
| 장학 프로그램 소개 | 네 가지 장학의 뜻. "게임 성적, 랭킹, GC, 결제 내역은 심사에 쓰이지 않아요", "게임 안에서 장학금을 주거나 받지 않아요" |
| 지원 자격 | 공고를 고르면 종류, 지원 방식, 모집 기간, 지원 자격, 심사 기준, 보호자 동의 나이. 공고가 없으면 고를 수 없음 |
| 모집 일정 | 공고마다 단계(모집 예정·모집 중·마감·발표)와 기간, 발표일 |
| 금융교육 | 도시은행에서 저축과 이자를 해 보는 법. "게임 속 통장과 GC 는 연습용이에요. 심사에도, 현실의 돈으로도 쓰이지 않아요" |
| 지원 방법 | 신청 순서 (로그인 코드 → 홈페이지 → 신청서 → 보호자 동의 → 결과 확인), 홈페이지 로그인 코드 받기 |
| 심사 진행 상태 | 홈페이지에서 낸 신청의 접수일과 상태. 결과는 발표된 뒤에만 보임. **신청서의 내용(개인정보)은 게임으로 오지 않습니다** |

**게임 화면에 없는 것**: 신청하기, 신청서 쓰기, 서류 내기, 장학금 받기, GC·아이템으로 받기. `IGameBackend` 에는 공고 목록, 공고 상세, 내 신청 상태를 읽는 요청 셋뿐입니다.

운영 승인 전에는 "장학 프로그램은 준비 중이에요"라고 보이고 공고가 없습니다.

구현: `Gameplay/Benefits/BenefitActions.cs` (`ScholarshipActions`), `Gameplay/World/CityBuilder.cs`, `Resources/Data/dialogues.json`. CITY PASS 와 같이 지금은 모의 서버만 씁니다 ([`CITY_PASS_SYSTEM.md`](CITY_PASS_SYSTEM.md) 4장의 주).

로그인은 게임의 휴대전화에서 받은 일회용 코드로 합니다. 기능이 꺼져 있으면 "장학 프로그램은 준비 중입니다. 지금은 모집 공고가 없습니다"라고 보이고, 임의의 프로그램을 넣어 두지 않았습니다.

구현: `server/src/Web/SiteScholarshipPages.php`, `server/src/Service/Scholarships.php`.

## 6. 보호자 동의

1. 신청서의 태어난 해로 나이를 봅니다. 날짜를 받지 않으므로 **올해 생일이 아직 지나지 않았다고 보고** (가장 어린 쪽으로) 판단합니다. 기준 나이(기본 19세, 최소 14세) 미만이면 미성년자입니다.
2. 신청할 때 보호자의 이름·관계·연락처를 적습니다. 서버가 **보호자 확인 주소**(추측할 수 없는 64자 값)를 한 번 보여 줍니다. 서버는 문자나 메일을 보내지 않습니다: 신청자가 보호자에게 직접 전합니다.
3. 보호자가 그 주소를 열면 학생의 이름, 프로그램, 수집하는 개인정보와 보관 기간이 나옵니다. 보호자가 **신청서에 적힌 것과 같은 이름**을 적고 동의에 표시하면 "보호자가 동의함"이 됩니다. 주소는 한 번만 쓸 수 있고, 접수 마감 14일 뒤까지 유효합니다. 잃어버렸으면 신청자가 새로 받을 수 있습니다 (앞의 주소는 죽습니다).
4. **장학 담당자가 보호자에게 연락해 확인**하고(통화, 서면 동의서, 대면) 방법과 내용을 기록하면 "보호자 동의 확인됨"이 됩니다.
5. 그 뒤에야 자격 확인을 거쳐 심사로 넘어갑니다. 보호자 동의가 확인되지 않은 신청서는 심사위원에게 가지 않습니다.

3번만으로는 보호자 본인임이 증명되지 않습니다 (주소를 받은 누구나 이름을 알면 누를 수 있습니다). 그래서 4번이 있습니다. 이 방식이 법이 요구하는 법정대리인 동의를 충족하는지는 **법률 검토가 필요합니다** ([`REAL_WORLD_REWARDS_POLICY.md`](REAL_WORLD_REWARDS_POLICY.md) 6.2).

## 8. 지급

지급은 게임 경제와 완전히 분리되어 있고, **이 시스템은 상태만 기록합니다.**

```
예정 (지급 담당이 기록) ──approve (다른 관리자)──→ 승인 ──complete (지급 처리 문서 번호 필수)──→ 완료
        └──────────────────────cancel──────────────────────┘
```

- 결과가 발표된 선정자에게만 기록을 만들 수 있습니다.
- 기록에는 지원 방식, 지원 내용(예: 교재 3권), 금액(장부용, 없어도 됨), 상태, 실제 지급을 처리한 절차의 문서 번호가 있습니다.
- 기록을 만든 사람은 승인할 수 없습니다. 완료하려면 **이 시스템 밖의 승인된 지급 절차**의 문서 번호를 적어야 합니다.
- 계좌번호, 송금, 은행 연동이 없습니다. 지급 담당 화면에는 신청자가 접수 번호로만 보입니다 (이름과 연락처 없음).
- 신청자는 진행 상태 화면에서 지급 상태(예정·승인·완료)만 봅니다. 게임의 지갑에는 아무 일도 일어나지 않습니다.
