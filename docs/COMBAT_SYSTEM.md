# COMBAT_SYSTEM — 3D 액션 전투

> 기준 v6.0 · 2026-11-13 · 상태: 근접·원거리 무기 2종, 체력과 쓰러짐, 사냥과 방어전의 보상 검증을 클라이언트와 모의 서버에 구현 (원거리 무기는 3.1장). 방어구·강화·NPC 협동은 설계 · 수치는 초기값

## 1. 방향

캐릭터를 직접 움직여 로봇을 물리칩니다. 조작은 "다가가서 좌클릭" 하나로 시작하고, 조준 실력보다 위치 잡기와 장비 선택이 중요하게 만듭니다.

## 2. 조작

| 키 | 동작 |
|---|---|
| WASD | 이동 |
| Shift | 달리기 |
| 마우스 | 카메라 |
| 좌클릭 | 공격 (누르고 있으면 연속 공격) |

조준 보조: 근접 공격은 정면 부채꼴 안의 적을 모두 맞히고, 원거리 공격은 화면 중앙 근처의 적에게 약하게 끌립니다. 초등학생도 맞히기 쉬워야 합니다.

## 3. 무기 (1차 2종)

| | 스파크 배턴 | 볼트 블래스터 |
|---|---|---|
| 종류 | 근접 | 원거리 |
| 얻는 법 | 처음부터 보유 | 상점 구매 (200 GC) |
| 피해 | 25 | 14 |
| 공격 속도 | 초당 2회 | 초당 4발 |
| 범위 | 1.8 m, 정면 100도 | 25 m |
| 특징 | 범위 안 여러 적 동시 타격 | 날아가는 탄환, 탄약 없음 |
| 역할 | 떼로 오는 적 | 멀리 있는 적, 공중 적 |

탄약과 재장전은 1차에 넣지 않습니다. 무기 이름과 외형은 제안입니다.

### 3.1 원거리 무기의 구현 (2026-11-13)

볼트 블래스터는 "화면을 대충 그쪽으로 돌리고 누르고 있으면 맞는" 무기로 만들었습니다.

| 항목 | 값 | 설명 |
|---|---|---|
| 겨누기 | 자동 | 화면 가운데에서 좌우 26도 안의 적, 또는 6 m 안의 적(화면 어디에 있든). 벽 뒤의 적은 겨누지 않음. 방금 겨누던 적을 우선 |
| 조준 표시 | 하늘색 네모 | 겨눈 적의 발밑. 메뉴가 열려 있으면 숨김 |
| 겨눌 적이 없을 때 | 화면이 보는 쪽으로 발사 | |
| 탄환 | 초속 45 m, 사거리 25 m | 겨눈 적 쪽으로 초당 220도까지 휨 |
| 쏘는 높이 | 캐릭터의 어깨 (약 0.8 m) | 캐릭터 발밑이나 머리 위가 아님 |
| 맞는 판정 | 적은 굵게(반지름 0.22 m), 지형은 가는 선 | 적은 넉넉하게 맞고, 울타리 모서리에는 걸리지 않게 |
| 적의 반응 | 멈칫하지 않음, 밀리지 않음 | 근접보다 안전한 대신 약하게 |
| 맞은 적 | 평소의 1.6배 거리까지 쫓아옴 | 멀리서 쏘기만 하면 아무 위험이 없는 것을 막음 ([ENEMY_AI](ENEMY_AI.md)) |
| 쏘는 동안 | 캐릭터가 쏘는 쪽을 향함 (겨눈 적, 없으면 화면이 보는 쪽) | |

전투 구역의 울타리는 0.9 m에서 **0.6 m**로 낮췄습니다. 캐릭터의 어깨가 0.8 m라서, 0.9 m 울타리 뒤에서는 구역 안의 적이 보이는데도 탄환이 모두 울타리에 맞았습니다. 구역 안의 잔해(0.8~1.8 m)는 그대로 두어 엄폐물이 됩니다.

자동 테스트로 잰 값: 울타리 밖 4.5 m에 서서 한 걸음도 움직이지 않고 로봇 3대를 15~18 m 거리에서 4.4초에 쓰러뜨렸습니다. 이 수치는 실수 없는 자동 조작의 결과입니다. 사람이 느끼는 난이도(너무 쉬운지)는 직접 해 봐야 압니다.

아직 없는 것: 휠로 무기 바꾸기, 탄환 궤적의 소리 구분, 공중의 적(보안 드론).

## 4. 피해 계산

```
피해 = max(1, round(무기 피해 × 강화 배율 × (100 − 대상 방어%) / 100))
```

- **방어는 비율(%)입니다** (2026-11-13에 바꿈). 처음 설계는 `피해 − 방어력`이었는데, 뺄셈은 약한 적(기계 곤충, 피해 4)의 피해를 사실상 없애고 강한 적(건설 메카, 피해 30)에게는 거의 소용이 없습니다. 비율은 어느 적에게나 같은 만큼 듣고, "받는 피해 -30%"로 아이에게 설명할 수 있습니다.
- 방어%는 입은 방어구의 합이고 한도는 80%입니다. 지금은 가디언 헬멧 10% + 가디언 조끼 20% = 30%가 최대입니다 ([ITEM_SYSTEM](ITEM_SYSTEM.md) 3.1).
- 구현: `DamageFormula.Reduce(damage, defensePercent)` (`CG.Domain`), `Health.defensePercent`. 지금은 플레이어에게만 방어가 있고, 적과 타워에는 없습니다 (강화 배율도 아직 없습니다).
- 치명타, 속성, 상태 이상은 1차에 없습니다.
- 계산식은 `CG.Domain`에 두어 개인 전투와 타워디펜스가 같은 식을 씁니다.
- 플레이어끼리는 피해를 주지 않습니다.

## 5. 체력과 쓰러짐

| 항목 | 값 |
|---|---|
| 최대 체력 | 100 + (레벨 − 1) × 10 |
| 자연 회복 | 5초 동안 피해를 받지 않으면 초당 5 |
| 회복 아이템 | 수리 키트: 체력 50 회복 |
| 침대 | 완전 회복 |
| 피격 무적 | 0.3초 |

쓰러지면 3초 뒤 광장에서 체력 50%로 일어납니다. GC·아이템·경험치를 잃지 않습니다.

## 6. 타격감

- 맞은 적은 하얗게 깜빡이고 살짝 밀립니다.
- 피해 숫자가 튀어 오릅니다.
- 적이 정지하면 블록 조각으로 흩어지고, GC 조각이 튀어나와 플레이어에게 빨려 들어옵니다.
- 근접 타격 순간 아주 짧은 멈춤(0.05초)과 화면 흔들림을 줍니다. 설정에서 끌 수 있습니다.

## 7. 적

1차에는 오작동 로봇과 기계 곤충 2종을 구현합니다. 능력치와 AI는 [ENEMY_AI](ENEMY_AI.md)에 있습니다.

전투 구역에는 적이 정해진 지점에서 일정 수까지 다시 나타납니다. 안전 구역으로 달아나면 적은 추적을 멈추고 제자리로 돌아갑니다.

## 9. NPC 협동

- 전투 구역 근처를 순찰하는 가디언 NPC가 가까운 적을 함께 공격합니다.
- NPC가 준 피해와 상관없이 플레이어가 한 번이라도 때린 적은 보상을 온전히 받습니다.
- NPC가 혼자 쓰러뜨린 적은 보상이 없습니다.

## 10. 서버 검증

전투 판정은 클라이언트에서 일어나므로, 서버는 **보상을 줄 때** 검증합니다. 보상 금액은 항상 서버가 계산합니다.

### 10.1 거리 사냥

1. 전투 구역에 들어가면 `POST /hunts` 로 사냥 세션을 엽니다.
2. 적을 쓰러뜨릴 때마다 모아 두었다가 일정 간격(초기값 3초. 보상이 확정되는 것이 바로 보이도록 처음 계획 10초에서 줄임. 집 앞 첫 전투 구역은 0.2초) 또는 구역을 나갈 때 `POST /hunts/{id}/report` 로 보냅니다. 내용은 적 종류별 처치 수입니다.
3. 서버가 확인하는 것:
   - 세션이 그 플레이어의 것이고 유효한가
   - 지난 보고 이후 흐른 시간에 비해 처치 수가 가능한 범위인가 (구역의 최대 출현 속도 기준)
   - 그 구역에 나오는 적 종류인가
   - 하루 사냥 보상 한도를 넘지 않았는가
4. 통과한 만큼만 GC·경험치를 지급하고 원장에 기록합니다.

### 10.2 스테이지 전투 (방어전 포함)

1. `POST /battles` 로 시작. 서버가 세션 ID를 주고 시작 시각을 기록합니다.
2. 끝나면 `POST /battles/{id}/finish` 로 결과(승패, 종류별 처치 수, 남은 방어 체력, 막아낸 웨이브 수)를 보냅니다. 걸린 시간과 금액은 보내지 않습니다.
3. 서버가 확인하는 것 (`BattleRules.Evaluate`, 방어전 "외곽 1구역"에 구현됨):
   - 세션이 그 플레이어의 것인가, 이미 끝난 전투가 아닌가 (끝났으면 처음 응답을 그대로 돌려준다)
   - 서버가 잰 시간이 "막아낸 웨이브 × 스테이지의 웨이브당 최소 시간(10초)" 이상인가
   - 스테이지에 나오는 적 종류인가, 종류별로 나오는 수 이내인가
   - 승리: 모든 웨이브를 막았는가, 방어 체력이 남았는가, 놓친 적 수만큼 방어 체력이 깎였는가
   - 패배: 막아냈다는 웨이브의 적 수를 처치 수와 방어 체력으로 설명할 수 있는가
4. 보상은 스테이지 정의에서 서버가 계산합니다. 자세한 규칙과 값은 [TOWER_DEFENSE](TOWER_DEFENSE.md) 10장.

이 검증이 막지 못하는 것: 전투를 실제로 하지 않고 "그럴듯한 승리 보고"를 최소 시간(50초) 뒤에 보내는 조작입니다. 전투 판정이 클라이언트에 있는 한 완전히 막을 수 없으므로, 보상 상한(전투 보상 일일 한도, 아직 미정)과 기록 감시로 피해를 제한하는 것이 다음 단계입니다.

한도와 임계값은 관리자에서 조정합니다. 검증에 걸린 보고는 지급하지 않고 기록을 남겨 관리자가 볼 수 있게 합니다.
