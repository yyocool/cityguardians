# REGIONAL_COMPETITION — 전국 지역 경쟁과 도시 간 지원

> 기준 v8.0 · 2026-11-13 · 상태: 랭킹 규칙과 지원 규칙, 모의 서버, PHP 서버, 관리자 화면 구현. 서버는 로컬 테스트 DB에서만 돌려 보았고, Unity 화면은 실행해 보지 못함 · 가중치는 초기값

## 1. 방향

전국 230개 시·군·구가 "누가 도시를 더 잘 지켰나"로 겨룹니다. 겨루는 것은 도시이고, 플레이어끼리 싸우지 않습니다.

- 인구가 많은 도시가 사람 수만으로 이기지 않아야 합니다. → 활성 가디언 한 사람당 값으로 봅니다.
- 침공이 많이, 크게 온 도시가 불리하지 않아야 합니다. → 침공의 규모로 보정합니다.
- NPC 수비대가 지킨 결과로 실제 플레이어의 도시를 앞지르지 않아야 합니다. → 플레이어가 한 것과 NPC가 한 것을 따로 세고, 순위도 따로 매깁니다.
- 현금 결제가 순위에 영향을 주지 않아야 합니다. → 랭킹 항목에 결제와 관계된 값이 없습니다. 게임에 현금 결제 기능 자체가 없습니다.

## 2. 랭킹 점수

다섯 항목을 각각 0~100으로 구하고 가중치로 평균합니다. 계산은 `RankingRules`(C#) / `Ranking`(PHP)에 있고 두 구현이 같은 결과를 내는지 표본으로 확인합니다.

| 항목 | 가중치 (초기값) | 계산 | 보정 |
|---|---|---|---|
| 안전도 `safety` | 30 | 100 − 위험도 | |
| 방어 성공률 `successRate` | 20 | (가디언의 승리 + 1) × 100 / (가디언의 시도 + 2) | 시도가 적은 도시가 한두 번의 결과로 0점이나 100점이 되지 않게 함. 시도가 없으면 50 |
| 기여도 `contribution` | 20 | 도시 기여도 / (활성 가디언 × `contributionTarget` 100) | **한 사람당** 기여도. 100%에서 자름 |
| 침공 대응 `response` | 20 | 가디언이 막아 낸 침공의 규모 합 / 끝난 침공의 규모 합 | **규모가 큰 침공일수록** 많이 반영. 침공이 없었으면 50 |
| 협동 `cooperation` | 10 | 다른 도시를 지원한 점수 / (활성 가디언 × `cooperationTarget` 30) | 한 사람당. 100%에서 자름 |

```
총점 = (각 항목 × 가중치의 합) × 100 / 가중치의 합        (0 ~ 10000)
```

- **활성 가디언**: 최근 7일 안에 전투·복구·기금에 참여했거나 전입한 주민 ([CITY_RISK_SYSTEM](CITY_RISK_SYSTEM.md) 4.2). 등록만 하고 떠난 주민은 세지 않습니다.
- **가디언의 승리·시도**: 방어전과 FPS 임무. 지원 나온 가디언의 것도 그 도시의 것으로 셉니다.
- **NPC가 막은 침공**은 `npc_held_count`에 따로 세고, 성공률과 침공 대응에는 들어가지 않습니다. 끝난 침공의 규모 합(분모)에는 들어가므로, NPC에게 맡겨 둔 도시는 침공 대응 점수가 내려갑니다.

## 3. 순위

1. **활성 가디언이 있는 도시끼리 먼저** 겨룹니다. 총점이 높은 순서이고, 같으면 지역 코드 순서입니다.
2. NPC 수비대만 지키는 도시는 그 뒤에 옵니다. 화면에도 "NPC 수비대" 도시로 따로 표시합니다 (`player_defended: false`).

전국 랭킹(`GET /cities/rankings`)은 전체 도시의 순위와 점수의 세부 항목, 플레이어가 있는 도시의 수, 우리 도시의 순위를 줍니다. 내 기여도는 도시 상세(`my_contribution`)에서 봅니다.

기여도는 플레이어별로도 쌓입니다 (`region_contributions`). 얻는 방법은 방어전 승리 10, FPS 임무 승리 12, 사냥 10마리마다 1, 시설 복구 5, 도시 기금 100 GC마다 2이고, 진행 중인 침공을 막는 승리에는 규모 1마다 50%가 더 붙습니다. 값은 관리자에서 조정합니다.

## 4. 도시 간 지원

위험도가 긴급 단계(`supportOpenAt` 75 이상)가 되면 그 도시에 지원 요청이 열립니다.

| 항목 | 내용 |
|---|---|
| 누가 보는가 | **같은 시·도의 다른 도시**에 사는 가디언. "주변 도시"를 지금은 같은 시·도로 정했습니다 |
| 나서기 | 지도나 도시 메뉴에서 지원 요청을 골라 나섭니다 (`POST /cities/support/{id}/join`) |
| 지원 중 | 방어전과 FPS 임무에서 이기면 **지원 나간 도시**의 위험도가 내려가고 그 도시의 침공 진행도가 오릅니다. 사냥은 여전히 소속 도시에 반영됩니다 |
| 소속 도시 | **바뀌지 않습니다.** 서버는 어느 요청을 돕고 있는지만 적어 둡니다 (`player_combat_state.support_request_id`). `players.region_id`는 그대로입니다 |
| 기록 | 위험도 이력에 주체가 "지원 가디언"(`supporter`)으로 남습니다. 지원으로 얻은 점수는 도시 기여도가 아니라 **지원 기여도**로 따로 쌓입니다 (`city_support_contributions`) |
| 돌아오기 | 언제든 그만둘 수 있습니다 (`POST /cities/support/leave`). 요청이 닫히면 자동으로 끝납니다 |
| 닫힘 | 위험도가 `supportCloseBelow`(50) 아래로 내려가면 "해결", `supportMinutes`(360분)이 지나면 "만료" |
| 만료 | 아무도 한 번도 이기지 못한 채 만료되면 "미해결 긴급 임무"로 위험도가 +4 오릅니다. 아직 긴급 단계면 새 요청이 열립니다 |
| 나설 수 없는 경우 | 이방인(`not_resident`), 우리 도시의 요청(`own_city` — 출동 게이트에서 바로 지키면 됩니다), 이미 끝난 요청(`not_open`), 다른 시·도(`too_far`) |

지원을 보낸 도시는 랭킹의 협동 점수를 얻고, 받은 도시는 위험도가 내려갑니다. 지원 점수는 도시 양쪽에 `support_given` / `support_received`로 집계됩니다.

### 앞으로의 확장

지금은 한 사람이 다른 도시의 전투에 혼자 나서는 구조입니다. 여러 도시의 가디언이 같은 전장에서 함께 싸우는 공동 방어는 실시간 서버가 생긴 뒤에 붙일 수 있도록 다음을 미리 갖춰 두었습니다.

- 지원 요청과 참가자별 기여가 테이블로 분리되어 있습니다.
- 침공의 진행도는 "필요한 승리 수"로 세므로, 공동 전투의 승리를 한 번의 승리로 더하면 됩니다.
- 위험도 이력이 소속 가디언과 지원 가디언을 구분합니다.

## 5. 공정성

| 걱정 | 대응 |
|---|---|
| 인구가 많은 도시가 유리 | 기여도·협동은 한 사람당 값. 위험도를 내리는 양은 활성 가디언이 20명을 넘으면 그만큼 나뉨. 침공을 막는 데 필요한 승리 수는 활성 가디언 수에 비례 |
| 한 사람이 도시를 좌우 | 한 사람이 하루에 내릴 수 있는 위험도는 20까지. 시설 복구 하루 3번, 도시 기금 하루 2,000 GC |
| 침공이 많이 온 도시가 불리 | 침공 대응은 규모로 보정. 침공이 없었던 도시는 중간값 50 |
| NPC만 있는 도시가 상위권 | 플레이어가 있는 도시 뒤에 따로 순위를 매김 |
| 비싼 장비가 순위를 결정 | 강화 효과는 단계마다 10%. 무료 기본 장비로 모든 전투에 참여 가능 ([EQUIPMENT_SYSTEM](EQUIPMENT_SYSTEM.md)) |
| 현금 결제 | 결제 기능이 없음. 장비와 기금은 게임 안에서 번 GC로만 |
| 조작된 승리 보고 | 서버가 걸린 시간과 처치 수를 검증하고, FPS 보상에는 일일 횟수 한도가 있음. 완전히 막지는 못함 ([COMBAT_SYSTEM](COMBAT_SYSTEM.md) 10장) |

## 6. 관리자

- **지역 랭킹** (메뉴 12): 순위표와 점수의 세부 항목, 가중치와 목표값 수정. 가중치는 0~100이고 합이 0보다 커야 합니다.
- **도시 간 지원** (메뉴 11): 지원 요청 목록(열림·해결·만료, 참가자 수, 승리 수), 지원을 많이 보낸 도시, 지원 조건 수정.

가중치를 바꾸면 변경 전후와 사유가 `config_history`에 남고, 다음 조회부터 새 점수로 순위가 매겨집니다.

## 7. 구현 상태와 한계

| 항목 | 상태 |
|---|---|
| 랭킹 계산, 지원 규칙 | 구현, 테스트 통과 |
| API | `GET /cities/rankings`, `GET /cities/support`, `POST /cities/support/{id}/join`, `POST /cities/support/leave`, `GET /cities/support/contributions` ([API_SPEC](API_SPEC.md) 17장) |
| Unity 화면 | 지도의 랭킹 표와 지원 요청 표시, 지원 나서기 메뉴. 실행해 보지 못함 |
| 랭킹 기간 | 누적 값으로만 매깁니다. 주간·시즌 랭킹과 보상은 없습니다 |
| 랭킹 계산 비용 | 조회할 때마다 230개 도시를 계산합니다. 접속이 많아지면 주기적으로 계산해 저장해야 합니다 |
| 주변 도시 | 같은 시·도. 실제 거리나 인접 여부는 보지 않습니다 |
| 공동 방어 | 혼자 나서는 지원만 있음. 함께 싸우는 전투는 실시간 서버 뒤로 미룸 |
