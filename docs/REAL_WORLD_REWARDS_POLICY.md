# 현실 혜택 운영 정책

> 기준 v7.0 · 2026-11-13 · 상태: **구현됨, 운영 전** — 모든 현실 혜택 기능은 꺼져 있습니다. 법률 검토와 제휴 계약이 끝나기 전에는 켜지 않습니다.

이 문서는 CITY PASS(지역 제휴 혜택)와 GUARDIANS SCHOLARSHIP(장학 지원)이 게임과 어떻게 나뉘는지, 무엇을 만들지 않았는지, 기능을 켜려면 어떤 절차를 거치는지 정리합니다. 법률 자문을 대신하지 않습니다. 6장의 항목은 **변호사·세무사의 검토를 받아야 하는 질문 목록**이지 결론이 아닙니다.

관련 문서: [`CITY_PASS_SYSTEM.md`](CITY_PASS_SYSTEM.md), [`COUPON_SYSTEM.md`](COUPON_SYSTEM.md), [`SCHOLARSHIP_SYSTEM.md`](SCHOLARSHIP_SYSTEM.md), [`PRIVACY_DATA_FLOW.md`](PRIVACY_DATA_FLOW.md)

---

## 1. 원칙

| 원칙 | 코드에서 지키는 방법 |
|---|---|
| GC, 가상 주식, 가상 대출, 신용점수는 현실의 현금·상품권·쿠폰·장학금으로 바꿀 수 없다 | 현실 혜택 테이블(0005, 0006 마이그레이션)은 `wallets`, `ledger_entries` 를 참조하지 않는다. 쿠폰과 장학 서비스 코드는 지갑 서비스를 부르지 않는다. 테스트가 쿠폰 발급·사용과 장학 신청 앞뒤로 GC 잔액과 원장 행 수가 그대로인지 확인한다 |
| 전투 점수, 랭킹, 아이템, 플레이 시간, 결제액을 현실 혜택의 기준으로 쓰지 않는다 | 쿠폰의 발급 사유는 `membership`, `promotion`, `partner_condition` 셋뿐이다. 장학 자격 규칙의 종류는 `school_level`, `birth_year`, `statement`, `document` 넷뿐이고, 그 밖의 종류는 서버가 거절한다. 심사 화면은 게임 테이블을 읽지 않는다 |
| CITY PASS 와 장학 프로그램은 정책·자격·절차가 따로다 | 테이블, 서비스, 관리자 메뉴, 관리자 역할, 기능 스위치가 모두 따로다. CITY PASS 회원이 아니어도 장학 신청을 할 수 있고, 그 반대도 같다 |
| 법률 검토가 끝나지 않은 기능은 꺼 둔다 | 4장의 승인 절차 |
| 준비되지 않은 혜택을 제공 중인 것처럼 보이지 않는다 | 제휴 상점·혜택·장학 프로그램의 초기 데이터가 없다. 승인된 것만 밖에 보이고, 없으면 "준비 중"이라고 보인다 |

## 2. 게임 보상과 현실 혜택의 경계

```
┌──────────── 게임 ────────────┐      ┌────────── 현실 혜택 ──────────┐
│ GC · 장비 · 레벨 · 랭킹       │  ✕   │ CITY PASS 쿠폰 · 장학 지원     │
│ 전투 보상 · 은행 · 가상 주식  │ ───→ │                                │
│ wallets, ledger_entries …    │  ✕   │ benefit_coupons,               │
│                              │ ←─── │ scholarship_* …                │
└──────────────────────────────┘      └────────────────────────────────┘
        공유하는 것: 계정(누구인가), 닉네임, 전입신고한 지역(관심 지역의 기본값)
```

두 쪽이 함께 쓰는 것은 **계정 식별**뿐입니다. 어느 방향으로도 값이 넘어가지 않습니다.

- 게임 → 현실: GC 로 쿠폰을 살 수 없고, 전투 성적으로 쿠폰이나 장학금을 받을 수 없습니다.
- 현실 → 게임: 쿠폰을 쓰거나 장학 프로그램에 선정되어도 GC, 아이템, 경험치가 생기지 않습니다.

## 3. 만들지 않은 기능

아래 다섯 가지는 지시서 9장이 "법률 검토 전까지 비활성화"하라고 한 것입니다. 이번 개발에서는 **끄는 스위치를 둔 것이 아니라 아예 만들지 않았습니다.** 코드도, 테이블도, API 도 없습니다. 관리자 화면의 "현실 혜택 기능" 메뉴 아래쪽에 이 목록이 "없는 기능"으로 적혀 있습니다.

| 만들지 않은 기능 | 이유 |
|---|---|
| 게임머니(GC)를 현실 상품으로 교환 | 게임산업법이 금지하는 환전·환전 알선에 해당할 수 있다 |
| 전투 성적에 따른 현금성 보상 | 게임 결과에 따라 재산상 이익을 주는 사행성 문제 |
| 게임 랭킹에 따른 장학금 자동 지급 | 위와 같다. 장학 심사는 사람이 정해진 기준으로 한다 |
| 유료 아이템 구매에 따른 장학금 가산점 | 결제를 유도하는 구조가 되고, 장학의 취지와 맞지 않는다 |
| 게임 내 대출·주식 수익의 현실 현금화 | 금융 관련 법령과 사행성 문제 |

나중에 법률 검토를 거쳐 이 가운데 어떤 것을 만들기로 한다면, 그때 설계·승인 절차·검토 기록을 새로 만들어야 합니다. 지금 있는 스위치로는 켤 수 없습니다.

## 4. 기능 승인 절차

현실 혜택을 주거나 개인정보를 받는 기능은 넷으로 나뉘고, 모두 **꺼진 채로** 설치됩니다 (`benefit_features`).

| 코드 | 기능 | 꺼져 있을 때 |
|---|---|---|
| `city_pass_membership` | CITY PASS 가입 | 가입할 수 없다. 안내만 보인다 |
| `city_pass_coupons` | 쿠폰 발급과 사용 | 제휴 혜택이 밖에 보이지 않는다. 발급·제시·사용 처리가 모두 거절된다. 이미 받은 쿠폰의 목록은 본인이 볼 수 있다 |
| `scholarship_applications` | 장학 신청 접수 | 모집 공고가 밖에 보이지 않는다. 신청할 수 없다. 이미 낸 신청의 상태 확인과 철회는 할 수 있다 |
| `scholarship_awards` | 선정 결과 확정·통지, 지급 상태 기록 | 최종 승인, 결과 통지, 지급 기록을 할 수 없다 |

`city_pass_coupons` 는 `city_pass_membership` 이 켜져 있어야 동작합니다.

### 켜는 순서

1. **법률 검토 기록** — 준법 담당(`compliance`) 또는 최고 관리자(`super`)가 검토 상태를 적습니다: 검토 전 → 검토 중 → **완료(승인)** 또는 반려. "완료"로 적으려면 검토 의견서의 문서 번호, 검토한 곳, 검토한 날짜가 있어야 합니다.
2. **켜기** — 최고 관리자(`super`)만 할 수 있습니다. 서버는 다음을 모두 확인합니다.
   - 법률 검토 상태가 "완료"인가
   - **검토 완료를 기록한 사람과 켜는 사람이 다른가** (한 사람이 혼자서 기록하고 켤 수 없습니다)
   - 사유를 적었는가
   - 장학 신청 접수라면, 개인정보 암호화 키(`DATA_KEY`)가 서버에 설정되어 있는가
3. 모든 기록·켜기·끄기는 `benefit_feature_history` 와 관리자 감사 기록에 남습니다.

### 끄기

- 준법 담당과 최고 관리자는 **언제든** 끌 수 있습니다 (사유 필수).
- 법률 검토 상태를 "완료"가 아닌 값으로 바꾸면 그 기능은 **자동으로 꺼집니다.**
- 서버의 환경 설정에 `BENEFITS_LOCKED=1` 을 넣으면 DB 의 값과 상관없이 넷 다 꺼진 것으로 다룹니다 (비상용).

### 이 절차가 보장하지 않는 것

서버는 "검토 완료라고 기록되었는가"만 확인합니다. 실제로 검토를 받았는지, 의견서의 내용이 무엇인지는 알 수 없습니다. 기록의 진실성은 운영 조직이 책임져야 하고, 그래서 기록한 사람과 켜는 사람을 나눴습니다.

## 5. 운영 승인이 필요한 일

| 일 | 누가 | 서버가 강제하는 것 |
|---|---|---|
| 제휴 업체를 밖에 보이게 하기 | CITY PASS 담당이 등록 → 다른 관리자가 승인 | 계약서 문서 번호, 계약 기간, 청소년 적합 확인이 있어야 승인된다. 등록한 사람은 승인할 수 없다 |
| 혜택을 밖에 보이게 하기 | 위와 같다 | 업체가 승인 상태여야 한다. 등록한 사람은 승인할 수 없다 |
| 장학 프로그램 공고 | 장학 담당이 작성 → 다른 관리자가 승인 | 평가 기준이 하나 이상 있어야 한다. 작성한 사람은 승인할 수 없다 |
| 선정 결과 확정 | 장학 담당이 제안 → 다른 관리자가 최종 승인 | 제안한 사람은 승인할 수 없다. 선정 인원이 정원을 넘을 수 없다 |
| 지급 상태 기록 | 지급 담당이 기록 → 다른 관리자가 승인 → 완료 | 기록한 사람은 승인할 수 없다. 완료하려면 실제 지급 절차의 문서 번호가 있어야 한다 |

운영 서버에 대한 다음 일은 **사전 승인 없이 하지 않습니다**: 배포, DB 마이그레이션, 실사용자에게 쿠폰 발급, 장학 지급.

## 6. 법률 검토가 필요한 질문

기능을 켜기 전에 전문가에게 확인해야 할 것들입니다. 답은 이 문서에 없습니다.

### 6.1 게임산업진흥에 관한 법률

- CITY PASS 쿠폰이 "게임물의 이용을 통하여 획득한 유·무형의 결과물"의 환전이나 "경품 제공"에 해당하지 않는가. 쿠폰은 게임 결과와 무관하게 가입만으로 받지만, **게임 계정으로 가입한다는 점**이 어떻게 평가되는가.
- 게임 안에 CITY PASS 안내센터와 쿠폰 보관함을 두는 것이 사행성 조장이나 경품 광고로 보일 여지가 없는가.
- 등급 분류를 받을 때 이 기능을 어떻게 기재해야 하는가.

### 6.2 개인정보 보호법

- 만 14세 미만 아동의 개인정보 수집에 필요한 법정대리인 동의를 지금의 방식(보호자 확인 주소 + 담당자의 확인)으로 충족하는가. 휴대전화 본인확인 같은 수단이 필요한가.
- 장학 신청에서 받는 항목(이름, 태어난 해, 학교급, 학교 이름, 이메일, 전화번호, 보호자 이름·연락처)이 최소한인가. 보관 기간(선정되지 않으면 180일, 선정되면 5년)이 적정한가.
- 개인정보 처리방침, 수집·이용 동의서의 문구. 지금 들어 있는 동의 문구는 **초안**입니다.
- 심사위원(외부 위원일 수 있다)에게 신청서를 보여 주는 것이 제3자 제공인가 위탁인가.
- 개인정보 영향평가, 개인정보 보호책임자 지정이 필요한 규모인가.

### 6.3 청소년 보호

- 제휴 업종의 제한. 청소년 유해업소, 주류·담배, 사행 업종이 제휴 대상이 되지 않게 하는 기준. 지금은 관리자가 "청소년에게 맞지 않는 업종이 아님"을 확인해야 승인되지만, 기준 문서는 없습니다.
- 청소년에게 쿠폰을 주는 것이 구매를 부당하게 유도하는 광고에 해당하지 않는가.
- 미성년자가 CITY PASS 에 가입할 때 보호자 동의가 필요한가. 지금은 받지 않습니다 (실제 개인정보를 받지 않기 때문입니다).

### 6.4 전자상거래, 표시·광고

- 운영사가 통신판매중개자에 해당하는가. 쿠폰은 무료이고 결제가 없지만, 할인 조건을 표시하는 주체로서의 책임.
- 제휴 상점이 혜택을 이행하지 않을 때의 책임 분담 (제휴 계약서에 넣을 조항).
- 할인율·조건 표시가 표시광고법에 맞는가.

### 6.5 세무

- 장학금(교육비, 교재, 이용권, 별도 장학금)이 받는 사람에게 비과세 학자금인가 기타소득인가. 원천징수 의무가 있는가.
- 장학 사업을 운영사가 직접 하는가, 공익법인이나 재단을 통해 하는가. 기부금을 받는다면 기부금품법.
- 지급 명세의 보관과 신고. 이 시스템의 지급 기록은 상태 관리용이고 회계 장부가 아닙니다.

### 6.6 그 밖

- 제휴 계약서의 표준 조항 (혜택 이행, 개인정보를 주고받지 않음, 해지, 상표 사용).
- 장학 심사의 공정성 규정 (심사위원 위촉, 이해충돌 회피, 이의신청). [`SCHOLARSHIP_REVIEW_POLICY.md`](SCHOLARSHIP_REVIEW_POLICY.md) 는 초안입니다.

## 7. 이 문서의 한계

- 이 정책은 개발자가 지시서를 바탕으로 정리한 **초안**입니다. 법률가가 검토하지 않았습니다.
- 3장의 "만들지 않았다"는 저장소의 코드로 확인할 수 있습니다. 4~5장의 절차는 서버 테스트(`BenefitFeatureTest`, `CityPassTest`, `ScholarshipTest`)가 확인합니다.
- 운영 조직의 실제 승인 체계(누가 준법 담당인가, 누가 최고 관리자인가)는 정해지지 않았습니다.
