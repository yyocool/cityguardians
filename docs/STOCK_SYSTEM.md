# STOCK_SYSTEM — 가상 주식투자

> 기준 v6.0 · 2026-11-13 · 상태: 설계 (Phase 4 구현, 1차에서는 DB·API 자리만 준비) · 수치는 초기값

## 1. 방향

게임 안의 가상 기업에 GC로 투자합니다. 값이 오르면 벌고 내리면 잃는다는 것을 작은 금액으로 겪어 보는 것이 목적입니다.

- 실제 증권시장, 실제 기업, 실제 시세와 연결하지 않습니다.
- 현실 화폐가 오가지 않습니다.
- 투자를 강요하거나 반복해서 권하지 않습니다. 하지 않아도 게임 진행에 불이익이 없습니다.

## 2. 가상 기업 (제안)

도시 방어 세계관 안의 기업으로 구성합니다. 게임에서 일어나는 일이 실적에 영향을 줍니다.

| 기업 | 업종 | 성격 | 게임 사건과의 관계 |
|---|---|---|---|
| 한빛에너지 | 전력 | 안정적, 변동 작음 | 도시 레벨 상승 시 실적 호전 |
| 가온로보틱스 | 로봇 수리 | 변동 큼 | 로봇 처치 수가 많을수록 수리 수요 증가 |
| 든든방어 | 방어 장비 | 침공에 민감 | 침공 이벤트 때 상승 |
| 새벽물류 | 물류 | 보통 | 침공으로 길이 막히면 하락, 방어 성공 시 회복 |
| 누리식품 | 식품 | 매우 안정적 | 사건 영향 작음 |
| 다솜건설 | 건설 | 변동 큼 | 건설 메카 침공 뒤 복구 수요로 상승 |

이름은 제안입니다. 실존 기업의 이름·상표와 겹치지 않는지 확인한 뒤 확정합니다. 기업은 관리자에서 추가·수정·상장 중지할 수 있습니다.

## 3. 주가

### 3.1 변동 방식

서버의 예약 작업이 일정 간격(초기값 10분)으로 모든 기업의 새 가격을 계산합니다.

```
새 가격 = 이전 가격 × (1 + 실적 추세 + 사건 영향 + 무작위 변동)
```

| 요소 | 내용 |
|---|---|
| 실적 추세 | 기업의 실적 점수에 따른 완만한 방향성. 관리자가 설정하거나 게임 통계에서 자동 계산 |
| 사건 영향 | 침공, 방어 성공, 도시 레벨 상승, 관리자가 등록한 뉴스. 기간과 크기를 가짐 |
| 무작위 변동 | 기업별 변동성 범위 안의 난수 |

### 3.2 안전 장치

| 장치 | 초기값 | 목적 |
|---|---|---|
| 하루 변동 한도 | 전날 종가 대비 ±15% | 하루에 큰 손실 방지 |
| 최저 가격 | 기준 가격의 20% | 주식이 휴지 조각이 되지 않게 |
| 최고 가격 | 기준 가격의 500% | 재화 폭증 방지 |
| 플레이어 매매의 가격 영향 | 없음 | 여럿이 짜고 시세를 움직이는 것 방지 |

플레이어의 주문은 가격을 움직이지 않습니다. 가격은 서버의 모형만으로 정해집니다. 이 점은 실제 시장과 다르며, 안내원이 "이건 연습용 시장이에요"라고 알려 줍니다.

### 3.3 시장 시간

24시간 열려 있습니다. 하루의 구분(종가, 변동 한도 기준)은 한국 시간 자정입니다. 늦은 밤 이용을 부추기지 않도록 시간 한정 급등 이벤트는 만들지 않습니다.

### 3.4 뉴스

사건이 생기면 한 줄 뉴스가 붙습니다 ("침공 경보로 방어 장비 주문 급증"). 가격이 왜 움직였는지 이해할 단서를 줍니다. 뉴스는 가격 변동과 **동시에** 공개되며, 미리 알려 주는 정보는 없습니다.

## 4. 매매

| 항목 | 규칙 |
|---|---|
| 주문 방식 | 현재가로 즉시 체결. 지정가·예약 주문 없음 |
| 단위 | 1주 |
| 결제 | 지갑의 GC. 외상·빌려서 투자 없음 |
| 수수료 | 매수·매도 각 0.3% (최소 1 GC) |
| 종목당 보유 한도 | 1,000주 |
| 하루 거래 횟수 | 20회 |
| 공매도, 신용 거래 | 없음 |
| 대출금으로 투자 | 대출 잔액이 있는 동안 매수 불가 (빚내서 투자 방지) |

체결 절차 (하나의 트랜잭션):

1. 현재가 확인. 클라이언트가 본 가격과 서버 현재가가 다르면 새 가격을 알려 주고 다시 확인받습니다.
2. 매수: 지갑 잠금 → 대금과 수수료 차감 → 보유 수량과 취득원가 갱신 → 주문 기록, 원장 기록.
3. 매도: 보유 수량 확인 → 수량 차감, 실현손익 계산 → 대금에서 수수료를 뺀 금액 입금 → 주문 기록, 원장 기록.

## 5. 손익 계산

보유 내역에는 수량과 **취득원가 합계**를 저장합니다. 평균 매입단가는 화면에 보여 줄 때 나누어 구합니다. 나눈 값을 저장하면 반올림 오차가 쌓이기 때문입니다.

| 항목 | 계산 |
|---|---|
| 보유 수량 | 매수로 증가, 매도로 감소 |
| 평균 매입단가 | 취득원가 합계 ÷ 보유 수량 |
| 매수 시 | 취득원가 합계 += 체결가 × 수량 (수수료는 별도 비용으로 기록) |
| 매도 시 덜어내는 원가 | round(취득원가 합계 × 매도 수량 ÷ 보유 수량). 전량 매도면 남은 원가 전부 |
| 실현손익 (매도 1건) | 체결가 × 매도 수량 − 덜어낸 원가 − 매도 수수료 |
| 평가금액 | 현재가 × 보유 수량 |
| 평가손익 | 평가금액 − 취득원가 합계 |
| 투자 수익률 | 평가손익 ÷ 취득원가 합계 |
| 누적 실현손익 | 매도 건별 실현손익의 합 |

모든 계산은 서버가 하고 정수 GC로 처리합니다.

## 6. 화면

| 화면 | 내용 |
|---|---|
| 기업 목록 | 기업 이름, 현재가, 오늘 등락 (오르면 빨강 ▲, 내리면 파랑 ▼) |
| 기업 상세 | 한 줄 소개, 주가 차트 (하루 / 일주일 / 한 달), 최근 뉴스, 사기·팔기 |
| 내 주식 | 종목별 보유 수량, 평균 매입단가, 평가손익, 수익률, 전체 합계 |
| 거래 기록 | 매매 내역, 실현손익 |

차트는 선 하나로 단순하게 그립니다.

## 7. 초보자 보호

- 해금 레벨(초기값 8)에 이르기 전에는 메뉴가 보이지 않습니다.
- 처음 열면 금융 안내원이 세 가지를 알려 줍니다: 값은 오르기도 내리기도 한다, 잃어도 되는 만큼만 한다, 실제 주식이 아니다.
- 첫 매수 전 확인 화면에 "값이 내려가면 돈을 잃을 수 있어요"를 보여 줍니다.
- 수익을 과시하게 만드는 랭킹(수익률 순위)을 두지 않습니다.
- "지금 사세요" 같은 권유 알림을 보내지 않습니다.
- 하루 거래 횟수 한도로 과몰입을 줄입니다.

## 8. 관리자

| 메뉴 | 기능 |
|---|---|
| 가상 기업 | 기업 추가·수정, 상장·중지, 기준 가격, 변동성, 실적 점수 |
| 주식 시세 | 현재가와 추이 조회, 사건·뉴스 등록, 변동 한도·수수료·거래 한도 설정, 가격 갱신 작업 상태 |

관리자가 가격을 직접 입력해 바꾸는 기능은 두지 않습니다. 사건 등록을 통해서만 영향을 주고, 그 기록을 남깁니다.

## 9. 데이터와 API

| 테이블 | 내용 |
|---|---|
| `companies` | 기업 정의, 기준 가격, 변동성, 실적 점수, 상장 여부 |
| `stock_prices` | 시각별 가격 |
| `stock_daily` | 일별 시가·고가·저가·종가 |
| `stock_events` | 사건과 뉴스, 영향 크기, 기간 |
| `stock_holdings` | 플레이어별 보유 수량, 취득원가 합계, 누적 실현손익 |
| `stock_orders` | 체결 기록 (가격, 수량, 수수료, 실현손익) |

| API | 용도 |
|---|---|
| `GET /stocks` | 기업 목록과 현재가 |
| `GET /stocks/{code}` | 기업 상세, 뉴스 |
| `GET /stocks/{code}/chart?range=` | 차트 데이터 |
| `POST /stocks/{code}/buy` | 매수 |
| `POST /stocks/{code}/sell` | 매도 |
| `GET /stocks/portfolio` | 내 주식, 손익 |
| `GET /stocks/orders` | 거래 기록 |

`stock_prices`는 빠르게 커지므로 일정 기간(초기값 30일)이 지난 시각별 가격은 일별 요약만 남기고 지웁니다.

## 10. 확인이 필요한 것

미성년자가 이용하는 게임에 모의 투자 기능을 넣는 것이 게임물 등급분류와 관련 규정에 어떤 영향을 주는지 Phase 4 착수 전에 전문가 확인이 필요합니다 ([SECURITY_POLICY](SECURITY_POLICY.md) 9장).
