# ROOM_SYSTEM — 개인 방

> 기준 v6.0 · 2026-11-13 · 상태: 기본 방과 첫 플레이 연출(1차), 컴퓨터의 은행, 옷장, 방 꾸미기(가구 놓기·옮기기·넣어 두기, 8장)를 클라이언트와 모의 서버에 구현. 거울·개인 보관함·벽걸이 장식은 설계

## 1. 역할

- 게임이 시작되는 곳이고, 실행할 때마다 돌아오는 곳입니다.
- 적이 들어오지 않는 안전한 공간입니다.
- 번 돈으로 꾸미는 나만의 공간입니다.
- 컴퓨터를 통해 지도·은행·투자를 여는 생활의 중심입니다.

## 2. 기본 구성

방 크기는 약 6 m × 5 m, 한쪽 벽에 문과 창문이 있습니다.

| 가구 | 상호작용 (E) | 기능 | 시점 |
|---|---|---|---|
| 침대 | 눕기 | 시작 위치. 체력 완전 회복 | 1차 |
| 책상 | — | 컴퓨터가 놓이는 자리 | 1차 |
| 컴퓨터 | 켜기 | 침공 경고, 도시 소식, 지도, 은행, 주식 (3장) | 1차 (경고·지도·은행) |
| 옷장 | 열기 | 방어구·의상 갈아입기 | Phase 3 (구현됨) |
| 거울 | 보기 | 얼굴·헤어·피부색 바꾸기 | 미룸 |
| 문 | 나가기 | 도시로 이동 | 1차 |
| 개인 보관함 | 열기 | 쓰지 않는 아이템 보관 (인벤토리와 별도 칸) | 미룸 |

거울과 보관함은 방에 놓여 있되, E를 누르면 보리가 "그건 아직 준비 중이야"라고 답합니다. 옷장은 입을 것이 하나도 없으면 열리지 않고 보리가 "입을 옷이 아직 없어. 알록달록 가게에서 살 수 있어!"라고 알려 줍니다.

안내 로봇 보리는 가구가 아니라 방에 사는 NPC입니다 ([NPC_SYSTEM](NPC_SYSTEM.md)).

## 3. 컴퓨터

컴퓨터는 방 안의 메뉴입니다. 켜면 큰 아이콘 몇 개만 있는 바탕화면이 나오고, 해금된 기능만 아이콘이 보입니다.

| 아이콘 | 기능 | 해금 |
|---|---|---|
| 경보 | 도시 침공 경고, 구조 요청 | 처음부터 |
| 소식 | 도시 공지, 홈페이지 공지사항 | 처음부터 |
| 지도 | 대한민국 지도 열기 (M 키와 동일) | 전입신고 안내 뒤 |
| 은행 | 잔액, 입출금, 저축 | 레벨 3 |
| 주식 | 가상 기업, 차트, 매매 | 레벨 8 (Phase 4) |
| 대출 | 신용점수, 대출 신청·상환 | 레벨 10 (Phase 4) |

같은 기능은 도시의 NPC 창구에서도 이용할 수 있습니다. 컴퓨터는 편의 경로이고, NPC 창구는 처음 배우는 경로입니다.

## 4. 꾸미기

### 4.1 배치 방식

- 바닥을 0.5 m 격자로 나눕니다 (12 × 10칸).
- 가구는 격자 칸 크기(가로 × 세로)를 가지며 90도 단위로 회전합니다.
- 벽걸이 장식은 벽면 격자에 붙입니다.
- 꾸미기 모드에 들어가면 가구를 집어 옮기고, 겹치는 자리는 붉게 표시합니다.
- 문 앞과 침대 옆 한 칸은 비워 두어야 합니다 (갇힘 방지).

### 4.2 가구 얻기

상점에서 GC로 삽니다. 가구는 인벤토리가 아니라 **가구 보관 목록**에 들어가고, 꾸미기 모드에서 꺼내 놓습니다. 기본 가구(침대·책상·컴퓨터·옷장·거울·보관함)는 옮길 수 있지만 팔거나 버릴 수 없습니다.

### 4.3 시점

1차는 기본 가구가 고정된 방만 제공했습니다. 가구 구매와 배치는 Phase 3에서 구현했습니다 (8장). 8장이 4.1·4.2와 다른 곳은 8.4에 적었습니다.

## 5. 장면 구성

| 항목 | 내용 |
|---|---|
| 장면 | `Room` 장면 하나. 모든 플레이어가 같은 틀을 쓰고 가구 배치만 데이터로 채운다 |
| 진입 | 게임 시작, 도시의 집 문, 쓰러진 뒤 부활(선택) |
| 나가기 | 문 → 대표 도시의 주거 지역 집 앞 |
| 카메라 | 좁은 공간용 설정 (가까운 거리, 높은 각도) |
| 조명 | 창문으로 들어오는 빛. 침공 경고 때는 붉은 경광 |

방은 개인 공간이라 다른 플레이어가 보이지 않습니다. 친구 초대는 추후 과제입니다.

## 6. 첫 플레이 연출

1. 화면이 밝아지며 침대에서 일어납니다.
2. 보리가 다가와 손짓합니다. 움직이기 전까지 다른 일은 일어나지 않습니다.
3. 몇 걸음 움직이면 컴퓨터가 붉게 깜빡이고 경보음이 울립니다.
4. 컴퓨터에 E를 누르면 "도시 침공 경고" 화면 한 장이 뜹니다.
5. 창밖에서 구조 요청이 들리고 문이 빛납니다.
6. 문에 E를 누르면 도시로 나갑니다.

컴퓨터를 보지 않고 바로 문으로 가도 진행됩니다. 순서를 강제하지 않습니다.

이 연출은 서버에 저장된 진행 표시(`tutorial_step`)로 한 번만 실행합니다.

## 7. 데이터와 API

| 데이터 | 저장 위치 |
|---|---|
| 가구 정의 (크기, 가격, 모델 코드) | `item_defs` (분류: 가구) |
| 보유 가구 | `room_furniture` |
| 배치 (칸 좌표, 회전, 배치 여부) | `room_furniture` |
| 보관함 내용 | `inventories` (위치 구분: 보관함) |

| API | 용도 | 시점 |
|---|---|---|
| `GET /room` | 방 배치 불러오기 (지금은 내 정보 `GET /me`에 가구 목록이 함께 옴) | Phase 3 |
| `PUT /room/furniture/{id}` | 가구 하나를 놓거나 옮김 — 칸 좌표, 회전. 서버가 8.2의 규칙으로 검사 | Phase 3 (모의 서버에 구현) |
| `DELETE /room/furniture/{id}/placement` | 가구 하나를 넣어 둠 | Phase 3 (모의 서버에 구현) |
| `POST /room/storage/move` | 인벤토리 ↔ 보관함 이동 | 미룸 |

설계는 배치 전체를 한 번에 저장하는 `PUT /room/furniture`였지만, 가구를 하나씩 놓는 조작에 맞춰 하나씩 보내도록 바꿨습니다. 서버는 매번 방 전체가 규칙에 맞는지 검사합니다.

## 8. 구현된 것: 방 꾸미기 (2026-11-13, 클라이언트와 모의 서버)

규칙은 `Domain/Room.cs`(`RoomLayout`, `RoomRules`)에 Unity와 무관한 C#으로 있고, 모의 서버와 클라이언트의 미리 보기가 같은 규칙을 씁니다. 실제 서버(PHP)의 검사가 이 규칙과 같아야 합니다.

### 8.1 조작

튜토리얼을 마친 뒤 방에서 **F**를 누르면 꾸미기가 시작됩니다. 메뉴 화면이 아니라 방 안을 걸어 다니며 합니다.

| 상태 | 키 | 하는 일 |
|---|---|---|
| 평소 | F | 꾸미기 시작. 가구가 하나도 없으면 시작하지 않고 "알록달록 가게에서 살 수 있어요"를 알림 |
| 고르기 | E | 놓인 가구 곁(1.1 m)이면 그 가구의 메뉴: 옮기기 / 넣어 두기 / 다른 가구 꺼내기. 아니면 넣어 둔 가구를 꺼내는 메뉴 |
| 고르기 | F | 꾸미기 끝 |
| 들고 있음 | (걷기) | 가구가 캐릭터 앞의 칸에 미리 보임. 놓을 수 있으면 바닥 칸이 초록, 아니면 빨강이고 이유가 안내에 뜸 |
| 들고 있음 | E | 그 자리에 놓기. 놓을 수 없으면 이유를 알리고 계속 들고 있음 |
| 들고 있음 | R | 90도 더 돌리기 |
| 들고 있음 | F | 그만두기 (옮기던 가구는 제자리에, 꺼낸 가구는 넣어 둔 채로) |

- 든 가구는 **앞면이 나를 봅니다.** 벽을 보고 서면 소파의 등받이가 벽 쪽으로 갑니다. 대부분은 R을 누를 필요가 없습니다. 옮기는 가구는 놓여 있던 방향 그대로 들립니다.
- 꾸미는 동안에는 공격, 가방(I), 지도(M), 평소의 상호작용(문, 컴퓨터, 보리와 말하기)이 쉬고, 화면 아래의 키 안내가 꾸미기용으로 바뀝니다.
- 놓은 가구는 지나갈 수 없습니다 (충돌체가 있습니다).

### 8.2 놓을 수 있는 자리 (서버가 검사)

바닥은 0.5 m 칸 12 × 10개입니다. 가구는 가로 × 세로 칸 수를 가지고 90도씩 돌립니다.

| 검사 | 놓을 수 없을 때의 안내 |
|---|---|
| 방 안에 들어가는가 | "방 밖으로 나가요." |
| 기본 가구(침대, 책상, 의자, 옷장, 보관함, 화분, 보리)와 겹치지 않는가 | "다른 가구가 있는 자리예요." |
| 비워 둘 자리가 아닌가: 문 앞, 거울 앞, 그리고 서서 무언가를 하는 자리(문, 옷장, 컴퓨터, 침대 옆, 거울·보관함, 보리 앞) | "여기는 비워 둬야 해요." |
| 이미 놓은 가구와 겹치지 않는가 | "다른 가구와 겹쳐요." |
| 놓은 뒤에도 문에서 서는 자리 모두로 걸어갈 수 있는가 | "여기에 놓으면 길이 막혀요." |

마지막 검사는 칸의 모서리를 따라 길을 찾습니다. 캐릭터(지름 0.6 m)는 모서리 둘레의 네 칸이 모두 비어 있어야 그 자리에 설 수 있다고 봅니다. 그래서 가구 사이의 한 칸짜리 틈은 길로 치지 않습니다.

클라이언트만 하는 검사가 둘 있습니다 (지금 서 있는 자리에 달린 것이라 서버는 알 수 없습니다): 가구가 캐릭터에 닿으면 "너무 가까워요. 한 걸음 물러나세요.", 놓으면 캐릭터가 문으로 가지 못하게 되면 "여기에 놓으면 갇혀요."

### 8.3 가구의 보관

- 가구는 가방이 아니라 가구 목록에 들어갑니다 (`MeDto.furniture`). 가방 칸을 쓰지 않습니다.
- 한 점마다 번호(id), 종류, 놓았는지, 칸 좌표와 회전을 가집니다.
- 놓은 것과 넣어 둔 것을 합쳐 20개까지 가집니다 (`RoomConfig.maxFurniture`).
- 되팔 때는 넣어 둔 것만 팔 수 있습니다 ([ITEM_SYSTEM](ITEM_SYSTEM.md) 7.3).

### 8.4 설계와 다른 곳, 없는 것

| 항목 | 설계 | 구현 | 이유 |
|---|---|---|---|
| 꾸미기 방식 | 꾸미기 모드에서 가구를 집어 옮김 | 캐릭터가 가구를 들고 걸어가서 놓음 | 마우스 커서를 풀지 않고 E·R·F만으로 됨. 다른 조작과 같음 |
| 기본 가구 | 옮길 수 있음 (팔거나 버릴 수는 없음) | 고정 | 침대·컴퓨터·문 앞의 서는 자리가 튜토리얼과 상호작용의 기준점. 옮기게 하려면 그 기준도 함께 옮겨야 함 |
| 비워 둘 자리 | 문 앞과 침대 옆 한 칸 | 문 앞 전체, 거울 앞, 서는 자리 여섯 곳 + 길 검사 | 한 칸만 비워서는 가구로 길을 막을 수 있음 |
| 벽걸이 장식 | 벽면 격자 | 없음 | 미룸 |
| 가구 수 | — | 20개까지 | 방이 12 × 10칸이라 그 이상은 놓을 자리가 없음 |
| 보리의 자리 | — | 칸 하나의 한가운데 (0.25, 0.25)로 옮김 | 칸에 맞춰 막아 두기 위해 |
| 가구의 쓰임 | — | 없음 (보기만) | 소파에 앉기, 조명 끄기 같은 상호작용은 없음 |

알려진 한계:

- 가구를 들고 있을 때 캐릭터의 손에 들린 모습은 없습니다. 가구가 앞의 칸 위에 살짝 떠서 보입니다.
- 가구를 한 번에 하나씩만 다룹니다. "모두 넣어 두기"는 없습니다.
- 꺼내기 메뉴는 여섯 종류까지 보여 줍니다 (지금 가구는 다섯 종류).
