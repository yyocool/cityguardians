# CITY_TAX_SYSTEM — 게임 내 지방세

> 기준 v9.0 · 2026-11-14 · 상태: PHP 서버(`CG\Service\Taxes`), 관리자 화면, 게임 화면(작전 본부 → 도시 살림 → 지방세) 구현. 로컬 테스트 DB에서만 돌려 보았고 운영에는 배포하지 않음. **세 가지 세금 모두 꺼진 채로 들어감** (관리자가 켜기 전에는 한 푼도 걷지 않음) · 세율과 면제 기준은 확정 전의 초기값

## 1. 방향

게임머니(GC)로만 움직이는 **가상의** 지방세입니다. "내가 낸 세금이 우리 도시에 어떻게 쓰이는가"를 게임 안에서 겪어 보는 교육용 장치입니다.

1. **실제 돈과 이어지지 않습니다.** GC 는 현실 화폐로 바꿀 수 없고, 이 세금은 현실의 세금·납부·환급과 아무 관계가 없습니다. 화면에도 그렇게 적습니다.
2. **서버만 걷습니다.** 세율이나 세액을 받는 API가 없습니다. 세금은 지갑 원장에 줄이 생길 때 서버가 계산합니다.
3. **투명합니다.** 걷을 때마다 낸 사람의 명세(`city_tax_transactions`)와 도시 재정 원장(`city_treasury_ledger`)에 한 줄씩 남고, 낸 사람은 자기 명세를, 누구나 도시 재정을 볼 수 있습니다 ([CITY_TREASURY_SYSTEM](CITY_TREASURY_SYSTEM.md)).
4. **초보자를 보호합니다** (4장).
5. **기여금은 세금이 아닙니다.** 주민이 스스로 내는 방어 기여금(`city_fund`)과 시설 복구비(`city_repair`)는 따로 관리되고, 과세 대상으로 고를 수도 없습니다 (5장).
6. **개인 금융을 임의로 건드리지 않습니다.** 세금 때문에 잔액이 음수가 되거나, 은행 예금·대출·신용점수가 바뀌는 일은 없습니다. 세금은 **지갑의 GC** 에서만, 정해진 규칙으로만 빠집니다.

## 2. 세금의 종류

| | 거래세 `trade` | 사업세 `business` | 재산세 `property` |
|---|---|---|---|
| 대상 | 장비 구매, 장비 강화, 타워 해금 | 방어전·FPS·사냥의 전투 보상 | 지갑의 GC |
| 세율 (기본) | 3% (`rate_bp` 300) | 5% (500) | 1% (100) |
| 면제 기준 | 100 GC 미만의 거래 | 하루 소득 1,000 GC 까지 | 보유 10,000 GC 까지 |
| 상한 | 없음 | 하루 300 GC | 한 기간 500 GC |
| 징수 시점 | 거래할 때 | 보상을 받을 때 | 한 주에 한 번 (또는 한 달에 한 번) |
| 내는 방식 | **값에 들어 있음** | 받은 직후 지갑에서 빠짐 | 예약 작업이 지갑에서 뺌 |
| 초보자 보호 (기본) | 레벨 3부터, 전입 7일 뒤부터 | 레벨 5부터, 전입 14일 뒤부터 | 레벨 10부터, 전입 30일 뒤부터 |

세액은 `과세 대상 × 세율 ÷ 10,000`을 **내림**합니다.

### 거래세: 값이 비싸지지 않습니다

거래세는 치른 값 **안에** 들어 있습니다. 600 GC 짜리 장비를 사면 지갑에서는 그대로 600 GC 가 빠지고, 그 가운데 18 GC 가 도시 재정으로 갑니다. 세금을 켜도 상점의 값은 달라지지 않습니다 — 게임 경제(v8.0의 값)를 흔들지 않기 위해서입니다. 명세에는 `included = 1`로 남습니다.

> 상점에서 쓴 GC 는 원래 모두 사라집니다. 거래세가 켜져 있으면 그 가운데 일부가 사라지는 대신 도시 재정으로 갑니다. 도시 재정의 GC 는 플레이어의 지갑으로 나가는 길이 없으므로, 플레이어가 가진 GC 가 늘어나지는 않습니다.

### 사업세: 하루 면제액을 넘는 소득에

오늘 번 과세 소득(한국 날짜 기준)을 더해 가다가 면제액을 넘는 부분에만 붙습니다. 보상을 받은 직후 같은 거래 안에서 지갑에서 빠지고, 지갑 원장에 `tax_business` 사유로 남습니다. 방금 받은 보상보다 많이 걷지 않고, 하루 상한을 넘지 않습니다.

### 재산세: 기간마다 한 번

예약 작업(`bin/tick.php`)이 걷습니다. 대상은 주민이고, 레벨이 되고, **최근 `absenteeDays`(7)일 안에 접속했고**, 면제액보다 많이 가진 사람입니다 (오래 쉬는 사람의 지갑이 조용히 줄어들지 않게). 세금을 내고 나서도 잔액이 면제액 아래로 내려가지 않습니다. 은행 예금은 대상이 아닙니다 — 지갑의 GC 만 봅니다.

## 3. 걷힌 세금이 가는 곳

낸 사람의 **주거 도시** 재정으로 들어갑니다. 다른 도시를 지원하러 나가 있어도 내 도시로 갑니다. 정해진 비율(`treasury.reservePercent`, 10%)은 예비비로, 나머지는 일반 회계로 갑니다. 이방인(전입신고를 하지 않은 사람)은 세금을 내지 않습니다.

## 4. 초보자 보호

| 장치 | 내용 |
|---|---|
| 최소 레벨 | 정책마다 `min_level`. 그 아래는 내지 않음 |
| 전입 뒤 유예 | 정책마다 `grace_days`. **처음 전입한 날**부터 셈. 이사해도 다시 시작되지 않음 (면제 기간을 되살리려고 이사할 수 없음) |
| 면제 기준 | 작은 거래, 적은 소득, 적은 보유액에는 붙지 않음 |
| 상한 | 사업세는 하루, 재산세는 한 기간의 최대 금액 |
| 이방인 | 내지 않음 |
| 처음에는 꺼져 있음 | 운영팀이 켜기 전에는 아무도 내지 않음 |

게임 화면의 "세금 정책"은 세금마다 **내가 지금 내는지, 아니라면 왜 면제인지**를 보여 줍니다 (`exempt`, `exempt_message`).

## 5. 세금이 아닌 것

| | 세금 | 자발적 방어 기여금 |
|---|---|---|
| 내는 계기 | 정책에 따라 자동으로 | 주민이 스스로 고름 |
| 원장 사유 | `tax_business`, `tax_property` (거래세는 원래 거래의 줄) | `city_fund`, `city_repair` |
| 들어가는 곳 | 도시 재정 (`city_treasury_accounts`) | 그 시설의 기금 (`city_defense_structures.funded_gc`) |
| 기록 | `city_tax_transactions` | 지갑 원장의 그 줄, 기여 점수(`region_contributions`, v8.0) |

과세 대상으로 고를 수 있는 원장 사유는 코드에 정해져 있습니다 (`Taxes::taxableReasons`). 기여금, 복구비, 정착 지원금, 이사 수수료 같은 사유는 목록에 없어서, DB 를 직접 고쳐 넣어도 세금이 붙지 않습니다.

## 6. 중복 징수 방지

명세의 `(tax_type, source_key)`가 유일 키입니다.

| 세금 | `source_key` | 뜻 |
|---|---|---|
| 거래세, 사업세 | `L<지갑 원장 번호>` | 같은 원장 줄에 두 번 걷지 못함 |
| 재산세 | `P<기간>:<계정>` (예: `P2026-W46:123`) | 한 기간에 한 사람에게 한 번 |

명세를 넣는 문장이 `INSERT IGNORE`이고, 들어가지 않았으면(이미 걷었으면) 도시 재정에도 넣지 않고 지갑에서도 빼지 않습니다. 재산세의 예약 작업이 같은 기간에 여러 번 돌거나 동시에 두 개가 돌아도 한 번만 걷힙니다 (`tests/TaxTest.php`, `ConcurrencyTest.php`).

명세·도시 재정·지갑은 **하나의 거래**로 바뀝니다. 중간에 실패하면 셋 다 되돌아갑니다.

## 7. 관리자 설정

"지방세 정책" 화면 (`city.policy` 권한: 최고 관리자, 밸런스 담당). 세금마다:

- 켜기·끄기, 세율, 적용 대상(허용된 사유 가운데 고름), 면제 기준, 최소 레벨, 유예 일수, 상한, 징수 시점
- 값마다 허용 범위가 있고 벗어나면 저장되지 않습니다. 켜려면 세율이 0보다 크고 적용 대상이 하나 이상이어야 합니다. 재산세의 징수 시점은 한 주 또는 한 달입니다.
- 사유를 적어야 하고, 바꾸기 전·후의 값이 `config_history`에, 누가 했는지가 감사 기록(`tax.policy.update`)에 남습니다.
- "변경 이력"에서 이전 값으로 되돌릴 수 있습니다. 되돌리는 것도 같은 검증을 거치고 이력에 남습니다 ([ADMIN_SYSTEM](ADMIN_SYSTEM.md) 12.5). 이미 걷은 세금은 되돌려지지 않습니다.

## 8. API

| 요청 | 내용 |
|---|---|
| `GET /tax/policies` | 세금 정책, 내가 면제인지와 이유, 오늘의 사업세 소득·세액 |
| `GET /tax/transactions` | 내가 낸 세금의 명세와 종류별 합 |

형식은 [API_SPEC](API_SPEC.md) 20장. 다른 사람의 명세를 보는 API는 없습니다.

## 9. 테스트

`server/tests/TaxTest.php` ([TEST_PLAN](TEST_PLAN.md) 15장): 꺼져 있을 때 걷지 않음, 세 가지 세금의 계산, 초보자 보호, 이사로 유예가 되살아나지 않음, 기여금에는 붙지 않음, 중복 징수 방지, 원장 일치, 정책 변경의 범위·사유·이력.

## 10. 남은 일

- 세율과 기준은 플레이 데이터를 본 뒤 정해야 함. 켜는 것 자체가 운영 결정 ([DEVELOPMENT_PLAN](DEVELOPMENT_PLAN.md) 7장).
- 은행 예금·주식(Phase 4)이 생기면 재산세의 대상을 다시 정해야 함.
- 클라이언트는 모의 서버에서 "걷지 않아요"만 보여 줌 (HTTP 구현이 없음).
