# CITY_MODELING_PIPELINE — 상징거리 모델링의 제작·검수·배포

> 기준 v9.0 · 2026-11-14 · 상태: 제작 관리와 배포 목록(PHP `CG\Service\Modeling`, 관리자 화면), 클라이언트의 확인 규칙(`CG.Domain.CityContent`) 구현. **실제 3D 콘텐츠와 Addressables 설정, 내려받아 장면에 올리는 코드는 없음** — 이 문서의 5~7장은 그 부분의 설계. 운영에는 배포하지 않음

## 1. 방향

전입자가 기준에 닿은 도시([CITY_GROWTH_SYSTEM](CITY_GROWTH_SYSTEM.md))의 상징물·상징거리·특화 구역을 만들어, **앱을 다시 내놓지 않고** 운영 중인 클라이언트에 내려보냅니다.

1. **제작 → 검수 → 배포를 건너뛸 수 없습니다.** 상태는 정해진 길로만 움직이고, 만든 사람은 자기 것을 검수할 수 없습니다.
2. **서버는 파일을 받지도 내보내지도 않습니다.** 콘텐츠 저장소 안의 경로와 해시만 기록합니다. 관리자 화면에서 임의의 주소를 클라이언트에 내려보낼 수 없습니다.
3. **조금씩 넓히고, 바로 되돌릴 수 있습니다.** 받는 비율(1~100%)을 정해 배포하고, 문제가 생기면 회수합니다.
4. **콘텐츠가 없어도 게임은 그대로 됩니다.** 받지 못했거나 확인에 실패하면 기본 도시를 보여 줍니다.

## 2. 제작 작업

도시의 상징물(`landmark`) · 상징거리(`street`) · 특화 구역(`special_zone`) 하나가 한 작업입니다 (`city_modeling_projects`).

| 항목 | 열 |
|---|---|
| 담당자 | `assignee_admin_id` |
| 작업 메모 | `memo` |
| 예정일 | `due_on` |
| 파일 버전 | `file_version` (마지막으로 등록·배포한 결과물의 버전) |
| 검수 결과 | `review_result` (`none` / `pass` / `fail`), `review_note`, `reviewed_by`, `reviewed_at` |
| 적용 일시 | `applied_at` (처음 배포한 때) |
| 계기가 된 알림 | `notification_id` |

### 상태

```
NOT_STARTED ⇄ PLANNING ⇄ MODELING ⇄ REVIEW ──(검수 통과)──▶ READY ──(배포)──▶ DEPLOYED
                              ▲            │                   │  ▲                │
                              └─(검수 반려)─┘                   └──┘ (회수하면 READY 로)
```

| 이동 | 누가 | 조건 |
|---|---|---|
| NOT_STARTED → PLANNING → MODELING → REVIEW, 그리고 한 칸 뒤로 | `modeling.manage` (운영자, 콘텐츠 제작 담당) | 사유를 적음 |
| REVIEW → READY (통과) / MODELING (반려) | `modeling.review` (운영자) | **담당자 본인은 검수할 수 없음.** 검수 의견 필수 |
| READY → REVIEW | `modeling.manage` | 다시 검수받을 때 |
| READY → DEPLOYED | 손으로 고를 수 없음 | 결과물을 배포했을 때에만 |
| DEPLOYED → READY | 손으로 고를 수 없음 | 배포 중인 결과물을 회수했을 때에만 |

상태가 바뀔 때마다 **모델링 진행 알림**(`city_growth_notifications.kind = 'modeling'`)과 감사 기록이 남습니다. 도시 현황(`city_population_stats.modeling_status`)은 그 도시의 상징거리 작업을 따르고, 상징거리 작업이 없으면 가장 많이 진행된 작업을 따릅니다.

## 3. 결과물

결과물(`city_modeling_assets`)은 작업의 한 판입니다. 같은 작업에 같은 버전을 두 번 등록할 수 없습니다 — 내용이 바뀌면 버전을 올립니다.

| 값 | 검사 |
|---|---|
| 버전 | `1.0.0` 형식 |
| 콘텐츠 주소 (`address_key`) | Addressables 의 키. 영문·숫자·`._-/` |
| 카탈로그 경로 (`catalog_path`) | 콘텐츠 저장소 안의 **상대 경로**. `..`, `//`, 주소 형식(`https://…`)은 거절 |
| 해시 (`content_hash`) | 카탈로그 파일의 SHA-256 (16진수 64자) |
| 크기 (`size_bytes`) | 1 이상 |
| 최소 클라이언트 버전 | 비우거나 `9.0.0` 형식 |

```
uploaded ──(승인)──▶ approved ──(배포)──▶ released ──(회수)──▶ withdrawn
    └──(반려)──▶ rejected
```

| 일 | 누가 | 조건 |
|---|---|---|
| 등록 | `modeling.manage` | 작업이 MODELING 이상 |
| 승인·반려 | `modeling.review` | **올린 사람은 자기 결과물을 승인할 수 없음.** 의견 필수 |
| 배포, 받는 비율 변경 | `content.release` (**최고 관리자만**) | 결과물이 승인됨, 작업이 READY 이상, 서버에 `CONTENT_BASE_URL` 설정됨, 사유 |
| 회수 | `content.withdraw` (최고 관리자, 운영자) | 배포 중인 것. 사유. 배포보다 넓게 주어 빨리 되돌릴 수 있게 함 |

새 판을 배포하면 같은 작업의 이전 배포판은 자동으로 회수 처리됩니다.

## 4. 배포 목록 (서버 → 클라이언트)

`GET /cities/content` (`X-Client-Version` 헤더를 봄)는 **이 계정이 받아도 되는 묶음**만 돌려줍니다.

- 배포 중(`released`)인 결과물 가운데,
- 클라이언트 버전이 `min_client_version` 이상이고 (버전을 알 수 없으면 주지 않음),
- 이 계정이 받는 무리에 든 것.

받는 무리는 `SHA-256(계정 공개 ID : 결과물 공개 ID)`의 앞자리로 정합니다. 계정마다 늘 같은 답이 나오고, 비율을 올리면 받는 사람이 **늘 뿐** 바뀌지 않습니다 (10%에 들었던 계정은 50%에도 듭니다).

응답의 `catalog_url`은 `CONTENT_BASE_URL + '/' + catalog_path`입니다. `CONTENT_BASE_URL`은 서버의 `.env`에만 있고 `https://`만 받습니다. 설정되지 않았으면 `available: false`이고 아무것도 내려가지 않습니다.

**정식 개방 일시**(`city_population_stats.opened_at`)는 상징거리의 결과물이 처음으로 100%에 배포된 때 한 번 적힙니다. 일부 배포는 정식 개방이 아닙니다.

## 5. 콘텐츠 저장소와 Addressables (설계)

검토한 방식과 고른 것:

| 방식 | 판단 |
|---|---|
| 도시를 빌드에 모두 넣기 | 도시가 늘 때마다 앱을 다시 내놓아야 하고 용량이 계속 늘어남. 쓰지 않음 |
| AssetBundle 을 직접 다루기 | 의존성·버전·캐시를 직접 만들어야 함 |
| **Unity Addressables + 원격 카탈로그** | 도시마다 묶음을 따로 만들고, 클라이언트는 카탈로그만 받아 필요한 묶음을 내려받음. Unity 6 에서 지원. **이것으로 설계** |

- **묶음의 단위:** 도시 × 종류 (예: `city/11110/street`). 한 도시의 묶음이 다른 도시의 묶음에 의존하지 않게 합니다. 여러 도시가 함께 쓰는 재질·소품은 빌드에 넣은 공용 묶음으로 둡니다.
- **저장소의 구조:** `<CONTENT_BASE_URL>/city-<지역 코드>/<버전>/catalog.json` 과 그 옆의 번들. **버전마다 폴더가 다르고, 올린 파일은 고치지 않습니다** (고치면 해시가 달라져 클라이언트가 거절합니다). 되돌리기는 이전 판을 다시 배포하는 것입니다.
- **저장소:** 정적 파일을 `https`로 내주는 곳이면 됩니다 (게임 서버와 다른 호스트를 권장). 저장소에 쓰는 권한은 관리자 화면과 분리합니다 — 관리자 화면에는 경로와 해시만 등록합니다.
- **스크립트는 내려보내지 않습니다.** Addressables 로 내려가는 것은 모델·재질·프리팹 같은 데이터뿐이고, 코드는 빌드에 든 것만 실행됩니다. 새 동작이 필요한 콘텐츠는 `min_client_version`을 올려 새 빌드에만 내보냅니다.
- **에셋의 출처:** 다른 게임의 캐릭터·에셋을 복제하지 않습니다. 실제 거리의 상표·간판·인물이 들어가는 모델은 검수 때 확인합니다 (8장 점검표).

## 6. 클라이언트의 확인 (구현됨: `CG.Domain.CityContent`)

서버가 정해 준 목록이라도 클라이언트가 다시 확인합니다. 하나라도 맞지 않으면 그 묶음을 쓰지 않고 기본 도시를 보여 줍니다.

| 확인 | 규칙 |
|---|---|
| 주소 | `catalog_url`이 **클라이언트에 들어 있는** 콘텐츠 저장소 주소(`https://`)로 시작해야 함. 서버 응답이 알려 준 주소를 기준으로 삼지 않음. 경로에 `..`, `//`, `\`, `?`, `#`, `@`, `%`가 있으면 거절 |
| 종류 | `landmark` / `street` / `special_zone` |
| 버전 | 내 클라이언트 버전이 `min_client_version` 이상 |
| 해시와 크기 | 내려받은 카탈로그의 크기와 SHA-256 이 서버가 알려 준 값과 같아야 함 (`HashMatches`) |
| 고르기 | 같은 도시·종류에 쓸 수 있는 것이 여럿이면 가장 새 버전 (`Pick`) |

## 7. 내려받아 올리는 흐름 (설계, 미구현)

1. 도시에 들어갈 때 `GET /cities/content`로 목록을 받습니다 (없거나 실패하면 기본 도시).
2. `CityContent.Pick`으로 이 도시의 묶음을 고릅니다.
3. 카탈로그를 내려받아 해시를 확인합니다.
4. Addressables 에 카탈로그를 더하고 `address_key`의 프리팹을 내려받습니다. 내려받는 동안에는 기본 도시를 보여 주고, 끝나면 다음에 도시에 들어올 때 바꿉니다 (플레이 도중에 바닥이 바뀌지 않게).
5. 내려받기·불러오기에 실패하면 그 판을 이번 실행 동안 쓰지 않습니다. 두 번 이상 실패한 판은 서버에 알려(추가할 API) 운영자가 회수를 판단할 수 있게 합니다.
6. 캐시: 쓰지 않게 된 판(회수되었거나 더 새 판이 온 것)은 다음 실행 때 지웁니다. 모바일에서는 Wi-Fi 가 아닐 때 크기를 알려 주고 묻습니다.

지금의 클라이언트에는 1~2의 규칙과 3의 해시 확인만 있고 (모의 서버는 빈 목록을 줍니다), HTTP 로 받는 부분과 4~6은 없습니다. 클라이언트의 빌드 버전(`bundleVersion`)은 지금 `0.1.0`입니다 — 첫 콘텐츠를 내기 전에 버전 체계를 정해 `min_client_version`과 맞춰야 합니다.

## 8. 배포 절차 (운영)

1. 기준 도달 알림을 확인하고 담당자를 배정, 제작 작업을 등록합니다.
2. 기획 → 제작. 묶음을 만들어 **스테이징 저장소**에 올리고 결과물을 등록합니다 (경로, 해시, 크기).
3. 검수 요청 → 담당자가 아닌 사람이 작업을 검수합니다. 점검표:
   - 저장소의 파일 해시와 크기가 등록한 값과 같은가
   - 지원하는 가장 낮은 사양에서 프레임과 메모리가 버티는가, 묶음의 크기가 한도 안인가
   - 충돌체·길 찾기·출입구가 기본 도시의 동선과 이어지는가
   - 다른 게임의 에셋, 허락받지 않은 상표·인물·간판이 없는가
   - `min_client_version`이 이 콘텐츠가 필요로 하는 빌드와 맞는가
4. 올린 사람이 아닌 사람이 결과물을 승인합니다.
5. 최고 관리자가 운영 저장소에 올라간 것을 확인하고 **10%**로 배포합니다. 오류 보고와 접속 기록을 살핀 뒤 50% → 100%로 넓힙니다. 100%가 되면 정식 개방 일시가 적힙니다.
6. 문제가 생기면 운영자가 바로 회수합니다. 클라이언트는 다음에 목록을 받을 때부터 기본 도시로 돌아갑니다.

운영 저장소를 새로 두는 것, `CONTENT_BASE_URL`을 운영 서버에 넣는 것은 사전 승인이 필요한 변경입니다 ([SERVER_DEPLOYMENT](SERVER_DEPLOYMENT.md) 13장).
