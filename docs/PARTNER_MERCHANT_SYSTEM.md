# PARTNER_MERCHANT_SYSTEM — 제휴 업체·지점·혜택

> 기준 v7.0 · 2026-11-13 · 상태: **구현됨, 운영 전.** 로컬 테스트 DB에서 테스트 통과. 제휴 업체·지점·혜택의 초기 데이터는 없습니다: 실제 제휴 계약이 생겼을 때 관리자가 등록합니다.

CITY PASS 에 나오는 상점은 모두 운영팀이 등록하고 **다른 관리자가 승인한** 업체입니다. 상점이 스스로 가입하는 화면은 없습니다.

관련 문서: [`CITY_PASS_SYSTEM.md`](CITY_PASS_SYSTEM.md), [`COUPON_SYSTEM.md`](COUPON_SYSTEM.md), [`ADMIN_SYSTEM.md`](ADMIN_SYSTEM.md) 11장

---

## 1. 원칙

| 원칙 | 지키는 방법 |
|---|---|
| 제휴하지 않은 상점을 제휴 상점으로 보여 주지 않는다 | 밖에 보이는 조건이 SQL 한 곳(`CityPass::visibleSql`)에 있다: 업체가 `approved` 이고 오늘이 계약 기간 안이며, 혜택이 `approved` 이고 이용 기간 안일 것. 게임·홈페이지·API 가 모두 이 조건을 쓴다 |
| 승인은 등록한 사람이 하지 못한다 | 등록하거나 마지막으로 고친 사람(`created_by`)과 승인하는 사람이 같으면 서버가 거절한다 |
| 계약 없이 승인되지 않는다 | 계약서 문서 번호, 끝나지 않은 계약 기간, 청소년 적합 확인, 운영 중인 지점 하나 이상이 모두 있어야 승인된다 (`resume` 도 같다) |
| 계약이 끝나면 저절로 내려간다 | 계약 종료일이 지나면 상태를 바꾸지 않아도 밖에 보이지 않는다 |
| 상점은 자기 것만 본다 | 5장 |

## 2. 제휴 업체 (`partner_merchants`)

| 항목 | 열 | 밖에 보이는가 |
|---|---|---|
| 상점명 | `name` | 예 |
| 업종 | `category`: cafe, restaurant, fitness, culture, education, retail, service | 예 |
| 제휴 상태 | `status` | 승인된 것만 보인다 |
| 계약서 문서 번호, 계약 기간 | `contract_reference`, `contract_starts_on`, `contract_ends_on` | 아니오 |
| 업체 담당자 이름·전화·이메일 | `contact_*` | 아니오 (관리자만) |
| 청소년 적합 확인 | `youth_safe_confirmed` | 아니오 |

업종 목록에는 주류·유흥·사행 업종이 없습니다. 그래도 업종만으로는 걸러지지 않으므로, 승인하는 사람이 "청소년에게 맞지 않는 업종·상품이 아님"을 확인해야 합니다. 그 기준 문서는 아직 없습니다 ([`REAL_WORLD_REWARDS_POLICY.md`](REAL_WORLD_REWARDS_POLICY.md) 6.3).

상태 전환 (모두 사유 필수, 관리자 감사 기록에 남음):

```
초안 ──submit──→ 승인 대기 ──approve──→ 승인됨(공개) ──suspend──→ 일시 중지
  ↑                  │                      │   ↑                    │
  └────return────────┘                      │   └──────resume────────┘
  └──────────────reopen (고치려고)───────────┴────────────────────────┘
어느 상태에서든 ──end──→ 제휴 종료 (되돌릴 수 없다)
```

승인된 업체의 내용을 고치려면 `reopen` 으로 초안으로 돌려야 하고, 그러면 다시 승인을 받아야 합니다. 업체가 승인 상태가 아니게 되면 그 업체의 혜택은 밖에 보이지 않고, 이미 나간 쿠폰은 쓸 수 없게 됩니다 (목록에는 남습니다).

## 3. 지점 (`partner_branches`)

| 항목 | 열 |
|---|---|
| 지점 이름 | `name` |
| 지역 | `region_id` (전국 시·군·구 표의 한 곳). 지역별 목록은 이것으로 고른다 |
| 주소, 연락처 | `address`, `phone` — 실제 매장의 것 |
| 지도 위치 | `lat`, `lng` (없어도 된다) |
| 대표 이미지 | `image_file` — 서버의 `public/media` 안에 있는 파일 이름. 응답에는 `/media/파일이름` 으로 나간다 |
| 쓰는가 | `is_active` |

혜택은 한 지점에만 걸 수도 있고(`partner_offers.branch_id`), 업체의 모든 지점에 걸 수도 있습니다 (NULL).

## 4. 혜택 (`partner_offers`)

| 지시서의 속성 | 열 |
|---|---|
| 할인 유형 | `discount_type`: percent, amount, free_trial, gift, special |
| 할인 금액 또는 비율 | `discount_value` (percent 면 %, amount 면 원) |
| 이용 조건 | `conditions` |
| 이용 가능 기간 | `starts_at` ~ `ends_at` |
| 이용 가능 횟수 | `per_member_limit` (한 사람이 받을 수 있는 수), `total_limit` (전체 수량. NULL 이면 제한 없음) |
| 쿠폰의 유효기간 | `coupon_valid_days` (받은 날부터. 혜택의 종료일을 넘지 않는다) |
| 발급 조건 | `issue_policy`: `membership`(가입한 회원), `promotion`(무료 프로모션), `partner_condition`(제휴사가 공개한 조건) |

`issue_policy` 는 이 셋뿐입니다. GC·레벨·전투·랭킹을 조건으로 거는 값은 없고, 발급 코드는 지갑과 전투 기록을 읽지 않습니다.

상태 전환은 업체와 같고(`paused` = 발급 중지), 다음이 더 있습니다.

- 승인하려면 업체가 승인 상태여야 하고, 혜택의 이용 기간이 **제휴 계약 기간을 넘지 않아야** 합니다.
- 쿠폰이 한 장이라도 나간 혜택은 `reopen` 할 수 없습니다 (이미 받은 사람의 조건이 바뀌면 안 됩니다). 종료하고 새로 등록합니다.
- 종료해도 이미 나간 쿠폰은 유효기간까지 쓸 수 있습니다.

## 5. 상점 계정과 접근 범위

상점 직원이 쓰는 계정은 `merchant_users` 에 있고, 운영 관리자(`pass.manage`)가 만듭니다. 웹에서 가입하는 길은 없습니다.

| 항목 | 내용 |
|---|---|
| 범위 | 계정은 **한 업체**에 묶입니다. `branch_id` 가 있으면 그 지점만 (지점 계정), 없으면 업체의 모든 지점 (본사 계정) |
| 볼 수 있는 것 | 자기 업체(지점 계정이면 자기 지점)에서 처리한 쿠폰의 내역과 통계. 혜택별 발급 수는 본사 계정에만 보인다 |
| 볼 수 없는 것 | 다른 업체의 쿠폰·내역, 손님의 닉네임·회원번호·계정. 확인 화면은 혜택과 조건만 보여 준다 |
| 다른 업체의 쿠폰 코드를 넣으면 | "쓸 수 있는 쿠폰을 찾지 못했습니다" — 모르는 코드, 다른 업체의 쿠폰, 이미 쓴 쿠폰을 구별해 알려 주지 않는다 |
| 임시 비밀번호 | 계정을 만들거나 재설정할 때 한 번만 화면에 나온다 (해시만 저장). 처음 로그인하면 바꿔야 쿠폰을 처리할 수 있다 |
| 로그인 보호 | 5번 틀리면 15분 잠금, 한 주소에서 10분에 10번까지 (`MERCHANT_LOGIN_PER_10MIN`) |
| 접속 | 쿠키 `cg_merchant` (HttpOnly, SameSite=Strict, HTTPS 전용). 조작이 없으면 30분, 길어도 12시간. 모든 변경에 CSRF 확인 |
| 멈추기 | 관리자가 계정을 멈추거나 비밀번호를 재설정하면 그 계정의 접속이 모두 끊긴다. 업체가 승인 상태가 아니면 쿠폰을 처리할 수 없다 |
| 기록 | 로그인, 확인, 확인 실패, 사용 처리가 `merchant_audit_logs` 에 남는다 |

화면과 사용 처리의 규칙은 [`COUPON_SYSTEM.md`](COUPON_SYSTEM.md) 5장.

**한계**: 상점 계정에는 2단계 인증이 없습니다. 운영 전에 필요한지 검토해야 합니다.

## 6. 관리자 화면

| 경로 | 내용 | 권한 |
|---|---|---|
| `/admin/pass/merchants` | 제휴 업체 목록, 등록, 상세 (지점, 혜택, 상점 계정), 상태 전환 | 보기 `pass.view`, 등록·수정 `pass.manage`, 승인 `pass.approve` |
| `/admin/pass/offers` | 혜택 목록, 상세, 상태 전환 | 위와 같음 |
| `/admin/pass/coupons` | 쿠폰 목록 (회원번호로만 보인다), 쓰지 않은 쿠폰의 취소 (사유 필수) | 보기 `pass.view`, 취소 `pass.manage` |
| `/admin/pass/redemptions` | 사용 내역 | `pass.view` |
| `/admin/pass/stats` | 이용 통계 | `pass.view` |
| `/admin/pass/fraud` | 부정 사용 탐지 | `pass.view` |
| `/admin/pass/audit` | 상점 계정 기록 | `benefit.audit` |

역할: CITY PASS 담당(`pass_manager`)은 보기·등록·승인, 준법 담당(`compliance`)은 보기·승인·감사. 등록한 사람은 승인할 수 없으므로 **담당자가 둘 이상**이거나 준법 담당이 승인해야 합니다.

## 7. 통계와 부정 사용 탐지

**이용 통계**: 회원 수, 승인된 업체·혜택 수, 쿠폰의 상태별 수, 혜택별 발급·사용·만료·취소, 지역별 사용 수, 최근 14일의 날짜별 사용 수.

**부정 사용 탐지** — 최근 24시간의 신호입니다. 판정이 아니라 사람이 들여다볼 목록입니다.

| 신호 | 기준 | 뜻할 수 있는 것 |
|---|---|---|
| 코드를 여러 번 틀린 상점 계정 | 확인 실패 5번 이상 | 코드를 추측하고 있다 |
| 짧은 시간에 몰아서 처리한 상점 계정 | 10분 안에 20건 이상 | 손님 없이 쿠폰을 처리하고 있다 |
| 코드를 만들기만 하고 쓰지 않은 회원 | 제시 15번 이상 | 코드를 다른 곳에 넘기고 있다 |

서버가 스스로 막는 것은 따로 있습니다: 상점 계정이 10분 안에 코드를 10번 틀리면 10분 동안 처리할 수 없고, 회원은 10분에 30번까지만 코드를 만들 수 있습니다.

## 8. 한계

- 상점이 직접 혜택을 등록·수정하는 화면이 없습니다. 운영팀이 대신 등록합니다.
- 제휴 계약서 자체는 이 시스템에 없습니다 (문서 번호만 적습니다).
- 정산이 없습니다. 쿠폰은 무료이고 운영사와 상점 사이에 오가는 돈을 다루지 않습니다.
- 청소년 적합 기준, 제휴 계약의 표준 조항은 법률 검토가 필요합니다.
