# CITY_RISK_SYSTEM — 도시 위험도

> 기준 v8.0 · 2026-11-13 · 상태: 규칙(`CG.Domain` / `server/src/Domain`), 모의 서버, PHP 서버, 관리자 화면 구현. 서버는 로컬 테스트 DB에서만 돌려 보았고 운영에는 배포하지 않음 · 수치는 플레이테스트 전의 초기값

## 1. 방향

플레이어가 싸운 결과가 "우리 도시가 지금 얼마나 안전한가"로 보여야 합니다. 도시마다 위험도 하나를 두고, 침공이 오면 오르고 주민이 막으면 내립니다.

지키는 원칙은 다섯 가지입니다.

1. **위험도는 서버가 계산합니다.** 위험도 숫자를 받는 API가 없습니다. 클라이언트는 "전투가 끝났다", "시설을 고치겠다"만 알리고, 서버가 그 보고를 검증한 뒤 위험도를 바꿉니다.
2. **위험도를 올리는 것은 시스템 사건뿐입니다.** 플레이어의 활동은 내리기만 합니다. 방어전에 져도 위험도는 오르지 않습니다 (시도 횟수만 셉니다). 져서 도시가 나빠진다면 초보자가 방어전에 나서지 않게 되기 때문입니다.
3. **바뀔 때마다 이력이 남습니다.** 누가(가디언·지원 가디언·NPC 수비대·시스템·관리자), 왜, 얼마나 바꿨는지 `city_risk_history`에 한 줄씩 쌓입니다.
4. **개인 금융과 독립입니다.** 위험도가 아무리 높아져도 은행 잔액, 대출, 게임 내 신용점수는 바뀌지 않습니다. 위험도 코드는 지갑·은행·신용 테이블을 읽거나 쓰지 않습니다. 플레이어의 GC가 줄어드는 것은 시설 복구나 도시 기금처럼 **스스로 고른 일**뿐입니다.
5. **계산식의 숫자는 관리자가 고칩니다** (7장).

## 2. 값과 단계

- 위험도는 0~100입니다. 서버는 1/100 단위(0~10000, `risk_centi`)로 저장해 작은 변화도 쌓이게 하고, 화면에는 소수점 아래를 버린 0~100을 보여 줍니다.
- 새 도시의 첫 값은 `initialRisk`(20)를 가운데로 도시마다 ±`initialSpread`(12) 안에서 정해집니다. 도시 코드로 정해지는 값이라 늘 같습니다.

| 단계 | 범위 (초기값) | 모양 | 색 | 코드 |
|---|---|---|---|---|
| 안전 | 0~24 | ● | 초록 | `safe` |
| 주의 | 25~49 | ▲ | 노랑 | `caution` |
| 위험 | 50~74 | ◆ | 주황 | `danger` |
| 긴급 | 75~100 | ■ | 빨강 | `emergency` |

단계는 색만으로 구분하지 않습니다. 어디에서나 모양과 이름을 함께 씁니다 ("▲ 주의"). 색을 구분하기 어려운 사람도 알 수 있어야 하기 때문입니다 (8장).

## 3. 위험도를 바꾸는 것

숫자는 1/100 단위의 초기 가중치입니다 (100 = 위험도 1).

### 3.1 올리는 사건 (시스템만)

| 사유 | 코드 | 가중치 | 언제 |
|---|---|---|---|
| AI 침공 발생 | `invasion_started` | +800 × 규모 | 외곽 침공·시내 침입이 시작될 때 |
| ZERO 이벤트 | `zero_event` | +1000 | ZERO 이벤트가 시작될 때 (규모는 늘 3) |
| 외곽 방어 실패 | `defense_failed` | +300 × 규모 | 외곽 침공을 제한 시간 안에 막지 못하고 NPC 수비대도 막지 못했을 때 |
| 시내 침입 | `intrusion_failed` | +300 × 규모 | 시내 침입·ZERO 이벤트를 막지 못했을 때 |
| 주요 시설 피해 | `facility_damaged` | +200 | 시내까지 들어온 침공을 막지 못해 시설 한 곳이 피해를 입었을 때 (9장) |
| 미해결 긴급 임무 | `emergency_unresolved` | +400 | 지원 요청이 아무 도움 없이 끝났을 때 ([REGIONAL_COMPETITION](REGIONAL_COMPETITION.md) 4장) |

### 3.2 내리는 활동

| 사유 | 코드 | 가중치 | 누가 |
|---|---|---|---|
| 타워디펜스 성공 | `defense_won` | −600 | 방어전에서 이긴 가디언 |
| 시내 침입 격퇴 | `fps_repelled` | −800 | FPS 임무에서 이긴 가디언 |
| 사냥 임무 완료 | `hunt_completed` | −100 | 서버가 인정한 처치 10마리(`huntKillsPerStep`)마다 |
| 방어시설 복구 | `facility_repaired` | −200 | 피해 입은 시설을 고친 주민 |
| 도시 공동 방어 | `joint_defense` | −300 | 도시 공용 방어시설이 한 단계 완성될 때, 마지막 기금을 낸 주민 |
| 침공 격퇴 완료 | `invasion_repelled` | −300 × 규모 | 필요한 승리 수를 채워 침공을 끝냈을 때 |
| 특별 위험 제거 | `special_mission` | −1000 | ZERO 이벤트를 끝까지 막아 냈을 때 |
| NPC 수비대 방어 | `npc_held` | −700 × 규모 | 제한 시간이 끝난 침공을 NPC 수비대가 막았을 때 |
| NPC 순찰 | `daily_stabilize` | 지금 위험도의 20% | 하루 한 번 (한국 시간) |
| 관리자 조정 | `admin_adjust` | −100 ~ +100 | 관리자. 사유 필수 ([ADMIN_SYSTEM](ADMIN_SYSTEM.md)) |

침공이 시작되면 +800, NPC가 막으면 −700이라 **아무도 플레이하지 않는 도시는 침공이 올 때마다 조금씩 나빠지고, 주민이 직접 막은 도시는 침공 전보다 좋아집니다** (방어전 승리 −600에 격퇴 −300이 더해집니다).

## 4. 계산

### 4.1 시스템 사건

```
새 위험도 = clamp(지금 + 가중치 × 규모, 0, 10000)
```

### 4.2 플레이어의 활동

```
원하는 양 = −가중치 × 활동 크기% / 100
          × 반영 비율% / 100
실제로 내리는 양 = min(원하는 양, 오늘 남은 한도, 지금 위험도)
```

| 항목 | 내용 |
|---|---|
| 활동 크기 | 그 도시에 진행 중인 침공을 막는 승리면 100%. 침공이 없을 때의 승리(순찰 출동)는 `patrolPercent`(50%). 사냥은 10마리 한 묶음이 100%이고, 위험 단계 이상인 도시에서는 `huntHighRiskPercent`(200%) |
| 반영 비율 | 그 도시의 활성 가디언이 `activePlayerNorm`(20명) 이하면 100%, 넘으면 `20 / 활성 가디언 수`. 주민이 많은 도시가 사람 수만으로 위험도를 0으로 만들지 못하게 합니다 |
| 활성 가디언 | 최근 `activeDays`(7일) 안에 전투·복구·기금에 참여했거나 전입한 주민 |
| 하루 한도 | 한 사람이 하루에 내릴 수 있는 양은 `dailyPlayerReduceCap`(20). 한도를 채운 뒤의 승리도 보상과 기여도는 그대로 받습니다 |
| 방향 | 가중치가 0 이상이면 아무것도 하지 않습니다. 정책을 잘못 고쳐도 플레이어의 활동이 위험도를 올리지는 않습니다 (관리자 화면도 그런 값을 거부합니다) |

침공 격퇴 완료(`invasion_repelled`, `special_mission`)는 침공 하나에 한 번뿐이라 사람 수로 나누지 않습니다.

### 4.3 어느 도시에 반영되는가

| 활동 | 반영되는 도시 |
|---|---|
| 방어전, FPS 임무 | 지원 나가 있으면 그 도시, 아니면 소속 도시 |
| 사냥 | 늘 소속 도시 (우리 도시의 거리에서 하는 일) |
| 시설 복구, 도시 기금 | 소속 도시 |
| 이방인의 모든 활동 | 반영되지 않음 (보상은 받습니다) |

## 5. 시간의 흐름

침공은 `tickMinutes`(60분)마다 한 번 판정합니다. 예약 작업 `server/bin/tick.php`가 부르고, `WORLD_LAZY_TICK=1`이면 예약 작업이 없어도 도시를 읽고 쓰는 요청이 올 때 밀린 판정을 따라잡습니다.

한 번의 판정에서 도시마다 차례로 합니다.

1. **끝난 침공 정리.** 제한 시간(`invasionMinutes`, 180분)이 지난 침공은 NPC 수비대가 판정합니다. 막을 확률은 `npcHoldBasePercent`(80%) + 도시 방어력 보너스(최대 20%) − 규모 벌점(규모 1마다 10%) + 플레이어가 채운 진행도 보너스(최대 20%)이고 5~95% 사이로 자릅니다. 막으면 `npc_held`, 못 막으면 `defense_failed`/`intrusion_failed`이고 시내 침입이었다면 시설 한 곳이 피해를 입습니다.
2. **NPC 순찰.** 한국 시간으로 날이 바뀌면 그날 첫 판정에서 위험도의 `dailyStabilizePercent`(20%)를 내립니다.
3. **새 침공.** 진행 중인 침공이 없는 도시에 `invasionChancePermille`(40‰, 하루에 약 한 번)의 확률로 침공이 시작됩니다. 종류는 ZERO 이벤트 20‰, 시내 침입 350‰, 나머지는 외곽 침공이고, 규모는 1(60%)·2(30%)·3(10%)입니다. 한 도시에 침공은 한 번에 하나입니다.
4. **지원 요청.** 긴급 단계가 되면 열고, 위험도가 충분히 내려가면 닫습니다.

판정은 난수가 아니라 `(씨앗, 도시 코드, 판정 순번)`으로 정해지는 값입니다. 같은 판정을 두 번 돌려도 결과가 같고, `(도시, 순번)`이 DB에서 유일해 침공이 두 번 생기지 않습니다. 판정 순번은 `city_world_state`의 한 행에 적어 두고 그 행을 잠근 채 처리하므로 예약 작업과 요청이 겹쳐도 한 번만 처리됩니다.

서버가 오래 멈춰 있었다면 최근 72번의 판정까지만 따라잡습니다. 그보다 오래된 일은 만들어 내지 않습니다. 관리자가 판정 간격을 바꾸면 순번의 기준이 달라지므로, 그 순간의 순번에서 다시 시작합니다 (지난 판정을 한꺼번에 다시 돌리지 않습니다).

### 침공을 막는 방법

| 침공 | 막는 전투 | 필요한 승리 수 |
|---|---|---|
| 외곽 침공 | 디펜스 모드 | 규모 × ⌈활성 가디언 / 20⌉ (최소 규모만큼) |
| 시내 침입 | FPS 모드 | 같음 |
| ZERO 이벤트 | 디펜스 또는 FPS | 같음 |

활성 가디언이 많은 도시는 더 많이 이겨야 합니다. 도시의 크기에 따라 난이도가 맞춰집니다.

## 6. 단계에 따른 도시의 변화

| 단계 | 도시 분위기 | 달라지는 것 |
|---|---|---|
| ● 안전 | "도시가 평화로워요." | 평소대로 |
| ▲ 주의 | "순찰이 늘었어요. 사냥 임무가 더 많이 나와요." | 안내 문구 |
| ◆ 위험 | "경보가 울려요. 방어전과 긴급 출동이 필요해요." | 전투 구역에 로봇 +1, 사냥이 위험도를 두 배로 낮춤 (특별 사냥 임무) |
| ■ 긴급 | "도시가 위험해요! 주변 도시에 지원을 요청했어요." | 전투 구역에 로봇 +2, 사냥 두 배, 같은 시·도의 가디언에게 지원 요청이 열림 |

**달라지지 않는 것**: 은행 잔액, 예금 이자, 대출 조건, 신용점수, 가진 아이템, 상점 가격. 위험도 때문에 플레이어가 무엇을 잃는 일은 없습니다. 전투에서 져도 마찬가지입니다.

조명·경보음 같은 도시의 연출 변화는 아직 안내 문구와 전투 화면의 위험도 표시뿐입니다 (11장).

## 7. 정책

위험도 계산에 쓰는 값은 모두 `city_risk_policy` 테이블의 한 행(JSON)에 있고, 관리자 화면의 "위험도 계산 정책"·"침공 이벤트"·"도시 간 지원"·"지역 랭킹"에서 고칩니다. 고칠 때마다 새 행이 생기고 가장 최근 행이 지금의 정책입니다. 지난 정책으로 되돌릴 수 있습니다.

| 묶음 | 값 (초기값) | 범위 |
|---|---|---|
| 단계 경계 | `cautionAt` 25, `dangerAt` 50, `emergencyAt` 75 | 주의 < 위험 < 긴급 순서여야 함 |
| 처음 값 | `initialRisk` 20, `initialSpread` 12 | 0~100, 0~50 |
| 도시 크기 보정 | `activePlayerNorm` 20, `activeDays` 7 | 1~10000, 1~90 |
| 플레이어의 활동 | `huntKillsPerStep` 10, `huntHighRiskPercent` 200, `dailyPlayerReduceCap` 20, `patrolPercent` 50 | |
| 침공 | `tickMinutes` 60, `invasionChancePermille` 40, `invasionMinutes` 180, `intrusionPermille` 350, `zeroEventPermille` 20 | 시내 침입 + ZERO ≤ 1000 |
| NPC 수비대 | `npcHoldBasePercent` 80, `defensePowerPerPercent` 20, `npcHoldMaxBonusPercent` 20, `npcHoldSeverityPenaltyPercent` 10, `dailyStabilizePercent` 20, `baseGarrisonPower` 100, `defensePointsPowerCap` 300 | |
| 도시 간 지원 | `supportOpenAt` 75, `supportCloseBelow` 50, `supportMinutes` 360 | 닫히는 값 ≤ 열리는 값 |
| 기여도와 한도 | `contribDefenseWin` 10, `contribFpsWin` 12, `contribHuntStep` 1, `contribRepair` 5, `contribPerFund100Gc` 2, `contribSeverityBonusPercent` 50, `dailyRepairLimit` 3, `dailyFundLimitGc` 2000 | |
| 가중치 | 3장의 표 | 올리는 사건은 0~10000, 내리는 활동은 −10000~0 |

범위를 벗어나거나 순서가 맞지 않는 값은 저장되지 않습니다. 범위는 "게임이 망가지지 않는 한도"일 뿐이고 알맞은 값은 플레이테스트로 정해야 합니다. 정확한 범위는 `Risk::policyRanges()`에 있습니다.

### 도시의 방어력

```
방어력 = baseGarrisonPower(100)
       + min(defensePointsPowerCap(300), 방어 포인트 / 10)
       + 도시 공용 방어시설의 단계 × 시설의 방어력
```

방어력은 NPC 수비대가 침공을 막을 확률을 올립니다 (20마다 1%, 최대 20%). 주민이 방어전에서 이겨 쌓은 방어 포인트와 함께 모은 기금이 여기에 들어갑니다.

## 8. 전국 지도 표시

지도(M 키)에서 도시마다 다음이 보입니다. 숫자는 모두 서버가 계산해 준 값입니다.

| 항목 | 표시 |
|---|---|
| 도시 이름 | 시·도와 시·군·구 |
| 위험도 | 0~100 |
| 단계 | 지역을 단계의 색으로 칠하고, 이름표와 정보 칸에는 **모양과 글자를 함께** 씀: "▲ 주의" |
| 방어력 | NPC 수비대 + 방어 포인트 + 공용 방어시설 |
| 최근 침공 | 진행 중인 침공의 종류·규모·진행도(막은 수 / 필요한 수)·남은 시간, 최근 침공 횟수 |
| 기여도 | 도시 전체와 내 기여도 |
| 랭킹 | 순위와 점수. NPC 수비대만 지키는 도시는 그렇게 표시 |
| 지원 요청 | 열려 있으면 표시. 같은 시·도의 가디언은 여기서 지원에 나설 수 있음 |

- 전국 보기에서는 시·도 이름 옆에 그 시·도에서 가장 높은 단계의 모양을 붙이고("부산 ◆"), 위험·긴급 단계이거나 지원을 요청한 도시에 표시를 붙입니다.
- 범례에 네 단계의 모양·이름·범위가 함께 나옵니다.
- 도시를 누르면 상세가 열립니다: 위험도와 단계, 도시 분위기, 침공 현황, 주요 시설의 피해, 공용 방어시설의 기금, 랭킹 점수의 세부 항목, 위험도 변경 이력.
- 우리 도시라면 여기서 시설 복구, 도시 기금, 지역 랭킹 보기를 고를 수 있습니다.

구현: `MapPanel`(화면), `MapController`(상태), `CityRiskService`(서버 값 보관), `CityActions`(복구·기금·지원·랭킹 메뉴).

## 9. 주요 시설과 도시 공용 방어시설

### 주요 시설

도시마다 발전소·통신 센터·정수장이 있습니다. 시내 침입이나 ZERO 이벤트를 막지 못하면 한 곳의 피해 단계가 1 오르고(최대 3) 위험도가 오릅니다.

주민은 피해 한 단계를 150 GC로 고칠 수 있습니다. 값은 서버가 정합니다. 하루 3번까지이고, 고치면 위험도가 내려가고 기여도 5를 받습니다.

### 도시 공용 방어시설

에너지 방어막(한 단계 5,000 GC, 3단계), 지휘 센터(8,000 GC, 3단계), 긴급 방어 지원 장치(6,000 GC, 2단계)는 주민이 함께 기금을 모아 세웁니다.

- 100 GC 단위로 내고, 한 사람이 하루 2,000 GC까지 낼 수 있습니다.
- 낸 GC는 **도시의 것**이 됩니다. 개인 자산이 아니어서 되찾거나 되팔 수 없고, 이사해도 가져가지 못합니다. `city_defense_structures`에 도시별로 따로 저장합니다 (개인이 해금한 타워는 `player_defense_structures`).
- 한 단계가 완성될 때마다 도시의 방어력이 오르고 위험도가 한 번 내려갑니다. 기금을 낼 때마다 100 GC당 기여도 2를 받습니다.

복구와 기금은 GC를 쓰는 일이므로 `Idempotency-Key`가 필수이고 원장에 `city_repair`, `city_fund`로 남습니다.

## 10. 서버 구현

| 항목 | 내용 |
|---|---|
| 규칙 | `server/src/Domain/Risk.php`, `Invasion.php`, `Support.php`, `Ranking.php`. 클라이언트의 `CG.Domain`(`CityRisk.cs`)과 같은 계산이고, C#에서 뽑은 표본 4,139건으로 결과가 같은지 확인합니다 (`RulesParityTest`) |
| 쓰는 곳 | 위험도를 바꾸는 코드는 `CityService::changeRisk()` 하나뿐입니다. 위험도와 이력을 함께 씁니다 |
| 잠금 | 도시를 바꾸는 일은 `city_world_state`의 한 행을 잠근 뒤에 합니다. 잠그는 순서는 지갑 → 전투 세션 → 캐릭터 → 전투 상태 → 일일 집계 → 도시입니다 |
| 저장 | `city_risk_status`(도시별 현재 값과 집계), `city_risk_history`(이력), `city_risk_policy`(정책), `city_invasion_events`, `city_facility_damage`, `city_defense_structures`, `city_support_requests`, `city_support_contributions` ([DATABASE](DATABASE.md)) |
| 집계의 구분 | 플레이어가 한 것(`player_wins`, `player_attempts`, `repelled_severity`, `contribution`)과 NPC가 한 것(`npc_held_count`)을 따로 셉니다 |
| 점검 | `CityService::findInconsistency()`가 이력의 마지막 값과 현재 위험도가 같은지, 한 도시에 진행 중인 침공과 열린 지원 요청이 하나 이하인지 봅니다. 예약 작업이 돌 때마다 확인합니다 |
| API | [API_SPEC](API_SPEC.md) 17장 |

## 11. 구현 상태와 한계

| 항목 | 상태 |
|---|---|
| 규칙과 테스트 | 구현. C# 규칙 테스트와 PHP 테스트(`CityRiskTest` 29개)가 통과 |
| Unity 화면 | 전국 지도의 위험도 표시, 도시 상세, 복구·기금·지원·랭킹 메뉴, 전투 화면의 위험도 표시를 구현. **Unity 에디터에서 실행해 보지 못했습니다** (형식 검사만 통과) |
| Unity ↔ 서버 | 클라이언트는 아직 `LocalMockBackend`로 동작합니다. PHP 서버를 부르는 HTTP 구현이 없습니다 |
| 도시 연출 | 단계에 따른 조명·경보음·NPC 대사 변화는 없음. 안내 문구와 표시뿐 |
| 성능 | 도시를 바꾸는 요청은 전국 230개 도시의 기록을 읽고 하나의 잠금을 거칩니다. 동시 접속이 많아지면 도시별 잠금으로 나눠야 합니다 |
| 수치 | 모든 가중치와 확률은 플레이테스트를 거치지 않은 초기값입니다 |
| 지역 코드 | 서버의 지역 목록은 클라이언트 지도의 230개 지역에서 만들었습니다. 운영 DB에 이미 있는 지역 목록과 코드가 같은지는 확인하지 못했습니다 |
