# TACTICAL_MINIMAP — 전술 미니맵과 전술 핑

> 기준 v9.0 · 2026-11-14 · 상태: 규칙(`Domain/Coop/Minimap.cs`, `PingBoard.cs`), 실시간 서버의 핑 처리, 관리자 화면(미니맵 및 전술 핑 설정), 클라이언트 화면(`UI/MinimapPanel.cs`) 구현. 규칙과 서버는 테스트했고, **Unity 화면은 컴파일 검사만 했고 실행해 보지 못함** (배치와 크기를 눈으로 확인하지 못함)

## 1. 방향

협동 방어전([COOP_DEFENSE_SYSTEM](COOP_DEFENSE_SYSTEM.md))에서 **말하지 않고도 협력하게** 하는 도구입니다. 채팅을 넣지 않은 대신(어린이가 함께 하는 게임입니다), 지도와 여섯 가지 핑으로 "여기를 막자", "여기에 세우자"를 전합니다.

- 지도에 그릴 내용은 **서버가 보낸 상태**에서 만듭니다. 적의 위치를 클라이언트가 추측하지 않습니다.
- 무엇을 어디에 그릴지는 규칙 코드(`Minimap.Build`)가 정하고, 화면은 그 결과를 점과 선으로 옮기기만 합니다. 그래서 Unity 없이도 테스트합니다.
- 핑을 받을지 말지는 서버가 정합니다.

## 2. 두 가지 모습

| | 접힌 미니맵 | 전술 지도 |
|---|---|---|
| 자리 | **화면 오른쪽 위** (GC 표시 아래), 280 px | 화면 가운데, 820 px |
| 여는 법 | 늘 보임 | `M` 키 |
| 범위 | 나를 가운데 둔 반경 28 m | 지도 전체 |
| 겹쳐 그리는 것 | 없음 | 적 이동 경로, 타워 사거리 (고를 수 있음) |
| 핑 | `Q` 로 고르면 내가 서 있는 곳에 | 지도를 눌러 그곳에 |

둘 다 북쪽이 위입니다. 1초에 15번 다시 그립니다.

## 3. 지도에 보이는 것

| 표시 | 종류 (`kind`) | 내용 |
|---|---|---|
| 나 | `self` | 향하는 방향 포함 |
| 팀원 | `teammate` | 전술 지도에서는 이름도. 연결이 끊긴 팀원은 흐리게 |
| 적 | `enemy`, `boss` | 위치와 **이동 방향** (작은 화살). 중간 보스는 크게 |
| 타워 | `tower` | 내구도가 절반 아래면 다른 색. 전술 지도에서는 사거리 원 |
| 관문 | `gate` | 내구도 |
| 방어벽 | `wall` | 지도의 주요 지점 |
| 주요 시설 | `facility` | 지도의 주요 지점 |
| 적이 나오는 곳 | `spawn` | |
| 위험 지역 | `danger` | 서버가 계산: 관문 가까이(길의 마지막 30%)까지 온 적의 무리, 길의 한 구간에 적이 여섯 넘게 몰린 곳 |
| 전술 핑 | `ping` | 종류별 글자, 보낸 사람 |
| 긴급 지원 요청 | `support_request` | "방어 요청"과 "수리 요청" 핑. 더 눈에 띄게 |

접힌 미니맵에서 **관문, 핑, 긴급 지원 요청, 위험 지역**은 보이는 범위 밖이어도 가장자리에 붙여 보여 줍니다 (어느 쪽인지 알 수 있게). 적과 타워는 범위 안의 것만 보입니다.

### 겹쳐 그리기 (전술 지도)

- **적 이동 경로:** 적이 나오는 곳에서 관문까지의 길.
- **타워 사거리:** 세워진 타워마다 원.

팀 메뉴(`F`)에서 각자 켜고 끕니다. 운영 설정(`ping.routeOverlay`, `ping.rangeOverlay`)으로 아예 막을 수도 있습니다 — 꺼져 있으면 메뉴에 나오지 않습니다.

## 4. 전술 핑

| 코드 | 이름 | 쓰임 |
|---|---|---|
| `focus_fire` | 공격 집중 | 이 적(이곳)을 먼저 |
| `defend_here` | 방어 요청 | 여기가 뚫린다 → 긴급 지원 요청으로 표시 |
| `build_here` | 타워 설치 제안 | 여기에 세우자 |
| `repair_here` | 수리 요청 | 이 타워를 고쳐 달라 → 긴급 지원 요청으로 표시 |
| `danger` | 위험 경고 | 이쪽으로 몰려온다 |
| `rally` | 집결 위치 | 여기로 모이자 |

보낸 핑은 그 판의 모든 팀원에게 바로 전해지고(`event: ping`), 지도와 전장(땅 위의 표시)에 `lifetimeSeconds`(8초) 동안 보입니다. 글을 쓸 수 없고 종류와 위치만 있습니다.

### 남용 방지

| 장치 | 기본값 | 내용 |
|---|---|---|
| 빈도 제한 | 연달아 3번(`burst`), 4초마다 하나씩 다시 참(`refillSeconds`) | 토큰 버킷. 넘으면 `ping_rate`로 거절. 지휘관 역할은 다시 차는 시간이 절반 |
| 동시에 떠 있는 핑 | 한 사람 3개(`maxActivePerPlayer`) | 새로 보내면 그 사람의 가장 오래된 핑이 사라짐 |
| 자동 일시 차단 | 거절 5번(`autoMuteStrikes`)이면 30초(`autoMuteSeconds`) | 그동안 그 사람의 핑을 받지 않음 (`ping_muted`). 그 판 안에서만 |
| 팀원이 가리기 | | 팀 메뉴에서 특정 팀원의 핑을 **내 화면에서만** 숨김. 서버가 나에게 보내지 않음. 그 판 안에서만. 상대에게 알리지 않음 |
| 관리자 차단 | | 그 계정의 핑을 모든 판에서 막음 (`ping_blocked`). **핑만** 막고 방어전 참여와 보상에는 영향이 없음 |
| 기능 끄기 | `ping.enabled` | 핑 전체를 끔 (`ping_disabled`) |

- 빈도 제한과 차단의 판정은 **서버**(`PingBoard`)가 합니다. 클라이언트의 제한은 없습니다.
- 받아들이지 않은 핑도 기록에 남습니다 (왜 거절했는지와 함께). 판이 끝나면 게임 서버로 넘어가 `defense_tactical_pings`에 보관됩니다 (한 판에 3,000줄까지).
- 핑의 위치는 지도 범위 안으로 맞춰집니다.

### 관리자 차단

"미니맵 및 전술 핑 설정" 화면 (`coop.manage` 권한: 최고 관리자, 운영 담당, 고객 지원).

- 최근 7일의 핑 종류별 사용, **핑이 많이 거절된 계정** (남용을 찾는 실마리).
- 계정의 공개 ID, 기간(시간. 0이면 풀 때까지, 최대 8,760), 사유를 적어 막음 → `defense_ping_blocks`. 푸는 것도 사유와 함께.
- 차단은 **다음에 받는 입장권부터** 적용됩니다 (입장권에 차단 여부가 실립니다). 지금 진행 중인 판에는 바로 닿지 않습니다.
- 감사 기록: `ping.block`, `ping.unblock`.

핑의 수치(빈도, 수명, 자동 차단, 겹쳐 그리기 허용)는 같은 화면에서 `city.policy` 권한으로 고칩니다. 바꾼 값은 **다음에 열리는 판부터** 적용됩니다.

## 5. 실시간 동기화

| 것 | 방식 |
|---|---|
| 위치 (대원, 적, 타워) | 서버가 초당 5번 전체 상태(`state`)를 보냄. 클라이언트는 그 사이를 부드럽게 이음 |
| 내 위치 | 내 화면에서는 바로. 서버에는 가고 싶은 곳을 보내고, 서버의 값이 팀원에게 감 |
| 핑 | 보낸 즉시 `event`로, 그리고 `state`의 핑 목록으로 (늦게 들어온 사람도 떠 있는 핑을 봄) |
| 위험 지역 | `state`에 포함 |

다중 접속에서 위치가 같은지는 `realtime/tests/RoomTests.cs`가 확인합니다 (여러 연결이 같은 틱의 같은 상태를 받는가).

## 6. 조작

| 키 | 일 |
|---|---|
| `M` | 전술 지도 펼치기 / 접기 |
