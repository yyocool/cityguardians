# NPC_SYSTEM — NPC 시스템

> 기준 v6.0 · 2026-11-13 · 상태: 보리, 도담, 강한울, 오미소, 은다온, 정나래와 방어대원은 구현 (2장 표의 "구현" 설명). 일과·순찰하는 가디언·일반 주민은 설계 · 인물 이름은 제안

## 1. 목표

접속한 플레이어가 적어도 도시가 살아 있는 것처럼 느껴져야 합니다. 광장에 서면 언제나 걷고, 말하고, 일하는 주민이 보입니다.

**NPC는 실제 플레이어로 위장하지 않습니다.** 이름표의 색과 모양, 역할 아이콘으로 NPC임을 항상 드러내고, 채팅 채널에 플레이어처럼 글을 쓰지 않으며, 접속자 수나 랭킹에 포함하지 않습니다.

## 2. 역할

| 역할 | 이름 (제안) | 위치 | 기능 | 구현 시점 |
|---|---|---|---|---|
| 안내 로봇 | 보리 | 내 방 | 다음 할 일 안내, 준비 중인 기능 안내 | 1차 |
| 구조 요청 주민 | 도담 | 집 앞 거리 | 첫 전투의 계기, 상점 안내 | 1차 |
| 방어대장 | 강한울 | 광장, 방어기지 | 전투 임무, 방어전 시작, 전입신고 권유 | 1차 (구현: 대화로 방어기지와 주민센터를 안내. 방어전 입장은 출동 게이트, 전입신고 선택은 정나래) |
| 상인 | 오미소 | 상점 | 아이템 판매 | 1차 (구현: 방어대장을 만난 뒤부터 E → 미소 상점 화면. 사면 "고마워요! 잘 써 줘요!") |
| 은행원 | 은다온 | 은행 창구 | 입출금, 저축 | 1차 (구현: E → "돈을 맡겨 두면 매일 조금씩 불어나요." → 은행 화면. 레벨 3 전에는 "레벨 3이 되면 다시 와 줘요!". 건물 안이 아니라 은행 문 앞에 서 있음) |
| 도시 행정관 | 정나래 | 주민센터 | 전입신고, 이사 | 1차 (구현: 전입신고. 이방인에게는 "전입신고 하기 / 나중에 할게요" 메뉴를 열고, 주민에게는 인사만 함. 튜토리얼 중에는 "복구 중" 안내. 이사는 미구현) |
| 금융 안내원 | 한셈 | 은행 로비 | 저축·투자·대출 설명 | Phase 4 |
| 가디언 | 여러 명 | 전투 구역 주변, 방어전 | 순찰, 협동 전투 | 1차 (2~3명) |
| 일반 주민 | 여러 명 | 광장, 주거 지역 | 걷기, 짧은 한마디 | 1차 (5~8명) |

## 3. 행동 (FSM)

1차에서는 유한 상태 기계로 만듭니다. 적과 같은 상태 기계 뼈대를 씁니다 ([ENEMY_AI](ENEMY_AI.md) 3장).

| 상태 | 내용 | 해당 NPC |
|---|---|---|
| 대기 | 제자리에서 두리번거림, 가끔 몸짓 | 전부 |
| 이동 | 지정한 지점으로 걸어감 | 주민, 가디언 |
| 순찰 | 여러 지점을 차례로 돎 | 가디언, 주민 |
| 대화 | 플레이어를 바라보고 멈춤 | 전부 |
| 전투 | 가까운 적을 공격 | 가디언 |
| 후퇴 | 체력이 낮으면 물러나 회복 | 가디언 |
| 상점 운영 | 창구에서 대기, 거래 화면 열기 | 상인 |
| 금융 안내 | 창구에서 대기, 은행 화면 열기 | 은행원, 금융 안내원 |
| 달아남 | 적이 가까우면 안전 구역으로 | 일반 주민 |

```
대기 ↔ 순찰/이동
  ↓ (플레이어가 E)
대화 → (역할에 따라) 상점 운영 / 금융 안내 → 대기
가디언: 순찰 → 전투 → 후퇴 → 순찰
주민: 순찰 → 달아남 → 대기
```

### 일과

NPC마다 지점 목록과 머무는 시간을 데이터로 줍니다. 1차는 시간대 구분 없이 지점을 순서대로 도는 단순한 방식입니다. 이후 아침·낮·저녁 일과로 확장합니다.

## 4. 대화

### 원칙

- 한 번에 두 문장 이하, 쉬운 말.
- 선택지는 최대 2개, 큰 버튼.
- 말풍선은 NPC 머리 위에 뜨고, 중요한 대화만 화면 아래 대화창을 씁니다.
- 닫으면 바로 놀이로 돌아갑니다. 건너뛸 수 없는 긴 대화를 만들지 않습니다.

### 데이터

대화는 코드가 아니라 데이터로 씁니다.

```json
{
  "id": "captain_residency_offer",
  "npc": "captain",
  "condition": { "residency": "stranger", "flag": "first_battle_won" },
  "lines": ["우리 도시를 지켜줘서 고마워!", "정식 주민이 되어줄래?"],
  "choices": [
    { "text": "좋아요!", "action": "open_residency" },
    { "text": "나중에요", "action": "close" }
  ]
}
```

- `condition`: 이방인/주민 여부, 레벨, 진행 표시에 따라 다른 대화가 나옵니다.
- `action`: 상점 열기, 은행 열기, 전입신고 열기, 방어전 입장, 임무 받기 등 미리 정한 동작.
- 대화 데이터는 클라이언트에 넣고, 문구 수정이 잦아지면 서버 관리로 옮깁니다.

### 일반 주민의 한마디

가까이 가면 말풍선으로 짧은 말을 합니다. 도시 상황(침공 단계, 최근 방어전 결과, 도시 레벨)에 따라 달라지게 하여 세계가 반응하는 느낌을 줍니다.

## 5. 서비스 NPC

| NPC | 여는 화면 | 서버 처리 |
|---|---|---|
| 상인 | 상점 | 구매 ([ITEM_SYSTEM](ITEM_SYSTEM.md)) |
| 은행원 | 은행 | 입출금, 저축 ([ECONOMY_SYSTEM](ECONOMY_SYSTEM.md)) |
| 금융 안내원 | 금융 안내, 주식, 대출 | [STOCK_SYSTEM](STOCK_SYSTEM.md), [LOAN_CREDIT_SYSTEM](LOAN_CREDIT_SYSTEM.md) |
| 도시 행정관 | 전입신고, 이사 | [RESIDENCY_SYSTEM](RESIDENCY_SYSTEM.md) |
| 방어대장 | 방어전 입장, 임무 | [TOWER_DEFENSE](TOWER_DEFENSE.md) |

거래는 NPC가 아니라 서버가 처리합니다. NPC는 화면을 여는 창구입니다.

지금 도시에 있는 서비스 NPC (2026-11-13):

| NPC | 자리 | 여는 화면 |
|---|---|---|
| 오미소 | 미소 상점 (광장 동쪽) | 무기, 수리 키트, 방어구 사기 · 되팔기 |
| 한아름 | 알록달록 가게 (광장 남동쪽) | 옷, 가구 사기 · 되팔기. 토끼 머리띠와 해님 후드티를 입고 있어 무엇을 파는 가게인지 보임 |
| 은다온 | 도시은행 | 맡기기, 찾기, 정기예금, 거래 내역 |
| 정나래 | 주민센터 | 전입신고 |
| 강한울 대장 | 방어기지 | 방어전 |

안내 로봇 보리(방)와 도담(광장)은 튜토리얼을 마친 뒤 "F 키를 누르면 방을 꾸밀 수 있어", "남동쪽 알록달록 가게에서는 예쁜 옷이랑 가구를 팔아요"를 알려 줍니다.

금융 안내원은 상품을 설명할 뿐 가입을 권유하지 않습니다. "빌린 돈은 꼭 갚아야 해요", "주식은 값이 내려갈 수도 있어요" 같은 주의를 먼저 말합니다.

## 6. 협동 전투

- 가디언 NPC는 플레이어 무기와 같은 계열의 장비로 싸웁니다.
- 플레이어의 보상을 가로채지 않습니다 ([COMBAT_SYSTEM](COMBAT_SYSTEM.md) 9장).
- 쓰러지지 않고 후퇴합니다. 주민이 쓰러지는 장면을 보여 주지 않습니다.
- 도시 레벨이 오르면 가디언의 수와 장비가 좋아집니다 (추후).

구현된 것 (2026-11-13): 방어전의 **방어대원 2명**(가람, 다솜, `GuardianAgent`). 방어선 앞 자리에서 10 m 안의 적을 쫓아가 때리고 돌아옵니다. 쓰러지지 않으며, 이름표가 "NPC 방어대원 가람"처럼 NPC로 시작합니다. 공격력은 1.2초마다 10으로 일부러 약하게 두었습니다 — 처음 값(0.9초마다 20)에서는 방어대원 둘과 타워 둘만으로 플레이어 없이 끝까지 막혔습니다 ([TOWER_DEFENSE](TOWER_DEFENSE.md) 6·9장). 방어대원이 쓰러뜨린 적도 에너지를 줍니다 (방어전은 처치마다 GC를 주지 않으므로 보상을 가로채는 문제가 없습니다).
도시의 전투 구역을 순찰하는 가디언은 아직 없습니다.

## 7. 인원과 성능

| 구역 | 동시 NPC 수 (1차) |
|---|---|
| 광장 | 6~8 |
| 주거 지역 | 3~4 |
| 시설 내부·창구 | 시설당 1~2 |
| 전투 구역 주변 | 가디언 2~3 |

멀리 있는 NPC는 판단 주기를 늦추고 애니메이션을 단순화합니다. 플레이어가 보지 않는 구역의 주민은 멈춥니다.

## 8. 데이터

| 데이터 | 위치 |
|---|---|
| NPC 정의 (코드, 역할, 이름, 외형, 배치 지점, 일과) | `npc_defs` (서버, 관리자에서 편집) |
| 대화 | 클라이언트 데이터 파일 (추후 서버) |
| 진행 표시 (누구와 어떤 대화를 마쳤는가) | `player_flags` |

관리자의 NPC 메뉴에서는 이름, 배치, 활성 여부, 상점·창구 연결을 바꿀 수 있습니다.

## 9. 확장

- 임무를 주는 주민 (구조 요청, 물자 운반)
- 시간대별 일과
- 도시 상황에 따른 행사 (방어 성공 축하)
- 대화 생성에 AI 모델을 쓰는 방안은 미성년자 보호와 비용 문제가 있어 지금은 채택하지 않습니다.
