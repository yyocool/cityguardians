## 2. 핵심 기술 선택

### 클라이언트

| 항목 | 선택 | 이유 |
|---|---|---|
| 엔진 | Unity 6000.3.28f1 | 지시서의 Unity 6 LTS. 이 PC에 설치된 Unity 6 중 최신 |
| 렌더링 | URP | 지시서. 모바일 확장에 유리 |
| 입력 | Input System + 자체 `IPlayerInput` | 키보드·마우스와 터치를 같은 게임 코드로 |
| 카메라 | 자체 `OrbitCamera` (처음 계획은 Cinemachine) | 필요한 것이 궤도 회전·거리 조절·벽 충돌뿐이라 직접 구현. 의존 패키지를 줄임. 구도 전환이 늘어나면 다시 검토 |
| 캐릭터 이동 | CharacterController 직접 제어 | 즉각적인 조작감, 가벼움 |
| 길 찾기 | AI Navigation (NavMesh) | 거리 사냥의 적과 NPC |
| UI | uGUI `Text` (처음 계획은 TextMeshPro) | 3D 공간의 이름표·말풍선과 화면 UI를 한 방식으로. TextMeshPro는 한글 글꼴 에셋이 따로 필요해 글꼴을 정한 뒤 전환 |
| 한글 글꼴 | Phase 1: Windows에 설치된 글꼴을 실행 중에 불러 씀 (맑은 고딕 등). 글꼴 파일을 배포하지 않음 | **모바일 확장 전에** 이용 조건을 확인한 배포 가능한 공개 글꼴로 바꿔야 함 |
| 캐릭터·환경 | 기본 도형과 코드로 조립한 블록 메시 | 외부 에셋 없이 시작, 고유 디자인, 나중에 교체 가능 |
| 애니메이션 | 관절 회전을 코드로 제어 | 부위가 적어 충분. 모델 교체에 강함 |
| 서버 통신 | UnityWebRequest, JSON | 표준 방식. 추가 의존 없음 |
| 테스트 | Unity Test Framework | 규칙 계산과 상태 기계의 단위 테스트 |

### 서버

| 항목 | 선택 | 이유 |
|---|---|---|
| 언어 | PHP 8.3 | 지시서. 운영 서버는 현재 7.3이라 전환 필요 ([SERVER_DEPLOYMENT](SERVER_DEPLOYMENT.md) 3장) |
| 구조 | 프레임워크 없이 얇은 자체 구조 (라우터, 요청·응답, PDO, 검증) | 배포가 단순하고 서버 요구 사항이 적음. **기존 v1의 구조를 확인한 뒤, 기존 구조가 쓸 만하면 그것을 이어받음** |

| 테스트 | PHPUnit | 금융 계산과 API |

- 서버가 진행 상황의 원본입니다. 클라이언트는 표시와 조작을 맡습니다.

## 4. 서버 없이도 진행하는 방법

서버 접속과 PHP 전환이 정해지기 전에도 클라이언트 작업이 멈추지 않도록, 서버 통신을 인터페이스(`IGameBackend`) 뒤에 둡니다.

| 구현 | 용도 |
|---|---|
| 로컬 모의 구현 | 서버 없이 Unity 안에서 같은 규칙으로 동작. Phase 1 개발과 자동 테스트용 |
| HTTP 구현 | 실제 PHP API 호출 |

구현한 것: 도시 방어기지의 출동 게이트와 선택 메뉴, 방어전 전장 "외곽 1구역"(장면 `Defense`), 설치 자리 6곳, 기관총 타워·폭발 타워와 전투 중 강화, 웨이브 5개, 도시 방어 체력, 건설 메카, NPC 방어대원 2명, 승리·패배·후퇴 결과 화면, 전투 결과 검증과 보상(모의 서버), 폭발 타워 해금(500 GC). 자세한 내용은 [TOWER_DEFENSE](TOWER_DEFENSE.md).

아직 확인하지 못한 것:

- **사람이 직접 해 본 재미와 난이도.** 자동 플레이는 사람보다 실수가 없고 망설이지 않습니다. 초등학생에게 쉬운지 어려운지, 타워를 세우는 조작이 설명 없이 통하는지는 실제 플레이로만 알 수 있습니다.
- 타워만 세우고 싸우지 않는 플레이, 싸우기만 하고 타워를 늘리지 않는 플레이의 결과.
- 빌드된 실행 파일에서의 방어전 (에디터의 PlayMode에서만 돌려 봄), 수십 마리가 한꺼번에 나올 때의 프레임, 소리.
- 결과 전송 실패 화면(R로 다시 보내기). 모의 서버는 실패하지 않아 코드만 있고 실행해 보지 못했습니다.
- 서버. PHP 쪽은 시작하지 않았습니다.

계획과 다르게 한 것:

| 항목 | 계획 | 구현 | 이유 |

만들면서 고친 것:

- **든 가구의 방향.** 든 가구의 앞면이 언제나 나를 보고 나와 함께 돌게 했습니다. 벽을 보고 서면 등받이가 벽 쪽으로 가므로 대부분 R이 필요 없습니다. 옮기는 가구는 놓여 있던 방향 그대로 들립니다.
- **거래 내역이 안내판을 넘쳤습니다** (캡처에서 발견). 정기예금으로 줄이 길어져 글이 접히면서 제목과 닫기 안내를 덮었습니다. 줄을 접지 않고, 넘치면 글자 크기를 줄입니다. 테스트가 넘치지 않는지 확인합니다.
- **방의 창문이 카메라를 가렸습니다** (캡처에서 발견). 북쪽 벽의 창문과 서쪽 벽의 거울이 두께가 있는 상자여서, 카메라가 벽 밖으로 나가면 큰 흰 네모로 보였습니다. 방 안쪽에서만 보이는 판으로 바꿨습니다.
- **사냥 보상의 수리 키트가 테스트의 가방 줄 수를 바꿨습니다.** 테스트가 드롭 확률을 0으로 두고 시작합니다 (게임은 바꾸지 않음).
- **상점 테스트가 전체 실행에서 한 번 실패했습니다.** "겨눌 적이 없으면 조준 표시가 없다"를, 전투 구역에서 광장으로 순간 이동한 바로 그 프레임에 확인하고 있었습니다. 조준 표시는 프레임의 끝에 갱신됩니다. 테스트가 한 프레임 뒤에 확인하게 했습니다 (게임은 바꾸지 않음). 고친 뒤 전체 15개 통과.

구현한 것:

- **유효 전입자 집계.** 도시마다 현재 유효 전입자, 누적 전입자, 최근 7일·30일 증가, 확장 단계, 다음 기준까지 남은 수를 서버가 셉니다 (`city_population_stats`, 날짜별 기록 `city_population_daily`). 기본 규칙은 **게스트가 아닌 로그인 수단이 붙은 계정만** 셉니다. 정지된 계정은 빠집니다. 한 계정은 한 도시에만 살고, 누적 전입자는 그 도시에 처음 들어온 계정만 한 번 셉니다 (`city_resident_marks`). 이사는 떠난 도시와 새 도시를 한 트랜잭션에서 고칩니다. [CITY_GROWTH_SYSTEM](CITY_GROWTH_SYSTEM.md).
- **확장 단계와 알림.** 기준 4개(100 / 500 / 1,000 / 3,000명)는 관리자가 바꾸고, 도시마다 상징거리 기준 인원을 따로 줄 수 있습니다. 기준에 닿으면 알림이 **도시·기준마다 한 번** 생깁니다 (고유 색인). 관리자가 확인하고, 담당자를 정하고, 제작 작업을 등록합니다. 기준 도달 알림과 모델링 진행 알림은 종류가 다릅니다.
- **모델링 제작과 배포 관리.** 작업의 상태는 `NOT_STARTED → PLANNING → MODELING → REVIEW → READY → DEPLOYED`의 정해진 길로만 움직입니다. 담당자, 메모, 예정일, 파일 버전, 검수 결과, 적용 일시를 남깁니다. 결과물은 검수를 통과해야 배포할 수 있고, **만든 사람이 자기 것을 검수하거나 배포할 수 없습니다.** 일부 배포(비율)와 철회가 있고, 클라이언트는 고정된 저장소 주소 아래의 파일만, 해시가 맞을 때만 씁니다. [CITY_MODELING_PIPELINE](CITY_MODELING_PIPELINE.md).
- **협동 타워디펜스.** 도시 외곽의 관문을 2~8명이 함께 지킵니다 (기본 정원 4명). 역할 4종(지휘관, 타워 설치, 수리·지원, 직접 전투)은 고르지 않아도 되고 작은 보정만 줍니다. **적의 이동, 타워, 웨이브, 관문 내구도, 설치 결과, 공동 예산은 실시간 서버가 정하고** 클라이언트는 요청만 보냅니다. 같은 자리의 동시 설치는 한 명만 성공하고, 공동 예산은 음수가 되지 않으며, 같은 요청은 한 번만 처리됩니다. 한 사람이 끊겨도 전투는 계속되고 돌아올 수 있습니다. 결과는 게임 서버가 다시 검증한 뒤 한 번만 보상합니다. [COOP_DEFENSE_SYSTEM](COOP_DEFENSE_SYSTEM.md).
- **전술 미니맵과 핑.** 오른쪽 위의 구석 미니맵과 펼친 전술 지도. 나, 팀원, 적과 그 방향, 타워, 관문, 방어벽, 주요 시설, 위험 지역, 지원 요청을 보여 주고, 전술 지도에서는 적 이동 경로와 타워 사거리를 켜고 끕니다. 핑 6종(공격 집중, 방어 요청, 타워 설치 제안, 수리 요청, 위험 경고, 집결 위치)은 글 없이 종류와 위치만 실시간으로 나눕니다. 빈도 제한(토큰 버킷), 되풀이하면 잠시 정지, 팀원이 내 화면에서 가리기, 관리자의 계정 차단. [TACTICAL_MINIMAP](TACTICAL_MINIMAP.md).
- **가상 지방세.** 거래세(구매 금액에 포함, 3%), 사업세(전투 보상에서, 5%), 재산세(일정 잔액을 넘는 보유 GC 에서, 1%). 적용 대상·세율·면제 기준·징수 주기를 관리자가 정해진 범위 안에서 바꿉니다. 초보자·새 주민·이방인은 내지 않습니다. 걷을 때마다 거래 명세(`city_tax_transactions`)와 도시 재정 원장에 함께 적고, 같은 거래·같은 기간에 두 번 걷지 않습니다. **현금·현실 세금과 이어지지 않습니다.** 자발적 방어 기여금(v8.0의 도시 기금)은 세금과 다른 장부에 그대로 있습니다. [CITY_TAX_SYSTEM](CITY_TAX_SYSTEM.md).

2. 화면이 다른 HUD 의 자리를 제대로 재는지 (규칙은 확인, 재는 코드는 실행해야 확인).
3. 프레임레이트에 주는 영향 (설계로만 줄임. 재 보지 않음).
4. 게임 화면이 실제 서버의 요약을 받는 것 (HTTP 구현 없음).
5. 요약 요청의 부하, 브라우저로 본 관리자 화면, 어린이가 써 보는 것.

지시서와 다르게 한 것, 지시서에 없어서 정한 것 (**승인 없이 정한 초기값이므로 확인이 필요합니다**):

만들면서 고친 것:

- 움직임을 계산하는 코드를 처음에 화면 계층에 두었다가, Unity 없이 테스트할 수 없어서 규칙 계층으로 옮기고 테스트를 붙였습니다 (`DashboardAnimationController`).
- 키 겹침 검사가 처음에는 느슨해서 대시보드와 상관없는 줄을 대시보드의 것으로 읽었습니다. "가장 가까운 앞의 멤버 선언"을 찾는 방식으로 고쳤습니다.
- 서버 테스트 하나가 실패해 원인을 찾으니 코드가 아니라 작업 창에 남아 있던 환경변수(v9.0 로컬 확인 때의 `ADMIN_COOKIE_SECURE=0`)였습니다. 지우고 전체를 처음부터 다시 돌렸습니다. 로컬 확인에 쓴 환경변수는 끝난 뒤 지웁니다.
- 로컬 확인 스크립트가 틀리게 가정한 것 둘(랭킹의 경로, PowerShell 의 예약된 변수 이름)을 고쳤습니다. 서버 쪽에서 고칠 것은 나오지 않았습니다.

## 6. 바로 시작할 수 있는 범위

승인만 있으면 서버 없이 이 PC에서 진행할 수 있는 작업입니다.

1. git 저장소 초기화
2. Unity 프로젝트 생성과 계층 구조
3. Phase 1 클라이언트 (로컬 모의 구현 사용): 캐릭터 → 방 → 도시 → NPC → 로봇 사냥

서버 접속 정보와 PHP 전환 결정이 필요한 작업: Phase 0의 서버 조사, 모든 운영 서버 변경.

## 9. 작업 규칙

- 각 단계의 끝난 조건을 통과한 뒤 다음으로 넘어갑니다.
- 한 번에 하나의 흐름을 끝까지 만듭니다 (화면 → 규칙 → 서버 → 저장).
- 수치는 코드에 박지 않고 정의 데이터에 둡니다.
- 설계가 바뀌면 문서를 함께 고칩니다.
- 기존 서비스에 영향을 주는 변경은 승인을 받습니다.
- 비밀 값을 저장소에 넣지 않습니다.
