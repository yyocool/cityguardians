# HUD_LAYOUT_SYSTEM — 대시보드의 자리 잡기와 디자인

> 기준 v10.0 · 2026-11-14 · 상태: 자리 잡기 규칙(`Domain/Dashboard.cs`의 `DashboardLayout`), 움직임(`Domain/DashboardAnimationController.cs`), 화면(`UI/Dashboard`), 키(`Input/PlayerInput.cs`), 설정 저장(`Services/DashboardPreferenceService.cs`) 구현. 규칙은 해상도 11가지로 테스트했고, **Unity 화면은 컴파일 검사만 했고 실행해 보지 못함**

[LIVE_DASHBOARD](LIVE_DASHBOARD.md)의 카드 세 장을 **어디에, 어떤 모습으로** 놓는지를 다룹니다.

## 1. 기존 HUD (분석)

v9.0까지의 HUD 는 `UI/Hud.cs` 하나가 코드로 만듭니다 (프리팹 없음). 캔버스는 1920×1080 기준이고 화면 크기에 따라 폭과 높이를 절반씩 따라 늘어납니다 (`UiFactory.CreateCanvas`). 이 캔버스에는 마우스 판정기(`GraphicRaycaster`)가 없고, 누르기는 입력 계층의 좌표로 직접 판정합니다.

화면 오른쪽을 쓰는 것들 (1920×1080 기준):

| 것 | 자리 | 보이는 때 |
|---|---|---|
| GC 표시 (`Wallet`) | 오른쪽 위, 280×60 | 첫 보상 뒤 늘 |
| 방어전 현황 (`DefenseStatus`), FPS 임무 현황 (`Mission`, 400×232) | 오른쪽 위, GC 표시 아래 (y 100부터) | 해당 전투 |
| 구석 미니맵, 협동 방어전 현황과 팀 목록 | 오른쪽 위, GC 표시 아래로 차례로 | 협동 방어전 |
| 무기 칸 (`Hotbar`), FPS 의 탄약·장비 (`Gear`, 380×188) | 오른쪽 아래 | 무기를 든 때, FPS |
| 지도, 선택 메뉴, 결과, 일시정지 | 화면 전체 | 열었을 때 (화면을 덮는 화면) |

그래서 오른쪽 기둥은 **늘 비어 있는 자리가 아닙니다.** 위쪽은 GC 표시가, 전투에서는 그 아래를 임무 현황과 미니맵이, 아래쪽은 탄약 표시가 씁니다. 대시보드는 이 자리들을 이름으로 알지 않고 **직접 재서** 비켜 섭니다 (3장).

기존 HUD 는 고치지 않았습니다. `Hud.cs`에 더한 것은 대시보드를 만들고 매 프레임 부르는 두 줄입니다. 대시보드는 무기 칸 다음, 화면을 덮는 화면들(지도, 선택 메뉴)보다 앞에 만들어져서 그 화면들 아래에 깔립니다.

## 2. 디자인 시스템

`UI/Dashboard/DashboardStyle.cs`. 그림 파일을 쓰지 않고 실행할 때 작은 무늬(32×32)를 만들어 아홉 조각으로 늘려 씁니다.

| 요소 | 값 |
|---|---|
| 판 | **반투명한 어두운 유리**: 짙은 남색, 불투명도 80% (`0.055, 0.075, 0.115, 0.80`). 마우스를 올리면 조금 밝아짐 |
| 테두리 | 흰색 17%의 **얇은 선** (고리 무늬) |
| 모서리 | 둥글게 (반지름 약 10) |
| 그림자 | 검정 36%, 판보다 조금 크고 가장자리가 흐린 **절제된 그림자** |
| 왼쪽 띠 | 카드의 상태를 알리는 가는 띠: 계좌는 강조색, 우리 도시와 전국은 **위험 단계의 색** |
| 글자 | 기존 HUD 와 같은 글꼴. 카드 이름 19(굵게), 핵심 수치 17, 줄의 이름 17(흐린 회색) · 값 18, 꼬리표 12, 상태 줄 13. 순자산은 굵게 |
| 나눔 선 | 흰색 9% |
| 막대 | 위험도와 안전도 아래의 3 px 막대 |
| 꼬리표 | "개발용 샘플", "준비 중": 옅은 노란 바탕의 작은 칩 |

카드의 뼈대 (`DashboardCardBase`):

```
┌──────────────────────────────────┐
│▌ 우리 도시          위험도 42 ▲ 주의 │  머리 줄 44: 이름 + 핵심 수치 (접혀도 남음)
│──────────────────────────────────│
│  위험도                42  ▲ 주의  │  줄 26 × n: 이름 · 값 · (꼬리표) · (막대)
│  ▔▔▔▔▔▔▔▔▔                        │
│  방어력                    1,240  │
│  …                                │
│  ● 실시간 · 14:03:21 갱신  Shift+F8 상세 │  연결 상태 줄 20
└──────────────────────────────────┘
```

상태에 따른 강조 (지시서 1장):

| 상태 | 표시 |
|---|---|
| 위험 단계 | 띠와 막대의 색 + **모양과 글자** `● 안전` `▲ 주의` `◆ 위험` `■ 긴급` |
| 침공·긴급 | 카드가 붉은빛을 띠고 띠가 깜박임. 머리 줄에 `■ 외곽 침공` |
| 늘고 줄어든 금액 | 초록 `▲ +1,200 GC` / 붉은 `▼ −300 GC` |
| 연결 끊김 | 상태 줄이 주황 `▲ 연결 끊김 · …` |
| 샘플·준비 중 | 값이 흐리고 꼬리표가 붙음 |

색만으로 뜻을 전하는 곳은 없습니다. 어린이부터 성인까지 읽을 수 있게 숫자는 쉼표를 넣고, 좁은 자리에서는 `1.2만`처럼 줄여 씁니다 (올림하지 않음 — 가진 것보다 많아 보이지 않게).

## 3. 자리 잡기

규칙은 `DashboardLayout.Compute` (순수 계산), 재는 일은 `DashboardLayoutManager`.

### 규칙

1. **폭**: 340 × 배율. 다만 **화면 폭의 24%를 넘지 않게** 줄입니다 (게임 시야를 가리지 않도록). 1920×1080에서 340 (17.7%).
2. **기둥**: 오른쪽 끝에서 32 떨어진 곳. 타워디펜스에서 이용자가 "왼쪽으로 옮기기"를 골랐을 때만 왼쪽 끝에서 32.
3. **쌓기**: 다른 HUD 가 위에서 쓰는 높이 아래(8 띄움)부터, 아래에서 쓰는 높이 위까지. 카드 사이는 8. 가장자리에서는 최소 28.
4. **넘치면 접기**: 펼친 카드를 **전국 → 계좌 → 우리 도시** 순으로 접습니다. 우리 도시 카드는 긴급 알림을 싣고 있어서 맨 나중입니다.
5. **그래도 넘치면 한 줄**: 세 장을 머리 줄 높이의 작은 칩으로 **한 줄에 나란히** 놓습니다 (`■ 42` 같은 가장 짧은 글).
6. 숨긴 카드는 자리를 차지하지 않습니다. 이용자가 숨긴 카드는 어떤 경우에도 나타나지 않고, 숨기지 않은 카드는 사라지지 않습니다.

펼친 높이 (배율 100%): 계좌 240, 우리 도시 270, 전국 330. 접힌 높이 44.

1920×1080, 걸어 다닐 때 (기본 상태: 계좌 펼침, 우리 도시 펼침, 전국 접힘):

```
                                          ┌──────────┐  y 28   GC 표시 (기존)
                                          └──────────┘  y 88
                                          ┌──────────┐  y 96
                                          │ 내 계좌   │        240
                                          └──────────┘  y 336
                                          ┌──────────┐  y 344
                                          │ 우리 도시 │        270
                                          └──────────┘  y 614
                                          ┌──────────┐  y 622
                                          │ 전국 현황 │  44    (접힘)
                                          └──────────┘  y 666
```

세 장을 모두 펴도 (240 + 270 + 330 + 16 = 856) 96부터 952까지로 1080 안에 들어갑니다.

### 다른 HUD 재기

0.25초마다, 또는 상태나 해상도가 바뀌면 잽니다.

- HUD 뿌리의 자식 가운데 **대시보드보다 먼저 만들어진 것**만 봅니다 (그 뒤의 것은 화면을 덮는 화면).
- 켜져 있고 그림(`Image`)이 있는 칸을 장애물로 봅니다. 그림이 없는 묶음(FPS 화면, 무기 칸, 이름·체력)은 한 단계 안쪽의 칸들을 봅니다.
- 화면의 절반 넘게를 가로·세로로 덮는 칸(피격 때 붉어지는 막)은 뺍니다.
- 카드 기둥의 폭과 **30% 넘게 겹치는 칸만** 셉니다. 가운데가 화면 위쪽이면 위에서 쓰는 높이로, 아래쪽이면 아래에서 쓰는 높이로.
- 잰 값이 6보다 적게 달라지면 무시합니다 (GC 표시가 잠깐 커지는 것 같은 떨림에 카드가 흔들리지 않게).

이름을 모르고 재므로 새 HUD 가 생겨도 카드가 알아서 비켜 섭니다. 반대로, 그림이 없는 글자만의 HUD 는 장애물로 보지 않습니다 (8장).

## 4. 움직임

`DashboardAnimationController` (카드마다 하나, Unity 없이 테스트).

- 접고 펴기, 자리 옮기기: **0.18초의 감속 움직임** (지수 감쇠. 끝에 가까울수록 느려짐). 높이와 자리만 바뀌고 몸통은 유리판에 가려져(마스크) 자연스럽게 접힙니다.
- 숨기기: 그 자리에서 흐려져 사라짐. 다시 나타날 때는 새 자리에서 곧바로 나타나 밝아짐 (화면을 가로질러 날아오지 않음).
- 처음 나타날 때와 **해상도가 바뀌었을 때**는 미끄러지지 않고 곧바로 제자리에.
- 목표를 지나치지 않습니다. 프레임이 길게 끊기면 (0.72초 이상) 바로 목표에 놓습니다.
- 목표에 닿으면 멈추고, 그 뒤로는 아무것도 고치지 않습니다.
- 게임이 멈춰 있어도 (일시정지) 움직이도록 실제 시간으로 움직입니다.
- 급한 일의 깜박임은 띠의 밝기만 바꿉니다.

## 5. 키

기존 키와 겹치지 않는지 먼저 확인했습니다. 게임의 키는 모두 `Input/PlayerInput.cs` 한 곳에서 읽습니다 (다른 소스는 키보드를 직접 읽지 않음).

| 이미 쓰는 키 | 쓰임 |
|---|---|
| W A S D, 마우스 | 이동, 시점 |
| 왼쪽 Shift | 달리기 |
| Space, E, Esc | 점프, 상호작용, 일시정지 |
| Q, R, N | 종료(일시정지 중) / 보조 장치·전술 핑, 다시 하기 / 재장전 / 돌리기, 새 게임 |
| M, I, P | 지도·전술 지도, 가방, 휴대전화 |
| F, V | 방 꾸미기 / 지원 장비 / 팀 메뉴, 시점 바꾸기 |
| 숫자 1~6 | 메뉴에서 고르기, 무기 바꾸기, 수리 키트 |

**F1~F12 는 하나도 쓰이지 않았습니다.** 그래서 지시서의 예시 그대로 정했습니다.

| 키 | 일 |
|---|---|
| `F6` | 대시보드 전체 보이기 / 숨기기 |
| `F7` / `F8` / `F9` | 내 계좌 / 우리 도시 / 전국 현황 카드 **접기 ↔ 펴기** (숨겨져 있었으면 폄) |
| `Shift` + `F7` / `F8` / `F9` | 그 카드의 **상세 보기** |
| `Ctrl` + `F7` / `F8` / `F9` | 그 카드만 **숨기기 / 다시 보이기** |
| `Shift` + `F6` | 대시보드 설정 (글자와 카드 크기, 타워디펜스에서의 자리, 기본값으로) |
| 왼쪽 `Alt` (누르고 있는 동안) | 커서가 풀림 → 마우스로 카드를 누름 |

마우스 (왼쪽 Alt 를 누른 채):

| 누르는 곳 | 일 |
|---|---|
| 머리 줄, 또는 접힌 카드 | 접기 ↔ 펴기 |
| 펼친 카드의 몸통 | 상세 보기 |
| 오른쪽 버튼 | 그 카드 숨기기 |

- Alt 를 누르는 동안에도 조작은 잠기지 않습니다 (걷던 방향으로 계속 걷습니다). 커서가 나와 있는 동안에는 기존 입력 규칙대로 시점이 돌지 않고 공격도 나가지 않습니다.
- 장면을 옮기는 중, 일시정지 중, 지도나 전술 지도가 떠 있을 때에는 대시보드 키를 받지 않습니다. 대화나 메뉴가 떠 있을 때에는 접고 펴는 것은 되지만 상세 보기와 설정은 그 위에 열리지 않습니다.
- 키가 겹치지 않는다는 것은 테스트가 소스를 읽어 확인합니다 (`tools/check/rules/KeyBindingTests.cs`): F6~F9 와 왼쪽 Alt 는 입력 계층에서 대시보드용으로 한 번씩만 읽히고, 다른 소스 파일은 키보드를 직접 읽지 않습니다.
- 알아 둘 것: `Shift`는 달리기 키이기도 합니다. 달리면서 F7 을 누르면 상세 보기가 열립니다. 상세 보기는 걸어 다닐 때만 열리고 Esc 로 닫히므로 해가 되지는 않지만, Unity 에서 직접 눌러 보고 불편하면 바꿔야 합니다 (8장).
- 키를 바꾸는 화면은 게임 전체에 아직 없습니다. 생기면 이 여섯 개를 거기에 올리면 됩니다 (입력이 한 곳에 모여 있음).

## 6. 사용자 설정 저장

`DashboardPreferenceService` → 게임 저장 폴더의 `dashboard_prefs.json` (다른 저장 파일과 같은 자리, 같은 저장 방식).

| 저장하는 것 | 값 |
|---|---|
| 대시보드 전체 보이기 | 예 / 아니오 |
| 카드별 상태 | 펼침 / 접힘 / 숨김 — **이용자가 손댄 카드만**. 손대지 않은 카드는 관리자의 기본값을 따름 |
| 글자와 카드 크기 | 80 / 100 / 120 / 140% |
| 타워디펜스에서의 자리 | 오른쪽에 접어 두기 / 오른쪽에 그대로 / 왼쪽으로 옮기기 |

- 바꾼 뒤 0.6초 동안 조용하면 한 번 씁니다 (키를 연달아 눌러도 파일은 한 번). 게임을 끌 때와 접속이 바뀔 때도 씁니다.
- 파일이 없거나 깨졌으면 기본값으로 시작합니다. 모르는 카드, 모르는 상태, 범위를 벗어난 크기는 걸러 냅니다. 저장에 실패해도 그 실행 동안에는 그대로 쓰입니다.
- **기기에 저장됩니다.** 서버에 올리지 않으므로 다른 PC 에서는 따라오지 않습니다. 개인정보나 금융 정보는 들어 있지 않습니다.
- 전투 중에만 바꾼 카드 상태는 저장하지 않습니다 ([LIVE_DASHBOARD](LIVE_DASHBOARD.md) 4장).
- "기본값으로 되돌리기"는 이 파일의 내용을 처음 상태로 돌립니다.

## 7. 해상도별 확인

Unity 가 없어 화면을 띄워 보지 못했습니다. 대신 자리 잡기 규칙을 **계산으로** 확인했습니다 (`DashboardTests.Layout_KeepsItsPromises_AtEveryResolutionScaleAndHudSituation`).

| 축 | 값 |
|---|---|
| 해상도 11가지 | 1280×720, 1366×768, 1600×900, **1920×1080**, 2560×1440, 3840×2160, 2560×1080(21:9), 3440×1440(21:9), 1920×1200(16:10), 1280×1024(5:4), 1024×768(4:3) |
| 배율 4가지 | 80, 100, 120, 140% |
| 다른 HUD 가 쓰는 자리 6가지 (위 / 아래) | 88 / 0 (평소: GC 표시만), 88 / 300 (아래쪽에 무기 칸), 332 / 216 (FPS: 임무 현황과 탄약 표시), 300 / 0 (혼자 하는 방어전), 780 / 0 (협동 방어전: 미니맵과 팀 현황), 940 / 60 (거의 다 찬 화면) |
| 카드 상태 5가지 | 모두 펼침, 전국만 접힘, 모두 접힘, 계좌 숨김, 우리 도시 숨김 + 전국 접힘 |
| 기둥 2가지 | 오른쪽, 왼쪽 |

2,640가지 모두에서 다음이 지켜집니다.

- 카드의 폭이 화면 폭의 24%를 넘지 않는다.
- 카드가 화면 밖으로 나가지 않는다 (좌우 32, 위아래 28 안쪽).
- 카드끼리 겹치지 않는다.
- 다른 HUD 가 쓰는 자리를 침범하지 않는다 (줄 하나의 높이도 없는 화면은 아래쪽 HUD 바로 위에 붙임).
- 이용자가 숨긴 카드는 나타나지 않고, 숨기지 않은 카드는 사라지지 않는다. 접어 둔 카드가 저절로 펼쳐지지 않는다.
- 16:9 화면은 해상도가 달라도 (720p ~ 4K) 같은 자리에 같은 비율로 놓인다.

접히는 순서(전국 → 계좌 → 우리 도시)와 한 줄로 줄어드는 것은 따로 확인합니다 (`Layout_CollapsesCardsInOrder_…`, `Layout_PutsThreeCardsInOneRow_…`).

1920×1080에서의 자리는 따로 한 번 더 확인합니다 (3장의 그림과 같은 수: 오른쪽 32, GC 표시 아래 8).

**확인하지 못한 것**: 실제 화면에서의 글자 크기와 줄바꿈, 4K 에서의 선명함, 다른 HUD 를 잰 값이 계산에 넣은 값과 같은지. Unity 에서 볼 때의 점검표는 [TEST_PLAN](TEST_PLAN.md) 16.7.

## 8. 한계

- **눈으로 본 적이 없습니다.** 색, 그림자의 세기, 모서리, 글자 크기는 값으로만 정했습니다.
- 다른 HUD 를 재는 방식은 "그림이 있는 칸"에 기댑니다. 글자만 있는 HUD 나 두 단계보다 깊이 묻힌 칸은 재지 못합니다. 지금의 HUD 에는 그런 것이 오른쪽에 없다고 보고 만들었지만 실행해서 확인해야 합니다.
- `Shift` + 카드 키는 달리기와 겹칩니다 (5장).
- 자리를 끌어서 옮기거나 카드의 순서를 바꿀 수 없습니다.
- 터치 화면용 조작과 크기는 없습니다 (Android · iOS 는 다음 단계).
- 배율은 대시보드에만 적용됩니다. 게임 전체의 UI 배율 설정은 아직 없습니다.
