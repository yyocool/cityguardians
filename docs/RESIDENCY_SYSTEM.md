# RESIDENCY_SYSTEM — 이방인과 전입신고

> 기준 v6.0 · 2026-11-13 · 상태: 전입신고 구현 (클라이언트, 모의 서버). 이사·계정 연결·닉네임 직접 입력은 미구현. 구현 내용과 설계와의 차이는 9장 · 수치는 초기값

## 1. 개념

| 용어 | 게임 안의 뜻 | 기술적 의미 |
|---|---|---|
| 이방인 | 어느 도시에도 속하지 않은 사람 | 지역 소속이 없는 플레이어 |
| 전입신고 | 한 도시의 주민이 되는 절차 | 플레이어에 지역과 닉네임을 등록 |
| 가디언 | 도시를 지키는 주민 | 지역 소속이 있는 플레이어 |
| 계정 연결 | 데이터를 안전하게 지키는 기능 | 게스트 계정에 로그인 수단을 추가 |

게임에서는 "회원가입"이라는 말을 쓰지 않습니다. 그리고 **전입신고와 계정 인증은 서로 다른 기능**입니다.

| | 전입신고 | 계정 연결 |
|---|---|---|
| 목적 | 도시 소속 | 데이터 보호, 기기 간 이동 |
| 필요한 것 | 지역 선택, 닉네임 | 로그인 수단 (추후 결정) |
| 개인정보 | 수집하지 않음 | 수단에 따라 수집 |
| 필수 여부 | 선택 | 선택 |
| 저장 | `players.region_id`, `players.nickname` | `player_credentials` |

게스트인 채로 전입신고를 할 수 있고, 계정을 연결한 이방인도 있을 수 있습니다.

## 2. 이방인이 할 수 있는 것

| 기능 | 이방인 | 주민 |
|---|---|---|
| 개인 방 | 가능 | 가능 |
| 도시 탐험 | 가능 | 가능 |
| 기본 전투, GC 획득 | 가능 | 가능 |
| 아이템 구매 | 가능 | 가능 |
| NPC 상호작용 | 가능 | 가능 |
| 방어전 | 가능 | 가능 |
| 은행 | 가능 | 가능 |
| 도시 소속, 완장 문양 | — | 가능 |
| 주민 전용 임무 | — | 가능 |
| 도시 기여도, 방어 포인트 적립 | — | 가능 |
| 도시 랭킹 반영 | — | 가능 |
| 공동 방어시설 | — | 가능 (추후) |
| 지역 커뮤니티 (지역 채팅) | — | 가능 (Phase 5) |
| 학교 방어대 | — | 가능 (추후) |

은행을 이방인에게 열어 두는 것은 지시서의 이방인 기능 목록에는 없는 확장입니다. 1차 완료 기준에서 전입신고가 은행 저축보다 앞에 있으므로, 원한다면 은행을 주민 전용으로 바꿀 수 있습니다.

## 3. 권유

- 첫 전투 뒤 방어대장이 한 번 권합니다: "우리 도시를 지켜줘서 고마워! 정식 주민이 되어줄래?"
- "나중에요"를 고르면 더 묻지 않습니다. 방어대장이나 도시 행정관에게 말을 걸면 언제든 할 수 있습니다.
- 이방인이라는 이유로 화면을 가리거나 진행을 막지 않습니다.
- 주민 전용 기능 앞에서는 "주민이 되면 할 수 있어요" 한 줄만 보여 줍니다.

## 4. 절차

| 단계 | 화면 | 서버 |
|---|---|---|
| 1. 지역 선택 | 대한민국 지도. 시·도 → 시·군·구 | 지역 목록 제공 |
| 2. 닉네임 | 입력칸 하나, 바로 사용 가능 여부 표시 | 규칙·중복·금칙어 검사 |
| 3. 캐릭터 확인 | 자동 생성된 모습. "다른 모습 보기" | 외형 저장 |
| 4. 완료 | 가디언 등록 연출, 완장에 도시 문양 | 지역·닉네임 등록, 축하금 지급 |

4단계의 등록, 주민 수 증가, 축하금 지급, 이력 기록은 하나의 DB 트랜잭션으로 처리합니다.

### 지역 선택 안내

지도 옆에 한 줄을 보여 줍니다: "실제로 사는 곳과 달라도 괜찮아요. 좋아하는 도시를 골라요." 실제 주소와 위치 정보는 묻지도 수집하지도 않습니다 (운영 홈페이지의 안내와 같은 방침).

## 5. 규칙

| 항목 | 값 | 비고 |
|---|---|---|
| 첫 전입 | 무료 | 운영 홈페이지 안내와 동일 |
| 전입 축하금 | 500 GC | 계정당 1회 |
| 이사 (도시 변경) | 가능 | 도시 행정관에게 신청 |
| 이사 수수료 | 1,000 GC | 관리자에서 조정 |
| 이사 대기 시간 | 전입 후 7일 | 관리자에서 조정 |
| 이사 시 기여도 | 이전 도시에 남고 새 도시에서 0부터 | 랭킹 조작 방지 |

"이사에 수수료와 대기 시간이 있다"는 것은 운영 홈페이지에 이미 안내된 규칙입니다. 금액과 기간은 기존 서버 설정을 확인해 맞춥니다.

### 닉네임

| 규칙 | 내용 |
|---|---|
| 길이 | 2~8자 (한글·영문·숫자) |
| 중복 | 불가 |
| 금칙어 | 욕설, 운영자 사칭, 실명·연락처로 보이는 형태 |
| 변경 | 추후 (GC 수수료) |

입력 화면에 "진짜 이름이나 전화번호는 쓰지 마세요"를 안내합니다.

## 6. 게스트와 계정 연결

### 게스트

1. 처음 실행하면 클라이언트가 서버에 게스트 생성을 요청합니다.
2. 서버가 플레이어 ID와 **게스트 비밀키**를 발급합니다. 비밀키는 이때 한 번만 전달되고 서버에는 해시로 저장됩니다.
3. 클라이언트는 비밀키를 기기에 보관합니다. Windows에서는 사용자 계정으로 암호화(DPAPI)한 파일에 둡니다.
4. 다음 실행부터 비밀키로 접속해 진행 상황을 복구합니다.

비밀키를 잃으면(PC 초기화, 게임 데이터 삭제) 게스트 진행 상황을 되찾을 수 없습니다. 이 점을 설정 화면과 고객지원에서 안내합니다.

### 계정 연결

게스트 계정에 로그인 수단을 붙여 기기를 바꿔도 이어 할 수 있게 하는 기능입니다. 데이터 보호 기능으로 안내하고 강요하지 않습니다.

- 수단 후보: 이메일, 외부 로그인. 결정 전입니다.
- 미성년자의 개인정보 수집에는 보호자 동의 등 법적 요건이 따르므로, 수단과 절차는 법적 검토 뒤 정합니다 ([SECURITY_POLICY](SECURITY_POLICY.md) 9장).
- 개인정보를 수집하지 않는 방식으로 **이어하기 코드**(게임이 발급하는 긴 코드를 다른 기기에 입력)를 먼저 제공하는 방안을 제안합니다.

1차 버전은 게스트만 제공합니다. `player_credentials` 테이블은 여러 수단을 담을 수 있게 설계해 둡니다.

## 7. 주민이 된 뒤

- 완장과 이름표에 도시 문양이 표시됩니다.
- 전투와 방어전 기록이 **방어 포인트**로 소속 도시에 쌓입니다.
- 도시의 방어 포인트 합계로 도시 레벨이 오르고, 시·군·구 랭킹과 시·도 랭킹(소속 시·군·구 합계)에 반영됩니다.
- 지도에서 내 도시가 강조됩니다.

## 8. 데이터와 API

| 테이블 | 내용 |
|---|---|
| `players` | `residency_status`, `region_id`, `nickname`, `registered_at` |
| `residency_history` | 전입·이사 이력, 수수료 |
| `region_contributions` | 플레이어별 도시 기여도 |
| `regions` | 방어 포인트, 레벨, 주민 수 |

| API | 용도 |
|---|---|
| `GET /nicknames/check?name=` | 닉네임 사용 가능 여부 |
| `POST /residency` | 전입신고 (지역, 닉네임) |
| `POST /residency/move` | 이사 |
| `GET /residency` | 내 소속, 기여도, 이사 가능 시점 |

운영 서버의 v1 API에 전입신고 기능이 이미 있을 가능성이 높습니다. 기존 경로와 테이블을 확인한 뒤 이 설계와 맞춥니다.

## 9. 구현 기록 (2026-11-13, 클라이언트)

### 9.1 지금 되는 흐름

1. 첫 방어전을 이기고 도시로 돌아오면 목표 줄이 "주민센터의 정나래에게 전입신고를 하면 정식 가디언이 돼요"로 바뀌고 정나래 머리 위에 표시가 뜹니다. 이방인일 때만, 한 번만 권합니다.
2. 광장 서쪽 주민센터 앞의 정나래에게 말을 걸면 선택 메뉴가 나옵니다: **전입신고 하기 (축하금 500 GC)** / **나중에 할게요**.
3. "나중에"를 고르면 그대로 보내 주고 목표 줄의 권유도 사라집니다. 다시 말을 걸면 언제든 할 수 있습니다.
4. "전입신고 하기"를 고르면 대한민국 지도가 열립니다. 시·도 → 시·군·구를 고르고 "여기로 전입신고"(E 키 또는 버튼)를 누릅니다 ([MAP_SYSTEM](MAP_SYSTEM.md) 8장).
5. 가디언 이름을 추천 이름 3개 중에서 고릅니다. "다른 이름 보기"로 계속 바꿔 볼 수 있습니다.
6. 도시와 이름을 한 번 더 확인합니다: 네 / 이름을 다시 고를래요 / 도시를 다시 고를래요.
7. 등록되면 축하금 500 GC가 들어오고, 완장이 도시 색으로 바뀌고, 이름 아래에 "부산 해운대구 가디언"처럼 소속이 표시됩니다.
8. 그 뒤로 방어전을 이길 때마다 소속 도시에 방어 포인트 100이 쌓이고, 지도에서 볼 수 있습니다.

튜토리얼을 마쳤다면 방어전을 이기기 전에도 정나래에게 가서 전입신고를 할 수 있습니다.

### 9.2 서버 쪽 규칙 (모의 서버 `LocalMockBackend` 에 구현, 실제 서버가 따라야 할 내용)

| 규칙 | 내용 |
|---|---|
| 한 번만 | 이미 주민이면 `ALREADY_RESIDENT` 로 거절. 도시는 이사로만 바꿈 (이사는 미구현) |
| 지역 확인 | 지역 목록에 없는 코드는 `NOT_FOUND`. 합쳐진 시의 구(수원시 장안구 등)는 고를 수 없음 |
| 닉네임 | 규칙 위반은 `NICKNAME_INVALID`, 다른 플레이어가 쓰는 이름은 `NICKNAME_TAKEN` (영문 대소문자 구별 없이 비교) |
| 축하금 | 계정당 1회. 원장에 `residency_bonus` 로 기록 |
| 주민 수 | 등록과 함께 그 지역의 주민 수 +1 |
| 방어 포인트 | 주민이 방어전을 이기면 +100 (`StageDef.winDefensePoints`). 이방인의 승리와 패배에는 쌓이지 않음 |
| 거절된 요청 | 잔액, 소속, 이름, 주민 수 어느 것도 바뀌지 않음 |

닉네임 규칙 (`NicknameRules`): 2~8자, 완성된 한글·영문·숫자만(띄어쓰기·기호·한글 낱자 불가), 숫자만으로 된 이름 불가, 숫자가 5개 이상 이어지면 연락처로 보고 불가, 운영자 사칭 낱말과 게임 속 인물 이름(보리, 강한울 등)·"이방인" 불가, 금칙어 불가. 금칙어 목록은 최소한만 들어 있으며 실제 서비스에서는 서버가 관리하는 목록으로 바꿔야 합니다.

### 9.3 설계와 다른 점, 하지 않은 것

| 항목 | 설계 | 구현 | 이유 |
|---|---|---|---|
| 닉네임 정하기 | 입력칸에 직접 입력 | **추천 이름에서 고르기** (꾸미는 말 20 × 이름 낱말 20) | 한글 입력기(IME)를 거치는 직접 입력은 자동으로 검증할 방법이 없어 확인하지 못한 기능을 넣게 됨. 추천 이름은 개인정보가 들어갈 수 없다는 장점도 있음. **자기 이름을 직접 짓고 싶어 할 가능성이 높으므로 직접 입력은 남은 일** |
| 캐릭터 확인 ("다른 모습 보기") | 3단계 | 없음 | 캐릭터 외형이 아직 한 가지뿐 |
| 권유하는 사람 | 방어대장이 한 번 권함 | 목표 줄과 표시로 주민센터를 안내, 권유 메뉴는 정나래 | 방어대장의 대화는 전입신고를 말로 안내만 함. 물어보는 곳을 한 군데로 모음 |
| 완장 | 도시 문양 | 시·도 색 | 문양 그림이 아직 없음 |
| 이사, 수수료, 대기 시간 | 5장 | 없음 | 범위 밖 |
| 주민 전용 임무, 도시 랭킹, 도시 레벨 | 2장, 7장 | 없음 | 방어 포인트 적립과 표시까지만 |
| 전투(거리 사냥) 기록의 방어 포인트 | 7장 "전투와 방어전 기록" | 방어전 승리만 | 사냥 보상에 방어 포인트를 붙이는 기준이 아직 없음 |
| 한 트랜잭션 처리 | 4장 | 해당 없음 | 모의 서버는 파일 하나에 한 번에 저장. 실제 서버에서 지켜야 함 |

### 9.4 검증

- 자동 테스트 (EditMode): 지역 목록 4건, 닉네임 규칙 27건(모든 추천 이름 조합이 규칙을 통과하는지 포함), 모의 서버 전입신고 11건(등록·축하금·원장, 재시작 뒤 유지, 두 번째 신고 거절, 없는 지역, 나쁜 이름, 다른 플레이어와 같은 이름, 방어 포인트, 옛 저장 파일 읽기 등).
- 자동 테스트 (PlayMode): 정나래에게 걸어가 대화 → "나중에" → 다시 대화 → 지도에서 부산 → 해운대구 → 이름 고르기 → 다른 이름 보기 → "도시를 다시 고를래요"로 돌아가기 → 다시 끝까지 → 등록 화면 → 지도에서 내 도시와 "1명" 확인 → 게임을 껐다 켜도 유지.
- **확인하지 못한 것**: 주민이 방어전을 이겼을 때 결과 화면에 뜨는 "방어 포인트 +100" 줄(서버 쪽 적립은 테스트했지만 그 화면은 띄워 보지 못함), 사람이 직접 해 봤을 때 이 흐름이 설명 없이 통하는지, 추천 이름만으로 아이들이 만족하는지.
