# PLATFORM_STRATEGY — 플랫폼 전략

> 기준 v6.0 · 2026-11-13 · 상태: 설계 (미구현)

## 1. 순서

| 차수 | 플랫폼 | 목표 |
|---|---|---|
| 1차 | Windows PC | 게임성 완성. 1차 플레이 가능 버전 |
| 2차 | Android | 같은 서버·같은 계정으로 플레이 |
| 3차 | iOS | Android와 같은 구조로 이식 |

Windows에서 재미를 먼저 증명합니다. 모바일은 그 뒤에 옮기되, 처음부터 입력·UI·게임 로직을 나눠 두어 다시 만들지 않게 합니다.

## 3. 모바일 확장을 위한 분리

### 3.1 계층

```
CG.Domain     순수 C#. 규칙, 계산식, 상태 기계, 데이터 모델 (UnityEngine 의존 없음)
CG.Services   서버 통신, 인증, 로컬 저장. 인터페이스로 노출
CG.Input      입력 추상화
CG.Gameplay   MonoBehaviour. 캐릭터, 적, 타워, 상호작용
CG.UI         화면. Gameplay와 Services의 상태를 보여 주고 의도를 전달
```

각 계층은 어셈블리 정의(asmdef)로 나눠 의존 방향을 컴파일러가 강제하게 합니다. UI는 Gameplay 내부를 직접 건드리지 않고, Gameplay는 UI를 모릅니다.

### 3.2 입력

게임 코드는 키 이름이 아니라 **의도**를 읽습니다.

| 의도 | Windows | 모바일 (2차) |
|---|---|---|
| 이동 | WASD | 왼쪽 가상 스틱 |
| 시점 | 마우스 | 오른쪽 화면 드래그 |
| 공격 | 좌클릭 | 공격 버튼 |
| 점프 | Space | 점프 버튼 |
| 상호작용 | E | 상황 버튼 (대상 근처에서 표시) |
| 인벤토리 | I | 가방 버튼 |
| 지도 | M | 지도 버튼 |
| 채팅 | Enter | 채팅 버튼 |

Unity Input System의 액션 맵으로 정의하고, `IPlayerInput` 인터페이스 뒤에 둡니다. 모바일에서는 터치 구현체만 추가합니다.

### 3.3 UI

- 기준 해상도에 맞춘 스케일링과 앵커 배치로 화면 비율 변화에 대응합니다.
- 버튼은 처음부터 손가락으로 누를 수 있는 크기(기준 해상도에서 최소 88px)로 만듭니다.
- 마우스 오버에만 의존하는 정보 표시를 만들지 않습니다.
- 글자는 큰 크기와 아이콘 중심으로 구성합니다. 초등학생 가독성과 모바일 화면 양쪽에 맞습니다.
- 화면 구성(레이아웃)은 플랫폼별 프리팹으로 갈아 끼울 수 있게 하고, 화면 로직은 공유합니다.

### 3.4 데이터

- 진행 상황의 원본은 서버입니다. 기기에는 게스트 인증 정보, 설정, 콘텐츠 정의 캐시만 둡니다.
- 같은 계정이면 PC와 모바일에서 같은 캐릭터·자산을 씁니다 (계정 연결 필요, [RESIDENCY_SYSTEM](RESIDENCY_SYSTEM.md) 6장).
- API는 플랫폼을 구분하지 않고, 요청 헤더로 플랫폼과 클라이언트 버전만 전달합니다.

### 3.5 그래픽

블록형 저폴리곤 스타일은 모바일 부담이 작습니다. URP 품질 단계를 PC 높음 / PC 낮음 / 모바일 세 가지로 미리 나누고, 그림자·후처리·시야 거리를 단계별로 조절합니다.

## 4. 빌드와 배포

| 단계 | 방식 |
|---|---|
| 개발 빌드 | Unity 에디터와 로컬 Windows 빌드 |
| 테스트 빌드 | 명령행 빌드 스크립트로 zip 생성, SHA-256 기록 |
| 공개 | 관리자에서 빌드를 등록해야 홈페이지 다운로드 버튼이 활성화 ([WEBSITE_SPEC](WEBSITE_SPEC.md) 5장) |
| 버전 확인 | 실행 시 `/api/v1/health`의 `min_client_version`과 비교해 낮으면 업데이트 안내 |

자동 업데이트 프로그램(런처)은 1차 범위에 넣지 않습니다. 필요해지면 별도로 검토합니다.
