# LOAN_CREDIT_SYSTEM — 대출과 신용점수

> 기준 v6.0 · 2026-11-13 · 상태: 설계 (Phase 4 구현, 1차에서는 DB·API 자리만 준비) · 수치는 초기값

## 1. 방향

빌린 돈에는 이자가 붙고, 약속을 지키면 신용이 쌓인다는 것을 게임 안에서 안전하게 겪어 보게 합니다.

**게임 내 신용점수는 현실의 신용평가와 아무 관계가 없습니다.** 화면에도 "게임 속 점수예요"라고 표시합니다.

## 2. 미성년자 보호 원칙

이 장의 규칙은 다른 모든 규칙보다 우선합니다.

| 금지 | 구현 |
|---|---|
| 과도한 채무 누적 | 동시에 1건만 대출. 한도는 작게. 이자 총액 상한. 복리 없음 |
| 반복적인 연체 압박 | 알림은 정해진 횟수만. 화면을 가리거나 진행을 막지 않음 |
| 현실 결제를 통한 상환 | 상환 수단은 게임에서 번 GC뿐. 결제 기능 자체가 없음 |
| 빚의 장기화 | 연체가 일정 기간을 넘으면 남은 빚을 정리(탕감)하고 대출 이용만 한동안 제한 |

추가로:

- 대출을 권유하는 알림이나 광고를 보내지 않습니다.
- 대출이 없어도 게임 진행에 지장이 없게 합니다. 대출이 있어야 살 수 있는 필수 아이템을 만들지 않습니다.
- 빚이 있다는 사실을 다른 플레이어에게 보여 주지 않습니다.

## 3. 신용점수

| 항목 | 값 |
|---|---|
| 범위 | 300~900 |
| 처음 점수 | 600 |
| 공개 범위 | 본인만 |

### 점수가 바뀌는 일

| 사건 | 변화 |
|---|---|
| 대출을 기한 안에 다 갚음 | +15 |
| 기한보다 일찍 다 갚음 | +15 (조기 상환과 정상 상환은 같은 점수. 일찍 갚아도 손해 없음) |
| 연체 시작 | −30 |
| 연체가 이어짐 | 7일마다 −5 (대출 1건당 최대 −20까지) |
| 빚 정리(탕감) | −50 |
| 예금을 꾸준히 유지 (7일 연속 일정 잔액 이상) | +2 (한 달 최대 +8) |

- 점수는 항상 300~900 안에 머뭅니다.
- 모든 변화는 사유와 함께 이력에 남고, 플레이어가 자기 이력을 볼 수 있습니다.
- 점수 규칙은 `credit_policy_rules`에 두고 관리자에서 조정합니다.
- 전투 실력, 채팅, 신고·제재 여부는 신용점수에 넣지 않습니다. 금융 행동만 반영합니다.

## 4. 대출 조건

신용점수 구간에 따라 한도와 이율이 달라집니다.

| 구간 | 신용점수 | 한도 (GC) | 하루 이율 | 승인 |
|---|---|---|---|---|
| A | 750~900 | 5,000 | 0.3% | 가능 |
| B | 650~749 | 3,000 | 0.5% | 가능 |
| C | 550~649 | 1,500 | 0.8% | 가능 |
| D | 450~549 | 500 | 1.0% | 가능 |
| E | 300~449 | — | — | 불가 |

처음 점수 600은 C 구간입니다.

### 공통 조건

| 항목 | 값 |
|---|---|
| 해금 레벨 | 10 |
| 동시 대출 | 1건 |
| 기한 | 7일 |
| 이자 방식 | 단리. 남은 원금에만 붙음 |
| 이자 총액 상한 | 원금의 20%. 상한에 닿으면 이자가 더 늘지 않음 |
| 다시 빌리기 | 다 갚은 다음 날부터 |
| 연체·탕감 이력이 있을 때 | 연체 중에는 불가. 탕감 뒤 14일간 불가 |

상품과 구간별 조건은 `loan_products`, `loan_rate_tiers`에 두고 관리자에서 조정합니다.

## 5. 대출의 흐름

```
신청 → 심사 → 승인 → 실행 → 상환 중 → 완납
              ↘ 거절            ↘ 연체 → 완납
                                      ↘ 정리(탕감)
```

| 단계 | 내용 |
|---|---|
| 신청 | 금액 선택. 화면에 "갚을 돈", "하루 이자", "갚는 날"을 먼저 보여 준다 |
| 심사 | 서버가 즉시 판정: 해금 레벨, 신용점수 구간, 한도, 기존 대출, 제한 기간 |
| 승인·거절 | 거절이면 이유를 쉬운 말로 알려 준다 ("지금 빌린 돈을 먼저 갚아야 해요") |
| 실행 | 지갑에 입금. 원장에 `loan_disburse` |
| 이자 | 매일 자정 이후 예약 작업이 남은 원금 × 하루 이율을 더한다 (상한까지) |
| 상환 | 언제든 일부 또는 전부. 이자부터 갚고 남는 금액이 원금으로 간다 |
| 완납 | 신용점수 상승, 이력 기록 |
| 연체 | 6장 |

신청 화면에는 확인 단계가 한 번 더 있습니다: "7일 뒤까지 1,584 GC를 갚아야 해요. 빌릴까요?"

### 이자 계산

```
하루 이자 = floor(남은 원금 × 하루 이율)
누적 이자 = min(누적 이자 + 하루 이자, 원금 × 20%)
```

예: 1,500 GC를 0.8%로 빌리면 하루 12 GC, 7일이면 84 GC. 이자 상한은 300 GC입니다.

이자 계산은 은행 이자와 같은 방식으로 "마지막 계산일"을 기준으로 하여, 예약 작업이 늦어져도 날짜마다 정확히 한 번 반영합니다.

## 6. 연체

| 항목 | 처리 |
|---|---|
| 시작 | 기한이 지나도 남은 금액이 있으면 연체 상태 |
| 신용점수 | 시작 때 −30, 이후 7일마다 −5 (최대 −20) |
| 이자 | 같은 이율로 계속 붙되 상한(원금의 20%)에서 멈춤. 연체 가산 이자 없음 |
| 자동 상환 | 전투·방어전 보상의 20%가 자동으로 상환에 쓰임. 보상 화면에 그 내용을 표시 |
| 새 대출 | 불가 |
| 주식 매수 | 불가 (대출 잔액이 있는 동안) |
| 그 밖의 게임 이용 | 제한 없음 |
| 알림 | 기한 하루 전 1회, 연체 시작 때 1회. 이후에는 은행 화면에 표시만 |
| 정리(탕감) | 연체 30일이 지나면 남은 빚을 0으로. 신용점수 −50, 14일간 대출 불가 |

자동 상환 비율을 20%로 둔 것은 빚이 있어도 놀이의 보상감을 대부분 남겨 두기 위해서입니다.

탕감은 "갚지 않아도 된다"는 인상을 줄 수 있으므로 신용점수 하락과 이용 제한을 분명히 보여 줍니다. 그래도 어린 이용자가 갚을 수 없는 빚에 묶여 게임을 떠나는 것보다 낫다고 판단했습니다. 이 정책은 운영 방침에 따라 조정할 수 있습니다.

## 7. 화면

| 화면 | 내용 |
|---|---|
| 내 신용 | 점수 (막대와 구간 색), "게임 속 점수예요" 안내, 최근 변화 이력 |
| 대출 안내 | 지금 빌릴 수 있는 금액, 하루 이자, 갚는 날 |
| 내 대출 | 남은 원금, 쌓인 이자, 갚을 날, "갚기" 버튼 (일부 / 전부) |

금융 안내원의 첫 설명: "돈을 빌리면 빌린 것보다 조금 더 갚아야 해요. 꼭 필요할 때만 빌려요."

## 8. 관리자

| 메뉴 | 기능 |
|---|---|
| 대출 상품 | 상품, 구간별 한도·이율, 기한, 이자 상한, 해금 레벨, 판매 중지 |
| 신용점수 정책 | 사건별 점수 변화, 구간 경계, 탕감 기간, 자동 상환 비율 |
| 금융자산 | 플레이어별 대출 현황, 연체 현황, 통계 (대출 총액, 연체율) |

조건을 바꿔도 이미 실행된 대출의 이율과 기한은 바뀌지 않습니다.

## 9. 데이터와 API

| 테이블 | 내용 |
|---|---|
| `credit_scores` | 플레이어별 현재 점수 |
| `credit_score_history` | 점수 변화 이력 (사유, 관련 대출) |
| `credit_policy_rules` | 사건별 점수 변화 규칙 |
| `loan_products` | 대출 상품 |
| `loan_rate_tiers` | 신용점수 구간별 한도·이율 |
| `loans` | 대출 (원금, 남은 원금, 누적 이자, 이자 상한, 이율, 상태, 기한) |
| `loan_repayments` | 상환 기록 (원금분, 이자분, 수동/자동) |

| API | 용도 |
|---|---|
| `GET /credit` | 내 신용점수, 구간, 이력 |
| `GET /loans/offer` | 지금 가능한 한도, 이율, 기한 |
| `POST /loans` | 대출 신청 (즉시 심사·실행) |
| `GET /loans/current` | 내 대출 |
| `POST /loans/{id}/repay` | 상환 |

대출 실행과 상환은 지갑·원장과 하나의 트랜잭션으로 처리하고 중복 방지 키를 받습니다 ([ECONOMY_SYSTEM](ECONOMY_SYSTEM.md) 3장).

## 10. 확인이 필요한 것

미성년자가 이용하는 게임에 모의 대출·신용점수 기능을 넣는 것에 대한 규정 검토가 Phase 4 착수 전에 필요합니다 ([SECURITY_POLICY](SECURITY_POLICY.md) 9장).
