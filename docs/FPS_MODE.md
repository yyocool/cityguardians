# FPS_MODE — FPS 모드 (1인칭 시내 침입 임무)

> 기준 v8.0 · 2026-11-13 · 상태: 임무 하나("도심 상가 구역")의 수직 슬라이스를 규칙, 모의 서버, Unity 장면, PHP 서버에 구현. **Unity 쪽은 형식 검사만 통과했고 한 번도 실행해 보지 못함** (이 개발 환경에 Unity가 없음) · 수치는 초기값

## 1. 방향

AI 로봇이 외곽 방어선을 넘어 시내로 들어오면, 가디언이 1인칭 시점으로 건물 사이를 누비며 로봇을 찾아 막습니다.

| 원칙 | 구현 |
|---|---|
| 단순한 PvE부터 | 임무 하나, 적 두 종류, 혼자 하는 전투 |
| PvP 없음 | 플레이어끼리 쏠 수 없습니다. 다른 플레이어가 장면에 없습니다 |
| 과도한 폭력 표현 없음 | 상대는 로봇뿐입니다. 맞으면 부품이 튀고 부서져 사라집니다. 피·신체 훼손·사람을 쏘는 장면이 없습니다. 무기는 "에너지 블래스터" 같은 가상의 에너지 장비입니다 |
| 시민은 다치지 않음 | 로봇은 시민을 공격하지 않습니다. 대피시키지 못한 시민은 보너스가 없을 뿐입니다. 시민에게는 체력이 없어 어떤 공격으로도 피해를 받지 않습니다 |
| 무료 장비로 끝낼 수 있게 | 에너지 블래스터와 회복 장치가 처음부터 무료이고, 임무는 이 둘만으로 끝낼 수 있게 맞췄습니다 (4장) |
| 캐릭터와 이동은 헌트 모드와 같게 | 같은 `PlayerController`, 같은 체력, 같은 적. 바뀌는 것은 카메라와 무기뿐입니다 |

## 2. 진행

| 지시서의 단계 | 지금의 구현 |
|---|---|
| 도시 침입 발생 | 서버의 침공 판정에서 "시내 침입"이나 "ZERO 이벤트"가 시작됩니다 ([CITY_RISK_SYSTEM](CITY_RISK_SYSTEM.md) 5장). `GET /fps/invasions`가 지금 출동할 수 있는 침입을 알려 줍니다 |
| 긴급 출동 | 방어기지의 **작전 단말기**에서 E → "시내 긴급 출동". 침입이 없을 때에도 순찰 출동으로 나설 수 있습니다 (위험도는 절반만 내려갑니다) |
| FPS 전투 구역 진입 | 장면 `Fps` "도심 상가 구역". 서버가 임무 시작을 받아 준 뒤에 로봇이 나오기 시작합니다 |
| 침입 로봇 탐색 | 북쪽 벽의 뚫린 세 곳에서 로봇이 차례로 나와 건물 사이의 길로 시설을 향합니다. 탐지 센서를 켜면 벽 너머의 로봇과 시민이 표시됩니다 |
| 주요 시설 방어 | 발전 설비·통신 중계기·급수 설비 세 곳. 로봇이 닿으면 내구도가 깎이고(시설마다 6), 다 깎이면 가동을 멈춥니다. 로봇은 나오는 차례대로 세 시설을 돌아가며 노리므로 한 곳만 지켜서는 막을 수 없습니다 |
| 침입 로봇 제거 | 18대 (오작동 로봇 8, 기계 곤충 10)가 네 번에 걸쳐 나옵니다 |
| 민간인 NPC 보호 | 골목에 숨은 시민 4명에게 다가가 E → 대피. "시민" 이름표가 붙은 NPC이고 실제 플레이어처럼 꾸미지 않습니다 |
| 결과 반영 | 서버가 보고를 검증하고 보상·방어 포인트·위험도·침공 진행도를 반영합니다 (7장) |

### 이기고 지는 조건

| | 조건 |
|---|---|
| 승리 | 로봇이 모두 나왔고 남은 로봇이 없으며, 시설이 한 곳 이상 가동 중 |
| 패배 | 시설 세 곳이 모두 멈춤, 또는 제한 시간 5분이 지남 |
| 후퇴 | 돌아가는 문에서 E → 확인. 패배로 기록되고 보상이 없습니다. 서버가 시작을 받기 전이면 기록 없이 돌아갑니다 |

끝나면 결과 화면이 서버의 판정(보상, 지킨 시설, 대피시킨 시민, 위험도 변화)을 보여 주고 E로 도시에 돌아갑니다. 결과를 보내지 못하면 R로 다시 보냅니다 (같은 임무를 다시 보내도 서버는 처음 결과를 돌려줍니다).

## 3. 조작과 카메라

| 입력 | 동작 |
|---|---|
| WASD | 이동 |
| 마우스 | 시점 (위아래 ±70도) |
| 마우스 왼쪽 | 공격 (누르고 있으면 연사) |
| 마우스 오른쪽 | 조준 — 시야가 좁아지고(무기마다 다름) 탄이 퍼지지 않음 |
| R | 재장전 |
| Space | 점프 |
| Shift | 달리기 |
| E | 상호작용 (시민 대피, 돌아가는 문) |
| Q | 보조 장치 (회복 장치 / EMP 장치 / 보호막) |
| F | 지원 장비 (탐지 센서 / 지원 드론) |

Q와 F는 지시서의 조작 목록에 없던 것으로, 지시서의 장비 8종 가운데 무기가 아닌 다섯 가지를 쓰기 위해 더했습니다.

**1인칭 카메라** (`FirstPersonCamera`)

- 눈높이에서 보고, 캐릭터의 몸은 숨깁니다. 몸의 방향은 보는 쪽을 따라가므로 걷는 방향과 겨누는 방향이 같습니다.
- 시야각 70도 (3인칭은 55도). 조준하면 무기의 `aim_zoom`만큼 좁아집니다.
- 쏠 때 시야가 살짝 들리고, 시설이 맞으면 화면이 흔들립니다.
- 세 카메라(3인칭·1인칭·전략)는 같은 카메라 오브젝트에 붙어 있고 `CameraRig`가 하나만 켭니다. 모드가 바뀌어도 보던 방향이 이어집니다.

**화면** (`CombatHud`): 조준점과 명중 표시, 탄창과 재장전 진행, 보조 장치·지원 장비의 재사용 대기, 시설 세 곳의 내구도, 대피시킨 시민 수, 남은 시간, 남은 로봇, 왼쪽 위의 도시 위험도.

## 4. 무기와 장치

여덟 가지의 수치와 가격은 [EQUIPMENT_SYSTEM](EQUIPMENT_SYSTEM.md) 3장에 있습니다. 여기에는 동작만 적습니다.

| 장비 | 칸 | 동작 |
|---|---|---|
| 에너지 블래스터 (무료) | 주 무기 | 보는 방향으로 곧게 나가는 탄. 처음 닿는 로봇이나 벽에서 멈춤. 조준이 조금 빗나가도 맞도록 판정이 넉넉함 |
| 정밀 에너지 라이플 | 주 무기 | 같은 방식. 한 발이 세고 느리며, 조준 배율이 큼 |
| 충격파 발사기 | 주 무기 | 정면 부채꼴(60도, 7 m) 안의 로봇이 모두 맞고 뒤로 밀림 |
| 회복 장치 (무료) | 보조 (Q) | 체력 회복. 체력이 가득하면 쓰이지 않음 |
| EMP 장치 | 보조 (Q) | 주변 로봇을 잠깐 멈춤 |
| 보호막 | 보조 (Q) | 잠깐 동안 정해진 양까지 피해를 대신 받음 |
| 탐지 센서 | 지원 (F) | 벽 너머의 로봇(빨강)과 시민(노랑)을 화면에 표시 |
| 지원 드론 | 지원 (F) | 따라다니며 가까운 로봇을 쏨. 드론이 쓰러뜨린 로봇도 임무의 처치 수에 들어감 |

- 탄은 재장전하면 다시 찹니다. 탄약을 사거나 줍지 않습니다.
- 장비는 임무에 들어올 때 장착 칸에서 읽습니다. 아무것도 사지 않았어도 주 무기와 보조 장치 칸에는 무료 기본 장비가 들어 있습니다.
- **무료 장비로 끝낼 수 있는가**: 로봇의 체력 합은 680(60 × 8 + 20 × 10)이고 에너지 블래스터의 초당 피해는 60입니다. 숫자로는 여유가 있지만, 세 시설을 오가며 막아야 하는 실제 난이도는 **플레이테스트로 확인하지 못했습니다.**

## 5. 전장

장면 `Fps`를 `FpsBuilder`가 코드로 만듭니다 (다른 장면과 같은 방식).

- 가운데 광장과 십자로, 네 구역에 상가 건물 두 채씩, 건물 사이의 골목, 둘레길.
- 북쪽 벽에 침입 지점 세 곳, 시설 세 곳은 서로 떨어져 있습니다.
- 길가의 물건 뒤에 몸을 숨길 수 있습니다.
- 로봇은 길 찾기 지도(NavMesh)로 건물 사이의 길을 잡아 시설로 갑니다. 7 m 안에 플레이어가 보이면 플레이어에게 덤빕니다.
- 플레이어가 쓰러지면 헌트 모드와 같은 코드로, 잠시 뒤 안전한 곳에서 체력 절반으로 다시 일어납니다. GC나 아이템을 잃지 않습니다. 그동안에도 임무의 시간은 흐릅니다.

## 6. 임무 "도심 상가 구역"

| 항목 | 값 |
|---|---|
| 코드 | `downtown_1` |
| 해금 레벨 | 1 |
| 로봇 | 3초부터 오작동 로봇 4 → 22초부터 기계 곤충 6 → 42초부터 오작동 로봇 4 → 60초부터 기계 곤충 4 |
| 시설 | 3곳, 내구도 6 (로봇 한 대가 닿으면 1) |
| 시민 | 4명 |
| 제한 시간 | 300초 |
| 인정하는 가장 빠른 승리 | 60초 |
| 승리 보상 | 250 GC, 경험치 120 |
| 첫 승리 보너스 | 150 GC (한 번) |
| 시민 보너스 | 대피 1명마다 10 GC |
| 시설 보너스 | 지킨 시설 1곳마다 20 GC |
| 방어 포인트 | 80 |
| 패배·후퇴 | 보상 없음 |

완벽하게 끝낸 첫 승리는 250 + 150 + 40 + 60 = 500 GC입니다.

## 7. 결과 검증과 보상

클라이언트는 "무슨 일이 있었는가"만 보고합니다: 결과(승/패), 적별 처치 수, 지킨 시설 수, 대피시킨 시민 수. **금액, 시간, 위험도는 보내지 않고, 보내도 무시합니다.** 판정은 `FpsRules`(C#) / `Fps`(PHP)가 하고 두 구현의 결과가 같은지 표본으로 확인합니다.

### 거절하는 보고

| 이유 (`reject_reason`) | 조건 |
|---|---|
| `invalid_result` | 결과가 승·패가 아님 |
| `invalid_count` | 처치 수가 음수이거나 같은 적이 두 번 나옴 |
| `enemy_not_in_mission` | 임무에 나오지 않는 적 |
| `kills_exceed_mission` | 나오는 수보다 많이 처치 |
| `invalid_facilities` | 지킨 시설이 0 미만이거나 시설 수 초과, 또는 승리인데 0곳 |
| `invalid_civilians` | 대피시킨 시민이 0 미만이거나 시민 수 초과 |
| `time_limit_exceeded` | 서버가 잰 시간이 제한 시간 + 30초(전송 여유)를 넘음 |
| `finished_too_fast` | 승리인데 서버가 잰 시간이 60초 미만 |
| `kills_and_facilities_mismatch` | 승리인데 숫자가 서로 맞지 않음: 쓰러뜨리지 못한 로봇은 모두 시설에 닿았어야 하므로 `전체 로봇 − 처치 수 ≤ 시설 수 × 내구도 − 지킨 시설 수` |

거절된 보고는 보상도, 위험도 변화도 없고 그 임무는 끝난 것으로 기록됩니다. 응답은 `200`에 `accepted: false`입니다.

### 보상

```
승리 GC = 승리 보상 + (처음이면) 첫 승리 보너스 + 시민 보너스 × 대피 수 + 시설 보너스 × 지킨 시설 수
```

- **GC 보상은 하루 5번까지** (`dailyFpsRewardLimit`, 한국 날짜 기준). 그 뒤의 승리는 GC가 0이고 `reward_limited: true`로 알립니다. 경험치, 방어 포인트, 위험도 반영, 침공 진행도는 그대로입니다. 그럴듯한 승리 보고를 되풀이해 GC를 찍어 내는 것을 막기 위한 한도입니다.
- 원장 사유는 `fps_reward`.
- 이기면 반영될 도시(지원 나가 있으면 그 도시)의 위험도가 내려갑니다: 시내 침입이나 ZERO 이벤트를 막는 승리면 −8, 순찰이면 −4. 기여도 12.
- **져도 위험도는 오르지 않고, GC·장비·신용점수를 잃지 않습니다.** 위험도가 오르는 것은 침공이 제한 시간 안에 막히지 않았을 때 시스템이 하는 일입니다.
- 임무 안에서 시설이 멈춘 것은 그 임무의 결과일 뿐입니다. 도시의 주요 시설 피해(`city_facility_damage`)는 시내 침입이 끝내 막히지 않았을 때 서버가 정합니다.

### 막지 못하는 것

실제로 플레이하지 않고 60초 뒤에 "모두 처치, 시설 3, 시민 4"라고 보내는 조작은 이 검증으로 가려낼 수 없습니다. 지금의 방어는 하루 보상 횟수(5번)와 한 사람이 하루에 내릴 수 있는 위험도 한도(20)입니다. 전투를 서버에서 재현하는 검증은 실시간 서버가 생긴 뒤의 일입니다.

## 8. 서버

| 항목 | 내용 |
|---|---|
| 서비스 | `FpsService` (`invasions`, `missions`, `start`, `finish`) |
| API | `GET /fps/invasions`, `GET /fps/missions`, `POST /fps/missions/{code}/start`, `POST /fps/sessions/{id}/finish` ([API_SPEC](API_SPEC.md) 16장). 공통 경로 `POST /combat/sessions`(`mode: "fps"`)로도 시작할 수 있습니다 |
| 테이블 | `fps_missions`(정의), `fps_mission_results`(시작부터 결과까지 한 행: 시작 시각, 연결된 침공, 보고 내용, 판정, 보상, 반영된 도시, 처음 응답) |
| 관리자 | "FPS 임무"(로봇 구성, 시설·시민 수, 시간, 보상, 검증 임계값), "전투 모드"에서 FPS 모드를 잠시 닫을 수 있음 (닫으면 시작이 `LOCKED`), "전투 통계"에 승패와 거절 이유 |

## 9. 구현 상태와 한계

| 항목 | 상태 |
|---|---|
| 규칙 (`FpsRules`), 모의 서버 | 구현, 테스트 통과 |
| PHP 서버 | 구현, 테스트 통과 |
| Unity 장면·임무·무기·카메라·화면 | 작성. **컴파일 형식 검사만 통과했고 Unity에서 실행해 보지 못함.** 장면 파일, 길 찾기 지도, 조준 감각, 난이도 모두 실제 확인이 필요합니다. PlayMode 테스트도 쓰지 않았습니다 |
| 임무 | 하나뿐 |
| 적 | 헌트 모드의 두 종류를 그대로 씀. FPS 전용 적(보안 드론 등) 없음 |
