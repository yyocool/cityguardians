# COMBAT_ECONOMY — 전투와 경제

> 기준 v8.0 · 2026-11-13 · 상태: 세 전투 모드의 보상, 장비·방어시설 구매, 도시를 위한 지출, 일일 한도를 규칙·모의 서버·PHP 서버에 구현. 은행·주식·대출은 v6.0 문서 그대로이며 이번에 바꾸지 않음 · 수치는 초기값
>
> GC와 원장의 기본 규칙은 [ECONOMY_SYSTEM](ECONOMY_SYSTEM.md), 대출과 신용점수는 [LOAN_CREDIT_SYSTEM](LOAN_CREDIT_SYSTEM.md), 주식은 [STOCK_SYSTEM](STOCK_SYSTEM.md)에 있습니다.

## 1. 방향

"전투로 번 GC를 다음 전투의 준비와 도시에 쓴다"가 한 바퀴입니다.

```
전투 (디펜스 · 헌트 · FPS)  ──▶  GC · 경험치  ──▶  장비 · 타워 해금  ──▶  다음 전투
        │                           │
        ▼                           ▼
   도시 위험도 ↓              시설 복구 · 도시 기금  ──▶  도시 방어력 ↑ · 위험도 ↓
```

지키는 선이 넷 있습니다.

1. **현금 결제가 없습니다.** GC를 현금으로 사거나 팔 수 없고, 현금으로만 얻는 장비도 없습니다. 그래서 결제 여부가 도시 랭킹에 영향을 줄 길이 없습니다.
2. **무료 기본 장비로 모든 핵심 전투에 참여합니다** (4장).
3. **비싼 장비가 승리를 보장하지 않습니다** ([EQUIPMENT_SYSTEM](EQUIPMENT_SYSTEM.md) 1장).
4. **전투와 도시 위험도는 개인 금융을 건드리지 않습니다** (5장).

## 2. 버는 곳

지갑은 하나이고 세 모드가 함께 씁니다. 모드별 잔액이 따로 없습니다.

| 모드 | 무엇으로 | GC | 경험치 | 한도 |
|---|---|---|---|---|
| 헌트 | 오작동 로봇 처치 | 10 | 10 | 사냥 GC 하루 3,000 (경험치는 한도 없음) |
| 헌트 | 기계 곤충 처치 | 3 | 3 | 〃 |
| 디펜스 | "외곽 1구역" 승리 | 300 | 150 | 없음 (6장) |
| 디펜스 | 첫 승리 보너스 | +200 | — | 1회 |
| 디펜스 | 패배·후퇴 (참가 보상) | 막아낸 웨이브마다 20 | — | — |
| FPS | "도심 상가 구역" 승리 | 250 | 120 | GC 보상 하루 5번 |
| FPS | 첫 승리 보너스 | +150 | — | 1회 |
| FPS | 시민 대피 | 1명마다 +10 (최대 40) | — | 승리했을 때만 |
| FPS | 시설 방어 | 1곳마다 +20 (최대 60) | — | 승리했을 때만 |
| FPS | 패배·후퇴 | 0 | 0 | — |
| 공통 | 전입 축하금 | 500 | — | 1회 |

- 보상은 서버가 정의에서 읽어 계산합니다. 클라이언트가 보낸 금액은 쓰지 않습니다.
- 도시 위험도가 높다고 보상이 늘거나 줄지 않습니다. 위험한 도시의 사냥은 위험도를 더 많이 내릴 뿐입니다.
- 도시 기여도, 방어 포인트, 지원 기여도는 **GC가 아닙니다.** 쌓이기만 하고 쓸 수 없으며 랭킹과 도시의 방어력에 쓰입니다.

## 3. 쓰는 곳

### 3.1 개인 자산

| 품목 | 값 | 비고 |
|---|---|---|
| 전투 장비 6종 | 300 ~ 1,200 GC | [EQUIPMENT_SYSTEM](EQUIPMENT_SYSTEM.md) 3장. 2종은 무료 |
| 전투 장비 강화 | 기본 비용 × 지금 단계 (한 번에 120 ~ 800 GC) | 한 단계 +10% |
| 타워 해금 4종 | 500 ~ 900 GC | 폭발 500, 감속 600, EMP 800, 레이저 900 |
| 준비 중인 시설 7종 | 700 ~ 3,000 GC | 아직 살 수 없음 |

전부 사고 끝까지 강화하는 데 드는 GC는 대략 장비 구매 4,100 + 타워 해금 2,800 + 강화입니다. 사냥 한도(하루 3,000 GC)만으로도 며칠이면 닿는 크기로 잡았습니다. 값이 알맞은지는 플레이테스트로 정해야 합니다.

### 3.2 도시를 위한 지출

| 품목 | 값 | 한도 | 돌아오는 것 |
|---|---|---|---|
| 주요 시설 복구 | 한 번에 150 GC (피해 1단계) | 하루 3번 | 위험도 −2, 기여도 5 |
| 도시 공용 방어시설 기금 | 낸 만큼 (100 GC 단위) | 하루 2,000 GC | 100 GC마다 기여도 2. 한 단계가 완성되면 도시 방어력이 오르고 위험도 −3 |

- **스스로 고른 지출만 있습니다.** 도시가 위험해졌다고 주민의 GC가 자동으로 걷히지 않습니다.
- 기금은 돌려받지 않습니다. 이사해도 도시에 남습니다. 낼 때 화면이 이것을 알려 줍니다.
- 완성된 시설에는 더 낼 수 없고, 목표를 넘는 금액은 받지 않습니다 (남은 만큼만 빠져나갑니다).
- 하루 한도는 한 사람이 GC로 도시 순위를 끌어올리는 것을 막기 위한 것입니다.

### 3.3 유지 비용

장비와 방어시설의 정의에 유지 비용 칸이 있지만 **걷지 않습니다** (모두 0). 걷게 되더라도 5장의 원칙을 지켜야 합니다: 못 냈다고 빚이 생기거나, 은행 잔액에서 자동으로 빠지거나, 신용점수가 내려가면 안 됩니다. 못 내면 그 장비를 잠시 쓸 수 없게 되는 정도가 한계입니다.

## 4. 무료로 할 수 있는 것

| 전투 | 무료로 가진 것 | 확인 |
|---|---|---|
| 디펜스 | 기관총 타워 (전투 에너지로 설치·강화) | 기관총 타워만으로 이기는 판이 v6.0 자동 테스트에 있음 |
| 헌트 | 스파크 배턴 (처음부터 가진 근접 무기) | v6.0 |
| FPS | 에너지 블래스터, 회복 장치 | 장착하지 않아도 들어가 있음. 난이도는 플레이테스트 필요 |
| 도시 방어 참여 | 전투 승리만으로 위험도를 내리고 기여도를 얻음 | GC를 쓰지 않아도 됨 |
| 다른 도시 지원 | 무료 | |

테스트가 지키는 것: "새로 만든 플레이어가 GC를 한 푼도 쓰지 않고 세 모드 모두를 시작해 결과를 인정받는다"(`testFreeBasicGearLetsANewPlayerJoinEveryMode`), "모든 장비는 GC 값만 있고 현금 값이 없다"(`EightGear_AllPricedInGc_NoneNeedsRealMoney`). 관리자 화면은 무료 기본 장비·타워가 없어지는 변경을 저장하지 않습니다.

## 5. 전투와 개인 금융의 분리

도시 위험도와 개인 금융 신용도는 독립된 시스템입니다.

| 일어난 일 | 일어나지 않는 일 |
|---|---|
| 방어전·FPS 임무에서 패배 | GC 차감 없음. 장비·타워를 잃지 않음. 신용점수 변화 없음. 위험도도 오르지 않음 |
| 도시 위험도 상승, 긴급 단계 | 은행 잔액·예금·이자·대출 조건·신용점수·상점 가격에 변화 없음 |
| 침공을 막지 못함 | 주민에게 벌금이나 복구비가 청구되지 않음. 시설 복구는 원하는 주민이 함 |
| 지원 요청이 만료됨 | 누구의 자산도 줄지 않음 |
| 방어전에서 타워가 부서짐 | 그 판의 전투 에너지로 세운 것. GC 손실 없음 |

구현에서 이것을 지키는 방법:

- 위험도를 바꾸는 코드(`CityService`)가 지갑을 건드리는 곳은 **시설 복구와 도시 기금 두 곳뿐**이고, 둘 다 플레이어가 요청했을 때만 실행됩니다. 침공 판정(`tick`)은 지갑 테이블을 읽지도 쓰지도 않습니다.
- 도시·전투 테이블은 은행·대출·신용 데이터를 참조하지 않습니다.
- 테스트: `testRisingRiskAndLostBattlesNeverTouchAPlayersGc`, `testLosingADefenseBattleNeverRaisesRiskOrTakesGc`, `testCityTablesDoNotReferToBankLoanOrCreditData` (서버), `Risk_NeverTouchesTheWalletOrTheBank` (클라이언트 규칙).

### 대출과 신용점수 (v6.0 원칙 그대로)

이번 작업에서 대출·신용 기능을 만들거나 바꾸지 않았습니다. [LOAN_CREDIT_SYSTEM](LOAN_CREDIT_SYSTEM.md)의 원칙이 그대로 적용되고, 전투 쪽에서 덧붙이는 것은 다음뿐입니다.

| 지시서의 요구 | 상태 |
|---|---|
| 대출은 필수 기능이 아님 | 대출이 있어야 살 수 있는 전투 장비가 없습니다. 가장 비싼 장비(1,200 GC)도 사냥 한도의 절반이 안 됩니다 |
| 무한 대출 금지, 과도한 이자 방지, 상환 일정 표시 | 설계에 있음 (동시에 1건, 이자 총액 상한, 복리 없음). 구현은 Phase 4 |
| 현실 결제를 통한 부채 상환 금지 | 결제 기능이 없음 |
| 신용점수는 게임 내부에서만 사용 | 설계에 있음. 전투·위험도·랭킹 어디에도 신용점수를 쓰지 않습니다 |
| 전투 실패로 대출·신용이 악화되지 않음 | 위 표. 신용점수는 금융 행동만 반영한다는 v6.0 규칙과도 맞습니다 |

"대출로 장비를 사서 전투에 진다 → 갚지 못한다"는 길은 남습니다. 이것은 전투가 신용을 깎는 것이 아니라 대출을 갚지 못한 결과이고, 대출 한도를 작게 두고 연체가 길어지면 탕감하는 v6.0의 보호 규칙이 여기에 적용됩니다.

## 6. 한도와 악용

| 대상 | 한도 | 기준 |
|---|---|---|
| 사냥 GC | 하루 3,000 GC | 한국 날짜. 경험치는 계속 |
| 사냥 처치 인정 | 구역별 분당 한도 (24 ~ 50) | 서버가 잰 시간 |
| FPS GC 보상 | 하루 5번 | 임무는 계속 할 수 있고 경험치·위험도 반영은 그대로 |
| 한 사람이 내리는 위험도 | 하루 20 | 모든 활동 합계 |
| 시설 복구 | 하루 3번 | |
| 도시 기금 | 하루 2,000 GC | |
| GC가 바뀌는 요청 | `Idempotency-Key` 필수 | 같은 요청이 두 번 처리되지 않음 |
| 계정 만들기·토큰 발급 | IP별 횟수 제한 (게스트 계정 시간당 20, 토큰 10분에 30) | 전투·구매 요청에는 **횟수 제한이 아직 없습니다** |

**디펜스 보상에는 일일 한도가 없습니다.** v6.0에서 "미정"으로 남긴 것([TOWER_DEFENSE](TOWER_DEFENSE.md) 10장)이 그대로입니다. 전투를 하지 않고 승리 보고만 보내는 조작으로 50초마다 300 GC까지 가능하므로, **실제 서버를 열기 전에 FPS와 같은 방식의 일일 횟수 한도를 넣어야 합니다.** [ECONOMY_SYSTEM](ECONOMY_SYSTEM.md) 2장의 초안은 하루 10회입니다.

## 7. 원장

GC의 모든 증감은 `ledger_entries`에 한 줄씩 남습니다 (금액, 뒤의 잔액, 사유, 참조).

| 사유 | 뜻 | 방향 |
|---|---|---|
| `hunt_reward` | 사냥 보상 | + |
| `battle_reward` | 방어전 보상 | + |
| `fps_reward` | FPS 임무 보상 | + |
| `residency_bonus` | 전입 축하금 | + |
| `tower_unlock` | 타워 영구 해금 | − |
| `gear_purchase` | 전투 장비 구매 | − |
| `gear_upgrade` | 전투 장비 강화 | − |
| `city_repair` | 주요 시설 복구 | − |
| `city_fund` | 도시 공용 방어시설 기금 | − |
| `admin_adjust` | 관리자 조정 | ± (자리만 있음. 관리자 화면에 지급·회수 기능은 아직 없음) |

`GET /combat/rewards`가 모드별 보상 합계와 최근 내역, 오늘의 한도 사용량을 원장에서 읽어 보여 줍니다. 잔액이 음수가 되는 차감은 거절됩니다.

## 8. 관리자가 조정하는 것

| 화면 | 값 |
|---|---|
| 적 유닛 | 처치 보상 GC·경험치, 사냥 구역의 분당 한도 |
| 디펜스 구역 | 승리·첫 승리·패배 보상, 경험치, 방어 포인트 |
| FPS 임무 | 승리·첫 승리·시민·시설 보상, 경험치, 방어 포인트 |
| 장비 가격 및 성능 | 가격, 강화 비용, 해금 레벨, 수치 |
| 타워 및 방어시설 | 해금 GC, 도시 기금 목표 |
| 공통 한도 | 사냥 GC 하루 한도, 전입 축하금, FPS 보상 하루 횟수 |
| 위험도 계산 정책 | 하루 복구 횟수, 하루 기금 한도, 기여도 |

모든 값에 범위 검증이 있고, 변경에는 사유가 필요하며, 변경 전후가 이력에 남습니다 ([ADMIN_SYSTEM](ADMIN_SYSTEM.md)).

## 9. 구현 상태와 한계

| 항목 | 상태 |
|---|---|
| 세 모드의 보상, 장비·타워 구매, 복구·기금, 일일 한도 | 구현, 테스트 통과 (규칙·모의 서버·PHP 서버) |
| 디펜스 보상 일일 한도 | **없음** (6장) |
| 유지 비용 | 걷지 않음 |
| 아이템 드롭·가방·상점·은행의 서버 구현 | 없음 (v6.0의 것은 클라이언트 모의 서버에만 있음) |
| 주식·대출·신용점수 | 설계만 (v6.0 그대로) |
| 수치의 균형 | 플레이테스트 전의 초기값 |
