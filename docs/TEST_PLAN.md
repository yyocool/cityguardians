# TEST_PLAN — 테스트 계획

> 기준 v6.0 · 2026-11-13 · 상태: 클라이언트 테스트 있음 (EditMode 198개, PlayMode 15개, 모두 모의 서버 기준. 3.1, 3.2장). 서버 테스트, 빌드된 실행 파일에서의 점검, 사람이 해 보는 테스트는 아직 없음

## 1. 원칙

- 돈과 인증에 관련된 코드는 자동 테스트 없이 배포하지 않습니다.
- 규칙(계산식, 상태 기계)은 화면 없이 테스트할 수 있게 분리해 작성합니다.
- "동작한다"는 직접 실행해 확인한 것만 말합니다.
- 재미와 쉬움은 자동 테스트로 알 수 없으므로 사람이 해 보는 테스트를 단계마다 합니다.

## 2. 테스트 종류

| 종류 | 대상 | 도구 | 실행 시점 |
|---|---|---|---|
| 클라이언트 단위 | `Domain`의 피해 계산, 경험치, 상태 기계, 웨이브 진행 | Unity Test Framework (EditMode) | 변경 때마다 |
| 클라이언트 장면 | 이동, 상호작용, 전투, 장면 전환 | Unity Test Framework (PlayMode) | 단계 끝 |
| 서버 단위 | 지갑, 원장, 이자, 보상 검증, 닉네임 규칙, 신용점수 | PHPUnit | 변경 때마다 |
| API 통합 | 실제 DB(테스트용)에 요청을 보내 흐름 확인 | PHPUnit + 테스트 DB | 변경 때마다 |
| 금융 동시성 | 같은 계정에 동시 요청 | 전용 스크립트 | 금융 코드 변경 때 |
| 전체 흐름 | 3장의 17단계 | 사람 + 점검 스크립트 | 단계 끝, 배포 전 |
| 사용성 | 처음 하는 사람이 설명 없이 진행하는가 | 관찰 | Phase 1 끝부터 |
| 성능 | 프레임, 로딩, API 응답 시간 | Unity Profiler, 부하 스크립트 | Phase 7 |
| 보안 | 9장 | 점검표, 스크립트 | 배포 전 |

테스트용 DB는 개발·운영과 별개이며 테스트마다 초기화합니다. 운영 DB에 대고 자동 테스트를 돌리지 않습니다.

## 3. 1차 플레이 가능 버전 점검표

Windows 빌드에서, 운영(또는 스테이징) 서버에 연결한 상태로 처음부터 끝까지 한 번에 진행합니다.

| 5 | NPC와 대화 | E로 대화 시작, 닫으면 조작 복귀 | — |

추가 확인:

- 17단계를 마친 뒤 지갑 잔액 = 원장의 마지막 잔액, 원장 증감의 합 = 지갑 + 통장.
- 다음 날 이자 예약 작업 뒤 통장에 이자가 들어오고 원장에 `bank_interest`가 남는다.
- 12단계에서 "나중에"를 고른 경우에도 15단계를 제외한 나머지가 진행된다 (은행 이용 조건에 따라).

### 3.1 지금 자동으로 확인되는 범위 (2026-11-13)

17단계가 모두 클라이언트에 구현되어 있고, 단계마다 자동 테스트가 있습니다. 다만 **위 점검표의 조건("Windows 빌드에서, 서버에 연결한 상태로, 처음부터 끝까지 한 번에")은 아직 한 번도 충족하지 못했습니다.** 아래 테스트는 Unity 에디터의 PlayMode에서, 서버 대신 `LocalMockBackend`로, 흐름별로 나뉘어 돕니다.

| 단계 | 자동 테스트 (PlayMode) | 자동 테스트가 보지 못하는 것 |
|---|---|---|
| 1 | — | 실행 파일로 시작하는 것 (빌드가 만들어지는 것만 확인) |
| 2~7 | `FirstPlayTests` | |
| 8~9 | `ShopTests` | |
| 10~11 | `DefenseTests` | |
| 12~14 | `MapTests` | |
| 15 | `BankTests` (은행원과 방 컴퓨터, 이틀 뒤 이자) | 실제로 하룻밤이 지나는 것 (서버 시계를 앞으로 감음) |
| 16~17 | 위 테스트들의 "껐다 켜기" | 실행 파일을 실제로 끄고 다시 켜는 것 (게임 안에서 접속을 끊고 다시 접속) |
| 서버에서 확인할 것 | 모의 서버의 원장과 잔액 (`FindLedgerInconsistency`: 지갑과 통장) | 실제 DB, 실제 트랜잭션과 잠금, 동시 요청 |

테스트는 사람처럼 걸어가서 E·숫자 키·마우스를 쓰지만, 사람보다 빠르고 실수하지 않습니다. 화면은 캡처(`client/Logs/shots`)를 눈으로 확인합니다.

테스트 준비를 위해 건너뛰는 곳: 상점·은행 테스트는 돈을 모의 서버에 사냥 보고를 직접 보내 마련하고, 방어전·지도·상점·은행 테스트는 튜토리얼을 마친 상태에서 시작합니다. 17단계를 한 사람이 한 번에 이어서 하는 테스트는 없습니다.

### 3.2 17단계 밖의 것: Phase 3의 나머지 (2026-11-13)

| 기능 | EditMode (규칙과 모의 서버) | PlayMode (걸어가서 키로) | 자동 테스트가 보지 못하는 것 |
|---|---|---|---|
| 방어구, 옷, 되팔기 | `WearSellTests` 16개: 머리·몸 칸, 방어 비율과 한도, 피해 계산, 되파는 값, 팔 수 없는 것, 입은 채로 팔기, 재전송, 원장 | `DecorTests.Wear_…`: 미소 상점에서 헬멧·조끼 → 맞아 보기(20 → 14) → 가방에서 벗고 쓰기 → 알록달록 가게에서 머리띠 사서 쓰고 되팔기 → 방 옷장 → 껐다 켜기 | 방어 30%가 싸움을 얼마나 쉽게 하는지 (사람이 해 봐야 함) |
| 가구, 방 꾸미기 | `RoomTests` 14개: 격자, 기본 가구, 놓기 검사의 이유마다, 회전, 길 막힘, 갇힘, 넣어 둔 것만 팔기, 20개 한도, 재시작 | `DecorTests.Decorate_…`: 가구 셋 구매 → F → 놓기(초록) → 문 앞은 거절(빨강) → 돌리기 → 옮기기 → 그만두기 → 넣어 두기 → 가구를 뚫고 걷지 못함 → 넣어 둔 것만 팔기 → 껐다 켜기 | 아이가 설명 없이 F·E·R을 쓰는지. 자동 조작은 정해 둔 자리에 정확히 섬 |
| 입은 모습, 가구 모습 | — | `DecorTests.Lookbook_…`: 위에서 지나가지 않는 옷 셋과 가구 둘을 입고 놓아 캡처 | 모습이 보기 좋은지는 캡처를 눈으로 봄 (`client/Logs/shots/130~153`) |
| 정기예금 | `TermDepositTests` 17개: 가입 조건, 이자 계산, 만기일(한국 날짜), 만기 정산의 순서, 중도 해지, 재전송, 원장, 재시작 | `BankTests.TermDeposit_…`: 은다온에게 7일 상품 1,000 GC 가입 → 30일 상품에 500 GC를 넣었다가 바로 찾기(원금만 돌아옴) → 7일 뒤 방에서 만기 알림(원금 + 이자 100 GC) → 방 컴퓨터에서 거래 내역 → 껐다 켜기 | 실제로 7일이 지나는 것 (서버 시계를 앞으로 감음) |

PlayMode 전체(15개)는 한 번에 약 6분, EditMode 전체(198개)는 약 30초 걸립니다.

한 번 실패한 뒤 고친 테스트 (2026-11-13): `ShopTests`의 "겨눌 적이 없으면 조준 표시가 없다"가 전체 실행에서 한 번 실패했습니다. 조준 표시는 프레임의 끝(LateUpdate)에 갱신되는데, 테스트가 전투 구역에서 광장으로 순간 이동한 바로 그 프레임에 표시를 확인하고 있었습니다. 게임의 동작은 바꾸지 않고, 테스트가 한 프레임 뒤에 확인하게 했습니다. 순간 이동은 테스트만 하는 일입니다.

## 4. 금융 거래 검증

### 4.1 정확성

| 항목 | 확인 |
|---|---|
| 구매 | 잔액 차감과 아이템 지급이 함께 일어나거나 함께 취소된다 |
| 잔액 부족 | 거절되고 아무것도 바뀌지 않는다 |
| 입출금 | 지갑과 통장의 합이 변하지 않는다 |
| 이자 | 최저 잔액 기준, 한도 적용, 1 GC 미만 버림 |
| 이자 중복 | 예약 작업을 두 번 돌려도 하루치만 지급된다 |
| 이자 누락 | 작업이 며칠 빠진 뒤 돌려도 빠진 날짜만큼 정확히 지급된다 |
| 음수 | 어떤 요청으로도 잔액이 음수가 되지 않는다 |
| 큰 수 | 한도 근처의 금액에서 넘침이 없다 |

### 4.2 동시성과 재전송

| 항목 | 확인 |
|---|---|
| 동시 구매 | 잔액 200으로 200짜리 구매를 동시에 10건 → 1건만 성공 |
| 동시 입출금 | 동시에 입금과 출금을 섞어 보내도 합계가 맞는다 |
| 같은 키 재전송 | 같은 중복 방지 키 → 한 번만 처리, 같은 응답 |
| 같은 키 다른 내용 | 거절 |
| 응답 유실 | 서버는 처리했지만 클라이언트가 응답을 못 받은 경우, 재전송으로 같은 결과 |
| 교착 | 반대 순서의 동시 요청에서 멈추지 않는다 |

### 4.3 정합성

- 매 테스트 뒤 "지갑 잔액 = 마지막 원장 잔액"과 "계정별 원장 합 = 잔액"을 검사한다.
- 무작위 거래를 대량으로 실행한 뒤에도 성립하는지 확인한다.

### 4.4 Phase 4 추가

| 항목 | 확인 |
|---|---|
| 주식 손익 | 여러 번 나눠 사고판 뒤 취득원가, 실현손익, 평가손익이 손 계산과 일치 |
| 가격 차이 | 본 가격과 현재가가 다르면 체결되지 않는다 |

| 대출 한도 | 신용점수 구간별 한도, 동시 1건 |

## 5. 데이터 저장과 복구

| 항목 | 확인 |
|---|---|

| 제한형 | 목록에 없는 문장은 어떤 방법으로도 전달되지 않는다 (조작된 요청 포함) |
| 욕설 필터 | 금칙어, 띄어쓰기·기호 변형, 초성 변형이 막힌다. 정상 단어가 잘못 막히는 경우를 기록 |
| 개인정보 | 전화번호, 이메일, 주소, 메신저 아이디 형태가 막힌다 |
| 속도 제한 | 연속 전송과 반복이 제한된다 |
| 차단 | 차단한 상대의 메시지·요청·초대가 보이지 않는다. 재접속 후에도 유지 |
| 신고 | 증거(대상 메시지와 앞뒤 대화)가 저장되고 관리자에 보인다 |
| 제재 | 채팅 정지 중 전송 불가. 기간이 끝나면 풀린다 |
| 권한 | 이방인은 지역 채팅을 읽고 쓸 수 없다 |
| 입장권 | 한 번 쓴 입장권, 만료된 입장권으로 접속할 수 없다 |
| 관리자 화면 | 채팅에 넣은 스크립트가 관리자 화면에서 실행되지 않는다 |
| 삭제 | 보관 기간이 지난 메시지가 지워진다 |
| NPC | NPC가 채팅 채널에 플레이어처럼 나타나지 않는다 |

## 8. 성능

목표 수치는 [PLATFORM_STRATEGY](PLATFORM_STRATEGY.md) 2장에 있습니다.

| 항목 | 측정 |
|---|---|
| 프레임 | 방, 광장(NPC 최대), 전투 구역, 방어전 마지막 웨이브(적 60기) |
| 로딩 | 실행 → 조작 가능, 방 ↔ 도시, 도시 → 방어전 |
| 메모리 | 1시간 연속 플레이에서 계속 늘지 않는가 |
| API 응답 | `/me`, 구매, 사냥 보고, 입금의 응답 시간 |
| 부하 | 동시 접속을 가정한 사냥 보고와 구매 요청 |
| 예약 작업 | 계좌 수가 많을 때 이자 지급에 걸리는 시간 |

기준 장비를 정해 같은 조건으로 측정하고 결과를 기록합니다.

## 9. 보안

| 항목 | 확인 |
|---|---|
| 인증 | 토큰 없이, 만료된 토큰으로, 다른 사람 토큰으로 접근 불가 |
| 본인 데이터 | 다른 플레이어의 ID를 넣어도 남의 데이터를 읽거나 바꿀 수 없다 |
| SQL 삽입 | 모든 입력에 대해 시도 |
| 스크립트 삽입 | 닉네임, 채팅, 공지에 스크립트 → 홈페이지와 관리자에서 실행되지 않음 |
| 요청 제한 | 게스트 대량 생성, 반복 요청이 제한된다 |
| 관리자 | 로그인 없이 접근 불가, 2단계 인증, 역할별 권한, CSRF |
| 파일 노출 | `.env`, 소스, 백업, 로그가 웹에서 열리지 않는다 |
| 오류 응답 | 내부 정보가 드러나지 않는다 |
| 보안 헤더 | 기존 헤더가 유지된다 |
| 비밀 값 | 저장소와 게임 빌드에 비밀 값이 없다 |
| 기기 저장 | 게스트 비밀키가 평문으로 저장되지 않는다 |

## 10. 배포 점검

배포 뒤 바로 실행하는 점검입니다 ([SERVER_DEPLOYMENT](SERVER_DEPLOYMENT.md) 6.3).

1. `/api/v1/health` 정상
2. 홈페이지 주요 경로 응답과 보안 헤더
3. 점검용 계정으로 게스트 생성 → 사냥 보고 → 구매 → 입금 → `/me` 확인
4. 같은 서버의 다른 사이트가 정상인지 확인
5. 예약 작업 등록 상태
6. 오류 로그

점검용 계정은 표시를 붙여 통계와 랭킹에서 제외합니다.

## 11. 사용성 — 초등학생도 쉽게

| 항목 | 방법 |
|---|---|
| 첫 플레이 관찰 | 게임을 처음 보는 사람에게 설명 없이 시키고 지켜본다. 막히는 지점과 시간을 기록 |
| 통과 기준 | 도움 없이 5분 안에 첫 로봇을 쓰러뜨리고, 15분 안에 첫 무기를 산다 |
| 글 읽기 | 글을 읽지 않고도 다음 할 일을 아는가 |
| 금융 화면 | 은행 화면에서 설명 없이 입금할 수 있는가 |
| 지표 | 관리자 대시보드의 첫 플레이 단계별 이탈 |

어린이가 참여하는 테스트는 보호자의 동의를 받고 진행합니다.

## 12. 결함 등급

| 등급 | 뜻 | 처리 |
|---|---|---|
| 치명 | 돈이 잘못 계산됨, 데이터 손실, 보안 문제, 실행 불가 | 즉시 수정. 배포 중단 |
| 높음 | 17단계 중 하나가 진행 불가 | 배포 전 수정 |

| 낮음 | 표시, 문구 | 모아서 수정 |

금융과 인증에서 발견된 결함은 재현 테스트를 먼저 추가하고 고칩니다.
