# CHARACTER_SYSTEM — 캐릭터 시스템

> 기준 v6.0 · 2026-11-13 · 상태: 설계 (미구현) · 수치는 초기값

## 1. 방향

친근한 블록형 3D 캐릭터입니다. 블록 캐릭터라는 장르적 형태에서 착안하되, 특정 게임의 비율·얼굴·부품 구성을 따라 하지 않고 고유한 디자인으로 만듭니다.

### 고유 디자인 요소

| 요소 | 내용 |
|---|---|
| 비율 | 약 2.5등신. 머리가 크고 몸통이 짧아 멀리서도 표정이 보인다 |
| 형태 | 모서리를 둥글린 블록. 몸통은 아래가 살짝 넓은 사다리꼴 |
| 손 | 손가락 없는 둥근 벙어리장갑 형태. 무기를 쥘 때 손 앞에 붙는다 |
| 얼굴 | 머리 앞면의 평면 표정 (눈·입 조합을 바꿔 감정 표현) |
| 가디언 표식 | 왼팔의 완장. 전입한 도시의 색과 문양이 들어간다. 이방인은 무늬 없는 회색 |
| 색 | 채도 높은 단색 면과 굵은 윤곽 대비. 재질 표현은 최소화 |

제작 전 다른 블록형 게임 캐릭터와 나란히 놓고 윤곽이 구별되는지 검토합니다.

## 2. 구조

| 부위 | 개수 | 비고 |
|---|---|---|
| 머리 | 1 | 얼굴 텍스처, 헤어·모자 부착점 |
| 몸통 | 1 | 상의, 등 부착점 (가방 등) |
| 팔 | 2 | 어깨 관절 1개씩. 완장은 왼팔 |
| 손 | 2 | 무기 부착점은 오른손 |
| 다리 | 2 | 골반 관절 1개씩 |

- 각 부위는 독립된 메시이고 관절은 단순 회전입니다. 부위를 바꿔 끼우는 방식으로 꾸미기를 구현합니다.
- 1차에서는 엔진의 기본 도형과 코드로 조립한 메시로 만들어 외부 에셋 없이 시작합니다. 이후 전용 모델로 교체할 수 있도록 `CharacterVisual` 컴포넌트가 부위 프리팹을 주입받는 구조로 둡니다.
- NPC도 같은 뼈대를 씁니다. 적 로봇은 별도 구조입니다.

## 3. 기본 동작

| 동작 | 입력 | 구현 | 1차 |
|---|---|---|---|
| 걷기 | WASD | 팔다리 교차 흔들기 | 포함 |
| 달리기 | Shift + WASD | 걷기보다 큰 폭, 몸 기울임 | 포함 |
| 점프 | Space | 웅크림 → 도약 → 착지 눌림 | 포함 |
| 공격 (근접) | 좌클릭 | 오른팔 휘두르기 | 포함 |
| 공격 (원거리) | 좌클릭 | 오른팔 조준, 반동 | 포함 |
| 피격 | — | 짧게 밀림, 깜빡임 | 포함 |
| 아이템 사용 | 숫자 키 / 인벤토리 | 손을 입으로, 회복 효과 | 포함 |
| NPC 대화 | E | 상대를 향해 돌아섬 | 포함 |
| 감정 표현 | 추후 지정 | 인사, 기쁨, 박수 등 | Phase 5 |

1차의 애니메이션은 관절 회전을 코드로 움직이는 절차적 방식으로 만듭니다. 부위 수가 적어 충분하고, 모델을 교체해도 다시 만들 필요가 없습니다. 이후 Animator 기반 클립으로 바꿀 수 있게 `ICharacterAnimator` 인터페이스 뒤에 둡니다.

## 4. 이동 수치 (초기값)

| 항목 | 값 |
|---|---|
| 걷기 속도 | 4.0 m/s |
| 달리기 속도 | 6.5 m/s |
| 점프 높이 | 1.2 m |
| 회전 | 이동 방향으로 부드럽게 (초당 720도) |
| 공중 조작 | 지상의 60% |
| 캐릭터 키 | 1.4 m |
| 충돌체 | 캡슐, 반지름 0.3 m |

이동은 `CharacterController` 기반으로 직접 제어합니다. 물리 엔진에 맡기지 않아 조작이 즉각적이고 모바일에서도 가볍습니다.

## 5. 카메라

- 3인칭 어깨 뒤 시점. 마우스로 좌우·상하 회전, 휠로 거리 조절.
- 벽에 가리면 카메라가 앞으로 당겨집니다. 1.3 m 안으로 당겨지면 캐릭터를 그리지 않아 머리가 화면을 가리지 않게 합니다.
- 방에서는 벽을 안쪽에서만 보이게 만들어 카메라가 방 밖에서 들여다봅니다 ("인형의 집" 방식). 좁은 방에서도 카메라가 벽에 끼지 않습니다.
- 대화·상점·은행 중에는 고정 구도로 전환하고 마우스 커서를 풀어 줍니다. (Phase 1에서는 대화 중 조작만 멈춥니다. 고정 구도는 상점·은행과 함께 구현합니다.)
- 자체 `OrbitCamera` 로 구현합니다. (처음 계획은 Cinemachine. [DEVELOPMENT_PLAN](DEVELOPMENT_PLAN.md) 2장)

## 6. 상태

```
대기 ↔ 이동 ↔ 달리기
  ↓        ↓
 점프 → 낙하 → 착지
공격 (이동 가능, 공격 중 회전 제한)
피격 (0.2초 경직)
상호작용 (이동 잠금)
쓰러짐 → 부활 (안전 지점)
```

상태 기계는 `CG.Domain`의 순수 C#으로 작성해 단위 테스트합니다.

## 7. 능력치

| 능력치 | 초기값 | 성장 |
|---|---|---|
| 레벨 | 1 | 경험치 |
| 최대 체력 | 100 | 레벨당 +10 |
| 공격력 | 무기에서 결정 | 장비 |
| 방어력 | 0 | 방어구 |
| 이동 속도 | 고정 | (추후 장비 효과) |

필요 경험치: `50 × 레벨^1.5` (소수점 반올림). 계산식과 계수는 서버 설정에 두고 관리자에서 바꿀 수 있습니다. 경험치와 레벨은 서버가 계산합니다.

## 8. 커스터마이징

| 항목 | 방식 | 시점 |
|---|---|---|
| 얼굴 | 눈·입 조합 선택 | 꾸미기 화면 (Phase 3 이후) |
| 헤어 | 머리 부착 부품 + 색 | 〃 |
| 피부색 | 색상표에서 선택 | 〃 |
| 의상 | 머리·몸에 부품을 덧붙이거나 색을 바꿈 | 상점 구매 (구현됨) |
| 액세서리 | 머리·얼굴·등 부착 | 상점 구매 (미룸) |
| 무기 | 오른손 부착 | 1차 |
| 장비 | 방어구 등 능력치가 있는 부품 | Phase 3 (구현됨) |

입은 모습 (2026-11-13 구현): 아이템 정의의 `look` 코드가 모습을 정합니다. `BlockCharacter.Wear(머리 look, 몸 look)`이 블록을 덧붙이고, `PlayerWear`가 서버의 장착 상태가 바뀔 때마다 모습과 방어를 맞춥니다.

| look | 아이템 | 모습 |
|---|---|---|
| `guard_helmet` | 가디언 헬멧 | 남색 헬멧, 빛나는 챙, 노란 볏 |
| `wave_cap` | 파도 모자 | 바다색 모자와 챙 |
| `bunny_band` | 토끼 머리띠 | 머리띠와 쫑긋한 귀 두 개 |
| `guard_vest` | 가디언 조끼 | 남색 조끼, 어깨 패드, 빛나는 가슴 표시 |
| `sunny_hoodie` | 해님 후드티 | 몸과 팔이 노란색 |
| `star_tee` | 별 티셔츠 | 보라색 반소매, 가슴에 별 |

머리와 몸에 하나씩만 입습니다. 헤어는 머리에 쓴 것 아래에 그대로 있습니다 (헤어를 숨기지 않습니다).

### 자동 생성

처음 접속하면 서버가 얼굴·헤어·피부색·옷 색을 미리 정해 둔 조합 가운데서 무작위로 골라 캐릭터를 만듭니다. 플레이어에게 묻지 않습니다. 전입신고의 "캐릭터 확인" 단계에서 처음으로 모습을 바꿀 기회를 줍니다 (1차에서는 "다른 모습 보기" 버튼 정도).

### 데이터

외형은 부품 코드의 묶음으로 저장합니다.

```json
{
  "face": "face_03",
  "hair": "hair_02",
  "hair_color": "#3B2A20",
  "skin": "skin_02",
  "top": "top_basic_blue",
  "bottom": "bottom_basic_gray",
  "accessories": []
}
```

장착 칸: 근접 무기, 원거리 무기, 머리, 몸, 액세서리 2칸. 무기 두 칸은 1·2 키 또는 마우스 휠로 전환합니다. 장착 상태는 서버에 저장합니다 ([ITEM_SYSTEM](ITEM_SYSTEM.md) 5장).

## 9. 이름표

| 대상 | 표시 |
|---|---|
| 내 캐릭터 | 없음 |
| 다른 플레이어 | 닉네임, 도시 문양 |
| 이방인 플레이어 | "이방인" + 번호 |
| NPC | 이름 + 역할 아이콘 (플레이어와 다른 색과 모양) |

닉네임은 전입신고에서 정합니다. 그 전에는 서버가 붙인 "이방인-1234" 형식의 임시 이름을 씁니다.
