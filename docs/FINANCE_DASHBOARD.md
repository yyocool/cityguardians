# FINANCE_DASHBOARD — 카드 1: 내 계좌 및 투자현황

> 기준 v10.0 · 2026-11-14 · 상태: 서버 요약의 `finance`, 모의 서버, 카드(`UI/Dashboard/FinanceDashboardCard.cs`), 상세 보기 구현. **서버에는 은행·가상 주식·대출이 아직 없어 그 항목은 "준비 중"으로 보임** (3장). Unity 화면은 컴파일 검사만 함

[LIVE_DASHBOARD](LIVE_DASHBOARD.md)의 첫 번째 카드입니다.

## 1. 방향

- **보여 주기만 합니다.** 이 카드와 상세 보기에서는 돈이 움직이지 않습니다. 맡기기·찾기·사기·갚기는 저마다의 자리(은행, 상점)에서 서버의 검증을 거쳐 일어나고, 카드는 그 결과를 서버에서 다시 받아 보여 줍니다.
- **클라이언트가 금융 결과를 정하지 않습니다.** 카드의 값은 모두 서버의 요약에서 옵니다. 거래가 끝난 것을 알아채면 카드의 숫자를 스스로 고치지 않고 **요약을 다시 받습니다**. 순자산도 클라이언트가 더해서 만들지 않고 서버가 준 값을 씁니다.
- **본인의 것만.** 요약은 접속 토큰의 주인에 대한 것이고 다른 사람을 고르는 길이 없습니다 (6장).
- GC 는 게임 안의 돈입니다. 현실의 돈으로 바꿀 수 없고, 게임 안의 대출·신용은 현실의 신용과 관계가 없습니다. 상세 보기의 대출 화면에도 그렇게 적습니다.

## 2. 카드

펼친 카드 (높이 240):

| 줄 | 값 | 출처 (`finance`의 항목) |
|---|---|---|
| 보유 GC | `12,340 GC` | `gc` — 지갑 잔액 |
| 은행 예금 | `8,000 GC` | `bankGc + termGc` (통장 + 정기예금). `bankAvailable`이 거짓이면 `— 준비 중` |
| 가상 주식 평가액 | `— 준비 중` 또는 `개발용 샘플 32,340 GC` | `stockValueGc`. `stocksAvailable`이 거짓이면 준비 중 / 샘플 |
| 평가손익 | `▲ +1,200 GC` (초록) / `▼ −300 GC` (붉음) | `stockProfitGc` |
| 대출 잔액 | `— 준비 중` 또는 샘플 | `loanBalanceGc`. `loansAvailable`이 거짓이면 준비 중 / 샘플 |
| **순자산** | `20,340 GC` (굵게) | `netWorthGc`. 빠진 항목이 있으면 이름이 **"순자산 (있는 항목만)"** (`netWorthPartial`) |

접힌 카드: `순자산 20,340 GC`. 한 줄로 줄어든 화면에서는 `GC 2만`.

값을 아직 받지 못했으면 줄 대신 "… 불러오는 중" 또는 연결 끊김 안내가 보입니다. 0 을 보여 주지 않습니다.

## 3. 서버에 아직 없는 항목과 개발용 샘플

지시서는 "기존 금융 시스템 API를 재사용"하라고 합니다. 지금 있는 것은 이렇습니다.

| 항목 | 게임 서버 (`server/`, PHP) | 게임 (모의 서버) |
|---|---|---|
| 보유 GC (지갑, 원장) | **있음** (v8.0) | 있음 |
| 은행 통장, 정기예금 | **없음** — v6.0의 은행은 서버에 옮겨지지 않았음 | 있음 (Phase 3) |
| 가상 주식 | 없음 (Phase 4 계획, [STOCK_SYSTEM](STOCK_SYSTEM.md)) | 없음 |
| 대출 | 없음 (Phase 4 계획, [LOAN_CREDIT_SYSTEM](LOAN_CREDIT_SYSTEM.md)) | 없음 |

그래서:

- **서버는 없는 것을 0 이라고 하지 않고 "없다"고 답합니다** (`bankAvailable`, `stocksAvailable`, `loansAvailable`이 `false`). 금액 항목은 0 으로 오지만 클라이언트는 `available`이 거짓이면 그 숫자를 쓰지 않습니다.
- 순자산은 **있는 항목만** 셉니다. 실제 서버에서는 보유 GC 와 같고, 모의 서버에서는 보유 GC + 통장 + 정기예금입니다. 어느 쪽이든 `netWorthPartial: true`이고 카드에 "(있는 항목만)"이라고 적힙니다.
- 은행·주식·대출이 서버에 생기면 `Dashboard::finance()`가 그 서비스의 값을 읽고 `available`을 참으로 바꾸면 됩니다. 클라이언트는 고칠 것이 없습니다.

### 개발용 샘플

지시서 14장: "실제 데이터가 아직 준비되지 않은 기능은 개발용 샘플 데이터로 구분하여 표시하세요."

| | |
|---|---|
| 어디에 | 가상 주식 평가액, 평가손익, 대출 잔액의 세 줄과 상세 보기의 주식·대출 화면 |
| 무엇 | `DashboardSamples`: 지어낸 종목 3개("가디언 전자", "새벽 에너지", "배턴 로보틱스")와 거래 3건, 상환 일정 3회. **누구에게나 같은 고정된 값** |
| 표시 | 값 앞에 노란 꼬리표 **"개발용 샘플"**, 글자는 흐리게. 상세 화면 첫 줄: "※ 개발용 샘플이에요. 실제 데이터가 아니고, 내 자산에 더해지지 않아요." 날짜도 "샘플 3일 전"처럼 적음 |
| 순자산 | **더하지 않음.** 샘플이 켜져 있어도 순자산은 서버가 준 값 그대로 (테스트가 확인) |
| 출처 | 클라이언트 안에 있음. **서버는 샘플 숫자를 만들지도 보내지도 않음** |
| 켜고 끄기 | 관리자 설정 "준비되지 않은 금융 항목" ([LIVE_DASHBOARD](LIVE_DASHBOARD.md) 7장). **서버의 기본값은 끔** → "준비 중"으로 보임. 개발용 모의 서버는 켬 |

기본을 끔으로 둔 까닭: 실제 이용자에게 지어낸 주식 잔액이 보이면, 꼬리표가 있어도 자기 자산으로 오해할 수 있습니다. 샘플은 화면을 만들고 살펴보는 동안에만 켭니다.

은행 예금에는 샘플이 없습니다. 서버에 은행이 없으면 "준비 중"입니다.

## 4. 상세 보기

`Shift` + `F7`, 또는 왼쪽 Alt 를 누른 채 카드의 몸통을 누릅니다. 걸어 다닐 때만 열립니다.

| 메뉴 | 내용 | 값의 출처 |
|---|---|---|
| 은행 계좌 | 통장 잔액, 정기예금, 이자 안내, 지금까지 받은 이자. "맡기고 찾는 일은 은행에서 해요" | 기존 `GET /bank` (은행 화면과 같은 글 `BankActions`) |
| 예금 거래 내역 | 통장에 들어오고 나간 돈, 최근 것부터 | 기존 `GET /bank`의 내역 |
| 주식 보유 종목 | 종목별 수량, 평가액, 평가손익 | 준비 중 / 개발용 샘플 |
| 주식 거래 내역 | 사고판 기록 | 준비 중 / 개발용 샘플 |
| 대출 상환 일정 | 회차, 날짜, 원금, 이자, 남은 원금 | 준비 중 / 개발용 샘플 |
| 자산 변동 그래프 | 최근 7일의 하루 끝 보유 GC: 글자 그래프(`▁▂▃▅▇`)와 날짜별 잔액, 전날과의 차이 | 요약의 `trend` |

- 은행 계좌는 **읽기 전용**입니다. 대시보드에서 연 화면에는 맡기기·찾기 단추가 없습니다.
- 은행이 아직 열리지 않은 레벨이면 "은행은 레벨 3부터 이용할 수 있어요"가 보입니다.
- 자산 변동은 지금은 **보유 GC(지갑)의 변동**입니다. 원장에 적힌 잔액을 날짜(한국 시간)별로 읽은 것이고, 마지막 날은 지금의 잔액입니다. 은행·주식·대출이 생기면 순자산의 변동으로 바꿉니다 (화면에도 그렇게 적혀 있음).
- 그래프는 그림이 아니라 글자입니다. 메뉴의 항목 옆에도 작은 그래프가 보입니다.

## 5. 갱신

[LIVE_DASHBOARD](LIVE_DASHBOARD.md) 5장의 규칙 그대로입니다. 금융 쪽에서는:

| 지시서 7장 | 한 것 |
|---|---|
| 금융 거래 완료 후 갱신 | 내 보유 GC, 통장, 정기예금 가운데 하나가 달라지면 0.3초 뒤에 요약을 다시 받음 (요청 사이는 2초 이상). 구매, 보상, 맡기기·찾기, 이자, 세금이 모두 여기에 걸림 |
| 일정 주기 상태 확인 | 기본 20초 |
| 가상 주식 시세 갱신 | 주식 기능이 없어 **하지 않음**. 생기면 요약에 실려 같은 주기로 옴 |

카드의 숫자는 요약이 올 때 바뀝니다. 그 사이에 화면 위쪽의 GC 표시(기존 HUD)는 먼저 바뀔 수 있습니다 — GC 표시는 거래 응답을 바로 받고, 카드는 서버의 요약을 다시 받기 때문입니다. 길어야 2초 남짓의 차이입니다.

## 6. 개인 금융 정보의 보호

| 것 | 방법 |
|---|---|
| 조회 권한 | `GET /dashboard/summary`는 접속 토큰이 있어야 하고 (없거나 틀리면 `401`), **토큰의 주인**에 대해서만 답함 |
| 다른 사람의 것을 볼 길 | 없음. 경로·쿼리·헤더·본문 어디에도 계정을 고르는 인자가 없음. `?player_id=…`를 붙여도 무시됨 (테스트와 로컬 HTTP 확인) |
| 응답의 내용 | 계정 ID, 닉네임, 이메일 같은 식별 값이 없음. 금액과 날짜뿐 |
| 전국·도시 항목 | 도시 단위의 값만 (위험도, 순위, 재정 합계). 다른 이용자의 잔액·기여액은 없음. "내 기여도"는 내 것만 |
| 캐시 | 응답에 `Cache-Control: no-store` |
| 관리자 화면 | 대시보드 설정 화면은 이용자의 금융 정보를 읽지 않음 ([ADMIN_SYSTEM](ADMIN_SYSTEM.md) 13장) |
| 기기 | 요약은 메모리에만 있고 파일로 저장하지 않음. 저장하는 것은 카드의 접힘·크기 같은 설정뿐 ([HUD_LAYOUT_SYSTEM](HUD_LAYOUT_SYSTEM.md) 6장) |
| 읽기 전용 | 요약을 몇 번 받아도 잔액·원장이 바뀌지 않음. `POST` / `PUT` / `DELETE`는 받지 않음 |

## 8. 남은 일

- **서버의 은행** (v6.0 은행을 서버로 옮기기). 그 전에는 실제 서버에서 이 카드의 실제 값이 보유 GC 하나입니다.
- 가상 주식과 시세 갱신, 대출과 상환 일정 (Phase 4). 생기면 샘플을 걷어 냅니다.
- 자산 변동을 순자산 기준으로. 그림으로 그린 그래프.
- 대시보드의 상세 보기에서 바로 은행을 여는 길 (지금은 읽기만 하고, 맡기고 찾으려면 은행원이나 방의 컴퓨터로 가야 함).
