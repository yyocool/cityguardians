# SECURITY_POLICY — 보안 정책

> 기준 v6.0 · 2026-11-13 · 상태: 정책 (구현 전)

## 1. 비밀 정보

| 규칙 | 내용 |
|---|---|
| 기록 금지 | 서버 비밀번호, SSH 키, DB 계정, API 키, 토큰을 문서·소스·저장소·채팅 기록·공지에 적지 않는다 |
| 보관 위치 | 서버는 문서 루트 밖의 `.env` (소유자만 읽기). 개발 PC는 환경변수 또는 저장소에서 제외된 `.env.local` |
| 저장소 | `.gitignore`에 `.env*`, 키 파일, 백업, 덤프를 넣는다. 커밋 전에 비밀 값이 섞이지 않았는지 검사한다 |
| 환경 분리 | 개발·스테이징·운영이 서로 다른 계정과 비밀 값을 쓴다 |
| 최소 권한 | 계정마다 필요한 권한만 준다. 애플리케이션은 DB 관리자 계정을 쓰지 않는다 |
| 접속 방식 | 서버 접속은 키 방식을 권장. 배포 전용 키를 따로 둔다 |
| 노출 시 | 노출된 값은 즉시 교체한다. 지우는 것만으로 끝내지 않는다 |
| 클라이언트 | 게임 빌드에 서버 비밀 값을 넣지 않는다. 빌드에 들어간 값은 누구나 꺼낼 수 있다고 본다 |

## 2. 인증과 세션

| 항목 | 정책 |
|---|---|
| 게스트 비밀키 | 서버가 생성한 긴 무작위 값. 발급 때 한 번만 전달. 서버에는 비밀번호 해시로 저장 |
| 기기 보관 | Windows에서는 사용자 계정으로 암호화(DPAPI)한 파일. 평문 저장 금지 |
| 접속 토큰 | 무작위 값. 서버에는 해시만 저장. 수명 24시간 |
| 전송 | HTTPS만. 인증서 검증을 끄지 않는다 |
| 생성 제한 | IP당 게스트 생성 횟수 제한 (계정 대량 생성 방지) |
| 폐기 | 로그아웃, 제재, 이상 징후 시 토큰 폐기 |
| 기록 | 토큰과 비밀키를 로그에 남기지 않는다 |

## 3. 서버 권한과 부정행위 방지

클라이언트는 조작될 수 있다고 전제합니다.

| 원칙 | 내용 |
|---|---|
| 금액은 서버가 | GC, 경험치, 가격, 이자, 확률, 드롭은 서버가 계산한다. 클라이언트가 보낸 금액은 받지 않는다 |
| 보상 검증 | 처치 수, 소요 시간, 순번, 일일 한도를 확인한다 ([COMBAT_SYSTEM](COMBAT_SYSTEM.md) 10장) |
| 소유 확인 | 장착, 사용, 판매 전에 보유 여부를 서버에서 확인한다 |
| 본인 데이터만 | 요청의 대상이 본인 것인지 항상 확인한다 |
| 한도 | 일일 보상, 거래 횟수, 보유량 한도로 피해 범위를 제한한다 |
| 기록 | 검증에서 거절된 요청을 남겨 관리자가 볼 수 있게 한다 |
| 대응 | 반복되는 조작은 관리자가 확인해 제재한다. 자동 영구 정지는 하지 않는다 (오판 방지) |

싱글 플레이 전투의 판정은 클라이언트에서 일어나므로 완벽히 막을 수는 없습니다. 목표는 조작으로 얻을 수 있는 이득을 한도 안에 묶고, 흔적을 남기는 것입니다.

## 4. 금융 거래 보호

| 항목 | 정책 |
|---|---|
| 원자성 | 잔액 변경, 원장 기록, 대응하는 변화는 하나의 트랜잭션 |
| 동시성 | 변경 전 행 잠금. 잠금 순서 고정 |
| 중복 방지 | 변경 요청마다 중복 방지 키 |
| 음수 금지 | 잔액이 음수가 되는 거래 거절. DB 제약으로도 막음 |
| 원장 | 추가만 가능. 수정·삭제 없음 |
| 점검 | 매일 잔액과 원장 합계 대조 |
| 수동 조정 | 관리자 기능으로만. 사유와 담당자 기록 |
| 현실 화폐 | 결제, 환전, 현금 상환 기능을 만들지 않는다 |

## 5. 웹과 API

| 위협 | 대책 |
|---|---|
| SQL 삽입 | 준비된 문장(바인딩)만 사용. 문자열로 SQL을 이어 붙이지 않는다 |
| 스크립트 삽입 (XSS) | 모든 출력 이스케이프. 콘텐츠 보안 정책 유지 (자기 출처만). 닉네임·채팅·공지 포함 |
| 요청 위조 (CSRF) | 홈페이지 양식과 관리자에 토큰. API는 쿠키가 아닌 Bearer 토큰 |
| 과도한 요청 | 경로별 요청 제한. 인증·금융 경로는 더 엄격히 |
| 정보 노출 | 오류 응답에 내부 정보 없음. PHP 버전 헤더 숨김. 디렉터리 목록 금지 |
| 파일 업로드 | 플레이어 업로드 기능 없음. 관리자 업로드는 형식·크기 검사, 실행 불가 경로에 저장 |
| 파일 접근 | 코드, 설정, 백업, 로그는 문서 루트 밖 |
| 전송 | HTTPS 강제, HSTS 유지 |
| 의존성 | 외부 라이브러리는 최소한으로. 버전을 고정하고 보안 공지를 확인 |
| 입력 검증 | 형식, 길이, 범위, 허용 값 검사 |

운영 사이트에 이미 적용된 보안 헤더를 약화시키지 않습니다.

## 6. 관리자

[ADMIN_SYSTEM](ADMIN_SYSTEM.md) 2장의 내용을 따릅니다. 요약: 별도 계정, 강한 비밀번호 해시, 2단계 인증 필수, 세션 쿠키 보호, CSRF 토큰, 로그인 시도 제한, 접속 IP 제한(선택), 역할별 권한, 모든 변경의 감사 기록.

관리자 계정을 여러 사람이 함께 쓰지 않습니다.

## 7. 미성년자 보호

초등학생이 이용한다는 것을 전제로 합니다.

| 영역 | 정책 |
|---|---|
| 나이를 모를 때 | 미성년자로 보고 가장 제한된 설정을 적용 |
| 결제 | 현실 결제 기능 없음 |
| 대출 | 1건 제한, 낮은 한도, 이자 상한, 복리 없음, 연체 가산 없음, 장기 연체 정리, 압박 알림 없음 ([LOAN_CREDIT_SYSTEM](LOAN_CREDIT_SYSTEM.md) 2장) |
| 투자 | 변동 한도, 최저 가격, 거래 횟수 한도, 빚내서 투자 불가, 권유 알림 없음 ([STOCK_SYSTEM](STOCK_SYSTEM.md) 7장) |
| 채팅 | 제한형부터. 욕설·개인정보 필터, 신고·차단, 1:1 비공개 대화 없음 ([COMMUNITY_SYSTEM](COMMUNITY_SYSTEM.md) 5장) |
| 개인정보 | 실제 주소, 위치, 학교, 연락처를 수집하지 않음. 닉네임에 실명을 쓰지 않도록 안내 |
| 표현 | 피·잔혹 표현 없음. 적은 기계 |
| NPC | 플레이어로 위장하지 않음 |
| 이용 시간 | 늦은 밤 접속을 유도하는 한정 이벤트를 만들지 않음. 긴 플레이 뒤 쉬어 가라는 안내 (보리의 한마디) |
| 설계 | 불안을 자극하는 문구, 놓치면 손해라는 압박, 확률에 돈을 거는 구조를 쓰지 않음 |
| 보호자 | 홈페이지에 보호자 안내 제공 |

## 8. 개인정보

| 항목 | 정책 |
|---|---|
| 수집 최소화 | 게스트는 개인정보를 받지 않는다. 서버가 붙인 ID와 게임 데이터만 가진다 |
| 접속 기록 | IP 등은 보안과 부정행위 대응에 필요한 범위와 기간만 보관 |
| 계정 연결 | 개인정보가 필요한 수단은 법적 검토 뒤 도입. 그 전에는 개인정보가 필요 없는 이어하기 코드 방식 |
| 닉네임 | 공개되는 정보임을 안내. 실명·연락처 형태는 거부 |
| 채팅 | 보관 기간이 지나면 자동 삭제 |
| 삭제 요청 | 계정과 데이터 삭제 요청을 처리하는 절차를 둔다. 금융 원장은 플레이어와의 연결을 끊은 뒤 통계용으로만 남긴다 |
| 관리자 열람 | 필요한 역할만, 열람 기록을 남김 |
| 개발 환경 | 운영 데이터를 개발 PC로 가져오지 않는다 |
| 문서 | 개인정보처리방침을 실제 수집 내용과 일치하게 유지 |

## 9. 법적 확인이 필요한 항목

아래는 **법률 판단이 아니라 확인이 필요한 목록**입니다. 공개 배포와 해당 기능 도입 전에 전문가의 검토를 받아야 합니다.

| 항목 | 확인할 내용 | 시점 |
|---|---|---|
| 게임물 등급분류 | 국내 배포에 필요한 등급분류 절차와 대상 연령 | Windows 빌드 공개 전 |
| 모의 투자·대출 콘텐츠 | 주식·대출·신용점수 기능이 등급과 관련 규정에 주는 영향 | Phase 4 착수 전 |
| 아동의 개인정보 | 만 14세 미만의 개인정보 수집과 보호자 동의 요건 | 계정 연결 도입 전 |
| 채팅 | 미성년자 대상 채팅 운영 요건, 메시지와 신고 증거의 보관 기간 | Phase 5 착수 전 |
| 청소년 보호 | 이용 시간 등 청소년 보호 관련 의무 | 빌드 공개 전 |
| 약관·방침 | 이용약관과 개인정보처리방침의 문안 | 기능 추가 때마다 |
| 지도 데이터 | 행정구역 경계 데이터의 이용 조건. 2026-11-13에 개발자가 라이선스 문서를 읽고 확인함: 통계청 SGIS 행정동 경계(공공누리 제1유형) → vuski/admdongkor 가공본(CC BY 4.0), 출처 표시 의무. 지도 화면에 출처를 표시함 ([MAP_SYSTEM](MAP_SYSTEM.md) 2.1). **전문가 검토는 받지 않았음** — 출처 표시 문구와 방법이 두 조건을 충족하는지 확인 필요 | 빌드 공개 전 |
| 글꼴·음원·그림 | 사용하는 모든 자원의 이용 조건. 게임 배포에 쓸 수 있는지 | 자원 추가 때마다 |
| 명칭 | 게임명, 가상 기업명, 캐릭터 이름이 기존 상표와 겹치지 않는지 | 공개 전 |
| 모바일 스토어 | 아동 대상 앱 요건 | Phase 8 착수 전 |

## 10. 기록과 보관

| 기록 | 내용 | 보관 |
|---|---|---|
| 원장 | 모든 GC 증감 | 삭제하지 않음 |
| 관리자 감사 기록 | 관리자의 변경과 민감한 조회 | 장기 보관 |
| 시스템 로그 | 오류, 예약 작업 결과 | 90일 |
| 접속 기록 | 시각, 플랫폼, 버전, IP | 필요한 기간만 (법적 검토 후 확정) |
| 거절된 보상 보고 | 검증 실패 내용 | 90일 |
| 채팅, 신고 증거 | [COMMUNITY_SYSTEM](COMMUNITY_SYSTEM.md) 5.8 | 정해진 기간 |

로그에 비밀 값, 토큰, 게스트 비밀키를 남기지 않습니다.

## 11. 사고 대응

| 단계 | 내용 |
|---|---|
| 발견 | 감시 지표, 관리자 로그, 이용자 신고 |
| 차단 | 점검 모드, 문제 기능 끄기, 관련 토큰 폐기, 노출된 비밀 값 교체 |
| 파악 | 원장과 로그로 범위 확인. 증거 보존 |
| 복구 | 정정 거래(원장에 반대 행)로 바로잡기. 덤프 복원은 마지막 수단 |
| 알림 | 영향받은 이용자와 필요한 기관에 알림 (요건은 법적 검토) |
| 재발 방지 | 원인과 조치를 기록하고 테스트를 추가 |

기능을 설정으로 끌 수 있게 만듭니다 (은행, 주식, 대출, 채팅 각각).

## 12. 개발 규칙

- 운영 서버에서 직접 코드를 고치지 않습니다. 모든 변경은 저장소 → 스테이징 → 운영 순서로 갑니다.
- 운영 DB를 손으로 고치지 않습니다.
- 기존 서비스에 영향을 주는 변경은 사전 승인을 받습니다 ([SERVER_DEPLOYMENT](SERVER_DEPLOYMENT.md) 7장).
- 다른 프로젝트의 계정이나 인증정보를 이 프로젝트에 빌려 쓰지 않습니다.
- 다른 게임의 캐릭터, 에셋, 데이터를 복제하지 않습니다.
- 금융과 인증 코드는 테스트 없이 배포하지 않습니다 ([TEST_PLAN](TEST_PLAN.md) 4장).
