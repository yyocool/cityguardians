# MAP_SYSTEM — 대한민국 지도와 3D 도시

> 기준 v6.0 · 2026-11-13 · 상태: 전국 지도 화면 구현 (클라이언트, 모의 서버). 지도에서의 이동과 3D 도시 템플릿은 미구현. 구현 내용과 설계와의 차이는 8장
>
> v8.0 (2026-11-13): 지도에 도시별 위험도·위험 단계(색 + 모양 + 글자)·방어력·침공 현황·기여도·랭킹·지원 요청을 더했습니다. 내용은 [CITY_RISK_SYSTEM](CITY_RISK_SYSTEM.md) 8장과 [REGIONAL_COMPETITION](REGIONAL_COMPETITION.md)에 있습니다. **이 화면은 Unity에서 실행해 보지 못했습니다** (컴파일 검사만). 8.3의 검증 기록은 v6.0 시점의 것입니다.

## 1. 두 개의 층

| 층 | 내용 | 범위 |
|---|---|---|
| 전국 지도 | 실제 시·군·구 행정구역을 그린 2D 지도 화면 | 전국 |
| 3D 도시 | 걸어 다니는 가상 도시 | 1차는 대표 도시 1곳, 나머지는 템플릿 |

지도는 메뉴가 아니라 **이동 수단**입니다. 어디서든 M 키로 열고, 표시를 눌러 활동 장소로 갑니다.

## 2. 행정구역 데이터

운영 중인 홈페이지의 지역 소개 페이지는 16개 시·도와 229개 시·군·구를 표시하고 있습니다. 이 목록이 이미 운영 DB에 들어 있으므로 v6.0도 **그 지역 목록과 코드를 그대로 기준으로 삼습니다.**

확인이 필요한 것:

- 운영 DB의 지역 테이블 구조와 코드 체계 (서버 접속 후 확인)
- 현재 목록이 최신 행정구역과 일치하는지
- 홈페이지 지도에 쓰인 경계 데이터의 출처와 이용 조건. 게임 클라이언트에 같은 데이터를 넣을 수 있는지 확인한 뒤 재사용합니다.

경계 데이터를 새로 구해야 한다면 공공 기관이 공개한 행정구역 경계를 쓰고, 출처 표시 등 이용 조건을 지킵니다.

### 2.1 실제로 쓴 경계 데이터 (2026-11-13 결정·확인)

운영 서버에 접속할 수 없어 홈페이지의 데이터는 확인하지 못했습니다. 그래서 공공 기관이 공개한 경계를 내려받아 쓰기로 했습니다 (사용자 결정).

| 항목 | 내용 |
|---|---|
| 원천 | 통계청 통계지리정보서비스(SGIS)의 행정동 경계 |
| 원천의 이용 조건 | 공공누리 제1유형 (출처표시). 상업적 이용과 변형 가능 |
| 내려받은 곳 | [vuski/admdongkor](https://github.com/vuski/admdongkor) — SGIS 경계를 내려받기 쉬운 GeoJSON으로 가공해 배포하는 공개 저장소 |
| 가공본의 이용 조건 | CC BY 4.0 ([LICENSE-DATA](https://github.com/vuski/admdongkor/blob/master/LICENSE-DATA)). 출처를 표시하고 고친 사실을 밝히면 상업적 이용과 변형 가능 |
| 파일 | `ver20261001/HangJeongDong_ver20261001.geojson` |
| 기준 시점 | 2026-10-01 |
| 고정한 판 | 커밋 `3bc00489b76696db864bdbea4b19985cdfa8b403` |
| SHA-256 | `843ece3a0b3429742cd4a1b699cc13987a88b5e5401f382e7fdaaa194ea5e605` (도구가 내려받을 때마다 대조하고 다르면 멈춤) |

**지켜야 하는 것.** 두 조건 모두 출처 표시가 의무입니다. 다음 문구를 지도 데이터 파일(`attribution`)에 넣고 **지도 화면 아래쪽에 항상 표시합니다.** 지도를 끌어 옮겨도 가려지지 않도록 글자 뒤에 띠를 깔았고, 자동 테스트가 화면에 이 문구가 있는지 확인합니다.

> 지도 경계: 통계청 통계지리정보서비스(SGIS) 행정동 경계(공공누리 제1유형)를 vuski/admdongkor 가 가공(CC BY 4.0)한 ver20261001 자료를 시·군·구로 합치고 단순화함

이용 조건은 2026-11-13에 저장소의 라이선스 문서를 읽어 확인한 것입니다. **법률 검토를 받은 것은 아니므로** 상용 출시 전에 [SECURITY_POLICY](SECURITY_POLICY.md) 9장의 검토 목록에 따라 다시 확인해야 합니다. 원자료 파일은 저장소에 넣지 않습니다 (`tools/map/.cache`, git 제외). 게임에는 가공한 결과만 들어갑니다.

### 2.2 가공한 내용

`tools/map/build-regions.mjs` 가 한 번에 처리합니다. 실행 중에는 가공하지 않습니다.

| 단계 | 내용 |
|---|---|
| 합치기 | 행정동 → 시·군·구. 도에 속한 시의 구(수원시 장안구 등, 13개 시의 39개 구)는 **시 하나로 합침**. 특별시·광역시의 자치구는 그대로 |
| 단순화 | 점의 6%만 남김 (mapshaper, weighted). 2.2%에서는 부산 해안선이 깨져 보여 올렸음 |
| 작은 섬 | 1.5 km² 미만의 섬은 뺌. 지역마다 가장 큰 땅은 남김. 1 km² 미만의 구멍은 메움 |
| 독도 | 단순화하지 않고 원래 모양대로 남기고, 지도에 이름을 따로 표시 |
| 좌표 | 위도 36°에 맞춘 단순 평면 좌표. 한 칸 = 약 56 m, 정수, 왼쪽 아래가 (0,0) |
| 삼각형 | 지역마다 삼각형으로 나눔 (earcut). 그리기와 "어느 지역을 가리키는가" 판정에 같이 씀 |

결과 (2026-11-13 실행):

| | |
|---|---|
| 시·도 | 16 |
| 시·군·구 | 230 |
| 점 / 삼각형 | 23,076 / 22,310 |
| 파일 | `client/Assets/CityGuardians/Resources/Data/kr_regions.json` (570 KB), `Domain/Generated/KrRegions.g.cs` (지역 목록) |

다시 만드는 법:

```powershell
cd tools\map
npm install      # 처음 한 번
npm run build
```

### 2.3 운영 홈페이지와 다른 점 — 확인 필요

| 항목 | 홈페이지 | 이 데이터 | 상태 |
|---|---|---|---|
| 시·군·구 수 | 229 | 230 | **원인 모름.** 원자료의 시·군·구는 256곳이고, 구가 있는 시 13곳의 구 39곳을 시로 합치면 230곳입니다. 홈페이지가 어느 한 곳을 다르게 세고 있는지는 운영 DB를 봐야 알 수 있습니다 |
| 지역 코드 | 알 수 없음 | 원자료의 시·군·구 코드 5자리 (합친 시는 앞 4자리 + `0`) | **운영 DB의 코드와 같은지 확인하지 못했습니다.** 다르면 서버 연동 때 대응표가 필요합니다 |
| 시·도 | 16 | 16 | 수는 같음. 이름과 구성이 같은지는 미확인 |

위 "v6.0도 그 지역 목록과 코드를 그대로 기준으로 삼습니다"는 원칙은 그대로이며, 지금의 목록은 서버를 확인하기 전까지 쓰는 것입니다.

## 3. 전국 지도 화면

### 3.1 기능

| 기능 | 내용 | 1차 |
|---|---|---|
| 전국 보기 | 시·도 단위 색칠 지도 | 포함 |
| 지역 선택 | 시·도 클릭 → 확대 → 시·군·구 클릭 | 포함 |
| 확대·축소 | 마우스 휠 | 포함 |
| 드래그 이동 | 마우스 드래그 | 포함 |
| 내 도시 표시 | 전입한 시·군·구 강조 | 포함 |
| 지역 방어력 | 방어 포인트와 도시 레벨 | 포함 (수치 표시) |
| 도시 랭킹 | 시·도, 시·군·구 순위 | 포함 (목록) |
| AI 침공 현황 | 침공 단계에 따른 색과 경고 표시 | Phase 2 |
| 구조 요청 | 지역별 임무 표시 | Phase 2 |

### 3.2 그리는 방법

1. 경계 데이터를 단순화합니다 (점의 수를 줄여 게임용으로).
2. 에디터 도구가 시·군·구마다 다각형 메시와 중심점·경계 상자를 만들어 에셋으로 저장합니다. 실행 중에는 가공하지 않습니다.
3. 지도 화면은 별도 카메라로 이 메시를 그리고, 마우스 위치로 지역을 판정합니다.
4. 지역 상태(방어 포인트, 침공 단계, 주민 수)는 서버에서 받아 색으로 입힙니다.

섬 지역(울릉도·독도 등)은 운영 홈페이지와 같이 따로 표시합니다.

### 3.3 지역 정보 패널

시·군·구를 누르면 오른쪽에 패널이 뜹니다.

- 지역 이름, 도시 레벨, 방어 포인트, 주민 수, 순위
- 침공 단계 (평온 / 주의 / 침공 중)
- 버튼: "이 도시로 가기" (갈 수 있는 3D 도시가 있을 때), "여기로 전입신고" (전입신고 중일 때)

## 4. 지도에서 활동으로

| 지도에서 누르는 것 | 결과 |
|---|---|
| 내 방 아이콘 | 내 방으로 이동 |
| 내 도시 | 3D 도시 광장으로 이동 |
| 도시 안 시설 아이콘 (상점, 은행, 방어기지 등) | 그 시설 앞으로 이동 |
| 침공 표시 | 방어전 입장 확인 |
| 구조 요청 | 임무 장소로 이동 |

이동은 짧은 화면 전환 뒤 그 자리에 서는 방식입니다. 전투 중에는 이동할 수 없습니다.

지도 화면은 방과 도시 어디에서든 겹쳐 띄우는 공용 UI로 만들고, 장면에 속하지 않게 합니다.

## 5. 3D 도시

### 5.1 구성 구역

| 구역 | 내용 | 주요 NPC |
|---|---|---|
| 주거 지역 | 내 집 문, 이웃집 | 일반 주민, 도담 |
| 광장 | 도시의 중심. 부활 지점, 공지판 | 방어대장, 가디언 |
| 상점 | 무기·아이템 가게 | 상인 |
| 은행 | 창구와 로비 | 은행원, 금융 안내원 |
| 주민센터 | 전입신고 | 도시 행정관 |
| 방어기지 | 방어전 입장, 타워 강화 | 방어대장 (방어전 때) |
| 연구소 | 장비 강화, 적 도감 | 추후 |
| 학교 | 학교 방어대 | 추후 |
| 전투 구역 | 로봇이 출몰하는 거리 | 적 |

지시서의 구성 목록에 전입신고 장소가 없어 주민센터를 추가했습니다. 건물을 따로 두지 않고 광장의 창구로 줄일 수도 있습니다.

### 5.2 1차 대표 도시 크기

- 걸어서 끝에서 끝까지 1분 안팎 (약 200 m × 200 m)
- 광장을 가운데 두고 시설이 둘러싸며, 바깥쪽에 전투 구역 2곳
- 전투 구역은 안전 구역과 낮은 울타리·경고선으로 구분되고, 적은 안전 구역에 들어오지 않습니다
- 방어전은 도시 외곽의 전용 구역에서 진행합니다 ([TOWER_DEFENSE](TOWER_DEFENSE.md))

대표 도시는 **부산광역시 해운대구**입니다 (2026-11-13 결정).

| 반영할 지역 정체성 | 표현 |
|---|---|
| 바다와 모래사장 | 도시 남쪽에 해변과 바다. 걸어 내려갈 수 있다 |
| 바닷가의 높은 건물들 | 해변 옆에 높이가 다른 고층 건물 윤곽 (실제 건물·상호 재현 아님) |
| 지역 색 | 바다색 계열. 방어대 깃발과 완장에 파도 문양 |
| 지명 표지판 | 광장의 "해운대구" 표지 |

### 5.3 지역 정체성

실제 도시를 그대로 재현하지 않습니다. 다음 세 가지만 반영합니다.

1. 대표 지형 또는 건물의 윤곽 한두 개 (실제 상호·상표 제외)
2. 지역 색과 방어대 깃발 문양
3. 지명 표지판

### 5.4 도시 템플릿

다른 시·군·구는 템플릿으로 확장합니다.

| 템플릿 | 예 | 차이 |
|---|---|---|
| 도심형 | 특별시·광역시의 구 | 높은 건물, 넓은 광장 |
| 중소도시형 | 시 | 낮은 건물, 시장 거리 |
| 농산어촌형 | 군 | 넓은 들, 마을회관 |
| 해안형 | 바다를 낀 지역 | 항구, 방파제 |

도시는 구역 프리팹을 배치표에 따라 조립합니다. 지역 테이블에 템플릿 종류와 색·문양 설정을 두어 같은 템플릿이라도 지역마다 다르게 보이게 합니다.

3D 도시가 아직 없는 지역으로 전입한 주민은 대표 도시를 공용 거점으로 쓰고, 완장과 깃발만 자기 도시의 것으로 표시합니다. 방어 포인트는 자기 도시에 쌓입니다.

## 6. 장면 구조

| 장면 | 내용 |
|---|---|
| `Boot` | 접속, 초기 데이터 수신 |

## 7. 데이터와 API

| API | 용도 |
|---|---|
| `GET /regions` | 시·도와 시·군·구 목록, 방어 포인트, 레벨, 주민 수, 침공 단계 |
| `GET /regions/{id}` | 지역 상세, 3D 도시 이용 가능 여부 |
| `GET /regions/rankings` | 시·도, 시·군·구 순위 |

지역 목록은 자주 바뀌지 않으므로 클라이언트가 캐시하고, 상태 수치만 지도를 열 때 새로 받습니다.

## 8. 구현 기록 (2026-11-13, 클라이언트)

### 8.1 만든 것

| 기능 | 내용 |
|---|---|
| 열기 | M 키. 튜토리얼을 마친 뒤(6단계)부터, 방과 도시에서. 방어전 중이거나 적에게 쫓기는 중에는 열리지 않고, 열려 있다가 맞으면 닫힘 |

| 내 도시 | 주민이면 지도를 열 때 내 도시부터 보여 주고 "내 도시" 표시 |
| 전입신고 모드 | 주민센터에서 열면 "여기로 전입신고" 버튼이 생김 ([RESIDENCY_SYSTEM](RESIDENCY_SYSTEM.md) 9장) |
| 독도 | 지도에 표시하고 이름을 적음. 울릉군의 일부로 그려짐 |
| 출처 표시 | 화면 아래에 항상 |

지도는 장면에 속하지 않는 공용 UI입니다 (`MapController` 가 상태, `MapPanel` 이 화면). 지도 도형은 uGUI 메시로 그립니다 — 3.2의 "별도 카메라" 대신 HUD와 같은 캔버스에 그리는 쪽이 간단하고 해상도에 맞추기 쉬웠습니다.

### 8.2 설계와 다른 점, 하지 않은 것

| 항목 | 설계 | 구현 | 이유 |
|---|---|---|---|
| 지도에서 이동 (4장, "이 도시로 가기") | 포함 | **없음** | 갈 수 있는 곳이 아직 방과 해운대구뿐이라 걸어가는 것과 차이가 없음. "지도는 이동 수단"이라는 목표는 아직 이루지 못함 |
| 도시 랭킹 | 포함 (목록) | **없음** | 모의 서버에는 플레이어가 나 하나라 순위가 의미 없음. 꾸며낸 순위는 만들지 않음 |
| 도시 레벨 | 포함 | 없음 | 방어 포인트 합계만 표시. 레벨 기준은 서버와 함께 |
| 다른 가디언의 수 | 서버 수치 | 내 기록만 | 모의 서버는 이 PC 한 대의 기록만 가짐. 그래서 대부분 "0명" 으로 보이며, **숫자를 꾸며내지 않았음** |
| AI 침공 현황, 구조 요청 | Phase 2 | 없음 | 침공 단계 기능 자체가 아직 없음 |

### 8.3 검증

- 자동 테스트: 지도 데이터 검사 8건 (지역 목록과 일치, 모든 이름표 자리가 자기 지역 안, 출처 문구, 독도, 메시 한도), 실제 화면 조작 2건 (열기 → 부산 → 해운대구 → 확대·끌기 → 뒤로, 전입신고 전 과정). 화면은 캡처해서 눈으로 확인했습니다 (`client/Logs/shots/50~59`).
- **확인하지 못한 것**: 사람이 실제 마우스로 조작하는 느낌(끌기·휠의 감도), 1920×1080이 아닌 화면 비율에서의 배치, 수도권처럼 작은 구가 몰린 곳을 아이가 쉽게 누를 수 있는지. 자동 테스트의 마우스는 좌표를 넣어 흉내 낸 것입니다.
