# WEBSITE_SPEC — 공식 홈페이지

> 기준 v6.0 + v7.0 현실 혜택 · 2026-11-13 · 상태: 1~10장은 설계 (미구현). **11장(CITY PASS, SCHOLARSHIP, 로그인, 상점 확인 화면)은 이 저장소의 `server/`에 구현하고 로컬에서만 검증함.** 운영 중인 공식 홈페이지에는 올리지 않았고, 메뉴에도 연결하지 않음

## 1. 현황 (2026-11-13 공개 페이지 확인)

`https://www.dalfin.net`에 CITY GUARDIANS 공식 홈페이지가 이미 운영 중입니다. 내용은 이전 기획(좀비 테마)입니다.

| 경로 | 내용 |
|---|---|
| `/` | 메인. 소개 문구: "대한민국의 도시를 좀비로부터 지켜라…" |
| `/about` | 게임 소개: 감염 세계관, 이방인과 전입신고, 지역 방어, 타워디펜스, NPC 주민, 도시 경제, 지역 협력과 경쟁 |
| `/guide` | 게임 방법 4단계 (게스트 시작과 직업 선택, 좀비 방어, 보상, 도시 성장) |
| `/regions` | 지역 소개: 16개 시·도, 229개 시·군·구 지도와 방어 포인트, 순위 |
| `/news`, `/news/{id}` | 소식: 개발 소식, 업데이트, 공지사항 (글 3건, 2026-11-12) |
| `/download` | 다운로드: Windows·Android·iOS 모두 "준비 중", 권장 사양(예정) |
| `/support` | 고객지원: 자주 묻는 질문, 문의 안내(창구 준비 중) |
| `/privacy`, `/terms` | 개인정보처리방침, 이용약관 |
| `/sitemap.xml`, `/robots.txt` | 있음 (`/api/` 색인 금지) |

기술적 특징: HTTP → HTTPS 전환, HSTS, 자기 출처만 허용하는 콘텐츠 보안 정책(CSP), 프레임 금지 등 보안 헤더가 적용되어 있습니다. 이 수준을 유지합니다.

**기존 사이트를 지우고 새로 만들지 않습니다.** 기존 구조 위에서 문구를 바꾸고 페이지를 더합니다.

## 5. 다운로드

| 플랫폼 | 표시 |
|---|---|
| Windows | 빌드가 등록되어 있으면 다운로드 버튼, 없으면 "준비 중" |
| Android | 출시 예정 |
| iOS | 출시 예정 |

- **실제 게임 빌드가 준비되지 않았으면 다운로드 기능을 활성화하지 않습니다.**
- 버튼은 관리자가 `game_builds`에 빌드를 등록하고 공개로 바꿨을 때만 켜집니다. 코드나 설정 파일로 켜지 않습니다.
- 등록 정보: 버전, 파일, 크기, SHA-256, 공개 일시, 변경 내용.
- 다운로드 페이지에 버전, 파일 크기, SHA-256, 권장 사양을 보여 줍니다.
- 파일은 추측하기 어려운 주소가 아니라 버전이 붙은 고정 주소로 제공하고, 서버 저장 위치와 용량은 서버 조사 뒤 정합니다.
- "공식 홈페이지 외의 곳에서 받은 설치 파일은 실행하지 마세요" 안내를 유지합니다.

## 6. 정책 페이지

개인정보처리방침과 이용약관은 기능이 늘 때마다 갱신이 필요합니다. 특히 채팅, 계정 연결, 신고 증거 보관이 추가될 때입니다. 문안은 법적 검토를 거쳐 작성합니다 ([SECURITY_POLICY](SECURITY_POLICY.md) 9장).

## 7. 화면과 그림

- PC와 모바일 반응형. 기준 폭: 360, 768, 1280.
- 게임의 블록형 캐릭터와 같은 색·형태를 씁니다.
- **실제 게임 화면이 나오기 전에는 게임 화면처럼 보이는 이미지를 쓰지 않습니다.** 그 전에는 "개발 중 그림"이라고 표시한 설정화나 도형 그림을 씁니다. 빌드가 나오면 실제 화면으로 바꿉니다.
- 글자는 크게, 문장은 짧게.
- 그림에 대체 글을 넣고, 키보드만으로 메뉴를 이동할 수 있게 합니다.

## 11. CITY PASS 와 SCHOLARSHIP (v7.0, 구현됨)

### 11.1 어디에 있는가

운영 중인 공식 홈페이지(`www.dalfin.net`)의 소스는 이 저장소에 없습니다 (10장의 순서 1 "기존 사이트 소스 확보"가 그대로 남아 있습니다). 그래서 CITY PASS 와 SCHOLARSHIP 페이지는 **게임 서버 애플리케이션(`server/`) 안에** 만들었습니다. 게임 API·관리자와 같은 애플리케이션이고 같은 DB 를 씁니다.

| 묶음 | 경로 | 구현 |
|---|---|---|
| CITY PASS | `{설치 경로}/city-pass…` | `server/src/Web/SitePassPages.php` |
| SCHOLARSHIP | `{설치 경로}/scholarship…` | `server/src/Web/SiteScholarshipPages.php` |
| 로그인 | `{설치 경로}/login`, `/logout` | `server/src/Web/SiteKernel.php` |
| 상점 확인 화면 | `{설치 경로}/merchant…` | `server/src/Web/MerchantKernel.php` |
| 스타일 | `/assets/site.css` (홈페이지와 상점 화면이 함께 씀) | `server/public/assets/site.css` |

**하지 않은 것**: 기존 홈페이지의 상단 메뉴에 "CITY PASS", "SCHOLARSHIP"을 더하는 일. 기존 사이트의 소스를 확보한 뒤, 이 애플리케이션을 어느 경로에 둘지(예: `www.dalfin.net/city-pass`로 바로 잇기, 또는 하위 경로) 정하고 승인을 받아 진행해야 합니다. 그 전까지 이 페이지들은 로컬에서만 열립니다.

### 11.3 준비되지 않은 것을 보여 주지 않는다

- 기능이 꺼져 있으면(기본) 각 페이지는 **"준비 중"** 이라고만 말합니다. 제휴 상점·혜택·모집 공고의 목록은 비어 있습니다.
- 초기 데이터에 제휴 상점, 혜택, 장학 프로그램이 없습니다. 예시용 가짜 상점이나 가짜 공고를 넣지 않았습니다.
- 승인되지 않은(초안·승인 대기·일시 중지·종료) 업체와 혜택, 계약 기간이 지난 업체, 공고되지 않은 프로그램은 나오지 않습니다.
- 제휴 문의의 연락처도 실제로 설정했을 때만 보입니다.
- 모든 페이지 아래에 "CITY PASS 와 GUARDIANS SCHOLARSHIP 은 게임 보상이 아닙니다. 게임머니(GC), 전투 성적, 랭킹, 아이템, 결제 금액은 현실의 현금·상품권·쿠폰·장학금으로 바뀌지 않습니다"가 있습니다.

### 11.4 로그인

게임 계정에는 아이디와 비밀번호가 없습니다 (게스트). 그래서 **게임 안에서 받은 일회용 코드**로 로그인합니다.

1. 게임의 휴대전화(P 키) → "홈페이지 로그인 코드": 8자 코드 (5분, 한 번).
2. 홈페이지 `/login`에 넣습니다.

| 항목 | 내용 |
|---|---|
| 쿠키 | `cg_web`: `HttpOnly`, `SameSite=Lax`, `Secure`(기본. `WEB_COOKIE_SECURE`) |
| 수명 | 30분 동안 쓰지 않으면 끝남. 길어도 4시간 |
| 시도 제한 | 접속 주소마다 10분에 10번 (`WEB_LOGIN_PER_10MIN`) |
| 저장 | 코드와 토큰은 해시만 |
| 게임 접속과의 관계 | 별개. 이 접속으로 게임 API 를 부를 수 없음 |
| 돌아갈 주소 | `/city-pass…`, `/scholarship…` 모양만 받음 (다른 사이트로 보내는 데 쓰이지 않게) |

게임을 설치하지 않은 사람은 로그인할 수 없습니다 — 쿠폰과 장학 신청은 게임 계정이 있어야 합니다. 게임 계정으로 가입·신청한다는 점이 법적으로 어떻게 평가되는지, 장학 신청을 게임과 무관하게도 받을지는 검토와 정책 결정이 필요합니다 ([REAL_WORLD_REWARDS_POLICY](REAL_WORLD_REWARDS_POLICY.md) 6.1).

### 11.5 상점 확인 화면

`/merchant`. 제휴 상점의 직원이 휴대전화나 PC 의 웹 브라우저로 씁니다. 자세한 것은 [COUPON_SYSTEM](COUPON_SYSTEM.md) 5장, [PARTNER_MERCHANT_SYSTEM](PARTNER_MERCHANT_SYSTEM.md) 5장.

| 경로 | 내용 |
|---|---|
| `/merchant/login` | 상점 계정 로그인 (운영팀이 만들어 준 계정. 웹에서 가입할 수 없음) |
| `/merchant/password` | 비밀번호 바꾸기. 임시 비밀번호로는 다른 화면을 쓸 수 없음 |
| `/merchant` | 쿠폰 코드 넣기, 오늘·최근 7일·전체 사용 처리 수 |
| `/merchant/redeem?code=…` | QR 로 들어오는 주소. **코드를 칸에 채워 줄 뿐, 확인도 사용 처리도 하지 않음** |
| `POST /merchant/verify` | 유효성 검증: 혜택, 할인, 이용 조건, 유효기간을 보여 줌 |
| `POST /merchant/redeem` | 사용 처리 (되돌릴 수 없음) |
| `/merchant/history` | 이 상점(지점)의 이용 내역 |
| `/merchant/stats` | 이 상점의 통계 |

상점 계정은 자기 업체(지점 계정이면 그 지점)의 것만 봅니다. 손님의 닉네임·회원번호는 나오지 않습니다. 쿠키 `cg_merchant`는 `SameSite=Strict`, 경로 `/merchant`입니다.

### 11.6 화면과 기술

| 항목 | 내용 |
|---|---|
| 반응형 | 좁은 화면(360)을 먼저 맞추고 넓으면 옆으로 폄. 표는 가로로 밀어 봄. `site.css` 하나 |
| 스크립트 | **자바스크립트 없음.** 모든 기능이 링크와 폼으로 동작 |
| 외부 자원 | 없음 (글꼴·스크립트·그림 모두 자체). 외부 지도를 불러오지 않음 |
| 응답 헤더 | `Content-Security-Policy: default-src 'none'; style-src 'self'; img-src 'self'; form-action 'self'; base-uri 'none'; frame-ancestors 'none'`, `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` |
| 로그인한 화면 | `Cache-Control: no-store`, `X-Robots-Tag: noindex, nofollow` |
| 값을 바꾸는 요청 | POST 만. 출처(`Origin`) 확인 + CSRF 토큰. 로그인과 보호자 동의는 접속이 없으므로 출처 확인과 횟수 제한 |
| 출력 | 모든 값을 이스케이프. 상점 이름·혜택 설명에 넣은 태그가 실행되지 않는 것을 테스트로 확인 |
| 접근성 | 본문으로 건너뛰기 링크, 폼의 라벨, 오류에 `role="alert"`, 안내에 `role="status"` |
| 시각 | 한국 시간으로 표시 |

### 11.7 확인한 것과 한계

- `BenefitWebTest` 14개: 꺼져 있을 때의 "준비 중", 로그인 코드, 세션·CSRF·출처, 승인된 것만 보이는지와 이스케이프, 가입·쿠폰 받기·코드 표시와 GC 불변, 공고와 기준, 신청, 미성년자의 보호자 동의, 이의신청, 상점 로그인과 비밀번호 강제 변경, QR 주소, 다른 상점의 쿠폰, 기능을 끈 뒤의 상점 화면.
- 테스트는 화면 처리기를 직접 부르는 방식입니다. **실제 브라우저, 실제 휴대전화 화면, Apache / nginx 위에서는 확인하지 않았습니다.** 반응형 배치는 CSS 를 작성했을 뿐 눈으로 확인한 화면 캡처가 없습니다.
- 홈페이지는 쿠폰 코드를 글자로만 보여 줍니다 (QR 그림은 게임 화면에만 있음).
- `sitemap.xml`에 새 페이지를 더하지 않았습니다 (기존 사이트의 것이므로).
- 이용약관·개인정보 동의서의 문구는 초안입니다 (`2026-11-draft`).
- `Origin` 헤더가 없는 POST 는 출처 확인을 통과합니다 (오래된 브라우저 대비). 로그인한 뒤의 요청은 CSRF 토큰으로 막히지만, 로그인 요청 자체는 출처 확인과 쿠키 정책에만 기댑니다.
