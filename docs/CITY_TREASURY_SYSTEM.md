# CITY_TREASURY_SYSTEM — 도시 재정

> 기준 v9.0 · 2026-11-14 · 상태: PHP 서버(`CG\Service\Treasury`), 관리자 화면, 게임 화면(작전 본부 → 도시 살림 → 도시 재정) 구현. 로컬 테스트 DB에서만 돌려 보았고 운영에는 배포하지 않음. 세금이 꺼져 있는 동안에는 들어오는 돈이 없어 모든 도시의 재정이 0

## 1. 실제 사업의 예산과 분리

**게임 안의 도시 재정은 GC 로만 된 가상의 장부입니다.** v7.0의 CITY PASS(제휴 상점 쿠폰)와 GUARDIANS SCHOLARSHIP(장학)의 예산은 실제 돈이고, 이 장부와 어디에서도 만나지 않습니다.

| | 도시 재정 (이 문서) | CITY PASS · 장학 (v7.0) |
|---|---|---|
| 단위 | GC (게임머니) | 원 |
| 들어오는 곳 | 게임 안의 가상 지방세 | 제휴·후원·운영 예산 (게임 밖) |
| 테이블 | `city_tax_*`, `city_treasury_*`, `city_budget_*` | `city_pass_*`, `partner_*`, `benefit_coupons`, `coupon_*`, `scholarship_*` |
| 코드 | `Taxes`, `Treasury`, `Budget` | `CityPass`, `Partners`, `MerchantPortal`, `Scholarships`, `ScholarshipOffice` |
| 서로 부르는가 | **부르지 않음.** 왼쪽의 코드는 오른쪽의 테이블을 읽지도 쓰지도 않고, 그 반대도 같음 (테스트가 확인) | |

- 도시 재정이 많다고 그 도시에 쿠폰이나 장학금이 더 가지 않습니다. 세금을 많이 냈다고 실제 혜택이 생기지 않습니다.
- 도시 재정의 GC 를 실제 돈으로, 실제 예산을 GC 로 바꾸는 기능은 없고 만들지 않습니다.
- 게임 화면의 도시 재정에는 "게임 안의 도시 재정이에요. 실제 돈이 아니고, CITY PASS나 장학 사업의 예산과는 따로예요."라고 적힙니다 (응답의 `notice`).

## 2. 계정

도시(시·군·구)마다 두 계정이 있습니다 (`city_treasury_accounts`).

| 계정 | 뜻 | 들어옴 | 나감 |
|---|---|---|---|
| `general` 일반 회계 | 평소에 쓰는 돈 | 걷은 세금의 90% | 예비비를 뺀 여섯 분야의 집행 |
| `reserve` 예비비 | 급할 때를 위한 돈 | 걷은 세금의 10% (`treasury.reservePercent`) | "예비비" 분야의 집행 (관리자만. 참여예산으로는 쓸 수 없음) |

계정은 처음 세금이 들어올 때 만들어집니다. 잔액 말고도 들어온 합(`total_in`)과 나간 합(`total_out`)을 갖습니다.

## 3. 원장

**계정의 잔액이 바뀌는 곳은 `Treasury::post()` 하나입니다.**

1. 거래 안에서만 불립니다 (아니면 오류).
2. 계정 행을 잠급니다 (`SELECT … FOR UPDATE`).
3. 바뀐 뒤의 잔액이 음수이면 오류를 내고 아무것도 바꾸지 않습니다.
4. 잔액을 바꾸고, 원장(`city_treasury_ledger`)에 한 줄을 남깁니다: 계정, 변화량, **바뀐 뒤의 잔액**, 사유, 근거.

| 사유 | 근거 (`ref_type` / `ref_id`) |
|---|---|
| `tax_trade`, `tax_business`, `tax_property` | `tax_transaction` / 세금 명세의 번호 |
| `expenditure` | `expenditure` / 집행 내역의 번호 |

원장의 줄은 고치거나 지우지 않습니다 (그런 코드가 없습니다). 잘못 집행한 것을 되돌리는 기능도 없습니다 — 필요하면 새 줄로 바로잡아야 하고, 그 기능은 아직 없습니다 (9장).

### 들어오는 돈

가상 지방세뿐입니다 ([CITY_TAX_SYSTEM](CITY_TAX_SYSTEM.md)). 세금을 걷는 거래 안에서 명세 → 도시 재정 → (지갑) 순서로 함께 바뀝니다. 주민이 스스로 낸 방어 기여금은 여기로 오지 않고 그 시설의 기금에 바로 쌓입니다. 이사 수수료도 오지 않습니다.

### 나가는 돈

예산 집행뿐입니다 (4장). **도시 재정에서 플레이어의 지갑으로 GC 가 나가는 길은 없습니다.**

## 4. 예산의 사용처와 집행

| 분야 | 코드 | 집행하면 일어나는 일 |
|---|---|---|
| 공동 방어시설 | `defense_facility` | 고른 도시 공용 방어시설의 기금이 채워짐 (v8.0의 `city_defense_structures`). 단계가 오르면 그 도시의 방어전 관문이 튼튼해짐 |
| 방어시설 유지보수 | `defense_maintenance` | 피해를 입은 주요 시설이 고쳐짐 (v8.0의 `city_facility_states`). 한 단계의 값은 시설 정의의 복구비 |
| 도시 인프라 | `infrastructure` | **집행 내역만 남음** |
| NPC 복지시설 | `npc_welfare` | **집행 내역만 남음** |
| 게임 내 교육시설 | `education` | **집행 내역만 남음** |
| 도시 행사 | `event` | **집행 내역만 남음** |
| 예비비 | `reserve` | 예비비 계정에서 나감. **집행 내역만 남음** |

> 뒤의 다섯 분야는 아직 게임 안에 대응하는 시설·콘텐츠가 없습니다. 집행하면 재정에서 GC 가 빠지고 내역에 "집행 내역만 기록됩니다 (이 분야의 게임 내 효과는 준비 중)"이라고 남습니다. 콘텐츠가 붙기 전에는 이 분야의 집행을 미루는 것이 좋습니다.

집행은 관리자만 합니다 (`treasury.execute` 권한: 최고 관리자, 운영 담당). 두 길이 있습니다.

| 길 | 화면 | 내용 |
|---|---|---|
| 직접 집행 | 도시 재정 | 도시, 분야, 이름, 금액, 대상, 사유를 적음 |
| 참여예산의 집행 | 참여예산 관리 | 가결된 제안을 그대로 집행 ([PARTICIPATORY_BUDGET](PARTICIPATORY_BUDGET.md)) |

- 계정을 먼저 잠그고 잔액을 확인합니다. 모자라면 집행되지 않습니다.
- **실제로 쓰인 만큼만 빠집니다.** 시설이 거의 다 지어져 일부만 들어갔으면 그만큼만, 고칠 피해가 한 단계뿐이면 한 단계의 값만. 쓸 곳이 없으면(다 지었음, 고칠 곳 없음) 집행되지 않습니다.
- 집행 내역(`city_budget_expenditures`)과 원장, 시설의 변화가 하나의 거래로 바뀝니다.
- 사유를 적어야 하고 감사 기록(`treasury.spend`)에 남습니다.
- 동시에 두 번 집행해도 잔액을 넘겨 쓰지 못합니다 (`tests/ConcurrencyTest.php`).

## 5. 공개

누구나(이방인도) 어느 도시의 재정이든 볼 수 있습니다.

| 요청 | 내용 |
|---|---|
| `GET /cities/{code}/treasury` | 두 계정의 잔액, 세금 종류별 수입(누적, 최근 30일), 분야별 지출, 최근 원장 30줄, 예비비 비율 |
| `GET /cities/{code}/treasury/expenditures` | 집행 내역: 분야, 이름, 설명, 금액, 계정, 효과, 주민 투표로 정한 것인지, 때 |

공개하지 않는 것: 누가 얼마를 냈는지(세금 명세는 본인만 봄), 집행한 관리자의 계정, 관리자가 적은 내부 사유. 형식은 [API_SPEC](API_SPEC.md) 20장.

## 6. 맞는지 확인

예약 작업(`bin/tick.php`)이 돌 때마다 확인하고, 어긋나면 로그에 남기고 관리자 화면에 경고로 보입니다 (`Treasury::findInconsistency`).

| 확인 | 뜻 |
|---|---|
| 원장을 처음부터 더한 값 = 줄마다 적힌 "바뀐 뒤의 잔액" | 원장이 이어짐 |
| 잔액이 음수가 된 적이 없음 | |
| 원장의 합 = 계정의 잔액 | 원장 밖에서 잔액이 바뀌지 않았음 |
| 세금 명세의 합 = 원장에 들어온 세금의 합 | 걷은 것이 빠짐없이 들어옴 |
| 집행 내역의 합 = 원장에서 나간 합 | 내역 없이 나간 돈이 없음 |
| 지갑에서 빠진 세금(사업세·재산세)의 합 = 명세의 합(값에 들어 있는 거래세 제외) | 지갑과 명세가 맞음 |

## 7. 관리자

"도시 재정" 화면: 도시별 잔액과 누적, 한 도시의 원장, 집행 내역, 직접 집행. 보기는 `city.view`, 집행은 `treasury.execute`. [ADMIN_SYSTEM](ADMIN_SYSTEM.md) 12장.

## 9. 남은 일

- 다섯 분야(인프라, NPC 복지, 교육, 행사, 예비비)의 게임 내 효과. 지금은 기록뿐.
- 잘못한 집행을 바로잡는 기능 (반대 방향의 원장 줄).
- 시·도 단위의 재정, 도시 사이의 지원.
- 분기·연도별 결산 화면.
