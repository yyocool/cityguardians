# SCHOLARSHIP_REVIEW_POLICY — 장학 심사 규정 (초안)

> 기준 v7.0 · 2026-11-13 · 상태: **초안.** 아래에서 "서버가 강제한다"고 적은 것은 구현되어 테스트(`ScholarshipTest`)를 통과했습니다. "운영 규정"이라고 적은 것은 사람이 지켜야 하는 것이고, 확정되지 않았습니다. 법률가와 장학 운영 책임자의 검토가 필요합니다.

관련 문서: [`SCHOLARSHIP_SYSTEM.md`](SCHOLARSHIP_SYSTEM.md), [`PRIVACY_DATA_FLOW.md`](PRIVACY_DATA_FLOW.md), [`ADMIN_SYSTEM.md`](ADMIN_SYSTEM.md) 11장

---

## 1. 심사에 쓰는 것과 쓰지 않는 것

**쓰는 것**: 신청서(지원 동기, 활동·학습 계획, 본인이 확인한 문구), 제출 자료, 학교급.

**쓰지 않는 것** — 서버가 강제한다:

| 쓰지 않는 것 | 강제하는 방법 |
|---|---|
| 게임 플레이 기록, 전투 성적, 도시 랭킹, 레벨 | 심사 화면과 장학 서비스는 게임 테이블을 읽지 않는다. 심사위원 화면에 게임 계정·닉네임이 없다 |
| 게임머니(GC) 보유액, 은행·주식·대출 | 위와 같다 |
| 유료 결제 내역 | 위와 같다. 결제에 따른 가산점 기능이 없다 |
| 자격 조건으로서의 게임 기록 | 자격의 종류는 학교급·태어난 해·본인 확인 문구·제출 자료뿐. 다른 종류는 거절 |
| 평가 기준으로서의 게임 기록 | 기준의 이름·설명에 GC, 게임머니, 랭킹, 전투, 레벨, 결제, 플레이 시간, 아이템이 있으면 거절. 낱말 검사는 완전하지 않으므로 **공고를 승인하는 사람이 다시 확인한다** (운영 규정) |

**심사위원이 보지 못하는 것** — 서버가 강제한다: 이름, 태어난 해, 학교 이름, 이메일, 전화번호, 보호자 정보, 게임 계정. 심사위원에게 지원서는 접수 번호와 학교급으로만 보입니다. 신청자가 지원 동기나 제출 자료에 스스로 이름을 적으면 그것은 가려지지 않습니다 (신청 화면에서 적지 말라고 안내해야 합니다 — 운영 규정).

## 2. 역할과 권한의 분리

| 일 | 역할 | 서버가 강제하는 것 |
|---|---|---|
| 프로그램 작성, 자격·평가 기준 설정 | 장학 담당 (`sch_manager`) | 공고가 나간 뒤에는 바꿀 수 없다 |
| 공고 승인 | 장학 담당 또는 최고 관리자 | **작성하거나 마지막으로 고친 사람은 승인할 수 없다** |
| 접수, 보호자 동의 확인, 자격 확인 | 장학 담당 | 보호자 동의가 확인되지 않으면 자격 확인을 통과시킬 수 없다 |
| 신청자의 개인정보 열람 | 장학 담당, 최고 관리자 | 사유를 적어야 하고, 열 때마다 기록된다 |
| 심사위원 배정 | 장학 담당 | 역할이 `reviewer` 인 계정만 배정할 수 있다 |
| 평가 입력 | **심사위원 (`reviewer`) 만** | 최고 관리자도 점수를 넣지 못한다. 자기에게 배정된 지원서만 보인다 (남의 것은 "없는 심사") |
| 결과 집계, 선정 제안 | 장학 담당 | 필요한 수의 심사가 끝나야 한다. 선정 인원이 정원을 넘을 수 없다 |
| 최종 승인, 결과 통지 | 장학 담당 또는 최고 관리자 | **제안한 사람은 승인할 수 없다.** `scholarship_awards` 기능이 켜져 있어야 한다 |
| 이의신청 처리 | 장학 담당 또는 최고 관리자 | **원래 결정을 내린 사람은 처리할 수 없다** |
| 지급 상태 기록 | 지급 담당 (`finance`) | 기록한 사람은 승인할 수 없다. 신청자의 이름·연락처를 보지 못한다 |
| 감사 로그 열람 | 준법·개인정보 담당 (`compliance`), 최고 관리자 | — |

심사위원 역할은 게임 운영 화면(전투, 위험도)과 CITY PASS 화면을 보지 못합니다. 준법 담당은 장학 화면을 볼 수 있지만 개인정보를 열거나 결정을 내릴 수 없습니다.

이 분리 때문에 장학 사업을 돌리려면 **적어도 장학 담당 두 명(또는 장학 담당과 최고 관리자), 심사위원 두 명, 지급 담당 두 명(또는 지급 담당과 최고 관리자)** 이 필요합니다.

## 3. 심사 절차

### 3.1 평가 기준 설정

프로그램마다 평가 기준(이름, 설명, 만점 1~100, 가중치 1~100)을 정하고 공고에 공개합니다. 기준이 하나도 없으면 공고를 낼 수 없습니다.

### 3.2 접수와 자격 확인

1. 접수 기간 안에 들어온 신청만 받습니다 (서버 시각 기준).
2. 미성년자는 보호자 동의를 확인합니다 ([`SCHOLARSHIP_SYSTEM.md`](SCHOLARSHIP_SYSTEM.md) 6장).
3. 장학 담당이 자격을 확인합니다. 해당하면 확인 내용을, 해당하지 않으면 사유를 적습니다 (필수). 해당하지 않는다는 사유는 신청자에게 보입니다.
4. 자격이 확인되면 그 프로그램의 **모든 심사위원에게** 배정됩니다.

### 3.3 평가 입력

- 심사위원은 기준마다 0점부터 만점까지의 점수를 넣고, 심사 의견(10자 이상)을 적습니다.
- **낸 평가는 고칠 수 없습니다.**
- 지원자와 이해관계가 있으면 사유를 적고 **회피**합니다. 회피한 심사는 집계에서 빠집니다.
- 심사위원은 다른 심사위원의 점수를 보지 못합니다.

이해관계의 범위(가족, 사제 관계, 같은 학교 등)와 회피를 요구하는 절차는 **운영 규정으로 정해야 합니다.** 지금은 심사위원 스스로 회피하는 기능만 있습니다.

### 3.4 결과 집계

- 한 심사의 총점 = Σ(점수 ÷ 만점 × 가중치) ÷ Σ가중치 × 100. 소수 둘째 자리까지 저장합니다.
- 지원서의 점수 = 낸 심사들의 총점의 평균.
- 집계 화면은 점수가 높은 순서로 접수 번호, 학교급, 심사 수, 점수를 보여 줍니다. 개인정보는 없습니다.
- 지원서마다 필요한 수(기본 2건)의 심사가 끝나지 않으면 결정할 수 없습니다.

점수가 같을 때의 순서, 심사위원 사이의 점수 차가 클 때의 조정은 **정해져 있지 않습니다** (운영 규정 필요). 서버는 점수 순서대로 자동으로 선정하지 않습니다: 사람이 지원서마다 결정을 고릅니다.

### 3.5 선정 제안과 최종 승인

1. 접수를 마감한 뒤, 장학 담당이 심사 중인 지원서마다 **선정 / 예비 선정 / 선정되지 않음** 을 고르고 선정 사유를 적어 제안합니다. 선정 인원은 정원을 넘을 수 없습니다.
2. **다른 관리자**가 사유를 적고 최종 승인합니다. 승인 전에는 다시 제안할 수 있습니다.
3. 승인된 결과는 아직 신청자에게 보이지 않습니다.

### 3.6 결과 통지

- 자격 확인이나 심사가 끝나지 않은 신청이 하나라도 있으면 통지할 수 없습니다. **모두 결정한 뒤 한꺼번에** 알립니다.
- 통지하면 신청자의 진행 상태 화면에 결과가 보입니다. 서버는 문자나 메일을 보내지 않습니다 — 따로 연락할지는 운영 규정으로 정합니다.
- 이때 개인정보의 보관 기한이 정해집니다.
- 신청자가 결과를 처음 본 때가 기록됩니다.

### 3.7 이의신청

| 항목 | 내용 |
|---|---|
| 할 수 있는 사람 | 자격에 해당하지 않는다는 결정을 받은 신청자, 예비 선정 또는 선정되지 않음을 통지받은 신청자 |
| 기간 | 결정·통지를 받은 날부터 프로그램에 정한 기간 (기본 7일, 3~30일) |
| 횟수 | 신청 하나에 한 번 |
| 내용 | 사유 20~2000자. 암호화해 저장한다 |
| 처리 | 원래 결정을 내리지 않은 관리자가 받아들임/받아들이지 않음과 답변(10자 이상)을 적는다. 서버가 막는 "원래 결정을 내린 사람"은 자격을 확인한 사람(자격 미해당)과 선정을 제안한 사람(선정 결과)이다. **최종 승인만 한 사람은 서버가 막지 않는다** — 운영 규정으로 배제해야 한다 |
| 받아들이면 | 자격 미해당이었으면 접수 상태로, 결과 통지 뒤였으면 심사 중으로 되돌아간다. 선정 결과는 "다시 봄" 상태가 되고, 제안·승인·통지를 다시 거친다 |

이의신청이 받아들여져 선정이 바뀔 때 정원을 넘는 경우의 처리는 **정해져 있지 않습니다** (서버는 정원을 넘는 선정을 막습니다).

### 3.8 심사 로그

`scholarship_audit_logs` 에 추가만 합니다. 남는 것: 프로그램의 작성·수정·상태 전환, 자격·기준의 추가·삭제, 심사위원 배정, 신청 접수·철회, 보호자 동의의 열람·동의·확인, 신청서 열람, **개인정보 열람(사유 포함)**, 자격 확인, 심사 열람·제출·회피, 선정 제안·승인, 결과 통지, 신청자의 결과 확인, 이의신청과 처리, 지급 기록의 생성·승인·완료·취소, 개인정보 삭제.

## 4. 운영 규정으로 정해야 하는 것 (미정)

- 심사위원의 위촉 기준, 임기, 외부 위원의 비율, 서약서(비밀 유지, 이해충돌).
- 이해관계의 범위와 신고 절차.
- 동점, 점수 편차, 예비 선정자의 승계.
- 결과를 따로 연락하는 방법과 문구.
- 이의신청을 받아들였을 때 재심사하는 심사위원 (같은 사람인가, 다른 사람인가).
- 선정 뒤의 의무(활동 보고 등)와 선정 취소 사유.
- 장학 담당·지급 담당·준법 담당을 누가 맡는가.
